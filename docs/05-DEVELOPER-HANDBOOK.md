## 2. Железные правила

Нарушение любого — автоматический возврат тикета.

| № | Правило | Почему |
|---|---|---|
| **Ж1** | **Никогда не объявляй тикет готовым, не прогнав команды из §5.** | В волнах 2–3 сдано 12 красных тестов. Тест, ловящий баг в главной функции продукта, был написан и ни разу не запущен |
| **Ж2** | **Написал компонент — подключи его к рантайму в том же тикете.** | `TenantResolutionMiddleware` написан, но в `app.module.ts` вместо регистрации остался комментарий «EP-02 добавит позже». Ни один запрос не резолвил тенанта |
| **Ж3** | **Никогда не отключай проверку, чтобы гейт позеленел.** | `apps/admin` исключили из `arch:check`. Зелёный гейт, купленный исключением приложения из анализа, — это не гейт |
| **Ж4** | **Каждый `eslint-disable` — с обоснованием после `--`.** | Сейчас 54 подавления из 56 без причины. Подавление без причины неотличимо от сокрытия дефекта |
| **Ж5** | **Никогда не выдумывай `SRS-*` идентификаторы и API, которых нет.** | Если требования нет — напиши об этом в отчёте, а не сочиняй номер |
| **Ж6** | **Не реализуй то, что вне твоего тикета и вне текущей волны.** | В волнах 2–3 начали Analog Engine из волны 6 и не закончили. Потраченное время не дало ничего |
| **Ж7** | **Деньги — только целые дирамы (`int`). Ни одного `float` в денежной арифметике.** | 1 TJS = 100 дирам. Float на деньгах = расхождение бухгалтерии |
| **Ж8** | **В `domain/` запрещены: фреймворки, ORM, сеть, `Date.now()`, `Math.random()`, `process.env`.** | Только порты `Clock` и `IdGenerator`. Иначе тесты недетерминированы |
| **Ж9** | **Ноль хардкодных строк для пользователя (только i18n) и ноль хардкодных цветов (только CSS-переменные).** | White-Label: смена бренда обязана стоить смену конфига, ноль правок кода |
| **Ж10** | **Не трогай файлы вне своего `files_owned`.** | Кроме barrel-файлов — их правь только добавлением строк (§11) |

## 3. Что значит «готово»

Тикет готов, когда выполнены ВСЕ пункты. Не «в основном», не «почти».

- [ ] Реализовано всё из раздела «Что сделать» тикета
- [ ] **Каждый** критерий приёмки Given/When/Then выполнен, и ты можешь назвать файл и функцию,
      которые его реализуют
- [ ] Написаны тесты из раздела «Тест-план» тикета
- [ ] **Компонент подключён к рантайму** (§8) — модуль в `AppModule`, middleware в `configure()`,
      guard в провайдерах, роут отвечает
- [ ] Все команды из §5 зелёные — **прогнаны, а не предположены**
- [ ] Нет хардкода строк и цветов
- [ ] Нет подавлений линтера без обоснования
- [ ] Отчёт по формату §16 заполнен честно

**Если что-то не сделано — так и напиши.** Частично выполненный тикет с честным отчётом
принимается лучше, чем «готово» с сюрпризами. Ложное «готово» — худшее, что можно сдать.

grep -rn "ИмяКласса\|имяФункции" apps packages --include=*.ts | grep -v node_modules

Расширить существующее лучше, чем создать дубль. Новый класс оправдан, если старый

## 5. Обязательная проверка перед сдачей

Выполни **все** команды. Скопируй их вывод в отчёт.

```bash
# 1. Типы — по своему пакету
npx tsc --noEmit -p <твой-пакет>/tsconfig.json

# 2. Линтер — по своим файлам
npx eslint <свои файлы> --max-warnings=0

# 3. Тесты — по своему пакету, ЦЕЛИКОМ, а не только свой файл
npx vitest run --root <твой-пакет>

# 4. Архитектура — по всему репозиторию
npx depcruise --config .dependency-cruiser.cjs apps packages

# 5. Ловушка на ловушку — защита архитектуры всё ещё ловит нарушения
npx vitest run tests/arch/run-fixture-check.spec.ts

# 6. ПОЛНАЯ проверка — обязательна перед сдачей волны
pnpm verify
```

### Правила чтения результата

- **Красное — это стоп.** Не «потом починим», не «это чужой тест».
- Если упал тест, который ты не трогал — **разберись**. Скорее всего, ты сломал контракт,
  на который он опирался. Это не «чужая проблема», это твой регресс.
- Если упало из-за отсутствия БД или Redis — так и напиши в отчёте, с точным текстом ошибки.
  Не выдавай это за успех.

### Чего делать НЕЛЬЗЯ, чтобы получить зелёный результат

| Запрещено | Что делать вместо |
|---|---|
| Удалить или закомментировать падающий тест | Починить код или, если тест неверен, обосновать это в отчёте |
| Добавить `it.skip` | То же |
| Отключить правило линтера в конфиге | Исправить код |
| Исключить папку из `arch:check` | Исправить нарушение или починить резолвер |
| Понизить `severity` с `error` на `warn` | То же |
| Ослабить порог покрытия | Дописать тесты |
| Написать `expect(true).toBe(true)` | Написать настоящую проверку |

## 6. Архитектура: куда что класть

```
apps/api/src/modules/<контекст>/
├── domain/              ← сущности, VO, доменные сервисы, доменные ошибки, state machine
│   └── ЗАПРЕЩЕНО: @nestjs/*, drizzle-orm, pg, ioredis, bullmq, zod, pino, axios,
│                   Date.now(), Math.random(), process.env, импорты из соседних слоёв
├── application/         ← use case (один класс = один метод execute()), порты (интерфейсы), политики
│   └── ЗАПРЕЩЕНО: импорты из infrastructure и presentation, знание об HTTP
├── infrastructure/      ← репозитории Drizzle, HTTP-клиенты, продюсеры BullMQ, адаптеры провайдеров
│   └── реализует порты из application
├── presentation/        ← контроллеры, WS-gateway, guard'ы, pipe'ы, мапперы DTO↔domain
│   └── ЗАПРЕЩЕНО: импортировать domain напрямую в обход application
├── <контекст>.module.ts ← barrel: регистрация провайдеров
└── index.ts             ← barrel: публичный фасад модуля
```

### Направление зависимостей

```
presentation ──▶ application ──▶ domain ◀── infrastructure
```

**Стрелки только внутрь.** `infrastructure` реализует порты `application`, но `application`
о ней не знает.

### Межмодульное взаимодействие

Только через `modules/<контекст>/index.ts`. Импорт `orders/domain/order.entity` из модуля
`payments` — блокирующее нарушение. Правильно:

```ts
import { OrdersFacade } from '@/modules/orders'
```

### Куда класть общее

| Что | Куда |
|---|---|
| Zod-схемы API, коды ошибок, permission-строки | `packages/contracts` |
| Доменные VO, общие для нескольких модулей (Money, Dosage, Barcode) | `packages/domain-kernel` |
| Словари tj/ru/en | `packages/i18n` |
| React-компоненты дизайн-системы | `packages/ui` |
| Тест-дублёры (Clock, IdGenerator, builder) | `packages/testing-kit` |

### Фронтенд

```
src/app → src/pages → src/features → src/entities → src/shared
```

Зависимости строго вниз. **Горизонтальные импорты между фичами запрещены** — общее
выносится в `entities` или `shared`. Компонент не содержит бизнес-логики и не вызывает
`fetch` напрямую — только через слой `api` + TanStack Query.

## 7. Разбор реальных ошибок волн 2–3

Это не гипотетика. Каждая ошибка ниже была допущена и подтверждена проверкой.

### 7.1 Компонент написан, но не подключён

**Что было:** `TenantResolutionMiddleware` реализован полностью. В `app.module.ts` — комментарий:

```ts
// EP-02 добавляет `TenantResolutionMiddleware` СТРОГО ПОСЛЕ этих двух строк.
```

Middleware так и не добавили. **Результат: ни один запрос не резолвил тенанта.**
Ни `tsc`, ни `eslint`, ни `arch:check` этого поймать не могут — код формально безупречен.

**Как правильно:**

```ts
configure(consumer: MiddlewareConsumer): void {
  consumer.apply(RequestContextMiddleware, HttpLoggerMiddleware, TenantResolutionMiddleware).forRoutes('*')
}
```

**Правило:** оставлять в коде комментарий «следующий тикет подключит» — запрещено.
Подключаешь ты, в своём тикете.

### 7.2 Модуль-пустышка, не импортированный в приложение

**Что было:** `CatalogModule` — буквально `@Module({})`, и его нет в `AppModule.imports`.
У каталога — ядра продукта — **ноль HTTP-эндпоинтов**.

**Как правильно:** если тикет создаёт use case или контроллер — зарегистрируй их в модуле,
а модуль добавь в `AppModule.imports` **в том же тикете**.

### 7.3 Тесты написаны и ни разу не запущены

**Что было:** в `packages/domain-kernel` лежат тесты на эквивалентность дозировок:

```
× 500 mg equivalent to 0.5 g
× 500 mg equivalent to 500_000 mcg
× 500 mcg equivalent to 0.5 mg
```

Все три красные. Это **ядро подбора аналогов по МНН** — главная ценность продукта.
Тесты написали правильно, баг они ловят, но их не запустили.

**Правило:** `npx vitest run --root <пакет>` перед сдачей. Всегда.

### 7.4 Эндпоинты открыты без аутентификации

**Что было:** 9 контроллеров помечены `@Public()`, включая одобрение и отклонение заявок
аптечных сетей. Любой неаутентифицированный вызов мог утвердить или аннулировать заявку.

**Правило:** `@Public()` ставится ТОЛЬКО если тикет прямо этого требует (например, публичная
форма заявки или `/health`). Для всего остального — guard роли. Если авторизации ещё нет
в проекте — **не открывай эндпоинт, а заблокируй его и напиши об этом в отчёте**.

### 7.5 Скрипт указывает на несуществующий файл

**Что было:** `db:seed` вызывает `src/infrastructure/database/seed.ts`, а сид лежит в
`src/db/seed/`. Команда из документации не работает, 317 позиций каталога не грузятся.

**Правило:** добавил npm-скрипт — **запусти его**. Один раз, целиком.

### 7.6 Проверка отключена ради зелёного гейта

**Что было:** в `.dependency-cruiser.cjs` добавлено исключение `apps/admin` из анализа
с объяснением про резолвер алиасов. Проблема резолвера решаема; вместо решения — отключение.

**Правило:** гейт, который зеленеет за счёт исключения кода из проверки, не является гейтом.
Если инструмент настроен неправильно — чини инструмент и напиши об этом в отчёте.

### 7.7 Начата работа вне волны

**Что было:** начали Analog Engine (эпик волны 6) и не закончили: есть доменный сервис,
нет репозитория, use case, контроллера, i18n и фронтенда.

**Правило:** делай свой тикет. Увидел проблему в чужом — напиши в отчёте, не чини молча.

## 8. Подключение к рантайму — отдельный обязательный шаг

Это главный провал волн 2–3, поэтому вынесен в отдельный раздел.

**Написанный, но неподключённый код — это не сделанная работа.** Он проходит все статические
проверки и создаёт иллюзию готовности.

### Чеклист подключения

| Что написал | Где обязан подключить | Как проверить |
|---|---|---|
| Use case | Провайдер в `<контекст>.module.ts` | Приложение стартует, DI резолвит |
| Репозиторий (адаптер порта) | `{ provide: TOKEN, useClass: ... }` в модуле | То же |
| Контроллер | `controllers: [...]` в модуле | Маршрут отвечает |
| Модуль | `AppModule.imports` | Маршруты модуля доступны |
| Middleware | `configure(consumer)` в `AppModule` | Запрос проходит через него |
| Guard | Провайдер модуля или `APP_GUARD` | Неавторизованный запрос отклоняется |
| Обработчик очереди | Регистрация процессора BullMQ в worker | Job обрабатывается |
| npm-скрипт | `package.json` | **Скрипт запущен вручную** |
| Компонент React | Импортирован в страницу и отрисован | Виден в приложении |
| Ключ i18n | Есть во ВСЕХ трёх словарях tj/ru/en | Нет пропусков |

### Проверка «поднимается ли приложение»

```bash
# API поднимается и отвечает
pnpm --filter @dorutj/api dev
# в другом терминале:
curl -i http://localhost:3000/health
curl -i http://localhost:3000/ready
```

Если твой тикет добавил маршрут — **дёрни его curl'ом** и приложи ответ к отчёту.

## 9. Тесты

### Что покрывать обязательно

| Слой | Порог | Что тестировать |
|---|---|---|
| `domain/` | ≥90% | Инварианты, запрещённые переходы состояний, граничные значения VO |
| `application/` | ≥90% | Каждый use case: успех, отказ по политике, ошибка порта |
| `infrastructure/` | ≥70% | Маппинг, обработка ошибок БД/сети |
| `presentation/` | ≥70% | HTTP-контракт: коды ответов, формат ошибок, валидация |

### Как писать

**Тест проверяет поведение, а не реализацию.**

```ts
// ПЛОХО — повторяет реализацию, сломается при любом рефакторинге
expect(service.calculate).toHaveBeenCalledWith(100)

// ХОРОШО — проверяет результат, важный для бизнеса
expect(order.totalDiram).toBe(12_500)
```

**Обязательно негативные сценарии.** На каждый счастливый путь — минимум один отказ.

```ts
it('отклоняет переход paid_escrow → confirmed', () => {
  expect(() => order.markConfirmed()).toThrow(InvalidStatusTransitionError)
})
```

**Детерминированность обязательна.** Никакого реального времени и случайности:

```ts
import { FixedClock, SequentialIdGenerator } from '@dorutj/testing-kit'

const clock = new FixedClock('2026-08-28T10:00:00Z')
const ids = new SequentialIdGenerator()
```

### Чего в тестах быть не должно

- Тавтологии: `expect(x).toBe(x)`
- Тестов без единого `expect`
- `it.skip` и `it.todo` в сдаваемом коде
- Зависимости от порядка выполнения тестов
- Реальных сетевых вызовов

## 10. Подавления линтера

Подавление разрешено, когда правило **объективно неприменимо** к конкретному месту.
Оно **запрещено**, когда правило нашло настоящую проблему.

### Формат — обязателен

```ts
// eslint-disable-next-line no-restricted-globals -- этот файл И ЕСТЬ слой api, ему разрешён fetch (§5 архитектуры)
const response = await fetch(url)
```

Без части после `--` подавление считается сокрытием дефекта и возвращается на доработку.

### Примеры

| Ситуация | Можно? |
|---|---|
| Файл слоя `api` использует `fetch`, а глобальный запрет для компонентов | **Да**, с обоснованием |
| `.cjs`-конфиг использует `require` | **Да**, с обоснованием |
| NestJS-модуль с пустым телом класса | **Да**, с обоснованием |
| `domain/` импортирует `drizzle-orm` | **Нет.** Это нарушение архитектуры, выноси в infrastructure |
| `Date.now()` в domain | **Нет.** Используй порт `Clock` |
| Магическое число в бизнес-логике | **Нет.** Заведи именованную константу |
| Функция длиннее 40 строк | **Нет.** Разбей на функции |

## 11. Barrel-файлы (решение D-27)

Эти файлы **не принадлежат никому** и агрегируют вклад многих тикетов:

```
index.ts, *.module.ts, package.json, tsconfig.json,
.github/workflows/*.yml, infra/docker/docker-compose*.yml
```

**Правила работы:**

1. Правь **только добавлением строк**. Никогда не переписывай целиком.
2. **Перечитай файл непосредственно перед правкой** — его мог изменить другой тикет.
3. Не удаляй чужие строки.
4. При конфликте слияния — эскалируй архитектору, не решай сам.

## 12. Деньги, время, случайность

### Деньги

```ts
// ПРАВИЛЬНО: целые дирамы
const totalDiram: number = itemsDiram + deliveryDiram   // 1 TJS = 100 дирам

// ЗАПРЕЩЕНО
const total = 125.50 + 15.00        // float на деньгах
const total = price * 1.08          // процент через float
```

Комиссия и проценты считаются в целых с явным правилом округления, зафиксированным в тикете.

### Время

```ts
// ПРАВИЛЬНО — в domain и application
constructor(private readonly clock: Clock) {}
const now = this.clock.now()

// ЗАПРЕЩЕНО в domain
const now = Date.now()
const now = new Date()
```

### Идентификаторы

```ts
// ПРАВИЛЬНО
constructor(private readonly ids: IdGenerator) {}
const id = this.ids.next()

// ЗАПРЕЩЕНО в domain
const id = crypto.randomUUID()
const id = Math.random().toString()
```

## 13. Безопасность — обязательный минимум

1. **Каждый эндпоинт по умолчанию защищён.** `@Public()` — только когда тикет прямо требует.
2. **Каждый запрос имеет резолвленного тенанта.** Запрос без тенанта отклоняется.
3. **Каждый запрос к данным скоупится по тенанту** на уровне репозитория, а не в контроллере.
4. **Весь внешний ввод — через Zod** из `packages/contracts`.
5. **Никогда не логируй**: телефоны, токены, пароли, содержимое рецептов, платёжные данные.
6. **Секреты только из ENV.** Ни одного ключа, пароля или токена в коде и в git.
7. **Проверяй принадлежность объекта.** Нельзя получить чужой заказ по прямому id.
8. **Вебхуки**: проверка HMAC-подписи, `timestamp`, `nonce`, окно 5 минут.
9. **API-ключи аптек** хранятся как argon2-хеш, показываются один раз при создании.

## 14. Что делать, когда застрял

**Не додумывай молча. Не пропускай. Не имитируй.**

| Ситуация | Что делать |
|---|---|
| Требования SRS нет или оно противоречиво | Реализуй разумный вариант, зафиксируй в отчёте в поле `assumptions` |
| Нужен пакет, которого нет в зависимостях | **Не устанавливай.** Верни в `needsDependency` и обойдись имеющимся |
| Тикет зависит от несделанного тикета | Реализуй свою часть, порт застабь `null`-адаптером с явным TODO и ссылкой на тикет |
| Найдена ошибка в чужом коде | Напиши в отчёте в поле `foundIssues`. Не чини молча — это чужой `files_owned` |
| Не получается сделать проверку зелёной | Верни `blockers` с точным текстом ошибки. **Не отключай проверку** |
| Тикет оказался больше, чем казался | Сделай столько, сколько сделал качественно, честно опиши остаток |

**Заглушка оформляется явно:**

```ts
/**
 * Временная заглушка: отмена заказов реализуется в EP-10 (DTJ-24x).
 * До тех пор онбординг не каскадит отмены — это осознанное ограничение, а не пропуск.
 */
export class NullOrdersCancellationAdapter implements OrdersCancellationPort {
  async cancelPendingByPharmacy(): Promise<void> {
    // намеренно пусто: см. комментарий выше
  }
}
```

## 15. Чего не делать никогда

- ❌ Объявлять готовым непроверенное
- ❌ Оставлять написанный компонент неподключённым
- ❌ Отключать проверку, чтобы гейт позеленел
- ❌ Удалять или скипать падающий тест
- ❌ Подавлять правило линтера без обоснования
- ❌ Выдумывать `SRS-*` номера и несуществующие API
- ❌ Делать работу из другой волны
- ❌ Использовать `float` в денежных расчётах
- ❌ Класть `Date.now()`, `Math.random()`, `process.env` в `domain/`
- ❌ Хардкодить пользовательские строки и цвета
- ❌ Переписывать barrel-файл целиком
- ❌ Устанавливать зависимости внутри тикета реализации
- ❌ Оставлять `TODO` без ссылки на тикет, который его закроет
- ❌ Коммитить мусор (в волне 2–3 в корень попал каталог `false/v11` — след ошибки в shell-команде)

## 16. Формат отчёта о сдаче тикета

```
ТИКЕТ: DTJ-NNN

ФАЙЛЫ СОЗДАНЫ/ИЗМЕНЕНЫ:
  - путь/к/файлу.ts (что сделано)

ПОДКЛЮЧЕНИЕ К РАНТАЙМУ:
  - Модуль зарегистрирован в: apps/api/src/app.module.ts:21
  - Маршрут проверен: GET /api/v1/... → 200
  (или: подключение не требуется — почему)

КРИТЕРИИ ПРИЁМКИ:
  1. <текст критерия> → ВЫПОЛНЕН, реализация: файл.ts:функция
  2. <текст критерия> → НЕ ВЫПОЛНЕН, причина: ...

ТЕСТЫ:
  - файл.spec.ts — N кейсов, из них M негативных

ПРОВЕРКИ (вывод команд):
  tsc --noEmit        → OK / текст ошибки
  eslint              → OK / текст ошибки
  vitest run          → N passed, M failed / текст
  depcruise           → OK / текст
  test:arch           → 9 passed

ДОПУЩЕНИЯ: <что домыслил, потому что спека молчала>
БЛОКЕРЫ: <что не смог и почему>
НАЙДЕННЫЕ ЧУЖИЕ ПРОБЛЕМЫ: <что заметил вне своего тикета>
НУЖНЫЕ ЗАВИСИМОСТИ: <пакеты, которые не стал ставить сам>
```

**Честный отчёт с блокерами ценнее ложного «всё готово».**
Ложное «готово» стоит дороже всего: его находят через несколько волн, когда поверх
уже построено ещё три эпика.
