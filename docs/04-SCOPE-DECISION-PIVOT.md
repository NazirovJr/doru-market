## 2. Что изменилось и почему (одним абзацем для всех агентов)

Разведка доказала: боль **«я переплачиваю в разы, потому что не вижу дешёвого аналога и реальную
цену в аптеке рядом»** — реальна (разброс цен ×9.8–10 на идентичном МНН) и **не закрыта никем**.
Одновременно доказано: слой **«доставка лекарств домой» занят почти 3 года** (МегаФон Life +
Salomat.tj, 100k+ установок, 4.7★, доставка 45 мин), а **транзакционный спрос не подтверждён**
(единственный полноценный e-commerce конкурент Salomat.tj — 500+ установок, 0 отзывов).
Из 7 заявленных отличий защитимы **только два**: D1 (аналоги по МНН с расчётом экономии) и
D3 (мультиаптечные остатки в реальном времени). D6 (нейтральный агрегатор) уже занят `doru.tj`.
Поэтому: **строим полный продукт, но релизами, начиная с того, что проверяет гипотезу**, а не всё сразу.

### 2.1 Смена позиционирования (обязательна к соблюдению в UI и текстах)

| Было | Стало |
|---|---|
| «Закажи лекарства с доставкой» | **«Найди то же лекарство дешевле рядом с тобой»** |
| Главный экран — каталог и доставка | Главный экран — **поиск и сравнение цены с показом экономии** |
| Ключевая метрика — заказы | Ключевая метрика — **экономия пользователя в сомони** |

Доставка остаётся функцией, но **не является УТП** и не занимает первый экран. Конкурировать
с суперприложением оператора в его же поле — заведомо проигрышно.

### 2.2 Принцип разбиения на релизы

Отсрочке подлежит НЕ то, что дорого писать, а то, что **заблокировано внешней зависимостью,
которую не контролирует инженерная команда** (договор с банком, реальные эндпоинты 1С у аптек,
подписанный LOI сети) — или то, что **обслуживает неподтверждённый спрос**.
Архитектура (слои, порты, tenant-скоуп, ledger) закладывается **сразу и целиком** — ретрофит
мультитенантности и денежного учёта стоит дороже, чем сделать их с первого дня.

## 3. RELEASE 1 — «Дешевле рядом» (ядро). НОВЫЙ Definition of Product Done

**R1 — это законченный, полностью рабочий продукт, а не прототип.** Все стандарты качества
(`02-CLEAN-ARCHITECTURE-AND-CODE.md`, `pnpm verify`, покрытие, E2E) действуют в полном объёме.

### 3.1 Функциональный состав R1

| # | Возможность | Обоснование |
|---|---|---|
| R1-1 | **Движок аналогов по МНН** — множество действующих веществ + совместимость формы + эквивалентность дозировки (D-07), расчёт экономии в сомони и процентах, обязательные юридические дисклеймеры | **Ядро продукта.** Единственное отличие, признанное защитимым и не закрытым никем |
| R1-2 | **Каталог**: medicines, substances, medicine_substances, категории, i18n-описания; seed ≥300 курированных позиций с корректными связями | Основание для R1-1 |
| R1-3 | **Умный поиск**: PostgreSQL FTS + pg_trgm + unaccent, опечатки («цытрамон»→«цитрамон»), таджикская кириллица (ӣ ӯ ҳ қ ғ ҷ), транслит, поиск по МНН, бренду, штрихкоду; автодополнение | CUJ-1 |
| R1-4 | **Мультиаптечные цены и остатки** с привязкой к конкретной точке, `last_synced_at`, честная пометка «данные могут быть неактуальны» при просрочке SLA | D3 — второе защитимое отличие |
| R1-5 | **Приём данных от аптек — 3 канала**: импорт Excel/CSV, ручной ввод в веб-кабинете, REST API с ключом. Composite-матчинг (D-06) + очередь модерации | Работает с аптеками, у которых **нет** автоматизации. Не требует ни одного договора об интеграции |
| R1-6 | **Карта аптек** (MapLibre/OSM) с ценами, остатками, режимом работы, «открыто сейчас», «24/7», радиусом | CUJ-1 |
| R1-7 | **Корзина и оформление заказа**, резерв остатка с TTL, мультиаптечное разделение | Проверка «доходит ли до покупки» |
| R1-8 | **Оплата: наличными при получении** + полноценный **ledger двойной записи** (комиссия платформы, доля курьера). `MockBankProvider` реализован и покрыт тестами | Ledger нужен даже для наличных. Банковская интеграция — R3, но код готов |
| R1-9 | **Кабинет аптеки** (web): свои остатки и цены, входящие заказы, сборка, статусы, отчёты, API-ключи | Заменяет Flutter-терминал в R1 |
| R1-10 | **Курьерский веб-модуль** (адаптив): список назначений, ориентиры, карта, подтверждение вручения OTP | Заменяет Flutter-курьера в R1 |
| R1-11 | **Админ-панель**: модерация каталога, аптеки и верификация лицензий (D-22), пользователи, заказы, финансы | Операционка |
| R1-12 | **Auth**: OTP по телефону, JWT access/refresh, RBAC на 5 ролей, `MockSmsProvider` | Основание всего |
| R1-13 | **Telegram-бот** как основной канал уведомлений (D-23) + **Telegram Mini App** режим веб-приложения | Основной канал в РТ, дешевле SMS |
| R1-14 | **i18n tj / ru / en**, дефолт `tj`, словари отдаются по API | Требование рынка и §3.6 |
| R1-15 | **Продуктовая аналитика и метрики** — воронка: показ экономии → клик на аналог → добавление в корзину → заказ; экономия в сомони; готовность аптек присылать данные | **Обязательно.** Без этого невозможно проверить kill-критерии |
| R1-16 | **Мультитенантность на уровне схемы и репозиториев** (`tenant_id` везде, guard, тест на утечку) | Ретрофит дороже. UI White-Label — R3 |

### 3.2 Критерии приёмки R1

1. `docker compose up -d` поднимает весь стек; `pnpm install && pnpm db:migrate && pnpm db:seed && pnpm dev` работает без Docker.
2. `pnpm verify` (typecheck + lint + arch:check + test + build) — зелёный.
3. Покрытие `domain/` и `application/` ≥ 90 %, остального ≥ 70 %.
4. E2E зелёные: **CUJ-1** (поиск и аналоги), **CUJ-2'** (заказ с оплатой наличными),
   **CUJ-3'** (сборка в веб-кабинете аптеки), **CUJ-4'** (доставка + OTP вручения),
   **CUJ-6'** (импорт остатков Excel/REST → видно в поиске), **CUJ-7'** (изоляция тенантов).
5. Работает **без единого внешнего API-ключа** (все провайдеры — Mock).
6. Смена `BRAND_NAME` в конфиге меняет бренд везде; E2E проверяет отсутствие хардкода.
7. Метрики R1-15 пишутся и доступны в админке.

## 5. RELEASE 3 — Escrow с банком и White-Label

Заблокирован **внешними зависимостями**, которые не контролирует инженерная команда.

| # | Возможность | Блокер |
|---|---|---|
| R3-1 | **Escrow с реальным банком**: `AlifMobiProvider` / `DcNextProvider`, QR/deeplink, вебхуки с HMAC, hold/capture или отложенный payout (D-02) | Договор мерчанта и sandbox от банка |
| R3-2 | **White-Label UI**: конфигуратор брендинга, custom domains, боты под брендом сети, мерчант-креды тенанта | Подписанный LOI или оплаченный пилот сети/суперапп-платформы |
| R3-3 | **Споры и возвраты** (D-09, D-24): `order_returns`, `order_disputes`, заморозка payout | Требует реального объёма транзакций |
| R3-4 | **Фискализация** (`FiscalReceiptProvider`) | Актуальный регламент ККМ |

> **B2B-коррекция вердикта**: White-Label питчится **не мелким сетям** (там мы проигрываем по цене
> локальным веб-студиям Душанбе), а **суперапп-платформам** (DC Next, Humo) и только на функциях,
> которые веб-студия физически не воспроизведёт: 1С-синк, МНН-движок, escrow, OCR «из коробки».

## 6. Что НЕ строим (до явного триггера пересмотра)

- Полный `Definition of Product Done` устава **одним релизом** — прямо опровергается доказательствами спроса.
- Маркетинг и первый экран вокруг **«доставка лекарств домой»** — поле занято 3 года.
- **Публикация в сторах и регистрация домена** под именем DoruTJ до юридического заключения.
- **White-Label питч мелким сетям** с позиционированием «у вас нет сайта».

## 7. Kill-критерии (проверяются на данных из R1-15)

Разработка следующего релиза **останавливается**, если после 6–8 недель реальной эксплуатации R1:

1. Доля кликнувших на показанный дешёвый аналог и дошедших до заказа близка к нулю.
2. Менее 3 из 5–10 пилотных аптек готовы присылать цены/остатки хотя бы вручную.
3. Пользователи видят разницу в цене, но систематически идут в ближайшую аптеку («недалеко» побеждает «дёшево»).
4. МегаФон Life / Alif / игрок по паттерну Kaspi.kz добавляет мультиаптечное сравнение с МНН-подбором.
5. Банки не дают sandbox в течение 2 кварталов переговоров (блокирует R3-1).
6. Ни одна сеть/суперапп не проявляет интереса к B2B-пилоту (блокирует R3-2).
7. Конфликт бренда с `doru.tj` эскалирует в юридический спор.

**Явно НЕ основание для остановки**: лидерство `doru.tj` в слое «поиск + сравнение» — он
подтверждённо не решает МНН-экономию и мультиаптечную актуальность остатков даже за 5 лет.

## 8. Требование к бренду (следствие решения владельца)

`DoruTJ` остаётся рабочим именем. **Хардкод строки бренда, домена, палитры и логотипа в коде и
UI — блокирующий дефект ревью.** Источники: `BRAND_*` в конфиге, i18n-ключ `brand.name`,
CSS-переменные `--brand-*`. Обязательный E2E-тест: смена `BRAND_NAME` меняет бренд во всех
приложениях, старой строки не остаётся нигде.
