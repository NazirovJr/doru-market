# Шаблон брифа исполнителю

Бриф — то, что координатор даёт субагенту вместе с номером тикета. Правила исполнителя не дублируются: они в
[`AGENTS.md`](../../AGENTS.md), формат отчёта — [report-format.md](report-format.md), протокол волны — [wave-protocol.md](wave-protocol.md).
Бриф добавляет только то, что меняется от волны к волне. Значения в угловых скобках подставляет координатор.

---

```markdown
# Бриф: <волна, тема, дата>

## Задача
Тикет `DTJ-NNN` (`tickets/<эпик>/DTJ-NNN.md`). Исполняешь ты — субагент, не координатор; принимает координатор.

## База и ветка
`git checkout -b <ветка> <базовый SHA>`; `git log --oneline -1` должен показать <SHA и сообщение>.
Дифф — `git diff <базовый SHA>...HEAD`. В `development` не мёржь и не пушь. `git stash` не использовать.

## Назначенные ресурсы
- Порт своего API для живой проверки: <31NN>; vite: <порт>.
- Redis: тестовый на 6380, БД номер <N> (`REDIS_URL` — в переменной окружения, не в коде и не в отчёте).
- Тестовая БД: <общая dorutj_test | своя dorutj_test_<тикет>>.
- Миграция: <номер и `when` из журнала | не нужна>. Номер не назначен, а миграция нужна — остановись, блокер в отчёт.

## Чтение
Целиком: `AGENTS.md`, свой тикет, `docs/guides/developer-handbook.md` §4, §5, §6, §8, §9. Повторяй идиомы соседнего кода.
Перед новым VO, утилитой, портом — `grep`; копия существующего = возврат.

## Комментарии (нарушение = возврат)
Не больше <40> добавленных строк комментариев на весь дифф; число — в отчёт
(`git diff <SHA>...HEAD | grep -cE '^\+\s*(\*|/\*\*|//)'`). Одна строка, только «почему», где не видно из кода. Без пересказа
тикета и номеров SRS/DTJ/D-* — это в тело коммита и отчёт. TODO — только `TODO(DTJ-NNN)` с тикетом, который реально закроет.

## Подавления линтера
Только с обоснованием после `--`. Не подавлять, когда правило нашло настоящую проблему (`max-params` → объект-параметр,
`complexity`/`max-lines-per-function` → разбить). Исключение — конструктор NestJS с DI-инъекциями.

## Инструменты и установка
`pnpm install --frozen-lockfile`, затем сборка `@dorutj/contracts`, `@dorutj/domain-kernel`, `@dorutj/i18n`
(`pnpm --filter <пакет> build`); после правки словарей i18n или contracts — пересобрать пакет. Новые пакеты не ставить —
`НУЖНЫЕ ЗАВИСИМОСТИ`. Если подключён MCP-сервер символьной навигации, привязанный к другому worktree, — не использовать его.

## Окружение и замок
- Постгрес и Redis уже подняты; контейнеры из своего worktree не создавать. Порт Redis 6379 — чужой проект, туда никогда.
- Через замок (`scripts/coordinator/heavy-run.ps1`, таймаут команды 10 мин; код 99 — повторить) идёт всё тяжёлое или трогающее БД:
  tsc API, весь vitest API/worker, depcruise, `tests/arch`, миграции, интеграционные и e2e спеки, полная проверка.
  Без замка: tsc фронтов и contracts, eslint по своим файлам, точечные unit-спеки, vitest фронтов.
- Dev-окружение владельца и E2E-стенд не останавливать, порты не занимать, БД `dorutj` не трогать. Тесты — только в
  тестовых БД. Секреты (строки подключения, пароли, ключи, токены) не печатать ни в stdout, ни в логи, ни в отчёт.
- Известные красные до тебя (не чинить, имя и текст ошибки — в отчёт): <список классов окружения из docs/status/state.md>.

## Полная проверка перед коммитом
Через замок, с `NODE_OPTIONS=--max-old-space-size=8192` и `REDIS_URL` на 6380:
typecheck → lint → arch:check → test:arch → `pnpm exec turbo run test --env-mode=loose --concurrency=1` → build
(после каждой — проверка кода выхода; полный текст — wave-protocol.md §4). Называй её «verify (test с --env-mode=loose)».
<Исключения этой волны, например `--filter=!@dorutj/security` с пометкой в отчёте.>

## Известные ловушки
- Интеграционные спеки `apps/api` (`test/integration/**`) не входят в `turbo run test`; свои гоняй отдельно:
  `npx vitest run --config vitest.integration.config.ts <файлы>` из `apps/api`. Зелёный turbo test — не доказательство.
- Запрос в БД на пути checkout — только до открытия транзакции группы или внутри неё; запрос через общий пул во время чужих
  транзакций даёт self-deadlock.
- В тестовых харнессах не ставить `PORT='0'`.
- Адаптер/провайдер регистрируется в одном модуле; межмодульно — только через фасад `index.ts`.
- Компоненты фронта — из `packages/ui` (`@dorutj/ui`), не свои Button/Input/Table/Modal/Toast.

## Миграции
Drizzle применяет миграцию, только если её `when` в `meta/_journal.json` больше максимума применённых; в общей БД параллельные
исполнители сбивают порядок. Тикет с миграцией работает на своей БД `dorutj_test_<тикет>` (создание, миграции дважды для
идемпотентности, `GRANT app_role TO test`) — [integration-tests.md](../guides/integration-tests.md). Общую `dorutj_test` не мигрируй.

## Сдача
Коммит только при зелёной полной проверке; сообщение по-русски `feat(<scope>): DTJ-NNN — <что>`, обоснования — в теле.
Без `Co-Authored-By` и упоминаний ИИ. Не пиши «готово/закрыт» — «сдаю на приёмку». Финальный ответ — отчёт по
report-format.md + ветка, путь worktree, хэши коммитов, число строк комментариев. Если остановили по лимиту — незакоммиченное
сохранится в worktree, координатор возобновит.
```

## Дополнение для E2E-волны

Добавляется к брифу, если тикеты пишут сценарии Playwright (`tests/e2e`); при противоречии прав этот раздел.

```markdown
## База
`git checkout -b <ветка> <базовый SHA>` — development плюс эндпоинт `GET /api/v1/_test/last-otp`, контракт сида и хелпер входа.

## Стенд координатора (общий, не перезапускать и не останавливать)
| Что | Адрес | Переменная для Playwright |
|---|---|---|
| API | http://localhost:<порт API> | `E2E_BASE_URL` |
| apps/web | http://localhost:<порт> | `E2E_WEB_URL` |
| apps/pharmacy | http://localhost:<порт> | `E2E_PHARMACY_URL` |
| apps/admin | http://localhost:<порт> | `E2E_ADMIN_URL` |
- Стенд крутит код <базового SHA>, а не твоей ветки; БД стенда `dorutj_e2e` общая — ничего не TRUNCATE/DELETE массово,
  данные сценария уникальные. Стенд не отвечает — блокер координатору, сам не поднимай.
- Прогон своих спек (без замка): из `tests/e2e` с заданными `E2E_*_URL` — `npx playwright test specs/<файл>`.

## Где писать
- Спеки — `tests/e2e/specs/cuj-<N>-<slug>.pw.spec.ts` (конфиг берёт только `*.pw.spec.ts`).
- Вход по API — `helpers/login-via-api.ts`, код OTP — `helpers/get-otp-from-mock-sms.ts`. Свои хелперы — `helpers/<cujN>-*.ts`;
  общие файлы (`playwright.config.ts`, `package.json`, `tsconfig.json`) — только добавлением строк, с объяснением в отчёте.
- Сид-данные — только через `@dorutj/testing-kit` (`SEED_USERS`, `SEED_PHARMACIES`, `SEED_CHAINS`, `SEED_TENANTS`,
  `SEED_ANALOG_CLUSTER`); ID и телефоны в спеках не хардкодить. Своего сида и SQL-вставок нет — второй источник данных = возврат.

## Красный тест из-за бага приложения
Не подгоняй тест под баг и не скипай. Сузь до минимального воспроизведения и опиши в БЛОКЕРАХ (шаги, ожидалось/получено,
файл приложения). Код приложения вне своего тикета не чини.

## Проверки
Полная проверка — без фильтра на `@dorutj/e2e`. `pnpm test` пакета e2e идёт в verify без стенда, поэтому сценарий при
незаданных `E2E_*_URL` обязан делать `test.skip` с явной причиной (образец — `tests/e2e/smoke/web-opens.pw.spec.ts`).
В отчёте — вывод живого прогона своих спек против стенда.
```
