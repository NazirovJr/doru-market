# Формат отчёта о сдаче тикета

Единственная копия формата. Исполнитель заполняет отчёт честно: нераскрытый блокер хуже невыполненного критерия.
Он не пишет «готово» / «закрыт» / «волна завершена» — он пишет «сдаю на приёмку». Вердикт выносит координатор
([coordinator.md §3](coordinator.md)).

```
ТИКЕТ: DTJ-NNN

ФАЙЛЫ СОЗДАНЫ/ИЗМЕНЕНЫ:
  - путь/к/файлу.ts (что сделано)

ПОДКЛЮЧЕНИЕ К РАНТАЙМУ:
  - Модуль зарегистрирован в: apps/api/src/app.module.ts:21
  - Маршрут проверен: GET /api/v1/... → 200 (curl'ом)
  (или: подключение не требуется — почему)

КРИТЕРИИ ПРИЁМКИ:
  1. <текст критерия> → ВЫПОЛНЕН, реализация: файл.ts:функция
  2. <текст критерия> → НЕ ВЫПОЛНЕН, причина: ...

ТЕСТЫ:
  - файл.spec.ts — N кейсов, из них M негативных

ПРОВЕРКИ (вывод команд, не пересказ):
  tsc --noEmit        → OK / текст ошибки
  eslint              → OK / текст ошибки
  vitest run          → N passed, M failed / текст
  depcruise           → OK / текст
  test:arch           → N passed
  (или «verify (test с --env-mode=loose)» — см. executor-brief-template.md)

ДОПУЩЕНИЯ: <что домыслил, потому что спека молчала>
БЛОКЕРЫ: <что не смог и почему; точный текст ошибки>
НАЙДЕННЫЕ ЧУЖИЕ ПРОБЛЕМЫ: <что заметил вне своего тикета: файл, строка, что не так>
НУЖНЫЕ ЗАВИСИМОСТИ: <пакеты, которые не стал ставить сам>
```

Дополнительно, если этого требует бриф волны: ветка, путь worktree, хэши коммитов, число добавленных строк комментариев
(`git diff <база>...HEAD | grep -cE '^\+\s*(\*|/\*\*|//)'`).

**Честный отчёт с блокерами ценнее ложного «всё готово».** Ложное «готово» находят через несколько волн, когда поверх уже
построено ещё три эпика. См. [lessons-learned.md](lessons-learned.md), правила 10 и 14.
