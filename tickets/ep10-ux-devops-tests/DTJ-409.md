## Задача

Карта аптек — обязательная возможность R1 (`docs/04-SCOPE-DECISION-PIVOT.md` R1-6) и часть
критического пути приёмки CUJ-1. Дизайн-канвас НЕ специфицирует реальную карту — везде iframe-
заглушка `map-view.html` (`32-design-reference.md`: «Реальный MapLibre GL JS-компонент дизайном не
специфицирован — только точки входа/размеры контейнера»), поэтому этот тикет реализует компонент
строго по письменной спецификации `docs/spec/30-ux-screens-and-flows.md` (карта аптек §3.1, модуль
каталога §20 — пины/кластеризация/bbox), без визуального прецедента для копирования.

## Технический контекст

`MapView` — единый API пропсов, задуманный переносимым на Flutter `flutter_map` в R2
(`SRS-UX-021`: «единый API пропсов между платформами» — на этом тикете реализуется только React/
MapLibre GL JS сторона, но именование пропсов проектируется с оглядкой на будущий Dart-эквивалент,
не специфичными для веба именами вроде `onClick` там, где уместнее платформо-нейтральное `onSelect`).
Тайлы — OSM (`MapLibre`/`OSM`, без проприетарных SDK и API-ключей, `01-TECH-BASELINE.md`). Компонент
домен-агностичен: принимает массив точек `MapPoint[]` (id/lat/lng/label/meta), не знает про
«аптеку» напрямую — маппинг доменных данных на точки делает фича-потребитель (EP-08 карта аптек).

## Что сделать

1. `MapView` — базовые пропсы: `points: MapPoint[]`, `center?: GeoPoint`, `zoom?: number`,
   `bbox?: BBox`, `onSelect?: (pointId: string) => void`, `mode: 'preview' | 'full'` (150-190px
   превью на карточках товара/чекауте vs полноэкранный `/map`).
2. Кластеризация точек при высокой плотности (несколько аптек рядом на низком zoom) — использовать
   встроенную кластеризацию MapLibre GL (`cluster: true` источник данных), не реализовывать вручную.
3. Ленивая загрузка — `MapLibre`-чанк грузится ТОЛЬКО при монтировании компонента в DOM (реальном
   скролле/явном клике «Показать на карте»), НЕ предзагружается на главном экране, даже если
   превью карты присутствует как статичный плейсхолдер (`SRS-UX-038` — динамический `import()`
   MapLibre GL внутри компонента, статичное изображение-заглушка рендерится до монтирования
   реальной библиотеки).
4. `use-map-markers.ts` — хук, синхронизирующий React-состояние `points` с нативными MapLibre
   маркерами/источниками данных (императивный API MapLibre оборачивается декларативным React-хуком,
   не наоборот).
5. Текстовый список-дубликат под картой (`bottom sheet` на мобильном) — реализуется потребителем
   (EP-08), НЕ этим компонентом (`MapView` предоставляет `onSelect` колбэк и данные точек,
   чтобы потребитель мог построить синхронизированный список рядом — `SRS-UX-034` требование
   «карта не единственный способ увидеть результаты» реализуется композицией, не внутри `MapView`).
6. Пустое состояние «нет точек в bbox» — `MapView` принимает опциональный `emptyStateSlot: ReactNode`
   (композиция, переиспользует `EmptyState` из DTJ-406 на стороне потребителя), сам компонент не
   хардкодит текст.
7. Обновить `packages/ui/src/index.ts`.

## Критерии приёмки

1. Given `<MapView points={[]} mode="full" />` (пустой bbox), When рендер, Then компонент
   рендерит переданный `emptyStateSlot`, не «падает» с ошибкой и не показывает пустую серую карту
   без объяснения.
2. Given `<MapView points={manyClosePoints} />` (много точек в одной точке экрана на низком zoom),
   When рендер, Then точки визуально сгруппированы в кластер с числом (не 50 наложенных друг на
   друга пинов).
3. Given страница с `<MapView mode="preview" />`, When компонент НЕ смонтирован в видимой области
   (например, ниже сгиба, ленивая загрузка изображений уже применена в родительском списке), Then
   `import()` MapLibre GL НЕ инициирован сетевым запросом (проверяется через мок динамического
   импорта/анализ сетевых запросов в тесте).
4. Given `onSelect` передан, When пользователь кликает на пин, Then `onSelect(pointId)` вызывается
   с корректным id точки.

## Тест-план

Unit (Vitest + мок MapLibre GL, т.к. реальный WebGL-рендер недоступен в jsdom):
- `renders emptyStateSlot when points array is empty`
- `clusters points that are geographically close at low zoom` (через мок `cluster`-опции источника
  данных MapLibre — проверяется, что источник ДАННЫХ сконфигурирован с `cluster: true`, не
  визуальный пиксельный рендер)
- `calls onSelect with correct point id on marker click`
- `does not trigger dynamic import of maplibre-gl until component mounts` (мок `import()`,
  подтверждение отложенной загрузки)
- `use-map-markers syncs added/removed points without full re-render of the map instance`
  (проверка, что смена `points` не пересоздаёт карту целиком — производительность)

Интеграционный/визуальный тест — Storybook история `map-view.stories.tsx` с реальным MapLibre в
браузере (не в jsdom) — ручная/E2E-проверка (переиспользуется E2E картой аптек в EP-08, вне
объёма этого тикета).

Порог покрытия — 90% для `use-map-markers.ts`; для `map-view.tsx` (много интеграции с внешней
библиотекой, сложно unit-тестировать построчно) — 70% приемлемо по правилу «остальное — ≥70%»,
если разработчик обоснует в PR, какие ветки не покрыты юнитами и почему (визуальные детали,
покрытые Storybook/E2E).

## Риски и подводные камни

`maplibre-gl` — сравнительно тяжёлая библиотека (сотни KB) — обязательный код-сплиттинг критичен
для бюджета `SRS-UX-036`/`SRS-UX-037`; если по итогам сборки чанк карты всё равно затягивается в
основной бандл транзитивно (например, через статический импорт типов без `import type`) — это
блокирующий дефект ревью, не «доработаем потом». Кластеризация MapLibre имеет собственные пороги
`clusterRadius`/`clusterMaxZoom` — дефолтные значения библиотеки взять как отправную точку
(ASSUMPTION), тонкая настройка под реальную плотность аптек Душанбе — за пределами этого тикета,
данные для калибровки появятся только после реального seed от EP-04/EP-08.
- Файл `packages/ui/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- D-27: одна подволна с `DTJ-405` (оба дописывают `packages/ui/src/index.ts`) — получен явный
  `depends_on: DTJ-405`.
