## Задача

`AnalogBanner`/`SavingsBadge`/`PriceTag` — визуальное воплощение единственного защищённого УТП
продукта (`docs/04-SCOPE-DECISION-PIVOT.md` §2.1: «Найди то же лекарство дешевле рядом с тобой»,
D1 — аналоги по МНН, ключевая метрика — экономия в сомони, не заказы). Это самые часто
рендерящиеся компоненты продукта — карточка товара и результаты поиска показывают их на каждом
экране CUJ-1. `CountdownTimer` дублируется в SLA сборки аптекой и TTL резерва корзины/OTP — обязан
существовать один раз с эталонной цветовой эскалацией (уже подтверждённой хорошей практикой в
дизайн-канвасе, `32-design-reference.md`: «хорошая эталонная реализация правила эскалации»).

## Технический контекст

Формально эти компоненты ближе к `entities`-слою фронтовой архитектуры (`02-CLEAN-ARCHITECTURE-AND-CODE.md`
§5: «переиспользуемые доменные представления»), но по решению `00-EPICS.md` §«Пересекающееся
владение» п.6 весь `packages/ui` — единый источник компонентов независимо от того, насколько
доменно-специфичен конкретный компонент; конкретные фичи (`apps/web/src/features/search`,
`.../cart`) импортируют их отсюда, не создают локальные копии. Компоненты принимают уже
посчитанные бэкендом данные (`savingsDiram`, `isStale`, `pickupSlaSeconds`) — НЕ содержат бизнес-
логики расчёта экономии/устаревания (эта логика — в `application`-слое backend-модулей `EP-06`/
`EP-07`), только форматирование и отображение через `useT()`/`formatMoney` (DTJ-402).

## Что сделать

1. `PriceTag` — `amountDiram: number`, `strikethrough?: boolean` (для пары «было/стало»),
   использует `formatMoney()` из DTJ-402, крупный контрастный текст (`--font-size-lg`, целевой
   контраст 7:1 для критичных цифр, `SRS-UX-003`).
2. `SavingsBadge` — «Сэкономьте N сомони» акцентный бейдж, ОБЯЗАТЕЛЬНО рядом текст-объяснение (не
   изолированная цифра без контекста — REQ-UX-1 письменного документа), собирается поверх `Badge`
   (DTJ-404) с `tone="success"`.
3. `AnalogBanner` — inline-плашка (НЕ модальная, REQ-UX-2), принимает `substanceName`,
   `dosage`, `analogPriceDiram`, `referencePriceDiram`, `savingsPercent`, рендерит текст по шаблону
   «Тот же действующий компонент — X {dose} — за Y сомони вместо Z сомони (P% дешевле)» через
   параметризованный i18n-ключ (заводится этим тикетом в `packages/i18n`, т.к. специфичен для
   этого компонента — координация с DTJ-402 через добавление ОДНОГО нового ключа в существующие
   словари, не пересоздание файла), + юридический дисклеймер под баннером (текст дисклеймера —
   `pending_legal_review`, placeholder-ключ заводится, финальный текст — вне тикета).
4. `MedicineCard` — карточка препарата для списка результатов поиска: название/МНН/форма/
   производитель, `PriceTag`, дистанция, бейдж Rx (если `controlCategory !== 'none'`), индикатор
   остатка; вся карточка — `interactive Card` (DTJ-404) с единой кликабельной областью.
5. `PharmacyOfferRow` — строка предложения аптеки в карточке товара: название аптеки, `PriceTag`,
   расстояние, остаток, кнопка «В корзину» (`Button`), визуальный `isStale`-индикатор (иконка +
   текст `ux.warning.stale_data` с интерполяцией `{{minutesAgo}}`, DTJ-402).
6. `CountdownTimer` — `targetTimestamp: number`, `warningThresholdSeconds`/`dangerThresholdSeconds`
   (пороговые параметры, НЕ хардкод конкретных 7 минут/420с внутри компонента — SLA-время
   приходит от бэкенда конкретного эпика, компонент только визуализирует), цветовая эскалация
   `--brand-text` → `--brand-warning` (порог) → `--brand-danger` (просрочено, отрицательное время
   отображается явно, не скрывается), моно-шрифт для цифр (визуальная стабильность при смене
   значений — не «прыгает» ширина), `aria-live="polite"` с оповещением ТОЛЬКО на пороговых
   переходах (5 мин/1 мин/просрочено — не каждую секунду, `SRS-UX-034` «Screen reader»).
7. `OrderTimeline` — вертикальная шкала статусов заказа, каждый шаг — иконка + время + текст
   (принимает массив шагов с `status`/`timestamp`/`isCompleted`/`isCurrent` — маппинг конкретных
   `order_status` enum-значений на шаги делает потребитель-фича, компонент домен-агностичен).
8. Обновить `packages/ui/src/index.ts`.

## Критерии приёмки

1. Given `<CountdownTimer targetTimestamp={now+400000} warningThresholdSeconds={300}
   dangerThresholdSeconds={0} />` (400с до цели, порог предупреждения 300с), When таймер достигает
   300 секунд до цели, Then цвет меняется на `--brand-warning`, `aria-live` регион получает
   ОДНО обновление именно в этот момент (не на каждую секунду до этого).
2. Given таймер уходит в отрицательное значение (просрочка), When `remainingSeconds < 0`, Then
   отображается явно отрицательное время (не «00:00», не скрывается), цвет — `--brand-danger`.
3. Given `<AnalogBanner savingsPercent={65} ... />`, When рендер, Then текст экономии и
   дисклеймер оба присутствуют в DOM, компонент НЕ является `<Modal>`/`role="dialog"` (проверка
   структуры — inline, не оверлей).
4. Given `<PharmacyOfferRow isStale minutesAgo={12} />`, When рендер, Then текст содержит
   интерполированное «12 мин назад» на текущей локали теста, рядом с текстом — иконка (не только
   изменение цвета фона строки).
5. Given `<MedicineCard>` целиком кликабельна, When клик в любую точку карточки (не только на
   заголовок), Then срабатывает единый `onClick`/переход — нет «мёртвых зон» внутри карточки,
   кроме вложенной кнопки «В корзину» у `PharmacyOfferRow`, если она отрендерена внутри (клик по
   вложенной кнопке не триггерит переход карточки — проверка `stopPropagation`).

## Тест-план

Unit (по компоненту):
- `CountdownTimer`: пороговая цветовая эскалация на точных границах; `aria-live` дискретные
  обновления (не на каждый тик — мокнутые таймеры + подсчёт вызовов `aria-live` мутации);
  отрицательное время отображается, не скрывается/не клэмпится к нулю.
- `PriceTag`: `strikethrough` рендерит зачёркнутую цену рядом с новой; форматирование через
  `formatMoney` для всех 3 локалей (переиспользует моки DTJ-402).
- `AnalogBanner`: рендерит структуру `inline`, не модальную; дисклеймер присутствует всегда,
  независимо от величины экономии (даже небольшая экономия не убирает дисклеймер).
- `MedicineCard`/`PharmacyOfferRow`: единая кликабельная область; вложенная кнопка не всплывает
  клик наружу (`stopPropagation`); `isStale` рендерит иконку+текст, не только цвет.
- `OrderTimeline`: шаги рендерятся в переданном порядке; `isCurrent`-шаг визуально отличим не
  только цветом (форма/иконка).

Порог покрытия — 90%.

## Риски и подводные камни

`AnalogBanner`/дисклеймер — юридический текст `pending_legal_review` (тот же статус, что и
i18n-ключи ошибок, `docs/spec/30-ux-screens-and-flows.md` §5 примечание) — плейсхолдер-текст на
этом тикете НЕ финальный, замена на юридически вычитанный текст не требует изменения структуры
компонента (только значения ключа) — явно зафиксировать это как ограничение, не блокер. Пороговые
параметры `CountdownTimer` НЕ хардкодятся в компоненте (7 минут сборки — значение из
`tenant_settings`/конкретного заказа, конфигурируемо per-tenant по D-19) — если разработчик по
ошибке зашьёт `420` как дефолт внутри компонента вместо required-пропа, это нарушение C6
(магические числа) и блокирующее ревью-замечание.
- Файл `packages/ui/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
