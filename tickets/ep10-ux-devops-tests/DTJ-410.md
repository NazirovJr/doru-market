## Задача

`AudioAlertPlayer` реализует единственный в продукте механизм двойного канала для критичных
событий (`SRS-UX-007`: новый заказ на терминале аптеки ОБЯЗАН сопровождаться звуком И визуальным
сигналом одновременно, ни один канал не единственный — целевая аудитория персонала аптеки может
не смотреть на экран постоянно). `FileDropzone` — загрузка фото рецепта (CUJ-5, флаг R1) и
документов онбординга аптеки (лицензия) — оба сценария требуют одинакового превью+чек-листа
качества файла.

## Технический контекст

Оба компонента — независимые, без пересечения. `AudioAlertPlayer` использует `AudioContext`
(не просто `<audio autoplay>`, который браузеры блокируют без предшествующего жеста пользователя) —
разблокируется явным жестом («Начать смену» в кабинете аптеки, реализуется потребителем через
вызов `unlock()`, экспортируемый этим компонентом). `FileDropzone` — превью + базовая клиентская
проверка (тип файла, размер) ДО отправки на сервер, финальная валидация — всегда серверная.

## Что сделать

1. `FileDropzone` — drag-and-drop зона + fallback кнопка «Выбрать файл» (для touch-устройств без
   drag), превью загруженного изображения, чек-лист качества (проп `qualityChecks:
   { label: string; passed: boolean }[]`, содержимое чек-листа — ответственность потребителя,
   CUJ-5 фото рецепта задаёт свой набор критериев в соответствующем эпике), состояния
   `idle`/`dragging`/`uploading`(прогресс)/`error`(`ux.error.image_illegible`-подобный i18n-ключ
   передаётся пропом, не хардкодится).
2. `AudioAlertPlayer` — `useAudioAlertPlayer()` хук, экспортирующий `unlock(): Promise<void>`
   (разблокировка `AudioContext` по явному жесту) и `play(soundKey: string): void` (звук ТОЛЬКО
   после `unlock()`, попытка `play()` до `unlock()` — no-op с предупреждением в консоли уровня
   `warn`, не тихий провал без объяснения при отладке); ОБЯЗАТЕЛЬНО сопровождается визуальным
   компонентом-индикатором в этом же тикете (`AudioAlertPlayer` рендерит пульсирующий/мигающий
   визуальный баннер ОДНОВРЕМЕННО со звуком — компонент физически не позволяет подключить только
   звук без визуала, оба канала — часть одного компонента, не два раздельных API).
3. Оба компонента используют `useReducedMotion()` (DTJ-403) для визуальной части (пульсация
   `AudioAlertPlayer`, drag-hover анимация `FileDropzone`) — звук `AudioAlertPlayer` НЕ отключается
   `prefers-reduced-motion` (это не декоративная анимация, а функциональный сигнал, `SRS-UX-034`
   правило «функциональные переходы сокращаются до мгновенной смены», не отключаются полностью).
4. Обновить `packages/ui/src/index.ts`.

## Критерии приёмки

1. Given `useAudioAlertPlayer()` без вызова `unlock()`, When `play('new_order')`, Then звук НЕ
   воспроизводится, в консоли — предупреждение уровня `warn` (не `error`, не тихо).
2. Given `unlock()` вызван (эмуляция клика пользователя в тесте), When `play('new_order')`, Then
   и звуковой, и визуальный канал активируются одновременно (визуальный баннер видим в DOM в
   момент вызова `play`).
3. Given `<FileDropzone accept="image/*" maxSizeMb={10} />`, When пользователь перетаскивает файл
   15 МБ, Then показывается `error`-состояние ДО отправки на сервер (клиентская пре-валидация),
   `onUpload` НЕ вызывается для этого файла.
4. Given `<FileDropzone qualityChecks={[{label:'Хорошее освещение', passed:false}]} />`, When
   рендер, Then непройденный пункт чек-листа визуально отличим от пройденного не только цветом
   (иконка ✕/✓).

## Тест-план

Unit:
- `AudioAlertPlayer`: `play()` до `unlock()` — no-op + предупреждение; `play()` после `unlock()` —
  звук и визуал одновременно; повторный `play()` разных `soundKey` не создаёт наложение (текущий
  звук останавливается перед новым, либо явно документированное поведение очереди — выбор
  реализации фиксируется в PR, тест проверяет ЛЮБОЕ детерминированное поведение, не «как получится»).
- `FileDropzone`: drag-and-drop и кнопка «Выбрать файл» дают идентичный результат обработки файла;
  превышение `maxSizeMb`/несовпадение `accept` блокируется клиентски с понятным `error`-текстом;
  `qualityChecks` рендерит все пункты с корректным визуальным статусом; `renderWithA11yCheck` ноль
  нарушений для обоих компонентов.

Порог покрытия — 90%.

## Риски и подводные камни

`AudioContext` требует реального аудиофайла-ассета (звук сигнала) — конкретный звуковой файл НЕ
специфицирован ни в одном SRS-документе (пробел требований) — на этом тикете используется placeholder-
звук (короткий синтетический тон, генерируемый через `AudioContext.createOscillator()`, без
внешнего аудио-ассета, чтобы не блокировать тикет отсутствием дизайн-актива), финальный звуковой
файл — доработка эпика, реально потребляющего компонент (веб-кабинет аптеки, EP-12), зафиксировать
это явно в Storybook-заметке компонента. Мобильный Safari/iOS исторически особенно строг к
автовоспроизведению звука — `unlock()` обязан вызываться СИНХРОННО внутри обработчика реального
пользовательского жеста (клик/тап), не после `await` внутри того же обработчика — иначе браузер
не засчитает разблокировку; задокументировать это ограничение в JSDoc `unlock()`.
