## Задача

Все фронтовые эпики (EP-03 `apps/admin`, EP-05 `apps/pharmacy`, EP-06 `apps/web` поиск и далее
каждый следующий вертикальный эпик) начинают потреблять компоненты уже в волне 1–2
(`tickets/00-EPICS.md` §«Волны выполнения», §«Обязательные сквозные тикеты»: «минимальный скелет
(токены, `useT()`-заглушка) нужен уже здесь, иначе экран OTP-логина EP-01 хардкодит строки/цвета»).
Без готового пакета с настроенной сборкой, `exports`-картой и tsconfig любой потребитель вынужден
либо ждать, либо копировать компоненты локально — прямое нарушение владения файлами
`02-CLEAN-ARCHITECTURE-AND-CODE.md` §5 и правила «единственный источник компонентов/строк»
(`00-EPICS.md` §«Пересекающееся владение» п.6). Это подготовительный (scaffolding) тикет эпика —
без него ни один из следующих тикетов EP-18 не имеет куда класть код.

**D-27:** этот тикет инициализирует ТОЛЬКО `packages/ui`. Пакет `packages/i18n` уже создан
тикетом `DTJ-004` (EP-01, единственный владелец создания пакета) — минимальный скелет словарей
`tj/ru/en` и хук `useT()` для OTP-логина существует до старта этого тикета. `DTJ-400` НЕ создаёт
`packages/i18n` заново и НЕ трогает его файлы; `packages/i18n` потребляется этим и последующими
тикетами EP-18 (`DTJ-401/402/403`) как готовая зависимость, которую `DTJ-402` затем расширяет до
полноценного ядра (словари всех модулей, форматирование, `i18n-provider`).

## Технический контекст

`packages/ui` — независимый pnpm-workspace пакет (не приложение), потребляемый через
`pnpm-workspace.yaml` alias-импорт (`@dorutj/ui`) всеми `apps/*` (кроме Flutter-клиентов R2, у
которых свой `packages_dart/dorutj_ui` по той же номенклатуре токенов, `SRS-UX-021`). Стек —
React 19 + TypeScript 5.9 + Vite 7 (library mode) + Tailwind v4 CSS-first
(`01-TECH-BASELINE.md`). Корневой `tsconfig.base.json`/`eslint.config.mjs` уже существуют
(владелец — EP-19) — новый `tsconfig.json` только `extends` их, не переопределяет правила C1–C18.
`pnpm-workspace.yaml` уже покрывает `packages/*` глобом (проверить при выполнении; если пакет
`packages/i18n` из `DTJ-004` уже резолвится как workspace-зависимость — отдельная правка не нужна).

## Что сделать

1. `packages/ui/package.json`: `name: "@dorutj/ui"`, `type: module`, `main`/`module`/`types` из
   `dist/`, `exports`-карта с под-путями `./tokens`, `./components`, зависимости
   `react`/`react-dom` как `peerDependencies` (версии из `01-TECH-BASELINE.md`), `devDependencies`
   `vite`, `@vitejs/plugin-react`, `vitest`, `@vitest/coverage-v8`, `storybook`,
   `@storybook/react-vite`, `@storybook/addon-a11y`.
2. `packages/ui/tsconfig.json` — `extends: "../../tsconfig.base.json"`, `composite: true`,
   `rootDir: src`, `outDir: dist`.
3. `packages/ui/vite.config.ts` — режим библиотеки (`build.lib`), `formats: ['es']`, внешние
   `react`/`react-dom`, плагин `dts` для генерации `.d.ts` (`vite-plugin-dts`).
4. `packages/ui/src/index.ts` — пустой публичный баррель-экспорт с комментарием-заглушкой
   `// компоненты добавляются последующими тикетами EP-18`.
5. `packages/ui/.storybook/main.ts` + `preview.tsx` — Storybook 8 на Vite-билдере, аддон
   `@storybook/addon-a11y` подключён по умолчанию (переиспользуется тикетом DTJ-403 для
   автоматических axe-прогонов историй).
6. Убедиться, что `packages/i18n` (создан `DTJ-004`) резолвится как workspace-зависимость
   (`pnpm-workspace.yaml` уже покрывает `packages/*` глобом) и прогнать `pnpm install` — этот
   тикет НЕ создаёт и НЕ правит файлы `packages/i18n/**`.
7. `package.json` пакета `packages/ui` получает скрипты `build`, `test`, `lint`, `typecheck` —
   совместимые с корневым `turbo.json` pipeline (запускаются через
   `pnpm turbo run build --filter=@dorutj/ui`).

## Критерии приёмки

1. Given чистый чекаут репозитория (с уже выполненным `DTJ-004`), When `pnpm install`, Then
   `packages/ui` и `packages/i18n` резолвятся как workspace-зависимости без ошибок пиров.
2. Given `packages/ui`, When `pnpm --filter @dorutj/ui build`, Then в `dist/` появляются `index.js`
   и `index.d.ts` без TypeScript-ошибок.
3. Given `packages/ui/.storybook`, When `pnpm --filter @dorutj/ui storybook`, Then Storybook
   поднимается локально без ошибок конфигурации (пустой список историй — это ожидаемо на этом
   тикете).
4. Given намеренно добавленный импорт `drizzle-orm` в `packages/ui/src/index.ts` (временная
   проверка), When `pnpm --filter @dorutj/ui typecheck`, Then сборка падает (пакет UI не должен
   уметь резолвить backend-зависимости — проверка изоляции workspace, откатить после проверки).

## Тест-план

Скелетный тикет — не вводит бизнес-логики, поэтому unit-тестов на этом шаге нет. Интеграционная
проверка — сама сборка (`pnpm turbo run build --filter=@dorutj/ui`) как часть `pnpm verify`.
E2E не требуется.

## Definition of Done

- [ ] Код соответствует `docs/02-CLEAN-ARCHITECTURE-AND-CODE.md` (слои, C1-C18)
- [ ] `pnpm verify` зелёный локально (на этом шаге — только `typecheck`/`lint`/`build` пакета
      `packages/ui`, `test`/`arch:check` не имеют предметной логики для проверки)
- [ ] Тесты из тест-плана написаны и проходят
- [ ] Нет хардкода строк (i18n) и цветов (CSS-переменные) — неприменимо к самому скелету, но
      структура каталогов подготовлена под правило
- [ ] Storybook поднимается локально, `pnpm-workspace.yaml` содержит `packages/ui`
- [ ] `packages/i18n/**` не создан и не изменён этим тикетом (D-27: единственный владелец
      создания — `DTJ-004`)

## Риски и подводные камни

`vite-plugin-dts` иногда конфликтует с `composite: true` в `tsconfig` — при конфликте предпочесть
`tsc --emitDeclarationOnly` отдельным шагом сборки вместо плагина. Версия Storybook 8 и Vite 7 —
проверить совместимость на момент реализации (Storybook исторически отстаёт на 1 мажор от Vite);
если `@storybook/react-vite` не поддерживает Vite 7 на дату реализации — зафиксировать в PR
конкретную работающую комбинацию версий, отклонение от `01-TECH-BASELINE.md` для Storybook
(не входящего в этот документ) допустимо без ADR, т.к. это dev-инструмент, не рантайм-зависимость.
- Файл `packages/ui/package.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `packages/ui/tsconfig.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `packages/ui/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- D-27: `packages/i18n` — заблокировавший конфликт волны 1 (создавался И здесь, И в `DTJ-004`).
  Решение — единственный владелец создания `DTJ-004`, этот тикет получил `depends_on: [DTJ-004]`
  и переформулирован как потребитель `packages/ui`-скелета, не создатель `packages/i18n`. Не
  возвращать пути `packages/i18n/**` в `files_owned` этого тикета.
