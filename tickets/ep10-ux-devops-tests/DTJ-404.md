## Задача

Это первый набор реальных компонентов, потребляемых каждым фронтовым эпиком с волны 2 (поиск,
корзина, кабинет аптеки, курьер, админка) — `Button`/`Input`/`Card` встречаются на каждом экране
`docs/spec/30-ux-screens-and-flows.md` §3. Ошибка в этих 8 компонентах размножается на десятки
экранов, поэтому 7 обязательных состояний (`SRS-UX-019`) и минимальные тап-зоны (`SRS-UX-002`)
реализуются здесь один раз и правильно, а не переоткрываются в каждой фиче.

## Технический контекст

`packages/ui/src/components/**`, каждый компонент — собственная папка `component-name/` с файлом
реализации, unit-тестом и Storybook-историей (паттерн, задаваемый ЭТИМ тикетом для всех
последующих: DTJ-405..DTJ-411 следуют той же структуре без повторного объяснения). Используются
токены из DTJ-401 (`var(--brand-*)`/`var(--space-*)`/`var(--radius-*)`), утилиты доступности из
DTJ-403 (`assertHitArea` в тестах, `useReducedMotion` в анимациях), строки — из `useT()` DTJ-402
(только для встроенных, не-пропсовых текстов вроде `aria-label` дефолтов).

## Что сделать

1. `Button` — `variant: 'primary' | 'secondary' | 'danger' | 'ghost'`, `size: 'md' | 'lg'` (48px/
   56px высоты, `SRS-UX-021`), 7 состояний `SRS-UX-019` (`default/hover/active/focus/disabled/
   loading/error` — `error` для кнопки трактуется как визуальный вариант `danger` в контексте
   формы, не отдельное состояние поверх остальных шести): `loading` — спиннер ВНУТРИ кнопки на
   месте текста БЕЗ изменения ширины (текст скрыт через `visibility: hidden` + `aria-busy="true"`,
   не удалён из DOM — сохраняет layout), `disabled` — `opacity: 0.45` + `aria-disabled="true"` +
   `cursor: not-allowed`, курсор клавиатуры НЕ убирается из tab-order без причины. Переход между
   состояниями — `framer-motion`, ≤200мс, обёрнут `useReducedMotion()` (мгновенная смена без
   анимации при включённом предпочтении).
2. `IconButton` — круглая кнопка-иконка, `--radius-full`, минимум 48×48px эффективной области
   независимо от визуального размера иконки внутри (используется паттерн hit-slop через
   `padding`/псевдоэлемент, не раздувание видимого круга) — `aria-label` ОБЯЗАТЕЛЕН пропсом, TS-тип
   не даёт скомпилироваться без него (`aria-label: string` — required prop, не optional).
3. `Input`/`Textarea` — `error`-слот ПОД полем (иконка + текст, не только рамка, `SRS-UX-019`
   error-состояние), `aria-invalid="true"` + `aria-describedby`, указывающий на id текста ошибки,
   когда есть ошибка; `<label>` связывается через `htmlFor`/`id`, НЕ полагается на `placeholder`
   как единственную подсказку (`SRS-UX-034` таблица «Форма»); высота ~48px.
4. `Skeleton` — форма под строку/карточку/чип (`variant: 'text' | 'card' | 'row'`), shimmer-анимация
   ~1.4s через CSS (не JS-таймер), уважает `useReducedMotion()` (статичный полупрозрачный фон вместо
   shimmer при reduce).
5. `Badge` — `variant` по enum статусов (принимает произвольную строку варианта + маппинг цвет/иконка
   определяется ПОТРЕБИТЕЛЕМ через проп `tone: 'success' | 'danger' | 'warning' | 'neutral'`, сам
   `Badge` не знает про доменные enum типа `order_status` — остаётся в `shared`, не в `entities`),
   текст ОБЯЗАТЕЛЕН (не только цвет/иконка — `SRS-UX-019`/`SRS-UX-034` «статус не передаётся только
   цветом»).
6. `Chip` — переключаемый фильтр, `selected: boolean`, визуальная высота может быть меньше 48px
   (компактность, `32-design-reference.md` допускает), НО эффективная область — 48×48px через
   hit-slop (расхождение №4 design-reference, `assertHitArea`-тест обязателен).
7. `Card` — `interactive: boolean` (рендерит `<a>`/`<button>`-семантику со своим фокус-кольцом,
   когда `interactive`) / `static` (обычный `<div>` контейнер), `padding: var(--space-4)`,
   `border-radius: var(--radius-md)`.
8. Обновить `packages/ui/src/index.ts` — реэкспорт всех 8 компонентов и их пропс-типов.

## Критерии приёмки

1. Given `<Button loading>Оформить</Button>`, When рендер, Then текст «Оформить» присутствует в
   DOM (не удалён), визуально скрыт, кнопка имеет `aria-busy="true"` и `disabled` атрибут, ширина
   кнопки идентична ширине в состоянии `default` с тем же текстом (снимок `getBoundingClientRect`
   до/после переключения `loading`).
2. Given `<IconButton>` без пропа `aria-label`, When TypeScript-компиляция, Then ошибка компиляции
   (не рантайм-warning).
3. Given `<Input error="Обязательное поле">`, When рендер, Then `input` имеет `aria-invalid="true"`
   и `aria-describedby`, указывающий на элемент с текстом «Обязательное поле», и рядом с текстом
   есть иконка (не только текст, не только рамка).
4. Given `<Chip>` с визуальной высотой 32px, When `assertHitArea` (DTJ-403) применён к элементу,
   Then эффективная область ≥48×48px.
5. Given `prefers-reduced-motion: reduce`, When `<Skeleton>` рендерится, Then shimmer-анимация не
   запускается (статичный фон), проверяется через отсутствие активной CSS-анимации в
   `getComputedStyle`.

## Тест-план

Unit (Vitest + `@testing-library/react`, по файлу на компонент из списка `files_owned`):
- `Button`: рендер всех 4 вариантов × 2 размеров без ошибок; `loading` сохраняет layout и текст в
  DOM; `disabled` не триггерит `onClick`; `renderWithA11yCheck` — ноль critical/serious нарушений
  для каждого варианта.
- `IconButton`: TS-тест типов (`tsd`/`expectTypeOf`) — `aria-label` required; `assertHitArea` ≥48px
  для дефолтного и минимального визуального размера.
- `Input`/`Textarea`: связка `label`↔`input` через `aria-labelledby`/`htmlFor`; `error`-состояние
  выставляет `aria-invalid`+`aria-describedby`; ввод текста не мутирует переданный `value`-проп
  (контролируемый компонент).
- `Badge`: рендерит текст ВСЕГДА, даже если передан только `tone` без явного текста-пропа (тест
  на то, что компонент требует `children`/`label` — TS или рантайм-проверка).
- `Chip`: `assertHitArea` ≥48px; переключение `selected` меняет `aria-pressed`.
- `Card`: `interactive` рендерит фокусируемый элемент с видимым `--focus-ring` при `:focus-visible`;
  `static` не фокусируется Tab-ом.

Порог покрытия — 90% для всех файлов `.tsx` (не генерируемых) в этом тикете, эквивалент
`domain`/`application` строгости по правилу пакета `packages/ui`, зафиксированному DTJ-401.

## Риски и подводные камни

`variant: 'danger'` для `Button` в дизайн-канвасе показан только «в бою» (не в общей матрице
состояний, `32-design-reference.md` §«Инвентарь компонентов» строка `Button`) — реализовать по
30-ux спецификации (`variant: primary|secondary|danger|ghost`, `SRS-UX-021`) как полноценный
четвёртый вариант с собственными hover/active/focus состояниями, не как одноразовый inline-стиль
в потребляющей фиче (иначе нарушится C15 DRY при первом повторном использовании кнопки отмены в
другом экране). Framer Motion переходы внутри `Button.loading` — проверить реальный вес добавляемого
кода в бюджет 250KB (`SRS-UX-036`, гейт бюджета — отдельный тикет DTJ-427 EP-19, но если уже на
этом тикете видно, что `framer-motion` даёт непропорционально большой прирост веса для простого
fade — рассмотреть CSS-transition вместо библиотеки для этого конкретного случая, зафиксировать
решение в PR).
- Файл `packages/ui/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
