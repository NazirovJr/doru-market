## Задача

`03-ARCHITECT-DECISIONS.md` §D-26 зафиксировал принцип: «визуальное расхождение — выигрывает
дизайн, но обязано быть кодифицировано обратно в спеку токеном, а не остаться "как нарисовано"».
Этот тикет применяет 4 визуальных решения D-26 к `docs/spec/30-ux-screens-and-flows.md` §2
(«Дизайн-система: токены и базовые элементы»), чтобы спека и реализация DTJ-401 говорили одно и то
же, и архитекторский ревью EP-18 не споткнулся о «по спеке 20, в коде 22».

**Не блокирует EP-18 старт**: DTJ-401 уже ссылается на SRS-UX-011..018 с пометкой «обновлено
`[D-26]`» и реализует правильные значения, даже если сама `30-ux-screens-and-flows.md` §2 ещё
описывает старую шкалу. Цель тикета — закрыть техдолг документации ДО старта EP-18 компонентной
волны (DTJ-404+), иначе расхождение «спека/код» накопится и его уже нельзя будет отличить от
архитектурного долга.

## Технический контекст

Изменяется ТОЛЬКО §2 (дизайн-система), остальные разделы спеки остаются нетронутыми. Все правки —
точечные, через `edit`, без переписывания файла. Каждое решение ссылается на D-26 и на
конкретный абзац/таблицу, чтобы будущий ревьюер видел, что не «выдумка», а явное архитектурское
решение.

## Что сделать

1. **§2.3 Типографика (SRS-UX-014)**: расширить шкалу `--font-size-*` на два значения:
   - `--font-size-h2: 22px` (line-height 30, weight 700) — между текущими `lg` 20 и `xl` 24;
   - `--font-size-h1: 28px` (line-height 36, weight 700) — между текущими `xl` 24 и `2xl` 30.
   Добавить в таблицу размеров с пометкой «введено `[D-26]` для соответствия дизайн-канвасу».
2. **§2.4 Веса (SRS-UX-014)**: добавить `--font-weight-semibold: 600` (Inter даёт 600 штатно,
   используется для body-strong). Текущая шкала 400/500/700 — слишком резкий скачок для акцентного
   текста. Помета `[D-26]`.
3. **§2.6 Радиусы (SRS-UX-017)**: заменить формулу `sm/md/lg` (даёт 4/8/12 при base=8) на
   фиксированный набор `--radius-sm: 8px`, `--radius-md: 12px`, `--radius-lg: 16px`,
   `--radius-full: 999px` (последний — ВСЕГДА фиксированный, не производный от `--brand-radius`).
   Удалить упоминания `10px` и `14px` из дизайн-канваса. Помета `[D-26]`.
4. **§2.7 Тени (SRS-UX-018)**: уточнить `--shadow-modal: 0 8px 24px rgba(15,23,42,0.08)`
   (alpha снижена с `0.16` — `.16` визуально тяжела для светлой темы; `.08` — то, что показывает
   дизайн). Помета `[D-26]`.
5. **§2.8 Фокус-кольцо (SRS-UX-018)**: явно зафиксировать `--focus-ring: 0 0 0 3px
   color-mix(in srgb, var(--brand-primary) 40%, transparent)` — реализуется от `--brand-primary`,
   НЕ от `--brand-accent`. Это явное разрешение расхождения №5 из `32-design-reference.md`:
   фиксированный акцент сломал бы White-Label (у сети с синим брендом кольцо фокуса осталось бы
   голубым и потеряло контраст). Помета `[D-26]`.
6. **§2.5 Цвета (SRS-UX-011)**: добавить в таблицу семантических оттенков явные
   `--brand-warning-fg: #b45309` (иконка/акцент) и `--brand-warning-strong: #92400e` (усиленный
   текст). Помета `[D-26]`.

## Критерии приёмки

1. Given `30-ux-screens-and-flows.md` §2, When grep по `22px|28px|600|8 / 12 / 16|0.08|--brand-warning-fg`,
   Then все 5 находок присутствуют с пометкой `[D-26]`.
2. Given `30-ux-screens-and-flows.md` §2, When grep по `10px|14px|0.16`, Then ноль находок
   (старые значения полностью удалены).
3. Given `30-ux-screens-and-flows.md` §2, When читатель ищет «фокус-кольцо», Then видит
   явное `var(--brand-primary)` с обоснованием White-Label.
4. Given `git diff` после PR, Then изменён ТОЛЬКО §2 файла (diff не затрагивает §3+).

## Тест-план

Ручная проверка (не автоматизируется):
1. `git diff docs/spec/30-ux-screens-and-flows.md` — все 6 правок применены, ничего лишнего.
2. `rg -n '10px|14px|0.16' docs/spec/30-ux-screens-and-flows.md` — ноль находок.
3. `rg -n '\[D-26\]' docs/spec/30-ux-screens-and-flows.md` — минимум 5 находок (по одной на каждое
   изменение).
4. Синтаксис markdown валиден (открыть в VS Code preview — без ошибок рендера).

## Definition of Done

- [ ] §2 спеки обновлён по 6 пунктам выше
- [ ] Все правки имеют пометку `[D-26]` и ссылку на конкретное решение
- [ ] Старые значения (`10px`, `14px`, `0.16`, формула `sm/md/lg`) физически удалены, а не
      закомментированы
- [ ] `pnpm verify` зелёный (изменена только разметка, кода не касаемся)
- [ ] `git diff` показывает только §2

## Риски и подводные камни

- **Минимальный риск**: §2 — справочный, не генерируемый. Ни один компонент DTJ-404+ не парсит
  §2, поэтому позднее применение правки не сломает ничего.
- **Зависимость от DTJ-401**: тикет DTJ-401 реализует токены по правильным значениям СЕЙЧАС,
  до этой правки спеки. Это означает, что кратковременно код «обгоняет» доку — допустимо, потому
  что DTJ-401 ссылается на `SRS-UX-011..018` с пометкой «обновлено `[D-26]`» (это видно в
  DTJ-401 §Технический контекст).
- **НЕ касаться §3+ (карта экранов)**: там визуальные расхождения уже разрешены дизайн-канвасом
  и реализуются компонентами EP-18 без отдельной кодификации.
