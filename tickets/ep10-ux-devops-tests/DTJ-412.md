## Задача

`docs/04-SCOPE-DECISION-PIVOT.md` критерий приёмки R1 №1: «`docker compose up -d` поднимает весь
стек» — это первый пункт Definition of Product Done, проверяемый буквально при финальной приёмке
(`docs/spec/31-nfr-security-testing-devops.md` §«Готовность к продакшену»). Без этого стека ни
`test:integration` (эфемерная БД), ни `test:e2e` (полный стек) не могут запускаться — это блокер
для ВСЕХ последующих тикетов тестовой пирамиды этого эпика, поэтому реализуется первым в EP-19.

## Технический контекст

`infra/docker/**` — единоличное владение EP-19 (`tickets/00-EPICS.md` §«Порядок владения
файлами»). Три профиля compose-файлов: базовый `docker-compose.yml` (dev/staging, порты БД
опубликованы на хост для локальной отладки), `docker-compose.prod.yml` (override — `replicas: 2`
для `api`, лимиты ресурсов, БЕЗ публикации портов БД на хост), `docker-compose.onprem.yml` (R3,
вне объёма этого тикета). `Dockerfile.api` — multi-stage, ОДИН файл для `api`/`worker`/`migrate`
через разные `target` (не дублирует `pnpm install` в трёх образах). `Dockerfile.web` —
параметризован `ARG APP` (`web`/`admin`/`pharmacy`/`courier`), финальная стадия — статика за
Nginx (Charter — не SSR).

## Что сделать

1. `infra/docker/docker-compose.yml` — сервисы `postgres:16` (healthcheck `pg_isready`,
   `POSTGRES_PASSWORD_FILE`, volume `pgdata`), `redis:7` (`--appendonly yes --requirepass`,
   healthcheck `redis-cli ping`, volume `redisdata`), `minio` (пиновать конкретный тег, НЕ
   `:latest` — правило `01-TECH-BASELINE.md`, healthcheck `/minio/health/live`, volume
   `miniodata`), `migrate` (одноразовый init-контейнер, `target: migrator`, `depends_on:
   postgres.condition: service_healthy`, `restart: "no"`), `seed` (`depends_on: migrate.condition:
   service_completed_successfully`, `profiles: ["dev", "e2e"]` — НЕ запускается в prod-профиле
   автоматически), `api`/`worker` (`target: runtime`/`runtime-worker`, healthcheck через
   `GET /ready`/`GET /health` на соответствующих портах, `start_period: 30s`), `web`/`admin`
   (статика за Nginx), `nginx` (порты `80:443`, `depends_on: [api, web, admin]`), `certbot`
   (`profiles: ["prod"]`).
2. `infra/docker/docker-compose.prod.yml` — override с `deploy.replicas: 2` для `api`, лимиты
   `resources.limits`, порты БД/Redis БЕЗ публикации на хост (в отличие от dev-профиля), `seed`
   не включается ни при каких условиях.
3. `infra/docker/Dockerfile.api` — стадии `base` (node:22.12-slim, corepack pnpm), `deps`
   (`pnpm install --frozen-lockfile --filter=api... --filter=worker...`), `build` (`pnpm turbo run
   build --filter=api --filter=worker`), `migrator` (только `dist`+`drizzle`+`node_modules`,
   ENTRYPOINT `migrate-entrypoint.js`), `runtime` (production-зависимости, `USER node`,
   непривилегированный, `EXPOSE 3000`), `runtime-worker` (наследует `runtime`, другой `CMD`).
   Обоснование `node:22.12-slim` (не `alpine`) — нативные аддоны (`argon2`) исторически
   проблемны на musl libc — зафиксировать это комментарием в Dockerfile для будущих
   разработчиков, не переключать на alpine «для экономии места» без повторной проверки.
4. `infra/docker/Dockerfile.web` — стадия `build` (`ARG APP`, `pnpm install --filter=${APP}...`,
   `pnpm turbo run build --filter=${APP}`), стадия `runtime` (`nginx:1.27-alpine`, копирует
   `dist` в `/usr/share/nginx/html` + `spa-fallback.conf`).
5. `infra/docker/nginx/nginx.conf` + `conf.d/*.conf` — глобальный контекст `http{}`, TLS-терминация,
   грубый `limit_req` rate-limit (первый, грубый рубеж по IP — уточнить, что более точные
   rate-limit'ы — на уровне приложения, Nginx не заменяет их), ОДИН catch-all
   `server_name ~^(?<tenant_host>.+)$` server-блок для ЛЮБОГО `Host` (резолвинг тенанта — ВНУТРИ
   `apps/api` через `TenantResolutionMiddleware`, НЕ на уровне Nginx — `SRS-API-065`, `nginx`
   отвечает только за TLS-терминацию и грубую маршрутизацию API vs статика).
6. `infra/docker/nginx/spa-fallback.conf` — `try_files $uri /index.html` для клиентского роутинга
   React Router v7 в каждом `web`/`admin`/`pharmacy`/`courier`.
7. Volumes: `pgdata`, `redisdata`, `miniodata`, `certbot-webroot`.

## Критерии приёмки

1. Given чистая машина с установленным Docker, When `docker compose -f infra/docker/docker-compose.yml
   up -d` (профиль `dev`), Then все сервисы переходят в `healthy`/`running`, `migrate` завершается
   успешно ДО старта `api`/`worker` (проверяется порядком `Created`/`Started` в `docker compose ps`
   и логами — `api` не должен пытаться подключиться к БД со старой/пустой схемой).
2. Given `docker compose up`, When `curl http://localhost/api/v1/health`, Then `200 OK` без
   проверки внешних зависимостей (liveness, не readiness).
3. Given `docker-compose.prod.yml` применён поверх базового, When `docker compose config`
   (просмотр итоговой конфигурации), Then порты Postgres/Redis НЕ опубликованы на хост, `seed`
   не включён.
4. Given намеренно удалённая зависимость `migrate.condition: service_completed_successfully` у
   `api` (тестовая проверка нарушителя), When `docker compose up`, Then `api` стартует ДО
   завершения миграций — эта проверка выполняется ОДИН раз вручную при ревью тикета для
   подтверждения, что реальная (не сломанная) конфигурация действительно этого не допускает, не
   становится частью постоянного автотеста.

## Тест-план

Инфраструктурный тикет — юнит-тестов в классическом смысле нет. Проверка — интеграционная,
выполняется как часть последующих тикетов (DTJ-413 эфемерный стек, DTJ-414 CI использует этот
compose-файл в стадии `e2e`). Ручная проверка при ревью: `docker compose up -d` на чистой машине
поднимает стек end-to-end (соответствует критерию приёмки R1 №1, `docs/04-SCOPE-DECISION-PIVOT.md`).

этих приложений. Зафиксировать в PR, что этот тикет — контракт инфраструктуры, финальная сквозная
проверка «поднимается с нуля» откладывается до появления реального кода `apps/api` (флагуется как
follow-up, не блокирует приёмку самого тикета — файлы синтаксически корректны и проходят

дату реализации — разработчик обязан подставить актуальный стабильный тег (не `:latest`), выбор
зафиксировать в PR одной строкой обоснования по правилу `01-TECH-BASELINE.md`.
