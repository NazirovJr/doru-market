## Задача

Каждый экран из карты `docs/spec/30-ux-screens-and-flows.md` §3 специфицирует пустое/ошибочное/
офлайн-состояние (§5 документа) — без готовых компонентов каждая фича изобретает собственный
баннер офлайна с чуть другим текстом (в точности проблема, найденная в дизайн-канвасе:
`32-design-reference.md` строка `OfflineBanner` — «дизайн даёт разные форм-факторы... текст должен
быть унифицирован при реализации»). `OfflineBanner`/`ErrorState` — единственный способ выполнить
правило «деградация, а не падение» (`SRS-UX-024`), критичное для целевой аудитории на нестабильном
2G/3G (`research §7.2`).

## Технический контекст

`Modal` (десктоп, по центру) и `BottomSheet` (мобильный `<768px`, снизу) — один логический
компонент с адаптивным рендером по `viewport`, используют `useFocusTrap` из DTJ-403. `Toast` —
глобальный контейнер + хук `useToast()` (императивный вызов `toast.success('...')` из любого места
приложения, не пропс-дрилинг). Тексты пустых/ошибочных состояний — ТОЛЬКО через `useT()` (DTJ-402),
компонент принимает `titleKey`/`descriptionKey` (i18n-ключи) либо готовый `useT()`-результат, НЕ
принимает свободный текст как основной API (защита от хардкода на уровне пропсов).

## Что сделать

1. `Toast` + `useToast()` — глобальный `ToastProvider`/контейнер в `app`-слое потребителя (сам
   пакет предоставляет провайдер, подключение — обязанность `apps/*`), автозакрытие 4с
   (`SRS-UX-021` таблица компонентов — 4с, НЕ 1.8с из дизайн-канваса, канонiчное значение письменной
   спецификации выигрывает по правилу `32-design-reference.md` §«Статус»), критичные тосты — без
   автозакрытия (проп `persistent: boolean`, остаётся до явного действия/закрытия).
2. `Modal`/`BottomSheet` — закрытие по `Escape`/клику вне контента/свайпу вниз (`BottomSheet`
   мобильный жест), `useFocusTrap(containerRef, isOpen)` из DTJ-403 подключается ВНУТРИ компонента
   (не оставляется на усмотрение потребителя — иначе гарантированно забудут), `role="dialog"` +
   `aria-modal="true"` + `aria-labelledby` на заголовок.
3. `EmptyState` — иконка + заголовок + подзаголовок + опциональный CTA, принимает `titleKey`/
   `descriptionKey` (не свободный текст) — используется для `ux.empty.search_no_results`,
   `ux.empty.cart`, `ux.empty.orders`, `ux.empty.offers_pool`, `ux.empty.order_queue` (все ключи
   из DTJ-402).
4. `ErrorState` — полноэкранный/инлайн (`variant: 'fullscreen' | 'inline'`) вариант, показывает
   пользователю ТОЛЬКО `ux.error.generic_500`-подобный дружелюбный текст, техническая деталь
   (реальный код ошибки/`requestId`) — в `<details>`, скрытом по умолчанию, видимом при явном
   раскрытии (для скриншота в поддержку).
5. `OfflineBanner` — ЕДИНЫЙ компонент (не разные форм-факторы под разный контекст — конкретно
   исправляет находку из design-reference), текст ВСЕГДА `ux.error.network_offline`
   («Нет подключения к интернету. Показаны последние сохранённые данные.»), НЕ закрывается
   пользователем, пока сеть не восстановлена (`SRS-UX-021`), два визуальных режима через проп
   `compact: boolean` (полноэкранный на списках/компактный инлайн на детальных экранах) — ОДИН
   компонент с двумя размерами, не два разных компонента с разным текстом.
6. `ProgressBar` — базовая генерическая версия (0–100%, `SRS-UX-021` таблица), проп
   `label`/`labelKey` для подписи прогресса; агрегирующий Excel-импорта вариант (N батчей) — ВНЕ
   зоны этого тикета, флагуется как пробел дизайна (`32-design-reference.md` §«Пробелы дизайна»),
   реализуется тем эпиком, чей экран его первым потребует (EP-05/EP-12 веб-кабинет аптеки),
   вероятно как обёртка над этим базовым `ProgressBar`, не с нуля.
7. `SRS-UX-025`/`SRS-UX-026`-специфичные утилиты (баннер потери WS-соединения с REST-поллингом
   деградацией, UI-уровневый circuit breaker после 3 подряд `502`/`503`/таймаутов) — реализуются
   как ХУКИ `use-connection-status.ts`/`use-ui-circuit-breaker.ts` в этом же тикете (тонкая
   переиспользуемая логика, не привязанная к конкретному экрану), потребляются конкретными
   фичами (`apps/pharmacy` order-queue и др.) в соответствующих эпиках — этот тикет производит
   готовый хук, не сам экран.
8. Обновить `packages/ui/src/index.ts`.

## Критерии приёмки

1. Given `<OfflineBanner />` показан на экране, When пользователь пытается его закрыть (нет кнопки
   закрытия в DOM в принципе), Then баннер остаётся видимым до тех пор, пока проп `isOnline`
   (управляется потребителем через `navigator.onLine`/событие) не станет `true`.
2. Given `<Modal isOpen>` открыт, When нажат `Tab` многократно, Then фокус циклически остаётся
   внутри модалки (не уходит на элементы страницы позади), `Escape` вызывает `onClose`.
3. Given `<Toast persistent>` показан, When проходит 10 секунд без действия пользователя, Then
   тост остаётся видимым (не закрывается автоматически в отличие от обычного тоста с таймером 4с).
4. Given `useUiCircuitBreaker()` фиксирует 3 подряд ошибки `503` за короткий период, When 4-й
   запрос инициируется пользователем нажатием «Повторить», Then хук возвращает состояние
   `blocked: true` на 60 секунд, кнопка «Повторить» — `disabled` весь этот период независимо от
   попыток клика.

## Тест-план

Unit (по компоненту):
- `Toast`: автозакрытие ровно через 4000мс (мокнутые таймеры `vi.useFakeTimers()`); `persistent`
  не закрывается по таймеру; несколько тостов подряд не перекрывают друг друга (очередь/стек).
- `Modal`/`BottomSheet`: focus trap — `Tab`/`Shift+Tab` циклируются; `Escape` закрывает; фокус
  возвращается на триггер-элемент после закрытия; `renderWithA11yCheck` ноль нарушений.
- `EmptyState`/`ErrorState`: рендерят переданный `titleKey`/`descriptionKey` через `useT()`,
  ОТКАЗЫВАЮТСЯ от рендера (TS-ошибка компиляции), если передан произвольный `string` вместо ключа.
- `OfflineBanner`: нет кнопки/элемента закрытия в DOM при любом состоянии пропсов (структурный
  тест на отсутствие, не просто «не находит по умолчанию»).
- `use-ui-circuit-breaker.spec.ts`: 3 последовательные ошибки → блокировка 60с; успешный запрос
  сбрасывает счётчик; блокировка снимается по истечении таймера ИЛИ явным pull-to-refresh
  (проверяется оба пути сброса).

Порог покрытия — 90%.

## Риски и подводные камни

`useFocusTrap` (DTJ-403) обязателен как зависимость — если DTJ-403 отстаёт по срокам, `Modal`/
`BottomSheet` не блокируются полностью (можно реализовать временный inline focus-trap), но ОБЯЗАН
быть заменён на общий хук до слияния PR — не дублировать логику. `use-ui-circuit-breaker` хранит
состояние per-эндпоинт (не глобально на всё приложение — иначе один упавший маршрут блокирует
повторные попытки на ДРУГОМ, не связанном маршруте) — потребитель обязан передавать стабильный
`key`/`endpointId` при инициализации хука, задокументировать это явно в JSDoc, иначе фичи будут
использовать хук неправильно по умолчанию (общий на всё приложение инстанс).
- Файл `packages/ui/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- D-27: одна подволна с `DTJ-405` (оба дописывают `packages/ui/src/index.ts`) — получен явный
  `depends_on: DTJ-405`.
