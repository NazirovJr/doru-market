## Задача

Каждый следующий компонент `packages/ui` и каждый экран любого фронтового эпика обязаны использовать
CSS-переменные вместо литеральных HEX/px — это единственный механизм, которым White-Label
перекраска (R3) и смена нейтрального дефолта работают без правки кода (`03-ARCHITECT-DECISIONS.md`
D-01: «ребрендинг обязан стоить изменение конфига и ассетов, ноль правок кода»). Без единого
источника токенов до появления первого компонента (DTJ-404) каждый разработчик будет вынужден
изобретать значения на месте — что и произошло в демо-канвасе Claude Design
(`docs/spec/32-design-reference.md`: несогласованные радиусы 8/10/12/14/16px, буквальные HEX
вместо переменных). Токены также обязаны включать серверную валидацию allowlist значений бренда
(`PATCH /tenant-settings`, `SRS-TEN-014`), иначе White-Label сеть сможет вставить произвольную
CSS/HTML-инъекцию через поле палитры (угроза `SRS-NFR-006`, TC-NFR-006).

## Технический контекст

Слой — чистый `packages/ui/src/tokens/**`, без зависимости от React (CSS custom properties +
TS-функция валидации, переиспользуемая и фронтендом при отправке формы брендинга, и потенциально
бэкендом EP-15/EP-03 при валидации `PATCH /tenant-settings` — модуль экспортирует чистую функцию
`validateBrandingPayload()` без побочных эффектов, пригодную для импорта в любой слой). Источник
формул — `docs/spec/30-ux-screens-and-flows.md` §2 (`SRS-UX-011..018`, актуализирован `[D-26]`) и
расхождения, разрешённые архитектором в `03-ARCHITECT-DECISIONS.md` D-26 (функциональное — выигрывает
спека; визуальное — выигрывает дизайн, но кодифицируется токеном): фокус-кольцо от `--brand-primary`
(спека), типографика +22/+28, вес 600, радиусы 8/12/16/999, `--shadow-modal` alpha 0.08,
`--brand-warning-fg`/`--brand-warning-strong` (дизайн).

## Что сделать

1. `packages/ui/src/tokens/colors.css` — блок `:root` с полным списком `--brand-*` (нейтральный
   дефолт из таблицы `SRS-UX-011`: `primary #64748b`, `primary-hover #475569`, `secondary #94a3b8`,
   `accent #0ea5e9`, `bg #f8fafc`, `surface #ffffff`, `text #0f172a`, `text-muted #64748b`,
   `border #e2e8f0`) + зафиксированные (не редактируемые тенантом, `SRS-UX-012`) `--brand-success
   #16a34a`, `--brand-danger #dc2626`, `--brand-warning #d97706` и их производные семантические
   оттенки фон/рамка/текст (`--brand-success-bg/-border/-text` и аналогично danger/warning,
   значения — из `32-design-reference.md` §«Расширенные семантические оттенки»:
   success `#f0fdf4`/`#bbf7d0`/`#166534`, danger `#fef2f2`/`#fecaca`/`#991b1b`,
   warning-bg `#fffbeb`/warning-border `#fde68a`) + **[D-26]** явные `--brand-warning-fg: #b45309`
   (иконка/акцент на предупреждении) и `--brand-warning-strong: #92400e` (усиленный/тёмный текст) —
   вводятся ИМЕННО как отдельные токены, а не хардкод в компонентах, чтобы не разъезжаться с
   `--brand-warning` при White-Label перекраске (`SRS-UX-011`, обновлено `[D-26]`).
2. `packages/ui/src/tokens/typography.css` — `--font-size-xs..3xl` (12/14/16/18/20/24/30/36px)
   **[D-26] расширено**: добавить `--font-size-h2: 22px` (между `lg` 20 и `xl` 24) и
   `--font-size-h1: 28px` (между `xl` 24 и `2xl` 30) — см. `SRS-UX-014`, обновлено `[D-26]`;
   `--line-height-tight` 1.25, `--line-height-normal` 1.5, `--font-weight-regular/-medium/-semibold/-bold`
   (400/500/**600 [D-26]**/700), `--brand-font-family: "'Inter', system-ui, sans-serif"`
   (`SRS-UX-014`).
3. `packages/ui/src/tokens/spacing.css` — `--space-1..16` (4/8/12/16/20/24/32/40/48/64px,
   `SRS-UX-016`).
4. `packages/ui/src/tokens/radii.css` — `--brand-radius: 8px` (base) и производные **[D-26]**:
   `--radius-sm: var(--brand-radius)` (8px), `--radius-md: calc(var(--brand-radius) * 1.5)` (12px),
   `--radius-lg: calc(var(--brand-radius) * 2)` (16px), `--radius-full: 999px` (ВСЕГДА фиксированное
   значение, не производное от `--brand-radius`, `SRS-UX-017`). Итоговый зафиксированный набор —
   ровно **8 / 12 / 16 / 999** — формула изменена относительно исходной (была `sm`=0.5×/`md`=1×/
   `lg`=1.5×, что давало 4/8/12) именно чтобы совпасть с этим набором; значения `10px`/`14px` из
   демо-канваса в токены НЕ переносятся.
5. `packages/ui/src/tokens/shadows.css` — `--shadow-sm: 0 1px 2px rgba(15,23,42,0.06)`,
   `--shadow-modal: 0 8px 24px rgba(15,23,42,0.08)` (**[D-26]**, alpha снижена с `0.16` — тяжело для
   светлой темы, `0.08` — то, что фактически показывает дизайн), `--focus-ring: 0 0 0 3px
   color-mix(in srgb, var(--brand-primary) 40%, transparent)` (офсет 2px описывается в компоненте,
   не в токене, `SRS-UX-018`; реализовать ИМЕННО от `--brand-primary`, НЕ от `--brand-accent` —
   явное разрешение расхождения `[D-26]` (было №5 в `32-design-reference.md`): фиксированный акцент
   сломает White-Label и потеряет контраст, дизайн-канвас в этом месте признан неверным ориентиром).
6. `packages/ui/src/tokens/index.ts` — реэкспорт всех CSS-файлов (`import './colors.css'` и т.д.)
   одним модулем `import '@dorutj/ui/tokens'` для подключения в `app/`-точке входа каждого
   приложения.
7. `packages/ui/src/tokens/branding-allowlist.ts` — чистая функция
   `validateBrandingPayload(payload: TenantBrandingInput): Result<ValidBranding, BrandingValidationError[]>`:
   - HEX-регэксп `^#([0-9a-fA-F]{3}|[0-9a-fA-F]{6})$` для `primary/primaryHover/secondary/accent/
     bg/surface/text/textMuted/border` — ЛЮБОЕ не-HEX значение (включая `url(...)`, `javascript:`,
     `<script>` — воспроизводит атаку `TC-NFR-006`) отклоняется без исключений и без попытки
     "исправить";
   - `success/danger/warning` — присутствие этих ключей во входном payload само по себе ошибка
     валидации (`BRAND_SEMANTIC_TOKEN_LOCKED`) — семантика не редактируется тенантом (`SRS-UX-012`);
   - `radius` — регэксп `^\d{1,2}px$` (`SRS-TEN-014` allowlist-формат);
   - `fontFamily` — сверка со статическим allowlist-массивом ≤10 Google Fonts-стеков + fallback
     `system-ui, sans-serif` (сам список фонтов заводится этим тикетом с одним проверенным
     значением `Inter` — расширение списка последующими тикетами/эпизодами не блокирует этот
     тикет, но структура данных обязана поддерживать добавление без переписывания валидатора).
8. `packages/ui/src/tokens/branding-allowlist.spec.ts` — unit-тесты валидатора (см. тест-план).

## Критерии приёмки

1. Given payload `{ primary: "#111827" }`, When `validateBrandingPayload`, Then возвращает
   `{ ok: true }` с нормализованным значением.
2. Given payload `{ primary: "url(javascript:alert(1))" }` (воспроизводит `TC-NFR-006`), When
   `validateBrandingPayload`, Then возвращает `{ ok: false, errors: [{ field: 'primary', code:
   'INVALID_HEX_FORMAT' }] }`, значение НЕ проходит дальше валидатора ни в каком виде.
3. Given payload с ключом `success: "#000000"` (попытка переопределить семантический токен), When
   `validateBrandingPayload`, Then возвращает ошибку `BRAND_SEMANTIC_TOKEN_LOCKED` для поля
   `success`, остальные валидные поля payload при этом НЕ отбрасываются целиком (частичная ошибка
   по конкретному полю, не отказ всего запроса).
4. Given `--radius-full` вычисляется независимо от `--brand-radius`, When `--brand-radius`
   устанавливается в `0px` (тестовый CSS override), Then вычисленное значение `--radius-full`
   в DOM остаётся `999px` (проверяется через `getComputedStyle` в компонентном/визуальном тесте).

## Тест-план

Unit (`packages/ui/src/tokens/branding-allowlist.spec.ts`, Vitest):
- `accepts valid 6-digit and 3-digit hex colors`
- `rejects non-hex color value (url/javascript/script injection payloads)` — набор пейлоадов из
  `TC-NFR-006`-подобного списка (переиспользовать пейлоады из тикета DTJ-425, если он написан
  раньше, иначе — локальный `tests/fixtures/branding-injection-payloads.json`, создаваемый этим
  тикетом и переиспользуемый DTJ-425 в обратную сторону)
- `rejects semantic token override (success/danger/warning) with BRAND_SEMANTIC_TOKEN_LOCKED`
- `accepts radius matching ^\d{1,2}px$, rejects otherwise (e.g. "8", "100px", "-4px")`
- `accepts fontFamily from allowlist, rejects arbitrary font stack`
- `partial validation: one invalid field does not drop other valid fields from the result`

Интеграционных тестов не требуется (чистая функция без ввода-вывода). E2E не требуется на этом
тикете — используется позже E2E-инвариантом бренда (DTJ-423).

Порог покрытия для `packages/ui/src/tokens/branding-allowlist.ts` — 90% (эквивалент `application`/
`domain`-логики по строгости, хотя формально лежит в `packages/ui`, `02-CLEAN-ARCHITECTURE-AND-CODE.md`
§6.4 применяется по духу правила, а не по пути файла).

## Риски и подводные камни

`color-mix(in srgb, ...)` не поддерживается в очень старых WebView (некоторые Android Go
устройства, целевая аудитория по `research §7.1`) — если при ручной проверке на реальном дешёвом
устройстве обнаружится проблема с рендерингом фокус-кольца, предусмотреть статичный HEX-фоллбэк
через `@supports not (color: color-mix(in srgb, red, blue))`, не блокирующий этот тикет, но
фиксируемый как follow-up. Список allowlist-шрифтов ограничен одним `Inter` на этом тикете —
полная проверка покрытия таджикских спецбукв (`Ғ ғ Ӣ ӣ Қ қ Ӯ ӯ Ҳ ҳ Ҷ ҷ`) для ДОБАВЛЕНИЯ новых
шрифтов в будущем — обязательный ручной шаг per `SRS-UX-015`, не автоматизируется этим тикетом.
- Файл `packages/ui/src/tokens/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
