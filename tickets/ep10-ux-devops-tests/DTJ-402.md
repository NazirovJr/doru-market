## Задача

`packages/i18n` — единственный источник строк для React (R1) и Flutter (R2) клиентов
(`SRS-UX-027`: «ни один словарь не хранится дублирующе в клиентском коде»). Без готового `useT()` и
канонических ключей `ux.*` каждый фронтовый эпик рискует хардкодить русские строки «для скорости» —
это прямое нарушение `02-CLEAN-ARCHITECTURE-AND-CODE.md` §5 («ноль хардкодных строк») и
блокирующее замечание ревью по `SRS-UX-010`. Таджикский язык как дефолт (не `ru`, не auto-detect по
системному языку устройства) — это осознанное架構ное решение продукта (`research §8`), а не техническая
деталь, поэтому резолвинг локали обязан быть реализован именно по специфицированному приоритету, а
не «как обычно делают i18n-библиотеки».

## Технический контекст

Слой — `packages/i18n/src/**`, без побочных эффектов кроме `localStorage`/`fetch` в явно
обозначенных функциях. Используется `i18next` + `i18next-icu` (плюрализация по CLDR, покрывает
`ru`/`en` тремя формами `one/few/many`; для `tj` — одна неизменяемая форма без plural-вариантов,
`SRS-UX-032`). Источник канонических текстов — таблица `docs/spec/30-ux-screens-and-flows.md` §5
(`SRS-UX-023`), статус текстов — `pending_legal_review` (текущая рабочая версия, финальная вычитка
носителем `tj` — вне этого тикета, флагуется в «Рисках»). Форматирование чисел/дат/валюты — через
`Intl.NumberFormat`/`Intl.DateTimeFormat`, локаль `tg-TJ` для `tj` (ближайшая доступная ICU-локаль,
`SRS-UX-031`).

## Что сделать

1. `packages/i18n/src/locales/{tj,ru,en}.json` — заполнить ВСЕ ключи из таблицы `SRS-UX-023`
   (`ux.empty.search_no_results`, `ux.empty.cart`, `ux.empty.orders`, `ux.empty.offers_pool`,
   `ux.empty.order_queue`, `ux.error.network_offline`, `ux.error.action_requires_network`,
   `ux.error.search_timeout`, `ux.error.payment_provider_unavailable`, `ux.error.otp_expired`,
   `ux.error.otp_locked`, `ux.error.stock_changed`, `ux.error.pharmacy_unavailable`,
   `ux.error.image_illegible`, `ux.error.mic_permission_denied`, `ux.error.geolocation_denied`,
   `ux.error.generic_500`, `ux.warning.stale_data`, `ux.warning.duplicate_substance`,
   `ux.info.partial_fulfillment_timeout`) буквально теми строками RU/TJ/EN, что приведены в
   документе — НЕ формулировками из `docs/spec/32-design-reference.md` (канонический текст
   выигрывает у дизайн-канваса, явно зафиксировано расхождение №6/§«Реализационные заметки» п.2
   design-reference). Плейсхолдеры `{{minutesAgo}}`/`{{substanceNames}}` — сохранить как есть
   (интерполяция i18next).
2. Добавить группу-заглушку `ux.plain_language.*` (`SRS-UX-005`: «МНН» → «действующее вещество» /
   «моддаи фаъол»; «OTP» → «код подтверждения» / «рамзи тасдиқ»; «эскроу» пользователю не
   показывается вообще, ключ не заводится) — минимум 2 ключа (`ux.plain_language.inn`,
   `ux.plain_language.otp`) как основа для последующих фронтовых эпиков, полный список расширяется
   ими по мере появления текстов экранов, не блокирует этот тикет.
3. Добавить служебные ключи форматирования: `currency.somoni_suffix` (`сомони`/сомонӣ`/пусто для
   `en`, т.к. `TJS` не переводится автоматически движками в слово — `SRS-UX-031`), базовые ключи
   `common.back`/`common.retry`/`common.cancel`/`common.confirm` — минимальный набор, достаточный,
   чтобы `packages/ui`-компонентам (DTJ-404+) было на что ссылаться без придумывания новых ключей
   на лету.
4. `packages/i18n/src/use-t.ts` — хук `useT()` поверх `react-i18next` `useTranslation()`, тонкая
   обвязка (не бизнес-логика) с типизацией ключей через сгенерированный `type TranslationKey =
   keyof typeof ruDictionaryFlat` (защита от опечатки в ключе на этапе компиляции — TS ошибка при
   несуществующем ключе).
5. `packages/i18n/src/resolve-locale.ts` — чистая функция `resolveLocale(input: {
   sessionOverride?: Locale; userPreferredLocale?: Locale; storedLocale?: Locale;
   tenantDefaultLocale: Locale }): Locale`, реализующая ТОЧНО приоритет `SRS-UX-028`: (1) явный
   выбор в текущей сессии → (2) `users.preferred_locale`, если авторизован → (3)
   `localStorage.dorutj.locale` → (4) `tenants.default_locale` резолвленного тенанта. `Accept-Language`
   заголовок браузера НЕ используется НИГДЕ в этой функции (`SRS-UX-028` п.5 — явный анти-паттерн,
   намеренно не реализуется).
6. `packages/i18n/src/format-money.ts` — `formatMoney(amountDiram: number, locale: Locale):
   string`, `Intl.NumberFormat` для числовой части + `currency.somoni_suffix` ключ (НЕ встроенный
   ISO-код `TJS`), дирамы делятся на 100 перед форматированием.
7. `packages/i18n/src/format-date.ts` — `formatDate`/`formatRelativeDate`/`formatTime` по таблице
   `SRS-UX-031` (полная дата `ДД.ММ.ГГГГ`, относительная <7 дней «сегодня/вчера/N дней назад» с
   ключами локали, время `ЧЧ:ММ` 24-часовой формат ВСЕГДА, без AM/PM).
8. `packages/i18n/src/format-number.ts` — форматирование количества упаковок с разрядами через
   пробел + плюрализация: для `ru`/`en` — через `i18next-icu`/`Intl.PluralRules` (3/2 формы), для
   `tj` — ОДНА неизменяемая строка с классификатором «дона» (`SRS-UX-032`) — реализовать явной
   веткой `if (locale === 'tj') return singleForm`, не полагаться на то, что ICU-движок сам
   корректно даст 1 форму для `tj` (движок может не знать `tg`-плюральные правила вовсе).
9. `packages/i18n/src/format-phone.ts` — маска отображения `+992 XX XXX XX XX`, одинаковая во всех
   локалях (`SRS-UX-031`, использует формат VO `PhoneNumber` из `SRS-DOM-069` как контракт, но не
   импортирует backend-код — принимает уже провалидированную E.164-подобную строку и только
   форматирует для отображения).
10. `packages/i18n/src/i18n-provider.tsx` — React-провайдер, инициализирующий `i18next` с
    `dir="ltr"` фиксированным глобально (`SRS-UX-033` — RTL не поддерживается, не оставлять
    открытым вопросом в коде), `spellcheck`/`autocorrect` НЕ включаются провайдером ни для одного
    поля (обязанность конкретного `SearchBar`, см. DTJ-408 — здесь только не мешать).
11. `packages/i18n/src/index.ts` — публичный баррель: `useT`, `resolveLocale`, `formatMoney`,
    `formatDate`, `formatRelativeDate`, `formatNumber`/`formatPluralized`, `formatPhone`,
    `I18nProvider`, типы `Locale`/`TranslationKey`.

## Критерии приёмки

1. Given словарь `ru`, When запрошен ключ `ux.error.otp_locked`, Then возвращается ровно
   «Слишком много неверных попыток. Запросите новый код через SMS/Telegram.» (дословно, не
   формулировка design-reference «Повторите попытку через 5 минут»).
2. Given `resolveLocale({ storedLocale: 'ru', tenantDefaultLocale: 'tj' })` (гость, ранее выбирал
   `ru`, без сессионного оверрайда и без профиля), When вызов, Then результат `'ru'` (приоритет 3
   выигрывает у приоритета 4).
3. Given `resolveLocale({ tenantDefaultLocale: 'tj' })` (ничего не задано вообще, включая
   `Accept-Language` браузера — не передаётся в функцию как параметр в принципе), When вызов, Then
   результат `'tj'` (дефолт тенанта, НЕ auto-detect устройства).
4. Given `formatNumber(1, 'ru', 'package')`/`formatNumber(2, 'ru', 'package')`/
   `formatNumber(5, 'ru', 'package')`, When вызов, Then результаты «1 упаковка»/«2 упаковки»/
   «5 упаковок» (три разные формы); Given `formatNumber(1, 'tj', 'package')` и
   `formatNumber(5, 'tj', 'package')`, Then обе формы идентичны по грамматической структуре
   (число + неизменяемое существительное + классификатор), НЕ пытаются подобрать русское-подобное
   склонение.
5. Given несуществующий ключ передан в `useT()` в режиме разработки (`NODE_ENV=development`), When
   рендер, Then TypeScript отказывается компилировать вызов (проверяется тестом типов
   `expectTypeOf`/`tsd`, не рантайм-тестом).

## Тест-план

Unit (`packages/i18n/src/resolve-locale.spec.ts`):
- `session override always wins regardless of other inputs`
- `authenticated user preferred_locale wins over stored/default when no session override`
- `guest falls back to localStorage stored locale`
- `falls back to tenant default locale when nothing else is set`
- `never reads or is influenced by Accept-Language header (parameter does not exist in signature —
  compile-time guarantee, documented by test comment)`

Unit (`packages/i18n/src/format.spec.ts`):
- `formatMoney formats diram as somoni with locale-specific suffix (ru/tj/en)`
- `formatDate — relative "today/yesterday/N days ago" boundary at exactly 7 days`
- `formatNumber — ru plural forms 1/2/5/11/21 (edge cases few/many boundary)`
- `formatNumber — tj always single form regardless of count`
- `formatPhone — normalizes to +992 XX XXX XX XX display mask`

Все словарные ключи из `SRS-UX-023` — снапшот-тест (`packages/i18n/src/locales/*.spec.ts` или
единый `dictionary-completeness.spec.ts`): проверяет, что множество ключей ИДЕНТИЧНО между `tj`/
`ru`/`en` (ни один ключ не забыт в одной из трёх локалей — иначе UI молча остаётся на предыдущем
языке при переключении, ровно сценарий шага 6 `SRS-NFR-076`/CUJ-12).

Порог покрытия — 90% для `resolve-locale.ts`/`format-*.ts` (чистые функции, эквивалент
`domain`/`application` по строгости).

## Риски и подводные камни

Тексты помечены `pending_legal_review` в самом SRS (§5 30-ux: «курируются лингвистом/фармацевтом
перед продакшен-релизом») — таджикские формулировки требуют вычитки носителем языка до
продакшен-релиза, это ЗА ГРАНИЦЕЙ данного тикета (программная реализация корректна и с текущими
текстами, замена текстов позже — не структурное изменение). `i18next-icu` может не иметь
встроенных CLDR-плюральных правил для `tg` (таджикский ISO-код) — на этот случай явно
зашивается собственная ветка `tj` в `format-number.ts` (шаг 8), не полагающаяся на движок; если
у движка ЕСТЬ правила для `tg` и они отличаются от «одна форма», собственная ветка всё равно
имеет приоритет (детерминированность важнее «магии» библиотеки). Источник строк по `SRS-UX-027`
формально — `GET /api/v1/i18n/:locale`, а не статический JSON-бандл; конкретный backend-эндпоинт,
раздающий эти словари, НЕ входит в зону владения `packages/ui`/`packages/i18n` (файлы этого
эпика) — он реализуется тем backend-модулем, который эксплуатирует эти JSON как источник данных
(вероятно EP-01 как часть базовых API-конвенций, точный владелец не зафиксирован в
`00-EPICS.md` таблице файлов явно). Зафиксировать в PR явную договорённость с Tech Lead
соответствующего эпика о том, что JSON-файлы этого пакета — единственный источник правды,
эндпоинт лишь их раздаёт (не дублирует копией).
- Файл `packages/i18n/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
