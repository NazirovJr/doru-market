## Задача

EP-18 закрыт, но `apps/web` продолжает жить на собственных копиях компонентов, написанных
до появления дизайн-системы. Пока копии не заменены, `packages/ui` — мёртвый код, а
исправление любого дефекта требуется делать дважды.

Шапка приложения до сих пор рисует строковую константу `'[ Бренд ]'` и самодельный
переключатель языка с комментарием `TODO(EP-18)` — притом что `BrandLogo` и
`LanguageSwitcher` готовы (DTJ-408).

## Известные расхождения API (выписаны исполнителями EP-18, не выдумывать заново)

1. **MapView.** Локальная карта рисует пины через `Marker` + `Popup` (React-портал);
   компонент дизайн-системы — через GeoJSON-источник со встроенной кластеризацией.
   Содержимое попапа переносится в собственный попап, открываемый по `onSelect`.
   URL тайлов локальная версия берёт из `import.meta.env.VITE_TILESERVER_URL` — общий
   компонент принимает `styleUrl` пропом и в `env` не лезет. Колбэка смены viewport в
   `MapView` НЕТ — он нужен экрану `/map`; добавить его в API `MapView` (тогда правка
   `packages/ui` входит в объём этого тикета) либо обосновать другое решение.
   Кластеризация меняет поведение экрана: на малом зуме пины сливаются — это осознанное
   изменение UX, отметить в отчёте.
2. **FileDropzone.** Локальный компонент сам ходит в сеть (`uploadOnboardingDocument`) и
   сам знает ключи переводов; общий — чистое отображение без сетевых вызовов и без
   `useT()`. Нужна тонкая обёртка: вызвать загрузку, транслировать прогресс и коды
   отклонения (`too_large`/`invalid_type`) в тексты `onboarding.upload.error_*`.
3. **Строки.** Ни один компонент `packages/ui` не вызывает `useT()` — тексты приходят
   пропами. Переводы резолвит потребитель, то есть `apps/web`.

## Развилка, которую надо закрыть

`packages/i18n` содержит `I18nProvider` (DTJ-402), написанный и никем не подключённый;
`apps/web` живёт на собственном `shared/config/locale-provider.tsx`. Два провайдера локали
в одном приложении — источник расхождений. Выбрать один и обосновать: либо `apps/web`
переходит на `I18nProvider`, либо `I18nProvider` признаётся лишним и удаляется из
`packages/i18n`. Оставить оба — не решение.

## Отдельный пункт: CSS карты

Сборка `packages/ui` линкует CSS библиотеки карт в общий `index.css` (24 КБ → 101 КБ),
потому что Vite в library-mode не делит CSS для динамических импортов. Это ~70 КБ на
КАЖДОМ экране, включая те, где карты нет. Проверить, уходит ли раздувание, если CSS
карты импортирует потребитель (`apps/web`), а не сам компонент; если да — так и сделать.

## Критерии приёмки

1. Given экран `/`, When рендер, Then шапка показывает `BrandLogo` и `LanguageSwitcher`
   из `packages/ui`; строки `'[ Бренд ]'` в кодовой базе не остаётся.
2. Given любой из заменённых файлов, When поиск по репозиторию, Then локальной копии
   компонента больше нет (файл удалён, а не оставлен неиспользуемым).
3. Given `grep` по `apps/web`, When поиск `toFixed(2)` рядом с `Diram`, Then совпадений нет.
4. Given экран `/map`, When открытие, Then карта работает: пины отображаются, выбор пина
   открывает карточку аптеки.
5. Given форма `/pharmacy-application`, When выбран файл 11 МБ, Then ошибка показывается
   ДО отправки в сеть (поведение DTJ-076 сохранено на общем компоненте).

## Тест-план

Существующие 313 тестов `apps/web` — регрессионная сеть. Их падение означает изменение
поведения; чинить кодом, а не правкой ожиданий, кроме случаев, где тест проверял
внутренности удалённого локального компонента (такие переписать на публичное поведение и
перечислить в отчёте поимённо).

Критерии 1 и 4 проверять запуском в браузере, а не только `jsdom`.
