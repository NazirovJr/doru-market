## Задача

Telegram Mini App — часть обязательной возможности R1-13 (`docs/04-SCOPE-DECISION-PIVOT.md`):
основной канал уведомлений в РТ дешевле SMS, и обязательный режим приложения. `docs/spec/32-design-reference.md`
прямо фиксирует: «Слой Telegram Mini App... в дизайне не показан вообще — реализуется по 30-ux §9
без визуального прецедента». Без готового каскада темизации (`--brand-*` → `--tg-theme-*`) и
хуков `MainButton`/`BackButton` каждый экран, открытый внутри Telegram, будет выглядеть как
обычный веб (нарушение нативности хоста) и дублировать логику активности кнопки в обход
существующей `model/`-логики компонента (`SRS-UX-046` — прямое требование ОДНОЙ и той же логики
для системной и обычной кнопки).

## Технический контекст

`@telegram-apps/sdk-react` поверх существующего `apps/web` — НЕ отдельное приложение (`SRS-UX-043`).
`is-twa-runtime.ts` — детектор `window.Telegram?.WebApp` присутствия, определяющий, какой из двух
путей рендера использовать (обычная `Button` DTJ-404 vs системная `MainButton`) — оба пути делят
ОДНУ модель состояния (`disabled`/`loading` вычисляются одинаково независимо от среды, `SRS-UX-046`).
Каскад темизации — третий, самый внешний слой поверх `--brand-*` (DTJ-401): нейтральный дефолт →
бренд тенанта → (только в TWA) `--tg-theme-*`.

## Что сделать

1. `is-twa-runtime.ts` — чистая функция `isTwaRuntime(): boolean`, проверяет
   `window.Telegram?.WebApp` без побочных эффектов, безопасна к вызову в SSR/тестовом окружении
   (не бросает при отсутствии `window`).
2. `use-telegram-theme.ts` — хук `useTelegramTheme()`, вызывающий (только если `isTwaRuntime()`)
   `themeParams.bindCssVars()` + `viewport.expand()` (обязателен при старте, `research 07 §1.3` —
   иначе приложение открывается в компактной половине экрана) и применяющий маппинг СТРОГО по
   таблице `SRS-UX-044`: `--brand-bg`←`--tg-theme-bg-color`, `--brand-surface`←`--tg-theme-secondary-
   bg-color`, `--brand-text`←`--tg-theme-text-color`, `--brand-text-muted`←`--tg-theme-hint-color`,
   `--brand-primary`←`--tg-theme-button-color`, текст на кнопке←`--tg-theme-button-text-color`,
   `--brand-border`←`--tg-theme-section-separator-color` (если хост не отдаёт значение — fallback
   остаётся `--brand-border`, не падает в `undefined`). `--brand-success`/`-danger`/`-warning` —
   ЯВНО НЕ включены в маппинг (проверяется тестом-нарушителем — попытка добавить их в таблицу
   должна быть поймана ревью, не только документацией).
3. `use-main-button.ts` — хук `useMainButton({ textKey, disabled, loading, onClick })`: при
   `isTwaRuntime()` — управляет системной `MainButton` (текст/цвет/`loading` синхронизированы с
   состоянием формы страницы, идентично обычной кнопке), при обычном вебе — хук возвращает `null`/
   `{ shouldRenderFallback: true }`, и потребитель рендерит обычную `<Button>` (DTJ-404) — двойной
   путь РЕНДЕРА по признаку среды, БЕЗ дублирования `disabled`/`loading`-логики (она вычисляется
   ОДИН раз до вызова хука, передаётся готовым значением, `SRS-UX-046`).
4. `use-back-button.ts` — хук `useBackButton({ isVisible, onClick })`: показывает/скрывает
   системную `BackButton` (скрыта на корневых табах `/`, `/cart`, `/orders`, `/profile`, видима на
   вложенных маршрутах — решение «корневой/вложенный» принимает потребитель через `isVisible`,
   хук не знает про роутинг), в обычном вебе — no-op (нет системной кнопки назад, потребитель
   рендерит обычную стрелку в шапке через уже существующий паттерн, вне этого хука).
5. Обновить `packages/ui/src/index.ts` — экспорт `isTwaRuntime`, `useTelegramTheme`,
   `useMainButton`, `useBackButton`.

## Критерии приёмки

1. Given `window.Telegram` отсутствует (обычный веб), When `isTwaRuntime()`, Then возвращает
   `false`, и `useTelegramTheme()` не пытается вызвать `bindCssVars()`/`viewport.expand()`
   (проверяется отсутствием вызова мока SDK).
2. Given `window.Telegram?.WebApp` присутствует (мок в тесте), When `useTelegramTheme()`
   монтируется, Then `--brand-primary` в вычисленных стилях документа принимает значение
   `--tg-theme-button-color`, а `--brand-success`/`-danger`/`-warning` остаются НЕИЗМЕННЫМИ
   (равны значениям бренда, не перезаписаны темой хоста).
3. Given TWA-режим, страница `/cart`, When `useBackButton({ isVisible: false, ... })`, Then
   системная `BackButton.hide()` вызвана (мок SDK), не `.show()`.
4. Given форма невалидна (`disabled: true` вычислено моделью страницы ДО вызова хука), When
   `useMainButton({ disabled: true, ... })` в TWA-режиме, Then системная `MainButton` переходит в
   неактивное состояние; Given ТОТ ЖЕ вычисленный `disabled: true` в обычном вебе, When рендер
   обычной `<Button disabled>`, Then оба пути используют ОДНО и то же входное булево значение без
   собственной повторной проверки условий формы внутри хука/компонента.

## Тест-план

Unit (мокается `@telegram-apps/sdk-react`, полностью изолированно от реального Telegram-рантайма):
- `is-twa-runtime.spec.ts`: `true`/`false` в зависимости от наличия `window.Telegram.WebApp`; не
  бросает при отсутствии `window` (SSR-safe проверка, если применимо к стеку сборки).
- `use-telegram-theme.spec.ts`: полная таблица маппинга `SRS-UX-044` — каждая пара токенов
  проверяется отдельным кейсом; `--brand-success/-danger/-warning` НЕ входят в применяемый
  маппинг (фикстура-нарушитель: тест намеренно проверяет, что добавление этих ключей в маппинг
  тестом ловится — аналог паттерна `tests/arch/`, «ловушка проверяется ловушкой»); `bindCssVars`/
  `viewport.expand` вызываются только при `isTwaRuntime() === true`.
- `use-main-button.spec.ts`: возвращает `shouldRenderFallback: true` вне TWA; синхронизирует
  `disabled`/`loading` из готовых пропов без внутреннего пересчёта; `onClick` вызывается один раз
  на клик по системной кнопке (мок SDK).
- `use-back-button.spec.ts`: `show()`/`hide()` вызываются в соответствии с `isVisible`; no-op вне
  TWA (мок SDK не вызывается вовсе).

Порог покрытия — 90%.
