## Задача

`packages/ui` закрыт целиком (DTJ-400..411): 27 компонентов, канонические токены, сборка
41 КБ JS. При этом `apps/web` не импортирует из него ни строки. Экраны рисуются шестью
временными токенами, заведёнными в `styles.css` тикетом DTJ-003 с явной пометкой
`TODO(EP-18): заменить значения токенов на итоговую дизайн-систему packages/ui`.

Пока этот тикет не выполнен, вся работа EP-18 невидима в браузере, а White-Label не
работает: тенант переопределяет `--brand-primary`, а экраны продолжают брать цвет из
захардкоженного `@theme`-блока.

## Технический контекст

Расхождение имён — не расхождение, а разные уровни. `--color-surface` в `apps/web` — это
запись Tailwind v4 `@theme`, из которой генерируются классы-утилиты (`bg-surface`,
`text-ink`). `--brand-surface` в `packages/ui` — обычная CSS-переменная. Переименовывать
288 вхождений в 33 файлах НЕ нужно: достаточно связать одно с другим.

Соответствие (левое — что уже используют экраны, правое — канон `packages/ui/src/tokens/colors.css`):

| Tailwind-имя в apps/web | Канонический токен |
|---|---|
| `--color-surface` | `--brand-surface` |
| `--color-ink` | `--brand-text` |
| `--color-ink-muted` | `--brand-text-muted` |
| `--color-line` | `--brand-border` |
| `--color-brand-primary` | `--brand-primary` |
| `--color-brand-danger` | `--brand-danger` |

## Что сделать

1. `apps/web/src/app/main.tsx` — подключить токены дизайн-системы: `import '@dorutj/ui/tokens'`
   ДО импорта `styles.css`, чтобы `:root`-переменные существовали к моменту разбора `@theme`.
2. `apps/web/src/app/styles.css` — удалить шесть временных значений и TODO-комментарий,
   вместо них связать Tailwind-имена с каноническими токенами по таблице выше.
3. Проверить, что White-Label жив: переопределение `--brand-primary` на `:root` в рантайме
   обязано перекрашивать кнопки и фокус-кольца БЕЗ пересборки. Это и есть смысл тикета.
4. Расширить набор, если экранам не хватает: в `packages/ui` есть также `--brand-bg`,
   `--brand-accent`, `--brand-secondary`, семантические `--brand-success/-warning` с
   производными `-bg`/`-border`/`-text`, шкалы `--space-*`, `--radius-*`, `--shadow-*`,
   `--font-size-*`. Добавлять в мост только то, что реально используется.

## Критерии приёмки

1. Given собранное `apps/web`, When открыт любой экран, Then значения цветов приходят из
   `--brand-*`, а не из литералов в `styles.css` (в файле не остаётся ни одного HEX).
2. Given в рантайме выполнено `document.documentElement.style.setProperty('--brand-primary', '#059669')`,
   When перерисовка, Then первичные кнопки и фокус-кольца становятся зелёными БЕЗ пересборки.
3. Given `pnpm --filter @dorutj/web test`, When прогон, Then 53 файла / 313 тестов зелёные —
   ни один существующий тест не сломан (класс-утилиты не переименовывались).
4. Given `--radius-full`, When тенант ставит `--brand-radius: 0px`, Then круглые элементы
   остаются круглыми (`--radius-full` фиксирован, не производный).

## Тест-план

Критерий 2 НЕ проверяется в `jsdom` — там нет каскада CSS и `getComputedStyle` не резолвит
`@theme`. Проверять запуском в браузере: поднять dev-сервер, открыть страницу, подменить
переменную в консоли, приложить наблюдение к отчёту. Утверждение «должно работать по
документации Tailwind» результатом НЕ считается.

## Риски

Tailwind v4 по-разному обходится со значениями-ссылками в `@theme`: для переменных, которые
обязаны резолвиться в месте использования, может потребоваться `@theme inline`. Какой из
вариантов верен — выясняется запуском, а не чтением. Если ссылочный мост окажется
нерабочим, зафиксировать это фактом и эскалировать: подстановка литеральных HEX ломает
White-Label (`SRS-TEN-017`) и является ухудшением, а не запасным планом.
