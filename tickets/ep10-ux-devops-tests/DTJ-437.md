## Задача

`SRS-API-058` (Must) — `GET /api/v1/i18n/:locale` отдаёт полный словарь локали из `packages/i18n`
(единственный источник строк для React и Flutter). Эндпоинт не принадлежит ни одному тикету:
DTJ-004 и README EP-19 отсылают его «владельцу API-конвенций», тикета нет. Найдено E2E DTJ-422
(критерий 5) и аудитом координатора (2026-09-27).

## Что сделать

1. Публичный `GET /api/v1/i18n/:locale`, `locale ∈ {tj, ru, en}`, ответ
   `{ data: { locale, dictionary } }` по SRS-API-058; неизвестная локаль — 400/404 по конвенциям API.
   Словарь — из `packages/i18n` (без копии), с учётом `i18n_overrides` тенанта, если они уже
   применяются где-то в API (найти и переиспользовать).
2. Кэш-заголовки (ETag или версия словаря), чтобы клиенты не качали словарь каждый раз.
3. Переключать apps/* на fetch НЕ нужно — только эндпоинт (переход — отдельное решение).

## Критерии приёмки

1. Given `GET /api/v1/i18n/ru`, Then 200 и непустой словарь, ключи совпадают с `packages/i18n` ru.
2. Given `GET /api/v1/i18n/de`, Then ошибка по конвенциям, не 500.
3. Спека CUJ-12 DTJ-422 «GET /api/v1/i18n/:locale» проходит вживую.
