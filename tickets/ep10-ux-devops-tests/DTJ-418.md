## Задача

CUJ-1 — единственный сценарий, напрямую проверяющий защитимое УТП продукта (`docs/04-SCOPE-DECISION-PIVOT.md`
D1: аналоги по МНН с расчётом экономии) и первый в списке обязательных E2E критериев приёмки R1
(`docs/04-SCOPE-DECISION-PIVOT.md` §3.2 п.4). CUJ-6' проверяет, что аптека без 1С-автоматизации
реально может присоединиться к платформе (D-12) и её товар реально появляется в поиске — без этого
теста разрыв между «аптека загрузила Excel» и «клиент видит товар» может остаться незамеченным до
продакшена.

## Технический контекст

Использует инфраструктуру DTJ-417 (`playwright.config.ts`, `getOtpFromMockSms`, `runAxeCheck`).
Полный пошаговый сценарий CUJ-1 и CUJ-6' — `docs/spec/30-ux-screens-and-flows.md` §4, таблицы
соответствующих CUJ (переносятся в шаги теста буквально, эндпоинты и SRS-ссылки уже зафиксированы
в письменной спецификации, не изобретаются заново). Оба сценария требуют seed-данных EP-04
(кластер «референт + ≥2 дженерика с разбросом цены», `SRS-NFR-031`) — тикет пишется по контракту
данных, реальный прогон возможен только после готовности seed (внешняя зависимость, см. «Риски»).

## Что сделать

1. `tests/e2e/cuj-1-search-and-analogs.e2e-spec.ts` — сценарий по таблице CUJ-1 (30-ux §4):
   (1) открыть `/`, ввести «цытрамон» в `SearchBar`, дождаться подсказки «Цитрамон» в

   `GET /medicines/search` вернул результаты через нормализованный запрос (`SRS-CAT-024`); (3) в
   списке результатов проверить приглушённое отображение позиций «нет в наличии рядом»
   (`SRS-CAT-045`); (4) открыть карточку референтного товара из seed-кластера, убедиться, что
   `AnalogBanner` показывает `savingsDiram > 0` и текст экономии по шаблону (`SRS-CAT-038/039`);
   (5) нажать «В корзину» на дешёвом дженерике, убедиться, что `AddCartItemUseCase` создал мягкий
   резерв (`SRS-ORD-005`) — товар появился в `/cart`; (6) негативная ветка — поиск заведомо
   отсутствующего товара, проверить `catalog.search.no_results` + предложение увеличить радиус
   (`SRS-CAT-077`); (7) `runAxeCheck` на финальном состоянии экрана поиска и карточки товара
   (`SRS-UX-035`).
2. `tests/e2e/cuj-6-inventory-sync.e2e-spec.ts` — сценарий по таблице CUJ-6' (30-ux §4): (1) как

   `tests/fixtures/inventory/valid-import-template.xlsx` (создать этим тикетом — валидные строки
   для позиций из seed-каталога), выбрать режим «Добавить/обновить»; (3) убедиться, что показан
   ОДИН агрегирующий прогресс-бар (`sourceUploadId`), дождаться завершения; (4) перейти на
   `/search`, найти только что загруженный товар — подтверждает, что
   `InventorySyncBatchCompletedEvent` инвалидировал кэш карточки (`SRS-CAT-059`); (5) негативная
   ветка — загрузить `tests/fixtures/inventory/import-with-ambiguous-date.xlsx` (файл с датой в
   неоднозначном формате в одной из строк, создать этим тикетом), убедиться, что импорт завершается
   `partial_success` со счётчиками «принято/отклонено» и раскрываемым списком ошибок, указывающим
   номер строки (`SRS-INV` §7); (6) отдельная проверка staleness — позиция с `last_synced_at`
   старше `inventory_delta_sla_minutes` (данные подготавливаются через прямую манипуляцию БД/API в

   стороны бэкенда, `SRS-NFR-036` строка 15/`TC-NFR-036`) — карточка товара показывает
   `isStale: true`/бейдж «данные могут быть неактуальны».
3. Создать оба `.xlsx`-файла фикстур по формату официального шаблона (`GET
   /inventory-import-template`) — минимальный набор колонок, достаточный для прохождения импорта
   (SKU/название/цена/остаток), согласовать точный формат с владельцем EP-05 при появлении
   реального шаблона (на момент написания тикета — по контракту `SRS-INV-014`).

## Критерии приёмки

1. Given seed-кластер «референт + ≥2 дженерика», When пройден CUJ-1 сценарий до шага 5, Then
   товар присутствует в `/cart` с корректной ценой, `AnalogBanner` на шаге 4 показал `savingsDiram`,
   численно равную разнице цен из seed-данных.
2. Given поиск заведомо отсутствующего термина, When выполнен запрос, Then экран показывает
   `catalog.search.no_results` (канонический i18n-текст из `packages/i18n`, DTJ-402) — НЕ generic
   «ошибка».
3. Given валидный Excel-файл загружен, When импорт завершён и выполнен поиск, Then загруженный
   товар находится в результатах поиска ДО истечения `inventory_delta_sla_minutes` (проверка
   отсутствия `isStale`-пометки сразу после успешного импорта).
4. Given файл с неоднозначной датой в одной строке, When импорт завершён, Then результат —
   `partial_success`, отчёт об ошибках указывает конкретный номер строки, ОСТАЛЬНЫЕ валидные
   строки того же файла успешно приняты (частичный успех, не отказ всего батча).
5. Given `axe.run()` на карточке товара с `AnalogBanner`, When проверка выполнена, Then ноль
   нарушений уровня `critical`/`serious`.

## Риски и подводные камни

Оба сценария физически не запускаемы до готовности: полного `apps/web` UI (EP-06 поиск/EP-07
аналоги), `apps/pharmacy` импорта Excel (EP-05), и seed-данных (EP-04, `SRS-NFR-031`). Тикет
пишется как готовый код ПО КОНТРАКТУ существующей письменной спецификации (эндпоинты/поведение уже
зафиксированы в 30-ux §4) — реальный первый зелёный прогон наступит только после соответствующих
волн (волна 4–5 по графу `00-EPICS.md`). Формат `.xlsx`-шаблона может измениться при реальной
имплементации `GET /inventory-import-template` в EP-05 — фикстуры этого тикета потребуют точечной
правки колонок при первой интеграции, не структурного изменения теста.
