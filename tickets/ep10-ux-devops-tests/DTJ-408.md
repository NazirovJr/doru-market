## Задача

`LanguageSwitcher` обязан присутствовать на КАЖДОМ экране каждого приложения без авторизации
(`SRS-UX-027`) — дизайн-канвас показал его только на одном экране (`32-design-reference.md`:
«дизайн показывает переключатель только на главном экране... не воспроизводит на остальных»),
поэтому именно письменная спецификация, а не визуальный референс, определяет обязательность
переиспользования этого компонента везде. `SearchBar` — точка входа CUJ-1, единственного
подтверждённого защитимого пути продукта. `BrandLogo` — единственное место в кодовой базе, где
разрешено ссылаться на «логотип бренда», не хардкодя его.

## Технический контекст

`CursorTable`/`CursorList` реализуют курсорную пагинацию по контракту `SRS-API-004` (принимают
`nextCursor: string | null` и колбэк `onLoadMore`, рендерят «Показать ещё» вместо номеров
страниц) — компонент домен-агностичен, конкретную форму строки данных передаёт потребитель через
`renderItem`. `BrandLogo` читает `tenant.settings.brandLogoUrl` (контракт `SRS-API-059`) —
компонент принимает `logoUrl?: string` пропом (не делает fetch сам, получение бренд-данных —
обязанность `app`-слоя bootstrap потребителя), фоллбэк — нейтральная иконка DoruTJ при
отсутствующем/невалидном URL.

## Что сделать

1. `Tabs` — переключение секций (сортировка результатов поиска, «Новые»/«В сборке» терминала,
   переключатель периода аналитики), `role="tablist"`/`role="tab"` + `aria-selected`, активная
   пилюля — заливка `--brand-primary`, клавиатурная навигация стрелками между табами.
2. `Stepper` — прогресс чекаута (адрес → оплата → подтверждение), визуализирует текущий/пройденные/
   будущие шаги, шаги домен-агностичны (принимает массив `{ label, status }`).
3. `CursorTable` — табличное представление с курсорной пагинацией, `<th scope="col">` для
   заголовков, заголовки НЕ теряются при горизонтальном скролле (`overflow-x: auto` на
   ОБЁРТКЕ таблицы, не на всей странице — `SRS-UX-034` таблица «Таблицы»).
4. `CursorList` — списочное представление той же курсорной пагинации (не табличное — карточки/
   строки), общая логика загрузки следующей страницы вынесена в переиспользуемый хук
   `use-cursor-pagination.ts` (потребляется обоими компонентами — избегает дублирования по C15).
5. `SearchBar` — поле поиска с debounce 150–300мс (`SRS-UX-009`, конкретное значение —
   конфигурируемый проп с дефолтом 200мс, не хардкод одного значения без возможности
   переопределения), `spellcheck="false"` и без агрессивного `autocapitalize`/`autocorrect`
   (`SRS-UX-030` — не мешать серверной нормализации таджикской кириллицы), голосовая иконка —
   ОПЦИОНАЛЬНЫЙ проп `onVoiceInput?: () => void` (рендерится только если передан — голосовой ввод
   `[R1·флаг]`, компонент не должен требовать эту функциональность).
6. `LanguageSwitcher` — 3 пилюли `TJ/RU/EN`, активная — заливка `--brand-primary`, работает БЕЗ
   авторизации (не проверяет наличие сессии внутри себя — просто вызывает переданный
   `onChange(locale)`, авторизационная персистентность — обязанность потребителя через
   `resolveLocale`/`PATCH /profile`, DTJ-402), минимум 48×48px на пилюлю (`assertHitArea`).
7. `BrandLogo` — `logoUrl?: string`, рендерит `<img>` с `alt="{{brand.name}}"` (интерполированный
   i18n-ключ, НЕ буквальный «DoruTJ» — `SRS-UX-010`), фоллбэк — встроенный нейтральный SVG-плейсхолдер
   при отсутствии `logoUrl` или ошибке загрузки (`onError`).
8. Обновить `packages/ui/src/index.ts`.

## Критерии приёмки

1. Given `<LanguageSwitcher currentLocale="tj" onChange={fn} />` без какого-либо контекста
   авторизации в пропсах, When клик по пилюле «RU», Then `fn('ru')` вызывается — компонент не
   требует токена/сессии для собственной работы.
2. Given `<SearchBar onSearch={fn} debounceMs={200} />`, When пользователь вводит 5 символов подряд
   с интервалом 50мс между нажатиями, Then `fn` вызывается РОВНО один раз (debounce схлопывает
   промежуточные вызовы), с финальным значением строки.
3. Given `<BrandLogo logoUrl={undefined} />`, When рендер, Then отображается встроенный нейтральный
   фоллбэк-SVG, а не сломанный `<img>` с пустым `src`.
4. Given `<CursorTable>` с широким содержимым, вложенным в узкий viewport, When рендер, Then
   горизонтальный скролл появляется на обёртке таблицы, а не на `<body>` страницы (проверка через
   `overflow-x` на правильном элементе DOM-дерева).
5. Given `<SearchBar>`, When инспектируется атрибут `input`, Then `spellcheck="false"` присутствует,
   `autocapitalize`/`autocorrect` не установлены в агрессивные значения по умолчанию.

## Тест-план

Unit (по компоненту):
- `Tabs`: клавиатурная навигация стрелками; `aria-selected` синхронизирован с активным табом;
  `renderWithA11yCheck` ноль нарушений.
- `Stepper`: визуально различает 3 состояния шага не только цветом (иконка/форма).
- `use-cursor-pagination.ts`: `onLoadMore` вызывается только при наличии `nextCursor !== null`;
  повторный вызов при уже идущей загрузке — не триггерит второй параллельный запрос (защита от
  двойной загрузки при быстром повторном скролле).
- `CursorTable`/`CursorList`: рендер `renderItem` для каждого элемента; кнопка «Показать ещё»
  скрыта/disabled, когда `nextCursor === null`.
- `SearchBar`: debounce схлопывает быстрый ввод в один вызов (мокнутые таймеры); `onVoiceInput`
  не рендерит иконку микрофона, если проп не передан.
- `LanguageSwitcher`: работает без пропов авторизации; `assertHitArea` ≥48px на пилюлю.
- `BrandLogo`: фоллбэк при отсутствующем/ошибочном `logoUrl`; `alt`-текст не содержит буквальной
  строки бренда.

Порог покрытия — 90%.

## Риски и подводные камни

Полный экран `/search` в дизайн-канвасе реализует сортировку как `Tabs`-пилюли, а не `Select`
(отмечено расхождением в `32-design-reference.md`: «в реальности реализовано как Tabs-пилюли, не
выпадающий список») — этот тикет уже строит `Tabs` для этого случая, `Select` (DTJ-405) остаётся
для форм онбординга/настроек, где выпадающий список уместнее — не повод объединять компоненты,
просто разные сценарии применения одного набора примитивов. `LanguageSwitcher` должен быть
внедрён потребляющими фичами на КАЖДЫЙ экран (не только главный) — это ответственность фронтовых
эпиков-потребителей при интеграции, не проверяется автоматически данным тикетом (кроме unit-теста
самого компонента); фиксируется как явное указание в README эпика для будущих ревьюеров.
