## Задача

`SRS-NFR-030` требует детерминированности ВСЕХ автоматических тестов (unit/integration/E2E) —
время, ID и OTP-коды НЕ могут порождаться реальными `Date.now()`/`crypto.randomUUID()`/случайным
генератором в тестах, иначе SLA-тесты (`pickup_sla`, TTL резерва, блокировка OTP) флапают или
требуют реального `sleep()`. Это ОСНОВАНИЕ, на котором строятся ВСЕ последующие unit/integration/
E2E-тесты каждого backend-эпика (EP-01..EP-17) — без него `TC-NFR-030` (идентичный результат двух
прогонов E2E CUJ-3') физически недостижим.

## Технический контекст

`packages/testing-kit` — новый независимый pnpm-workspace пакет (архитектурное решение Tech Lead
EP-19: НЕ размещать эти классы внутри `apps/api/src/infrastructure/testing/**`, т.к. на момент
этого тикета `apps/api` ещё не существует — волна 1, EP-01 не начат, — а размещение в отдельном
пакете даёт немедленно потребляемый артефакт БЕЗ ожидания EP-01 и без коллизии владения файлами
внутри чужого приложения). Классы реализуют интерфейсы-контракты, СПЕЦИФИЦИРОВАННЫЕ доменной
моделью (`docs/spec/10-domain-model.md` §2.6: `ClockPort`, `IdGenerator`, `OtpGeneratorPort`), но
САМИ порты (интерфейсы) этим тикетом НЕ объявляются заново — пакет экспортирует РЕАЛИЗАЦИИ,
совместимые по сигнатуре с портами, которые определит EP-01 (`Clock.now(): Date`,
`Clock.advance(minutes: number): void`, `IdGenerator.next(): string`,
`OtpGeneratorPort.generate(): string`); когда порты EP-01 появятся в `packages/contracts`, backend-
модули импортируют классы ИЗ ЭТОГО пакета и передают их в DI как реализацию чужого интерфейса
(структурная типизация TypeScript не требует явного `implements` для совместимости).

## Что сделать

1. `packages/testing-kit/src/fixed-clock.adapter.ts` — класс `FixedClockAdapter`: конструктор
   принимает начальное время (дефолт `2026-08-27T09:00:00.000Z` — стандартная точка отсчёта
   тестового набора, `SRS-NFR-030` п.1), методы `now(): Date`, `advance(minutes: number): void`
   (продвигает внутренние часы БЕЗ реального `sleep`), `reset(to?: Date): void` (сброс между
   тестами).
2. `packages/testing-kit/src/sequential-test-id-generator.ts` — класс
   `SequentialTestIdGenerator`: `next(): string` возвращает предсказуемые
   `00000000-0000-0000-0000-000000000001`, `...002`, ... по возрастающему счётчику; метод
   `reset(): void` для изоляции между тестовыми файлами.
3. `packages/testing-kit/src/fixed-otp-generator.adapter.ts` — класс `FixedOtpGeneratorAdapter`:
   конструктор принимает `{ loginCode?: string; handoverCode?: string }` (дефолты `'483920'`/
   `'1234'`, `SRS-NFR-030` п.3), метод `generate(purpose: 'login' | 'handover'): string` возвращает
   соответствующий заранее известный код.
4. `packages/testing-kit/src/builder.ts` — генерическая утилита `createBuilder<T>(defaults: T):
   { create: (overrides?: Partial<T>) => { build: () => T } }`, реализующая builder-паттерн
   ОДИН раз (`SRS-NFR-032`: «не сырые JSON-файлы... позволяет точечно переопределять только
   нужное поле») — конкретные доменные фабрики (`OrderFactory`, `MedicineFactory`,
   `PharmacyFactory`) создаются КАЖДЫМ владеющим эпиком поверх этой утилиты в СВОЁМ модуле
   (`tests/fixtures/*.factory.ts` по владению `00-EPICS.md`), не централизуются здесь — этот
   пакет даёт только переиспользуемый механизм builder, избегая дублирования реализации паттерна
   в каждом эпике по отдельности (C15).
5. `packages/testing-kit/src/index.ts` — публичный баррель.

## Критерии приёмки

1. Given `new FixedClockAdapter()` без аргументов, When `.now()`, Then возвращает
   `2026-08-27T09:00:00.000Z`.
2. Given `clock.advance(15)` (15 минут), When `.now()` вызван снова, Then возвращает время,
   ровно на 15 минут больше предыдущего значения, БЕЗ фактической паузы выполнения теста
   (тест завершается за миллисекунды, не за 15 реальных минут).
3. Given два последовательных вызова `new SequentialTestIdGenerator().next()`, When сравниваются,
   Then второе значение отличается от первого только последним сегментом (`...001` → `...002`),
   оба — валидные UUID-подобные строки одинаковой длины.
4. Given `createBuilder({ status: 'pending', amount: 100 })`, When
   `.create({ status: 'paid' }).build()`, Then результат `{ status: 'paid', amount: 100 }` —
   переопределено только явно указанное поле, остальное — дефолт.

## Тест-план

Unit (`packages/testing-kit/src/fixed-clock.adapter.spec.ts`):
- `returns configured default time when no initial time is given`
- `advance moves internal clock forward by exact given minutes without real delay`
- `reset restores clock to explicit or default timestamp`

Unit (`packages/testing-kit/src/builder.spec.ts`):
- `build() with no overrides returns exact defaults`
- `build() with partial overrides merges shallowly, keeping other defaults intact`
- `does not mutate the original defaults object across multiple create() calls` (защита от утечки
  состояния между тестами через общий объект дефолтов — соответствует правилу C13 «входные
  параметры не мутируются»).

`SequentialTestIdGenerator`/`FixedOtpGeneratorAdapter` — тесты аналогичной структуры, включаются
в тот же файл или отдельные `*.spec.ts` по решению разработчика (оба варианта приемлемы, главное —
покрытие).

Порог покрытия — 90% (эквивалент `domain`/`application` по строгости для тестовой инфраструктуры,
на которую полагаются все остальные тесты платформы).

## Риски и подводные камни

Главный риск — рассинхронизация СИГНАТУРЫ портов, которые реально определит EP-01
(`docs/spec/10-domain-model.md` §2.6), с сигнатурами, предположенными этим тикетом ДО появления
EP-01 кода. Если реальный `ClockPort` окажется, например, `getCurrentTime()` вместо `now()` —
потребуется точечная правка метода в этом пакете (без изменения архитектуры класса) при первой
интеграции с `apps/api`. Зафиксировать в PR явное примечание: «сигнатуры синхронизировать с
`ClockPort`/`IdGenerator`/`OtpGeneratorPort` при их первом появлении в `packages/contracts`,
владелец EP-01 — это ожидаемая точка ревизии, не архитектурная ошибка данного тикета». Название
пакета `packages/testing-kit` не входит в исходную таблицу владения файлами `00-EPICS.md` (только
`packages/contracts`/`packages/i18n`/`packages/ui` перечислены явно) — это осознанное расширение
