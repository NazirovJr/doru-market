## Задача
Ограничение нагрузки (`SRS-CAT-054`) предотвращает случайный запрос «вся территория Таджикистана»
при уменьшенном до предела зуме клиента — без серверной валидации площади `bbox` карта уязвима к
непреднамеренному тяжёлому запросу от любого клиента (не обязательно злонамеренному — просто
широкий зум). Use case — единственное место, вычисляющее «открыто сейчас» для каждого пина через
переиспользуемую доменную политику (DTJ-184), не полагаясь на клиент.

## Технический контекст
Слой `application`, один класс — один `execute()`. Получает `PHARMACY_MAP_REPOSITORY` (DTJ-194/195)
и `PharmacyOpeningHoursPolicy` (DTJ-184, ПЕРЕИСПОЛЬЗУЕТСЯ дословно тем же классом, что и в поиске —
DRY, единственный источник правды для правила «открыто сейчас», C15) через конструктор.

## Что сделать
1. `GetPharmacyMapPinsUseCase.execute(command: { bbox: Bbox; medicineId?: string; tenantId:
   TenantId }): Promise<readonly MapPinDto[]>`:
   а) вычислить площадь `bbox` (простая геометрия — прямоугольник в градусах, приближённая формула
      площади через `haversine` для сторон или библиотечную функцию — ТОЧНОСТЬ не критична, порог
      `BBOX_MAX_AREA_KM2 = 2500` — грубая защита, не геодезический расчёт);
   б) given площадь `> BBOX_MAX_AREA_KM2` → бросить `BboxTooLargeError` (доменная/application
      ошибка, маппится в `400 VALIDATION_ERROR details.field='bbox'` на уровне presentation,
      DTJ-197) — `SRS-CAT-054`;
   в) вызвать `repository.findPinsInBbox()` (DTJ-195);
   г) для каждого пина — вычислить `isOpenNow` через `PharmacyOpeningHoursPolicy.evaluate()`
      (DTJ-184), используя сырые `is24x7`/`openingTime`/`closingTime`, возвращённые репозиторием;
   д) замапить в `MapPinDto` (публичная форма use case, отдельная от `PharmacyMapPin` репозитория —
      репозиторий отдаёт СЫРЫЕ данные, use case отдаёт ОБОГАЩЁННЫЙ DTO с вычисленным `isOpenNow`).
2. `Bbox`-тип — value object с полями `lonMin/latMin/lonMax/latMax`, парсится ИЗ уже провалидированной
   форматом строки `packages/contracts` (DTJ-194) на границе presentation (DTJ-197) — use case
   получает уже структурированный объект, не парсит сырую строку сам (разделение ответственности:
   формат — контракт, площадь — бизнес-правило домена/application).

## Критерии приёмки
1. Given `bbox`, покрывающий площадь `> 2500 км²` (например, весь Таджикистан), When `execute()`,
   Then выброшена `BboxTooLargeError` (`TC-CAT-024` на уровне use case).
2. Given `bbox` в пределах лимита с 3 аптеками, одна из которых `is24x7=true`, вторая — обычный режим
   работы и сейчас закрыта, третья — обычный режим и сейчас открыта, When `execute()`, Then
   `isOpenNow` соответственно `true, false, true` для каждой (переиспользование `TC-CAT-020`-логики
   через тот же `PharmacyOpeningHoursPolicy`, что и в поиске).
3. Given `medicineId` не передан, When `execute()`, Then у всех пинов `offer: null` (пробрасывается
   как есть из репозитория, use case не выдумывает значение).
4. Given площадь `bbox` РОВНО НА ГРАНИЦЕ `2500 км²` (граничный тест), When `execute()`, Then НЕ
   выброшена ошибка (`<=`, не `<` — зафиксировать явно, чтобы избежать off-by-one неопределённости).

## Тест-план
Unit (моки `PHARMACY_MAP_REPOSITORY`, `PharmacyOpeningHoursPolicy`): расчёт площади bbox (несколько
размеров — маленький/на границе/превышающий), обогащение `isOpenNow` для разных комбинаций
`is24x7`/интервалов (переиспользуя тестовые кейсы `DTJ-184`, не изобретая новые). Порог покрытия
`application/` ≥ 90 %.

## Риски и подводные камни
- Приближённый расчёт площади bbox по широте/долготе не учитывает сжатие Земли у полюсов — для
  территории Таджикистана (широты ~37-41°) погрешность простой прямоугольной аппроксимации
  приемлема (`ASSUMPTION`, порог сам по себе грубая защита, не точный SLA) — не переусложнять точной
  геодезической библиотекой без необходимости (C15, избыточная точность не оправдана задачей).
- Если `PharmacyOpeningHoursPolicy` (DTJ-184) ещё не готов на момент старта этого тикета (хотя по
  графу зависимостей должен быть, т.к. `search`-поток EP-06 идёт первым в волне 6) — этот тикет
  БЛОКИРУЕТСЯ, не реализовывать параллельную копию логики «на скорую руку».
