## Задача
Персона «Биби Хосият» (research 06 §8.3, `SRS-CAT-024`) вводит запрос латиницей/русской раскладкой
без спецсимволов таджикской кириллицы, либо с опечаткой, либо сканирует штрихкод. Без пайплайна
нормализации ДО обращения к `SearchProvider` большая часть реальных запросов таджикоязычных
пользователей вернёт пустой список — это прямая угроза заявленному позиционированию «дешевле рядом»
(`04-SCOPE-DECISION-PIVOT.md` §2.1): бесполезно ранжировать результаты, которые поиск даже не нашёл.

## Технический контекст
Слой `domain` модуля `catalog` — по `02-CLEAN-ARCHITECTURE-AND-CODE.md` §2.6 домен обязан быть
чистой функцией без I/O и без `Date.now()`/сети. `QueryNormalizationService` вызывается ИЗ
`SearchMedicinesUseCase` (application, DTJ-188) ПЕРЕД обращением к `SearchProvider.search()`
(`SRS-CAT-024`, преамбула §4). Таблица транслитерации — курируемые данные лингвиста/фармацевта
(`packages/i18n/translit-map.json`), НЕ строки интерфейса — этот файл технически лежит в каталоге
`packages/i18n`, которым по умолчанию владеет EP-18 (`00-EPICS.md` «Пересекающееся владение» п.6),
но содержимое — доменные данные нормализации поиска, а не UI-словарь; ЭТОТ тикет создаёт файл
первым (владения UI-строками файл не касается, конфликт исключён по содержимому, не по каталогу).

## Что сделать
1. `QueryNormalizationService.normalize(rawText: string): NormalizedQuery` — чистая функция:
   а) `trim()` + схлопывание повторных пробелов через `replace(/\s+/g, ' ')`;
   б) детекция штрихкода: `/^\d{8}$|^\d{12,14}$/`, при совпадении — `{ mode: 'barcode', value }`,
      дальнейшие шаги пайплайна пропускаются (`SRS-CAT-024` п.2);
   в) эвристика «похоже на транслит»: доля латинских букв среди всех букв строки `> 0.6` ИЛИ
      (есть буквы, но ни одной из набора `а-яёӣӯҳқғҷ`) — обе ветки покрыть unit-тестами отдельно;
   г) при срабатывании (в) — вызвать `TransliterationNormalizerService.transliterate(text)`,
      результат добавляется КАК ДОПОЛНИТЕЛЬНЫЙ вариант (`{ mode: 'text', primary: rawTrimmed,
      alternate: transliterated | null }`), не заменяет исходный текст;
   д) иначе — `{ mode: 'text', primary: rawTrimmed, alternate: null }`.
2. `TransliterationNormalizerService.transliterate(text: string): string` — читает статическую
   таблицу `translit-map.json` (загружается один раз при старте модуля, не на каждый вызов —
   Requirement производительности, домен не делает I/O на файл при каждом запросе: файл читается
   `infrastructure`-загрузчиком при бутстрапе и передаётся в конструктор сервиса как
   `Record<string, string>` — сервис остаётся чистым, чтение файла НЕ внутри `domain/`).
3. Создать `packages/i18n/translit-map.json` — минимальный курируемый набор пар для R1 (не полный
   лингвистический словарь — минимум: `qalb→калб`, `gh→ғ`, `kh→х`, `j→ҷ`, `q→қ`, `h→ҳ`, `ii→ӣ`,
   `uu→ӯ`, плюс базовая латиница→кириллица `a→а, b→б, ...` для оставшихся букв) с полем-комментарием
   `_meta.status: "ASSUMPTION — требует вычитки лингвистом/фармацевтом до продакшена"` (аналогично
   `SRS-CAT-041` для дисклеймера — тот же принцип версионирования незавершённого лингвистического
   контента).
4. `NormalizedQuery` — тип, экспортируемый из этого же файла (не из `packages/contracts` — это
   внутренний тип домена, не пересекает границу API).
5. Unit-тесты на regression-кейс `TC-CAT-007` (`qalb` → находит `Калб`) и `TC-CAT-006`
   (`ӣ`/`и`-эквивалентность обрабатывается FTS-конфигурацией `tajik_ru`, НЕ этим сервисом — здесь
   тестируется только то, что сервис НЕ трогает уже корректно набранную таджикскую кириллицу).

## Критерии приёмки
1. Given `rawText = '4870123456789'` (13 цифр), When `normalize()`, Then `mode === 'barcode'`,
   `value === '4870123456789'`, `alternate` отсутствует в результате.
2. Given `rawText = 'qalb'`, When `normalize()`, Then `mode === 'text'`, `primary === 'qalb'`,
   `alternate === 'калб'` (через таблицу транслитерации).
3. Given `rawText = 'цытрамон'` (опечатка кириллицей, НЕ транслит — доля латиницы 0%, есть буквы
   кириллицы), When `normalize()`, Then `alternate === null` (эвристика транслита НЕ сработала,
   опечатка обрабатывается позже триграммой в `SearchProvider`, не здесь) — негативный сценарий,
   критичный: неверное срабатывание эвристики на обычной опечатке — regression.
4. Given `rawText = '   Цитрамон    '` (лишние пробелы), When `normalize()`, Then
   `primary === 'Цитрамон'`.

## Тест-план
Unit (`query-normalization.service.spec.ts`): барcode-детекция (8/12/13/14 цифр — позитив, 7/15
цифр и цифры с буквой — негатив), эвристика транслита (латиница >60%, отсутствие таджикских букв
при наличии букв вообще, обычная кириллическая опечатка — НЕ транслит), схлопывание пробелов.
Unit (`transliteration-normalizer.service.spec.ts`): таблица применяется посимвольно/по
подстрокам-триггерам (`qalb→калб`), пустая строка на входе → пустая на выходе, символы вне таблицы
не трогаются. Оба файла — `domain`, порог покрытия ≥ 90 % обязателен, тестируются БЕЗ БД/сети.

## Риски и подводные камни
- Эвристика «похоже на транслит» — не покрывает все возможные ложные срабатывания
  (`SRS-CAT-078` явно признаёт компромисс recall/precision) — regression-тест на «обычную
  кириллическую опечатку не путать с транслитом» обязателен, но не гарантирует нуль ложных
  срабатываний на реальных данных; мониторинг качества — задача продуктовой аналитики (EP-17), не
  блокирует этот тикет.
- `packages/i18n/translit-map.json` физически лежит в каталоге, которым владеет EP-18 — если EP-18
  параллельно создаёт свой собственный файл с тем же именем для других целей, разрешать конфликт
  через rebase, приоритет — доменное назначение файла (используется `domain`-сервисом, не
  UI-словарём переводов интерфейса).
- Курированная таблица для R1 — минимальный набор, не полный лингвистический охват; расширение —
  отдельный тикет после запуска, не блокирует приёмку R1 (в отличие от юридического дисклеймера,
  здесь отсутствие полноты не является юридическим риском).
