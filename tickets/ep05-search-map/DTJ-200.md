## Задача
`DTJ-198` реализовал `MapView` (обёртка `maplibre-gl`) ЛОКАЛЬНО в
`apps/web/src/features/pharmacy-map/ui/map-view.tsx`, потому что на момент волны 6 `packages/ui`
(EP-18) ещё не выпустил базовый компонент карты. Это обязательный тикет-перенос по чек-листу
`tickets/00-EPICS.md` §«Пересекающееся владение» п.6 (`SRS-UX-034`): локальная реализация без
переноса создаёт риск, что EP-09 (checkout, карта-пикер адреса) и EP-13 (курьер, карта маршрута)
реализуют СВОИ копии той же обёртки параллельно — прямое нарушение DRY (Ж12/C15) на уровне всего
продукта.

## Технический контекст
Источник: `apps/web/src/features/pharmacy-map/ui/map-view.tsx` +
`apps/web/src/features/pharmacy-map/model/use-map-viewport.ts` (DTJ-198). Карта используется
МИНИМУМ на 5 экранах (`32-design-reference.md` строка 152): курьер (EP-13), главный экран/превью
(EP-06/`pages/home`), checkout-пикер адреса (EP-09), экран заказа, отдельный `/map` (EP-08,
DTJ-199).

Текущая реализация DTJ-198 намеренно СВЯЗАНА с `PharmacyMapPinDto`
(`@dorutj/contracts`, DTJ-194) как типом `pins` — это осознанный компромисс ради Ж12 (не плодить
дублирующий shape) в рамках scope DTJ-198 (карта аптек), а НЕ финальная генерализация. Этот тикет
обязан:

## Что сделать
1. Перенести `map-view.tsx`, `use-map-viewport.ts`, `pharmacy-pin-popup.tsx` в `packages/ui/src/`
   (точная структура подпапок — на усмотрение владельца EP-18, консистентно с уже существующими
   компонентами пакета на момент переноса).
2. Обобщить проп `pins`: заменить прямую связь с `PharmacyMapPinDto` на генерик-параметр или на
   минимальный структурный тип `{ id, lat, lon }` + слот для попап-контента (`renderPopup?: (pin) =>
   ReactNode` или аналог) — так, чтобы курьерская карта маршрута (EP-13, точки без цены/остатка) и
   checkout-пикер адреса (EP-09, один драгабельный маркер без попапа) могли использовать ТОТ ЖЕ
   компонент без хаков.
3. Обновить импорты потребителей (`apps/web/src/features/pharmacy-map/**`, DTJ-198/199) на
   `@dorutj/ui` вместо локального пути — координация с EP-08 по времени (не ломать `/map` в процессе
   переноса, делать за один PR с обновлением обеих сторон).
4. Сохранить поведенческий контракт DTJ-198 без регрессов: тест-план DTJ-198 (монтирование без
   ошибок, N маркеров по пропсам, debounce `onViewportChange`, попап без XSS, фолбэк при
   недоступном tileserver) обязан остаться зелёным после переноса — тесты переезжают вместе с кодом.

## Критерии приёмки
1. Given компонент перенесён в `packages/ui`, When `apps/web` импортирует `MapView` из `@dorutj/ui`,
   Then локальной копии в `features/pharmacy-map/ui/map-view.tsx` больше не существует.
2. Given обобщённый проп `pins`, When другой потребитель (например, тест EP-09/EP-13 с одиночным
   маркером-адресом) использует `MapView` без полей `offer`/`isOpenNow`, Then компонент рендерится
   без ошибок типов и без вынужденных заглушечных полей.
3. Given тест-план DTJ-198, When прогнан после переноса, Then все сценарии зелёные.
