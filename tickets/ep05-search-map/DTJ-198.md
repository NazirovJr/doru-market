## Задача
`REQ-GEO-1` категорически запрещает Yandex Maps для диспетчеризации (лицензионный ToS) — единственный
разрешённый путь — `MapLibre GL JS` поверх self-hosted vector-тайлов (`infra/docker/tileserver`,
инфраструктурный сетап EP-19, вне scope этого тикета). Дизайн (`32-design-reference.md`) специфицирует
только точки входа и размеры контейнера — реальный компонент карты дизайном НЕ отрисован, этот тикет
реализует его с нуля по требованиям модуля каталога.

## Технический контекст
`docs/spec/32-design-reference.md` строка 152 (`MapView`, `.dc.html:67,581,889,973,1016` — везде
iframe-заглушка, реальный `MapLibre GL JS`-компонент дизайном не специфицирован) и строка 298-299
(явное указание: «при реализации нужно проектировать по требованиям 30-ux/модуля каталога»).
Компонент по конвенции ownership `packages/ui` принадлежит EP-18, но если на момент этого тикета
(волна 6) базовый `MapView`-wrapper там ещё не существует — реализовать ЛОКАЛЬНО в
`features/pharmacy-map/ui/**` с обязательным тикетом на перенос в `packages/ui` (`00-EPICS.md`
«Пересекающееся владение» п.6, ОБЯЗАТЕЛЬНЫЙ пункт `SRS-UX-034`) — карта используется МИНИМУМ на
5 экранах (курьер, главный, checkout, заказ, отдельный `/map`, `32-design-reference.md` строка 152),
поэтому локальная реализация без переноса создаёт реальный риск дублирования кода в других эпиках
(EP-09 checkout, EP-13 курьер).

## Что сделать
1. Проверить `packages/ui` на наличие `MapView`/аналога ПЕРЕД началом реализации — если уже создан
   EP-18, использовать его как базу, расширяя нужными пропсами, не переписывать с нуля.
2. `map-view.tsx` — тонкая React-обёртка над `maplibre-gl`: инициализация карты с self-hosted
   vector-tile источником (URL стиля — из ENV/конфига, НЕ хардкод — Charter §5), пропсы: `center`,
   `zoom`, `pins: MapPin[]`, `onViewportChange: (bbox) => void`, `onPinClick: (pharmacyId) => void`.
3. `use-map-viewport.ts` — хук, извлекающий текущий `bbox` видимой области карты при
   `moveend`/`zoomend` (debounce `300-500мс`, чтобы не слать запрос на каждый кадр панорамирования)
   — сырое значение передаётся наружу через `onViewportChange`, сетевой вызов — ответственность
   `features/pharmacy-map` (DTJ-199), НЕ этого низкоуровневого компонента (`MapView` не знает про
   HTTP, только про геометрию карты — разделение api/model/ui, `02` §5).
4. Рендер пинов: маркер с ценой (given передана `PharmacyMapPin.offer`), клик по пину → всплывающая
   карточка (имя аптеки, цена/остаток/`isStale`, «открыто сейчас»/`24/7`) — попап реализуется как
   React-компонент через `maplibre-gl` popup API, не голый HTML-строка (избегать XSS через
   неэкранированную интерполяцию имени аптеки).
5. Респонсивность: контейнер занимает `100%` доступной высоты/ширины родителя (превью 150-190px на
   встроенных карточках, полноэкранный на `/map` — управляется CSS родительского контейнера, не
   компонентом карты).
6. Ресурс `maplibre-gl` — НЕ через внешний CDN (Charter §3.3 self-hosted, консистентно с общим
   принципом «без внешних API-ключей», `04-SCOPE-DECISION-PIVOT.md` критерий 5) — устанавливается
   как npm-зависимость, стили тайлов — с self-hosted tileserver, URL берётся из `VITE_TILESERVER_URL`
   (или эквивалент сборщика, сверить с `01-TECH-BASELINE.md`).

## Критерии приёмки
1. Given `MapView` смонтирован с `pins=[]`, When рендер, Then карта отображается без ошибок в
   консоли, без пинов.
2. Given `pins` содержит 3 элемента с координатами, When рендер, Then на карте отображаются 3
   маркера в соответствующих координатах.
3. Given пользователь панорамирует карту, When движение завершено (`moveend`), Then
   `onViewportChange` вызван РОВНО ОДИН раз с итоговым `bbox` (не на каждый промежуточный кадр —
   debounce работает).
4. Given клик по маркеру с `offer !== null`, When попап открывается, Then отображаются цена,
   остаток, метка устаревания (given `isStale`), имя аптеки — БЕЗ HTML-инъекции при имени аптеки,
   содержащем спецсимволы (`<script>` в названии — негативный сценарий безопасности, имя должно быть
   экранировано/отрендерено как текст, не как HTML).
5. Given `VITE_TILESERVER_URL` не задан/недоступен, When карта пытается загрузить тайлы, Then UI не
   падает (error boundary/фолбэк-сообщение «карта временно недоступна»), не белый экран без объяснения.

## Тест-план
Компонентные (Vitest/RTL с мок `maplibre-gl`, т.к. реальный WebGL-рендер недоступен в jsdom):
монтирование без ошибок, рендер N маркеров по пропсам, вызов `onViewportChange` с debounce (fake
timers), попап без XSS на спецсимволах в имени. Playwright (реальный браузер, где WebGL доступен):
smoke-тест реального рендера карты на `/map` (DTJ-199) — визуальная проверка, что тайлы
загружаются с self-hosted источника (не Yandex/Google — assert на URL сетевых запросов). Порог
покрытия компонентов ≥ 70 %.

## Риски и подводные камни
- Наибольший архитектурный риск тикета: если `MapView` реализован локально в `features/pharmacy-map`
  и НЕ перенесён вовремя, EP-09 (checkout, карта-пикер адреса) и EP-13 (курьер, карта маршрута) с
  высокой вероятностью реализуют СВОИ копии той же обёртки параллельно — прямое нарушение DRY/C15 на
  уровне всего продукта, а не только этого модуля. Обязательно поднять вопрос владения `MapView`
  явно на синхронизации с Tech Lead'ом EP-18 ДО начала реализации, не постфактум.
- `maplibre-gl` — тяжёлая библиотека (WebGL) — тестирование в jsdom требует мокирования, реальная
  визуальная проверка возможна только в Playwright/браузере — не полагаться исключительно на
  unit-тесты для уверенности в работоспособности.
- Self-hosted tileserver (`infra/docker/tileserver`, EP-19) может быть недоступен локально на
  момент разработки этого тикета — предусмотреть графическую заглушку/понятную ошибку (см. критерий
  приёмки 5), не блокировать разработку компонента ожиданием готовности инфраструктуры.
