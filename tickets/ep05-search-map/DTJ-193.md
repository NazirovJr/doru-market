## Задача
Экран `/search` — место, где пользователь фактически видит доказательство ценности продукта: цену,
расстояние, наличие, метку устаревания данных. Плохо реализованные фильтры/состояния (пустой список
без объяснения, незаметная метка `isStale`) напрямую подрывают доверие к позиционированию «дешевле
рядом» — этот экран проверяется CUJ-1 целиком.

## Технический контекст
`apps/web/src/features/search/**` (продолжение DTJ-192) + `apps/web/src/pages/search/index.tsx`
(композиция — согласно `02-CLEAN-ARCHITECTURE-AND-CODE.md` §5, `pages/` содержит НОЛЬ бизнес-логики,
только сборку `features`). Дизайн-референс `docs/spec/32-design-reference.md` строка 175 (`Search`,
`.dc.html:606-696`): шапка с полем поиска и «назад», чипы фильтров, пилюли сортировки (`Tabs`, НЕ
`Select`-дропдаун — расхождение дизайна зафиксировано в референсе явно), счётчик результатов, список
`MedicineCard`. Данные — через `use-search-results.ts` → `GET /medicines/search` (DTJ-190).

## Что сделать
1. `search-filters.tsx` — чипы (`packages/ui` `Chip`, не выбран/выбран): «Только в наличии»
   (`inStockOnly`, дефолт `false`, `SRS-CAT-045`), «Открыто сейчас» (`openNowOnly`, `SRS-CAT-046`),
   «Круглосуточно» (`is24x7Only`, `SRS-CAT-047`, независим от предыдущего), селектор радиуса —
   ФИКСИРОВАННЫЙ набор пилюль `{1, 3, 5, 10, 20} км` (не слайдер, `SRS-CAT-044`), дефолт `5 км`.
2. `search-sort-tabs.tsx` — пилюли `Tabs`: «По релевантности» (дефолт при непустом `text`) / «Сначала
   дешёвые» / «Сначала дорогие» / «Ближе» (`distance_asc`, ДИЗЕЙБЛ/скрыт, если `geo` не получен —
   клиентская защита от заведомо невалидного запроса, дублирует серверную валидацию `SRS-CAT-048`,
   но не заменяет её).
3. `medicine-card.tsx` — карточка результата (interactive, целиком кликабельна, `Card`-компонент из
   `32-design-reference.md`): название, дозировка, цена самого дешёвого предложения, дистанция,
   бейдж Rx (given `isPrescriptionRequired`), плейсхолдер-иконка формы выпуска при отсутствии
   `imageUrl` (9 SVG-иконок `dosage_form_class`, `SRS-CAT-007` — консьюмер, не создатель иконок,
   если `packages/ui` ещё не содержит набор — координация с EP-18/EP-04 аналогично риску DTJ-192).
   Given товар без остатка в радиусе (`cheapestOffer === null`) — визуально приглушённая карточка с
   пометкой «нет в наличии рядом», НЕ скрыта из списка (`SRS-CAT-045`, дефолт `inStockOnly=false`).
   Given `isStale === true` у ближайшего предложения — видимая пометка (не скрытая в тултипе)
   «данные могли устареть» (`SRS-CAT-072` — расхождение цены между списком и карточкой ОЖИДАЕМО,
   но пользователь обязан быть предупреждён на уровне списка тоже).
4. Состояния экрана: skeleton (3 строки при первой загрузке), офлайн (полноэкранный, с кнопкой
   «Повторить» — отличается от компактного варианта на `Home`, `32-design-reference.md` подтверждает
   оба паттерна как допустимые при едином тексте), пусто (`catalog.search.no_results` — «По запросу
   «X» ничего не найдено», с предложением проверить написание/увеличить радиус, `SRS-CAT-077`),
   готово (с баннером опечатки-исправления «Показаны результаты по «X» — вы искали «Y»», если
   транслит/триграмма дали иное совпадение, чем буквальный ввод).
5. `use-search-results.ts` — TanStack Query, `queryKey` включает ВСЕ параметры запроса (текст,
   фильтры, `geo`, радиус, сортировку, курсор) — курсорная пагинация «показать ещё»
   (`SRS-API-004`), не infinite-scroll без явной кнопки (если дизайн не специфицирует иное).
6. URL — синхронизация состояния фильтров/сортировки/текста с query-параметрами `/search?q=...`
   (шеринг ссылки на результат поиска, стандартная практика — не отдельное SRS-требование, но
   необходимо для «сохранённого в URL значения радиуса из прошлой сессии», на которое явно ссылается
   `SRS-CAT-044`).

## Критерии приёмки
1. Given результаты содержат товар без остатка в радиусе, When рендер списка, Then карточка
   присутствует в списке (не скрыта), визуально приглушена, с текстом «нет в наличии рядом».
2. Given `inStockOnly` включён пользователем, When список перерисован, Then товары без остатка
   ПОЛНОСТЬЮ исчезают из списка (не просто перекрашиваются, `SRS-CAT-045`).
3. Given `geo` не передан (пользователь отклонил геолокацию), When открыт таб сортировки, Then
   вариант «Ближе» недоступен для выбора (disabled), выбор `sort=relevance` работает с
   перенормированными весами (визуально прозрачно для пользователя — веса не показываются в UI).
4. Given пустой результат поиска, When рендер, Then показан `EmptyState` с текстом
   `catalog.search.no_results` и предложением расширить радиус/проверить написание — НЕ пустой белый
   экран, НЕ `404`-страница.
5. Given ближайшее предложение товара помечено `isStale: true`, When рендер карточки, Then видимая
   (не скрытая по умолчанию) пометка устаревания присутствует в DOM.

## Тест-план
Unit/компонентные (Vitest/RTL): `medicine-card.tsx` — все визуальные состояния (в наличии/нет
рядом/`isStale`/Rx-бейдж/без изображения-плейсхолдер); `search-filters.tsx` — переключение чипов
корректно обновляет модель запроса; `search-sort-tabs.tsx` — `distance_asc` disabled без `geo`.
`use-search-results.ts` — синхронизация `queryKey`↔URL. Playwright E2E: полный сценарий «ввод текста
→ результаты → включение фильтра „только в наличии" → список сокращается» — привязывается к
CUJ-1 инфраструктуре EP-19 по готовности. Порог покрытия компонентов ≥ 70 %.

## Риски и подводные камни
- 9 SVG-иконок форм выпуска (`dosage_form_class`) — по спецификации это ресурс `packages/ui`
  (`SRS-CAT-007`), но реальный владелец их создания явно не указан ни в одном эпике `00-EPICS.md`
  (ближе всего — EP-04, каталог, или EP-18, UI-кит). Если к моменту реализации иконок нет ни там, ни
  там — временный набор-заглушка (единая нейтральная иконка «таблетка» для всех классов) с тикетом
  на замену полным набором, НЕ блокировать сдачу этого тикета ожиданием чужого набора.
- Текст `ux.error.network_offline` — единый ключ по требованию `32-design-reference.md`, но дизайн
  показывает РАЗНЫЕ форм-факторы на разных экранах (полноэкранный vs компактный) — не путать
  «разный текст» (запрещено) с «разная вёрстка одного текста» (разрешено).
- Курсорная пагинация «показать ещё» — если дизайн-макет фактически предполагает infinite-scroll
  (не показан явно в референсе для `/search`), уточнить с продуктом/дизайнером перед реализацией —
  оба варианта технически совместимы с `SRS-API-004`, выбор — не архитектурное решение, а UX.
