## Задача
Фильтры «открыто сейчас»/«24/7» требуют вычисления текущего времени в часовом поясе `Asia/Dushanbe`
и корректной обработки интервалов, переходящих через полночь (например, аптека работает `20:00–02:00`).
Это простое на вид правило — частый источник off-by-one-ошибок при наивной реализации; спецификация
явно требует юнит-тестируемости без реального ожидания времени, поэтому вычисление времени обязано
идти через порт `Clock`, а не `Date.now()` внутри бизнес-правила.

## Технический контекст
Слой `application` (НЕ `domain` — сам документ явно указывает: «фильтр не реализуется в `domain`,
`02` §2.6, домен чист от `Date.now()`»). `PharmacyOpeningHoursPolicy` получает `ClockPort` через
конструктор (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §2.6, `SRS-API-008` из `12-api-conventions...`
задаёт конвенцию ISO 8601 UTC для хранения времени, здесь используется для получения текущего
момента и перевода в `Asia/Dushanbe`). Используется ДВАЖДЫ в кодовой базе EP-06/EP-08:
`SearchMedicinesUseCase` (фильтры `openNowOnly`/`is24x7Only`, DTJ-188) и
`GetPharmacyMapPinsUseCase` (поле `isOpenNow` на пине карты, DTJ-196) — оба потребителя получают
готовый порт через DI, ни один не создаёт свою копию логики (DRY, C15).

## Что сделать
1. Создать `ClockPort` (`interface Clock { nowInTenantTz(tenantId: TenantId): TimeOfDay; }`, если
   порт ещё не существует из EP-01 — проверить `packages/contracts`/`common` ПЕРЕД созданием
   дубликата; если базовый `Clock`-порт уже определён фундаментом (EP-01), этот тикет ТОЛЬКО
   добавляет метод `nowInTenantTz`, не создаёт новый порт с нуля — зафиксировать факт проверки в
   PR-описании).
2. Реализовать `isOpenNow(now: TimeOfDay, opening: TimeOfDay, closing: TimeOfDay): boolean` —
   ДОСЛОВНО по алгоритму `SRS-CAT-046`:
   ```typescript
   function isOpenNow(now, opening, closing) {
     if (closing >= opening) return now >= opening && now <= closing;
     return now >= opening || now <= closing;   // переход через полночь
   }
   ```
3. `PharmacyOpeningHoursPolicy.evaluate(pharmacy: { is24x7: boolean; openingTime: TimeOfDay;
   closingTime: TimeOfDay }, tenantId: TenantId): { isOpenNow: boolean }` — «открыто сейчас» =
   `is24x7 === true OR isOpenNow(clock.nowInTenantTz(tenantId), openingTime, closingTime)`
   (`SRS-CAT-046`).
4. «24/7» — отдельный простой предикат `pharmacy.is24x7 === true`, независим от «открыто сейчас»
   (`SRS-CAT-047`) — не смешивать в одну функцию, вызывающий код применяет фильтры независимо.
5. `TimeOfDay` — value object (часы:минуты, без даты) с корректным сравнением `>=`/`<=` — если VO
   уже существует в `10-domain-model.md`/EP-01 baseline, переиспользовать, не плодить дубликат.

## Критерии приёмки
1. Given `opening='20:00', closing='02:00'`, `now='01:00'` (Asia/Dushanbe), When `isOpenNow()`, Then
   `true` (переход через полночь, `TC-CAT-020`).
2. Given `opening='09:00', closing='21:00'`, `now='08:59'`, When `isOpenNow()`, Then `false`
   (обычный интервал, граница не включена до начала).
3. Given `is24x7 = true`, `openingTime`/`closingTime` любые (даже некорректные placeholder-значения),
   When `evaluate()`, Then `isOpenNow: true` БЕЗ обращения к `isOpenNow()`-функции интервала —
   короткое замыкание, негативный сценарий: круглосуточная аптека не должна ложно закрываться
   из-за мусора в полях времени, которые для неё нерелевантны.
4. Given `opening='09:00', closing='09:00'` (вырожденный интервал — открыто и закрыто в одну
   минуту, `closing >= opening` формально true), When `isOpenNow('09:00', ...)`, Then `true` только
   в эту единственную минуту (граничный кейс, зафиксировать поведение явно тестом, не оставлять
   недокументированным).

## Риски и подводные камни
- `ClockPort` может уже существовать из EP-01 (Auth-модуль тоже нуждается в времени для OTP TTL) —
  создание второго конкурирующего порта с похожим именем — риск дублирования интерфейсов домена;
  первым шагом тикета — поиск существующего порта, не создание нового «на всякий случай» (C15,
  «абстракция на будущее без второго потребителя — замечание», здесь наоборот: не плодить
  повторного потребителя без переиспользования существующего).
- Часовой пояс `Asia/Dushanbe` не имеет перехода на летнее время (UTC+5 круглый год) — упрощает
  реализацию, но НЕ полагаться на системный TZ хост-машины, использовать явную библиотеку/встроенный
  `Intl` с фиксированной зоной, чтобы тесты были детерминированы независимо от TZ окружения CI.
