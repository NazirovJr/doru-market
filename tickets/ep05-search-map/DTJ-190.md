## Задача
HTTP-граница модуля поиска — единственное место, где `SearchQuerySchema`/`SearchResultPageSchema`
из `packages/contracts/src/search.ts` (DTJ-180) применяются к реальному запросу/ответу, и где
доменные/application-ошибки (`SearchTemporarilyDegradedError` из DTJ-185) маппятся в HTTP-коды.

## Технический контекст
Слой `presentation`, зависит ТОЛЬКО от `application` (`SearchMedicinesUseCase`/
`SuggestMedicinesUseCase`, DTJ-188/189) — не импортирует `domain`/`infrastructure` напрямую
(`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1). Валидация query-параметров — через zod-схему из
`packages/contracts` (единый источник для контроллера и фронтенда). Общие конвенции пагинации/ошибок
из `12-api-conventions-auth-tenancy.md` (`SRS-API-004` курсорная пагинация, `SRS-API-006` sort,
`SRS-API-012` rate limit) применяются как есть, без переопределения.

## Что сделать
1. `GET /api/v1/medicines/search` — query-параметры валидируются `SearchQuerySchema` (zod pipe);
   при невалидном `radiusMeters` (вне `{1000,3000,5000,10000,20000}`) → `400 VALIDATION_ERROR
   details.field='radiusMeters'` (`SRS-CAT-044`); при `sort=distance_asc` без `geo` → `400
   VALIDATION_ERROR details.field='sort'` с уточнением `"distance_asc requires geo"` (`SRS-CAT-048`).
   Given `radiusMeters` задан без `geo` — тихо игнорировать (НЕ ошибка, `SRS-CAT-044` второй абзац).
2. Вызвать `SearchMedicinesUseCase.execute()`, замапить `SearchResultPage` → JSON через
   `search-result.mapper.ts` (DTO→HTTP, `02` §1: presentation мапит domain/application результат в
   публичный контракт, сущность БД никогда не возвращается наружу).
3. Перехватить `SearchTemporarilyDegradedError` → `503 SERVICE_UNAVAILABLE
   details.reason='search_temporarily_degraded'` (`SRS-CAT-075`, обработка на границе presentation,
   не в use case — use case пробрасывает доменную ошибку как есть).
4. Пустой результат — обычный `200` с `data: []`, `meta.pagination.hasMore: false` (`SRS-CAT-077`,
   НЕ `404`).
5. `GET /api/v1/medicines/suggest` — `q` опционален (пустая строка допустима явно, не `400`), `limit`
   дефолт `10`. Вызвать `SuggestMedicinesUseCase.execute()`.
6. Rate limiting — переиспользовать ОБЩИЙ анонимный лимит `RATE_LIMIT_ANON_PER_MIN = 100`
   (`SRS-API-012`, конфигурация guard'а — из EP-01 baseline, здесь только подключить декоратор/guard
   к этим двум маршрутам, НЕ вводить отдельный более строгий лимит — `SRS-CAT-057` явно запрещает).
7. Тенант резолвится стандартным guard'ом (`X-Tenant-Slug`/домен, EP-02) — контроллер НЕ резолвит
   тенант вручную, только читает уже установленный `request.tenantId`.

## Критерии приёмки
1. Given `GET /medicines/search?radiusMeters=7000`, When запрос, Then `400 VALIDATION_ERROR
   details.field='radiusMeters'`.
2. Given `GET /medicines/search?sort=distance_asc` (без `lat`/`lon`), When запрос, Then `400
   VALIDATION_ERROR details.field='sort'`.
3. Given `GET /medicines/search?text=несуществующий_текст_xyz`, When запрос, Then `200` с `data: []`
   (`TC-CAT-077` на уровне HTTP, не `404`).
4. Given искусственно вызванный таймаут SQL (интеграционный тест с моком use case, бросающим
   `SearchTemporarilyDegradedError`), When запрос, Then `503 SERVICE_UNAVAILABLE
   details.reason='search_temporarily_degraded'` (`TC-CAT-025` на уровне HTTP).
5. Given 101-й запрос за минуту с одного IP к `/medicines/search` (анонимный), When запрос, Then
   `429 RATE_LIMITED` с заголовком `Retry-After` (переиспользование общего лимита, `TC-API-006`).

## Риски и подводные камни
- Маппинг ошибок — единственное место, где допустимо превращать доменную ошибку в HTTP-код;
  ревью обязано проверить, что НИ ОДНА доменная/application ошибка не «утекает» как generic `500`
  без явного перехвата (в частности, `DomainInvariantViolationError` из `RankingScoreMapper`,
  DTJ-183 — она НЕ ожидается на этом пути при корректных данных, но должна маппиться хотя бы в
  дефолтный `500 INTERNAL_ERROR` осознанно, не случайно).
- Rate-limit guard — общий с другими эндпоинтами каталога (EP-04); если EP-04 ещё не подключил
  decorator к своему модулю на момент этого тикета, синхронизировать подход (не изобретать второй
  паттерн подключения guard'а).
