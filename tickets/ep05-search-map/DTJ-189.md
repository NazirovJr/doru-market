## Задача
Автодополнение — REQ-UX-12, обязательная часть быстрого ввода на главном экране. Отдельный use case
от полнотекстового поиска, т.к. содержит принципиально другую ветку для пустого ввода (клиентская
история vs серверный trending) и НЕ пишет `search_query_log` (это только полноценные поисковые
запросы, а не подсказки на каждый символ).

## Технический контекст
Слой `application`. Given `q = ''` — специальный путь, который НЕ обращается к `SearchProvider`
вообще (`SRS-CAT-030`): клиентская история — целиком на фронтенде (`localStorage`, без сетевого
запроса, см. DTJ-192), поэтому use case для пустого `q` вызывается ТОЛЬКО когда фронтенд решает
показать серверный trending-фолбэк (история браузера пуста при первом визите) — это explicit-запрос
с пустым `q`, отличимый от «поле в фокусе, запрос ещё не отправлен» (последнее фронтенд вообще не
отправляет на сервер).

## Что сделать
1. `SuggestMedicinesUseCase.execute(command: { prefix: string; tenantId: TenantId; limit: number })`:
   given `prefix === ''` → вернуть `SearchCacheService.getTrendingSearches(tenantId)` (DTJ-187),
   смаппленное в форму `SuggestItem[]` (только `tradeName`, без `medicineId`/`innName`/`matchedVia`
   для чистых строк trending — задокументировать это отклонение от общей формы `SuggestItem`,
   т.к. trending хранит только текст запроса, не привязку к конкретному `medicineId`).
2. Given `prefix !== ''` → сначала проверить кэш (`SearchCacheService.getSuggestions`, DTJ-187) под
   `RedisLockGuard`, при промахе — вызвать `SearchProvider.suggest(prefix, tenantId, limit)` (DTJ-186),
   закэшировать на 5 минут.
3. НЕ писать в `search_query_log` — это отдельный от полнотекстового поиска путь, лог фиксирует
   только результаты `SearchMedicinesUseCase` (DTJ-188).
4. Debounce/`AbortController` — НЕ ответственность backend use case (клиентская часть, `SRS-CAT-027`
   реализуется во фронтенд-тикете DTJ-192) — здесь только зафиксировать это разделение комментарием,
   чтобы не возникло искушения реализовать искусственную задержку на сервере.

## Критерии приёмки
1. Given новый браузер (пустой `localStorage`, эмулируется фронтендом отправкой `q=''` только когда
   история пуста), `trending_searches` в Redis содержит 5 записей, When `execute({ prefix: '' })`,
   Then возвращены 5 популярных запросов, `SearchProvider.suggest()` НЕ вызван (`TC-CAT-022`).
2. Given `trending_searches` отсутствует в Redis (джоба ещё не запускалась), When
   `execute({ prefix: '' })`, Then возвращается `[]` без исключения.
3. Given `prefix = 'но-ш'`, When `execute()`, Then вызывается `SearchProvider.suggest()`
   (при промахе кэша) с результатом, замапленным в `SuggestItem[]`, дедуп уже выполнен на уровне
   адаптера (DTJ-186) — use case не переделывает дедупликацию повторно.
4. Given `prefix = 'но-ш'` вызван дважды подряд в течение 5 минут, When второй вызов, Then
   `SearchProvider.suggest()` НЕ вызван повторно (кэш-хит) — негативный сценарий дублирующего вызова.

## Тест-план
Unit (моки `SEARCH_PROVIDER`, `SearchCacheService`): пустой `prefix` с непустым/пустым trending,
непустой `prefix` с кэш-хитом/промахом, отсутствие записи в `search_query_log` (негативная проверка —
мок репозитория лога НЕ вызван). Порог покрытия `application/` ≥ 90 %.

## Риски и подводные камни
- Форма ответа для trending-ветки (`SuggestItem` без `medicineId`) — расхождение с полной формой
  интерфейса из `SRS-CAT-011`; на уровне presentation (DTJ-190) обязательно замапить это в
  консистентный JSON-контракт для фронтенда (например, `medicineId: null`, фронтенд трактует
  подсказку без `id` как «поисковая фраза, клик — просто заполняет поле и запускает полный поиск»,
  не переход на карточку) — согласовать с DTJ-192/193 ДО реализации UI, иначе фронтенд получит
  неожиданный `null` там, где ожидал `uuid`.
- `search-query-log` НЕ пишется этим use case — если в будущем продуктовая аналитика (EP-17) захочет
  анализировать «незавершённые» подсказки (набор без финального поиска), это отдельное расширение
  scope, не входящее в R1 (`R1-15` описывает воронку от полноценного показа экономии, не от
  промежуточных keystroke-подсказок).
