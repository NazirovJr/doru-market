## Задача
Собирает `MapView` (DTJ-198) в законченный продуктовый экран `/map` с реальными данными
(`GET /pharmacies/map`, DTJ-197) и обеспечивает переход «показать на карте» с карточки товара —
второй по важности после поиска элемент CUJ-1 (R1-6). Дизайн-референс (`32-design-reference.md`
строка 180) показывает только заглушку — этот тикет специфицирует реальное поведение сам, опираясь
на модульный документ (§9, §7).

## Технический контекст
`apps/web/src/features/pharmacy-map/**` + `apps/web/src/pages/map/index.tsx` (композиция,
`02-CLEAN-ARCHITECTURE-AND-CODE.md` §5). Данные — через `use-pharmacy-map-pins.ts` (TanStack Query,
`queryKey` включает `bbox`+`medicineId`) → `pharmacy-map.api.ts` → `GET /api/v1/pharmacies/map`.
Точка входа с карточки товара («показать на карте») передаёт `medicineId` в query-параметр `/map`.

## Что сделать
1. `pharmacy-map-page.tsx` — заголовок «Карта аптек» (i18n), `MapView` (DTJ-198) на весь доступный
   экран, given URL содержит `?medicineId=<uuid>` — прокидывать его в запрос пинов (`SRS-CAT-052`,
   переход с карточки товара «показать на карте»).
2. `use-pharmacy-map-pins.ts` — на `onViewportChange` от `MapView` пересчитывать `bbox` и
   рефетчить пины (debounce уже на уровне `MapView`, здесь — только TanStack Query с
   `keepPreviousData: true`, чтобы старые пины не исчезали мгновенно при панорамировании, создавая
   ощущение мерцания).
3. `pharmacy-preview-card.tsx` — карточка предложения аптеки (`Card static`, `32-design-reference.md`
   §Card) внутри попапа/боковой панели по клику на пин: имя, адрес (если есть в данных), цена/остаток
   (given `offer !== null`), метка `isStale`, «открыто сейчас»/`24/7`, CTA «показать в поиске»/
   «добавить в корзину» (given товар в наличии — переход в существующий поток корзины, реализация
   самой корзины — EP-09, здесь только точка перехода/deep-link).
4. Фильтры на экране карты: given `medicineId` НЕ передан — простой список без ценовых данных
   (пины показывают только `isOpenNow`/`24/7`); given `medicineId` передан — визуальное отличие
   пинов с/без остатка (цветовая кодировка через CSS-токены, не хардкод HEX — Charter §5).
5. given `bbox` (после ограничения `BBOX_MAX_AREA_KM2`) возвращает `400 VALIDATION_ERROR` (крайний
   зум-аут) — UI НЕ шлёт запрос за пределы разумного зума вовсе (клиентская защита — минимальный
   уровень зума карты ограничен программно, `MapLibre` `minZoom`) — избегать самого сценария ошибки
   на UI-уровне, серверная валидация (DTJ-197) остаётся defense-in-depth, не основным механизмом.
6. Точка входа «превью карты аптек» на `Home` (`pages/home`, `32-design-reference.md` строка 174,
   «превью карты аптек» как часть главного экрана) — компактный `MapView` (150-190px) БЕЗ
   интерактивного панорамирования (статичный вид вокруг геолокации пользователя ИЛИ дефолтного
   центра города при отсутствии геолокации), клик по превью → переход на `/map` — координация с
   владением `pages/home` (см. риск DTJ-192, тот же паттерн).

## Критерии приёмки
1. Given переход с карточки товара «показать на карте» (`medicineId` в URL), When открыт `/map`,
   Then запрос пинов включает `medicineId`, пины показывают цену/остаток для аптек с товаром.
2. Given пользователь панорамирует карту на `/map`, When новая область запрошена, Then предыдущие
   пины остаются видимыми до прихода новых данных (`keepPreviousData`, нет мерцания пустой карты).
3. Given ограничение зума достигнуто (пользователь пытается отдалить карту дальше минимального
   уровня), When взаимодействие, Then дальнейшее отдаление заблокировано на уровне `MapLibre`
   (`minZoom`), запрос за пределы `BBOX_MAX_AREA_KM2` НЕ отправляется.
4. Given клик по превью карты на `Home`, When переход, Then открывается `/map` с центром,
   соответствующим области превью (консистентность UX между превью и полным экраном).
5. Given у аптеки в попапе `isStale: true`, When рендер `pharmacy-preview-card.tsx`, Then видимая
   пометка устаревания присутствует.

## Тест-план
Компонентные (Vitest/RTL): `pharmacy-preview-card.tsx` — все состояния (`offer=null`/с остатком/
`isStale`), `use-pharmacy-map-pins.ts` — `keepPreviousData` не даёт пинам исчезнуть при рефетче
(мок API с задержкой). Playwright E2E: полный сценарий «карточка товара → показать на карте → пины
с ценой видны → клик на пин → попап с данными» — привязывается к CUJ-1-инфраструктуре EP-19 по
готовности (карта — часть косвенного UX-потока CUJ-1, `04-SCOPE-DECISION-PIVOT.md` таблица R1-6).
Порог покрытия компонентов ≥ 70 %.

## Риски и подводные камни
- CTA «добавить в корзину» из попапа карты зависит от готовности EP-09 (корзина) — если EP-09 ещё
  не готов на момент этого тикета (волна 6, EP-09 — параллельный поток той же волны, не
  гарантированно раньше), реализовать CTA как переход на карточку товара («открыть товар») вместо
  прямого добавления в корзину, с последующим тикетом на прямую интеграцию — не блокировать сдачу.
- Точка входа на `Home` — правка общего файла `pages/home`, которым НЕ владеет EP-08 напрямую
  (аналогичный риск DTJ-192 для EP-06) — минимизировать диff, только добавление секции превью карты.
- Цветовая кодировка пинов «в наличии / нет в наличии» — первая заметная точка соприкосновения карты
  с дизайн-токенами; если токены для этого конкретного смысла (успех/нейтраль) ещё не определены
  в `packages/ui` на момент реализации — временно переиспользовать существующие семантические токены
  (`--color-success`/`--color-muted` или их эквиваленты из дизайн-системы), не вводить новые
  hex-значения самостоятельно.
