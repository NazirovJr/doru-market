## Задача
Карта аптек (`R1-6`) — второй самостоятельный поток EP-06 после поиска (`00-EPICS.md`, волна 6,
зависит только от EP-06). Порт и контракт фиксируются первым тикетом эпика, чтобы `infrastructure`-
адаптер (DTJ-195), `application` use case (DTJ-196) и фронтенд (DTJ-198/199) могли разрабатываться
без взаимного ожидания готовой реализации друг друга.

## Технический контекст
`modules/catalog/application/pharmacies-map/**` — отдельная поддиректория ВНУТРИ `catalog`
(`00-EPICS.md`, владение EP-08), физически соседствует с `search/` (DTJ-180), но самостоятельный
порт — карта НЕ переиспользует `SearchProvider` (разные критерии выборки: `bbox`, не радиус;
разные поля ответа — статические данные аптеки vs ранжированный товар). `packages/contracts/src/
pharmacies-map.ts` — HTTP-контракт для `GET /api/v1/pharmacies/map` (`SRS-CAT-052`).

## Что сделать
1. Создать `PharmacyMapRepository` порт (`interface`, DI-токен `PHARMACY_MAP_REPOSITORY =
   Symbol('PHARMACY_MAP_REPOSITORY')`):
   ```typescript
   export interface BboxQuery {
     readonly lonMin: number; readonly latMin: number;
     readonly lonMax: number; readonly latMax: number;
     readonly medicineId?: string;
     readonly tenantId: TenantId;
   }
   export interface PharmacyMapPin {
     readonly pharmacyId: string;
     readonly name: string;
     readonly lat: number; readonly lon: number;
     readonly isOpenNow: boolean; readonly is24x7: boolean;
     readonly offer: { readonly priceDiram: number; readonly stockQuantity: number;
       readonly lastSyncedAt: string; readonly isStale: boolean } | null; // null если medicineId не передан
   }
   export interface PharmacyMapRepository {
     findPinsInBbox(query: BboxQuery): Promise<readonly PharmacyMapPin[]>;
   }
   ```
   — по контракту `SRS-CAT-052` (пин несёт цену/остаток ТОЛЬКО если `medicineId` передан, иначе —
   только статические данные).
2. Создать `packages/contracts/src/pharmacies-map.ts`: zod-схема query-параметров
   `PharmacyMapQuerySchema` (`bbox` — строка `lonMin,latMin,lonMax,latMax`, парсится и валидируется
   на 4 числа; `medicineId` опциональный UUID), `PharmacyMapPinSchema`,
   `PharmacyMapResponseSchema`.
3. Добавить строку экспорта в `packages/contracts/src/index.ts` (см. риск конфликта в DTJ-180 —
   тот же файл, координация по rebase).
4. Задокументировать константу `BBOX_MAX_AREA_KM2 = 2500` (`SRS-CAT-054`) как именованную константу
   модуля (используется в DTJ-196, но объявляется здесь рядом с портом как часть контракта области
   действия запроса — единственное место объявления, C6).

## Критерии приёмки
1. Given `BboxQuery`/`PharmacyMapPin` объявлены по спецификации, When `pnpm typecheck`, Then
   компиляция проходит без `any`.
2. Given `PharmacyMapQuerySchema.parse({ bbox: '68.5,38.5,68.9,38.9' })`, When валидация, Then
   успешно разобрано на 4 числа с сохранением порядка `lonMin,latMin,lonMax,latMax`.
3. Given `bbox` с нечисловым значением (`'a,b,c,d'`), When валидация, Then `ZodError` с указанием
   поля `bbox` — негативный сценарий на уровне контракта (реальная проверка площади — DTJ-196,
   здесь только формат).
