## Задача

Единственный человекочитаемый доступ к эскроу-леджеру заказа — нужен и для операционной поддержки
(`super_admin` видит всё), и для доверия аптеки к тому, сколько ей причитается (`pharmacy_admin`
видит только то, что относится к её payout, без деталей провайдерских ссылок клиента).

## Технический контекст

`GetOrderLedgerQuery` (application, query-объект — read-only, не use case в строгом смысле
мутации, но следует тому же паттерну «один класс, один метод `execute`», `02` §3.1). Видимость —
ПОЛИТИКА (не guard): `pharmacy_admin` видит записи `captured_to_pharmacy`/`platform_fee_captured`,
относящиеся к её payout, БЕЗ `hold_created`/`payment_transaction_ref` (провайдерские детали клиента
— чувствительные, не операционная необходимость аптеки).

## Что сделать

1. `GetOrderLedgerQuery.execute(orderId, actorRole, actorPharmacyId?): LedgerViewDto`:
   - `EscrowLedgerRepository.findByOrderId(orderId)` (DTJ-240).
   - Given `actorRole === 'super_admin'` → все записи, все поля.
   - Given `actorRole === 'pharmacy_admin'` → фильтр `entryType IN
     ('captured_to_pharmacy','platform_fee_captured')` И заказ принадлежит её сети (проверка через
     `PaymentsOrdersPort.getOrderById`, `pharmacyId` заказа ∈ аптеки её сети) — иначе `403`. Поля
     `paymentTransactionRef` исключены из ответа для этой роли.
   - `meta.isBalanced = EscrowLedger.isBalanced(entries)` — вызывается «на лету» для ЭТОГО заказа
     (не дожидаясь ночной `EscrowReconciliationJob`, DTJ-247), используя ПОЛНЫЙ набор записей
     (до фильтрации по роли — фильтрация только для отображения, расчёт баланса всегда на полном
     наборе).
   - Записи упорядочены по `created_at` ASC.
2. `GET /api/v1/orders/:id/ledger` — контроллер, вызывает query, маппит `LedgerViewDto` в ответ.

## Критерии приёмки

1. **Given** `super_admin`, **When** `GET /api/v1/orders/:id/ledger`, **Then** ответ содержит ВСЕ
   записи со всеми полями, включая `paymentTransactionRef`.
2. **Given** `pharmacy_admin` своей сети, **When** тот же запрос, **Then** ответ содержит только
   `captured_to_pharmacy`/`platform_fee_captured`, без `paymentTransactionRef`, без `hold_created`.
3. **Given** `pharmacy_admin` ЧУЖОЙ сети, **When** запрос на заказ не своей сети, **Then**
   `403 FORBIDDEN`.
4. **Given** заказ с расхождением (искусственно нарушенный баланс в тесте), **When** запрос,
   **Then** `meta.isBalanced === false`, рассчитано на полном наборе записей независимо от
   ролевой фильтрации отображаемых полей.

## Тест-план
