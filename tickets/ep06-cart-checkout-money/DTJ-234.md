## Задача

Экран корзины — первое место, где пользователь физически видит, что его покупка распадётся на N
отдельных заказов по аптекам, ДО перехода к оплате (REQ-UX-4). Дизайн-референс уже описывает
экран (`.dc.html:780-858`): группы по аптекам с подытогом, мультиаптечное предупреждение,
предупреждение о дубле действующего вещества, CTA «Перейти к оформлению».

## Технический контекст

`apps/web/src/features/cart/**` (владение — `tickets/00-EPICS.md`, EP-09). Структура —
`02-CLEAN-ARCHITECTURE-AND-CODE.md` §5: `api/` (TanStack Query поверх `GET /api/v1/cart`, DTJ-226),
`model/` (чистые функции — группировка предупреждений по типу для рендера), `ui/` (только рендер).
Компоненты `Button`/`Input`/`EmptyState`/`Toast` — из `packages/ui` (EP-18); если конкретного
компонента ещё нет на момент реализации — временный локальный компонент в `features/cart/ui/`
с тикетом на перенос в `packages/ui` в течение того же спринта (`tickets/00-EPICS.md`
«Пересекающееся владение» п.6, обязательный пункт SRS-UX-034). Тексты — ТОЛЬКО через `useT()`
(`packages/i18n`), НИ ОДНОЙ хардкодной строки на русском/английском/таджикском в JSX.

**Расхождение дизайн-референса с 30-ux (32-design-reference.md §«Статус», п.6):** тексты
EmptyState/предупреждений в `.dc.html` — БЛИЗКИЕ, но не идентичные каноническим ключам `ux.*`
(30-ux §5). Использовать канонический словарь `packages/i18n`, дизайн — ориентир по тону/длине,
не точная копия строк.

## Что сделать

1. `useCart()` (TanStack Query) — `GET /api/v1/cart`, поддержка `?extendHold=true` при открытии
   экрана (SRS-ORD-005 UX-эффект).
2. `useCartMutations()` — `addItem`/`updateQuantity`/`removeItem` (`POST`/`PATCH`/`DELETE`,
   DTJ-226), optimistic update + инвалидация `useCart` query key.
3. `CartScreen.tsx`: рендер `meta.pharmacyGroups` через `PharmacyGroupCard` (название аптеки,
   позиции, подытог, кнопка удаления позиции), баннер «Будет оформлено N отдельных заказов — по
   одному в каждой аптеке» (i18n-ключ, не дословный текст дизайна), кнопка «Перейти к оформлению»
   (фиксированной ширины по контенту, `32-design-reference.md` §«Реализационные заметки»).
4. `CartWarningBanner.tsx`: красный баннер для `warnings[].type === 'duplicate_substance'`
   («X есть в нескольких препаратах корзины — риск превышения дозы», канонический i18n-ключ) и
   для `insufficient_stock` (менее критичный стиль — товара стало меньше, чем в корзине).
5. `EmptyState` для пустой корзины: `ux.empty.cart` (30-ux §5, канонический текст, НЕ дословная
   калька `.dc.html`).
6. Тап-зоны интерактивных элементов ≥48×48px (SRS-UX-002) — hit-slop через padding компонента
   `packages/ui`, не через визуальный размер.
7. `CartPage.tsx` (`pages/cart/**`) — тонкая композиция `CartScreen`, ноль бизнес-логики
   (`02` §5).
8. TWA-режим (SRS-UX-045/046, за пределами DTJ, но роут должен НЕ ломать это поведение): если
   `MainButton` Telegram SDK уже реализован общей инфраструктурой TWA (вероятно EP-18) —
   `CartScreen` не рендерит дублирующую обычную кнопку CTA, когда TWA-режим активен (проверка
   через существующий хук/контекст TWA, если он есть; если ещё не существует — оставить TODO,
   рендерить обычную кнопку по умолчанию).

## Критерии приёмки

1. **Given** корзина с товарами от 2 аптек, **When** экран открыт, **Then** видны 2 отдельные
   карточки-группы с подытогами, суммарный баннер «Будет оформлено 2 отдельных заказов...».
2. **Given** `warnings` содержит `duplicate_substance`, **When** экран отрендерен, **Then** виден
   красный баннер с точным текстом из `packages/i18n`, не текст дизайн-референса дословно.
3. **Given** пустая корзина, **When** экран открыт, **Then** `EmptyState` с CTA «Найти лекарство» и
   каноническим текстом `ux.empty.cart`.
4. **Given** viewport 375×812 (мобильный), **When** измеряется bounding box каждого
   интерактивного элемента, **Then** все ≥48×48px (SRS-UX-002, тест TC-UX-001 переиспользуется
   для этого экрана).

## Риски и подводные камни

- **Зависимость от `packages/ui`/`packages/i18n` (EP-18).** Минимальный набор ожидается готовым к
  волне 1 (`tickets/00-EPICS.md`), но конкретных компонентов (`EmptyState`, `Toast`) может не
  хватать к волне 6 (когда стартует EP-09). Следовать established fallback-правилу: локальный
  компонент в `features/cart/ui/` + тикет на перенос, не блокировать сдачу этого тикета ожиданием
  EP-18.
- **`GET /orders/:id/payment-status`** и связанные с оплатой экраны — вне периметра этого тикета
  (переход к оформлению — DTJ-235); здесь только сама корзина.
