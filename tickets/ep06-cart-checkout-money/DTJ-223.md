## Задача

Корзина — НЕ доменный агрегат (`10-domain-model.md`, комментарий к таблице `cart`; §1 доработанной
21-module SRS): её инварианты — мультиаптечная привязка позиции, запрет наркотиков/психотропных
веществ уже на добавление, предупреждение о дублирующемся действующем веществе — реализуются на
уровне `application`-use case'ов над простым хранилищем. Этот тикет даёт клиенту честное «в корзине
товар именно той аптеки, откуда он его добавил» с первого касания, а не сюрпризом на checkout
(REQ-UX-4).

## Технический контекст

`apps/api/src/modules/orders/application/cart/**` (владение — `tickets/00-EPICS.md`, «application/
{cart,checkout}»). `cart_items` — `UNIQUE(cart_id, medicine_id, pharmacy_id)` уже в схеме (DTJ-220).
`CatalogFacadePort.getMedicineSnapshot`/новый метод `getSubstanceSet(medicineId)` (расширить порт
из DTJ-220 этим же тикетом, если ещё не содержит) — используется для проверки control_category и
пересечения действующих веществ. `SplitCartByPharmacyUseCase` — переиспользуется ДВАЖДЫ: здесь для
`meta.pharmacyGroups` в ответе `GET /cart` (готовит DTJ-225) и в `CheckoutUseCase` (DTJ-227) для
реального разбиения на N заказов — один класс, один источник группировки, не дублировать логику.

## Что сделать

1. `AddCartItemUseCase.execute(cartId, medicineId, pharmacyId, quantity)`:
   - `CatalogFacadePort.getMedicineSnapshot([medicineId])` → controlCategory.
   - Given `controlCategory ∈ {psychotropic, narcotic}` → `ControlledSubstanceNotOrderableError`
     немедленно, строка НЕ создаётся (SRS-ORD-003).
   - Upsert в `cart_items` по `(cartId, medicineId, pharmacyId)` — если строка уже существует,
     `quantity` увеличивается на переданное значение (не перезаписывается), не новая строка
     (`UNIQUE`-констрейнт).
   - Given в корзине уже есть позиция с непустым пересечением `substances` с новым товаром
     (`CatalogFacadePort.getSubstanceSet`), эмитировать `CartWarningEvent(type=
     'duplicate_substance', existingMedicineId, newMedicineId)` — добавление РАЗРЕШЕНО
     (SRS-ORD-004, SRS-DOM-175), событие не блокирует, только предупреждение в ответе use case.
2. `UpdateCartItemQuantityUseCase.execute(cartItemId, quantity)`: Given `quantity <= 0` →
   эквивалентно вызову `RemoveCartItemUseCase` (SRS-ORD-013, `chk_cart_items_quantity_positive` не
   допускает `<=0` персистентно). Иначе — `UPDATE cart_items SET quantity`.
3. `RemoveCartItemUseCase.execute(cartItemId)`: `DELETE FROM cart_items WHERE id = :id AND cart_id
   = :cartId` (проверка владения корзиной — параметр `cartId` из контекста аутентификации,
   presentation-слой передаёт).
4. `SplitCartByPharmacyUseCase.execute(cartItems): PharmacyGroup[]` — `GROUP BY pharmacy_id`,
   каждая группа: `{ pharmacyId, pharmacyName, items[], subtotalDiram, distanceMeters? }`
   (`distanceMeters` — опционально, требует `GeoPoint` клиента, заполняется presentation-слоем при
   наличии, use case не обязан знать о геолокации клиента, SRS-ORD-002).
5. `CartRepository` (infrastructure, Drizzle): `findById`, `findItemsByCartId`, `upsertItem`,
   `updateItemQuantity`, `deleteItem` — тонкий адаптер над `cart`/`cart_items` из DTJ-220.
6. `CartWarningEvent` — НЕ доменное событие в outbox (не пересекает границу транзакции/сервиса),
   простой application-level DTO, возвращаемый в `meta.warnings` ответа use case (presentation
   DTJ-226 прокидывает наружу).

## Критерии приёмки

1. **Given** пустая корзина, **When** `AddCartItemUseCase` дважды с тем же `(medicineId,
   pharmacyId)` и `quantity=2` каждый раз, **Then** одна строка `cart_items` с `quantity=4`.
2. **Given** товар с `controlCategory='psychotropic'`, **When** `AddCartItemUseCase`, **Then**
   `Err(ControlledSubstanceNotOrderableError)`, строка не создана.
3. **Given** в корзине товар А с веществом X, **When** добавляется товар Б с тем же веществом X
   (другая аптека или та же), **Then** добавление успешно, ответ содержит
   `warnings: [{ type: 'duplicate_substance', ... }]`.
4. **Given** корзина с товарами от 2 аптек, **When** `SplitCartByPharmacyUseCase`, **Then**
   ровно 2 группы, `Σ(group.subtotalDiram)` по каждой группе корректна.
5. **Given** `UpdateCartItemQuantityUseCase(cartItemId, 0)`, **Then** строка удалена, не записана
   с `quantity=0`.

## Тест-план

## Риски и подводные камни

- **`CatalogFacadePort.getSubstanceSet` может не существовать на момент реализации** (порт
  создан в DTJ-220 с минимальным набором методов). Расширить интерфейс порта этим тикетом — не
  блокирующее изменение файла, которым уже владеет DTJ-220 (тот же модуль `orders`, тот же эпик).
  Реальная реализация метода — на стороне `catalog`-модуля (EP-04), здесь только контракт + мок в
  тестах.
- Гостевая корзина (`session_token`, без `customer_id`) поддерживается на уровне `CartRepository`
  (`findById` работает по `cartId` независимо от владельца) — авторизация «эта ли корзина
  принадлежит этому гостю/юзеру» — ответственность presentation-слоя (DTJ-226), не этого тикета.
