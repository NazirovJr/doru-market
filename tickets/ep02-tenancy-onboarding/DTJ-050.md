## Задача
Ни один последующий тикет — ни резолвинг, ни guard, ни изоляция данных — не имеет доменного
основания без агрегата `Tenant`. Charter §3.4 требует, чтобы мультитенантность закладывалась
архитектурно целиком с первого дня, без флага «выключить» (SRS-TEN-000); этот тикет фиксирует
инварианты, которые физически не дают собрать систему без корректного резолвинга тенанта дальше по
цепочке. Это первый тикет эпика EP-02 — открывает волну 2 параллельно с EP-04.

## Технический контекст
Слой `domain` модуля `apps/api/src/modules/tenancy` (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1: ноль
импортов фреймворка, ноль Drizzle). Корень агрегата — `Tenant`, содержащий `TenantSettings` как
value entity (`10-domain-model.md` §«Tenant — domain»). Таблицы `tenants`/`tenant_settings` уже
полностью специфицированы `11-database-schema.md` Группа C (создаются тикетом DTJ-051) — здесь
только доменная модель, без знания о Drizzle-схеме (правило C1 `02`: утечка модели БД в домен
запрещена). Модуль `tenancy` экспортирует наружу ТОЛЬКО через `index.ts` (Facade-паттерн, `02`
§1.2) — прямой импорт `modules/tenancy/domain/*` из другого модуля блокируется
`dependency-cruiser`.

## Что сделать
1. `value-objects/tenant-id.vo.ts`: `TenantId` — обёртка над `UUID` (SRS-DOM-083), фабрика
   `TenantId.from(raw: string)` валидирует UUID-формат, бросает `ValidationError` при невалидном
   значении.
2. `value-objects/tenant-slug.vo.ts`: `TenantSlug` — `TenantSlug.parse(raw)` проверяет формат
   `^[a-z0-9-]{3,32}$` (SRS-DOM-084, SRS-TEN-001) и экспортирует константу `RESERVED_SLUGS =
   [neutral, admin, api, www, app, static]` (используется как для мгновенного отказа внутри VO,
   так и повторно в DTJ-057 для `ReservedTenantSlugError` на уровне use case — единственный источник
   списка, не дублировать литерал в других тикетах).
3. `tenant-settings.entity.ts`: `TenantSettings` (value entity, не отдельный агрегат) — поля:
   `brandName: string` (обязателен, без дефолта, SRS-TEN-038), `brandPalette: Record<string,
   string>` (дефолт пустой объект), `brandLogoUrl?: string`, `merchantCredentialsRef?: string`,
   `telegramBotTokenRef?: string`, `codLimitDiram`, `holdPeriodDays`, `pickupSlaMinutes`,
   `deliverySlaCityMinutes`, `deliverySlaRemoteMinutes`, `defaultLocale` — один в один с
   `11-database-schema.md` §14 (без деталей branding-валидации — это DTJ-059).
4. `tenant.entity.ts`: `Tenant` — приватный конструктор, статическая фабрика `Tenant.create(slug:
   TenantSlug, options: { chainId?: TenantId; isNeutral: boolean; legalOwnerRef?: string })`.
   Инварианты:
   - SRS-DOM-042 / БД-ограничение «нейтральный тенант без сети»: `isNeutral === true` требует
     `chainId === undefined`, иначе `ValidationError`.
   - `tenant.rename(newSlug)`: бросает `ImmutableNeutralTenantError`, если `this.isNeutral ===
     true` (SRS-DOM-042) — нейтральный тенант единственный и неизменяем.
   - `tenant.attachCustomDomain(domain)`: не проверяет уникальность сама (ответственность
     репозитория/БД, UNIQUE-индекс — последний рубеж), но нормализует домен (lower-case, без
     завершающей точки) и переводит `customDomainStatus` в `pending_verification` (§12 п.3
     `26-module-tenancy-whitelabel.md`).
   - `tenant.updateBranding(palette, logoRef?)` / `tenant.setCourierSourcingMode(mode)` — простые
     сеттеры; валидация формата палитры НЕ здесь (allowlist — ответственность `BrandPaletteSchema`
     в `packages/contracts`, DTJ-059; домен хранит уже провалидированные значения — сознательное
     разделение, домен не знает о CSS).
5. Доменные ошибки (`domain/errors/*.error.ts`), каждая — подкласс соответствующей базовой ошибки
   из каталога `10-domain-model.md` §«Доменные ошибки»: `ImmutableNeutralTenantError extends
   ForbiddenTransitionError`, `DuplicateCustomDomainError` / `DuplicateTenantSlugError extends
   ConflictError`, `ReservedTenantSlugError extends ValidationError`. Каждый класс объявляет
   статическое поле `code` (`TENANT_SLUG_TAKEN`, `DOMAIN_TAKEN` и т.д.) — по этому полю
   `DomainExceptionFilter` (уже определён SRS-API-016, не переопределяется здесь) резолвит HTTP-код
   без `instanceof`-цепочки.
6. `tenancy.module.ts` + `index.ts`: пустой NestJS-модуль-скелет (провайдеры добавляются
   тикетами DTJ-052..062) и барабанный экспорт — на этом шаге экспортировать ТОЛЬКО типы (`Tenant`,
   `TenantId`, `TenantSlug`) и классы ошибок; публичный сервисный интерфейс (Facade) появляется в
   DTJ-057/DTJ-070-совместимых тикетах.

## Критерии приёмки
1. Given `Tenant.create(TenantSlug.parse('sifat-demo'), { isNeutral: true, chainId: someId })`, When
   вызов, Then выбрасывается `ValidationError` (нейтральный тенант не может иметь `chainId`).
2. Given нейтральный тенант (`isNeutral: true`), When `tenant.rename(newSlug)`, Then
   `ImmutableNeutralTenantError`, слаг объекта не изменяется после вызова.
3. Given `TenantSlug.parse('admin')`, When вызов, Then результат явно помечен как зарезервированное
   значение (используется DTJ-057 для `ReservedTenantSlugError`); негативный сценарий:
   `TenantSlug.parse('ab')` (короче 3 символов) отклоняется форматной ошибкой независимо от списка
   зарезервированных значений.
4. Given `domain/**` модуля `tenancy`, When `pnpm arch:check` и `tsc --noEmit --strict`, Then ни
   один импорт из `@nestjs/*`, `drizzle-orm`, `zod` не обнаружен.

## Тест-план
Unit (Vitest, `apps/api`): `tenant.entity.spec.ts` (создание нейтрального/White-Label тенанта,
`rename()` на нейтральном/обычном тенанте, `attachCustomDomain()` — нормализация домена и установка
статуса); `tenant-slug.vo.spec.ts` (валидные/невалидные форматы, все 6 зарезервированных значений,
граничные длины 2/3/32/33 символа); `tenant-settings.entity.spec.ts` (дефолтные значения SLA-полей).
Интеграционные тесты не нужны (чистый домен, без I/O). Порог покрытия `domain/` ≥ 90% (Charter §5,
`02` §6.2) применяется ко всему модулю `tenancy/domain`.

## Риски и подводные камни
- `TenantSettings` как value entity, а не отдельный агрегат — сознательное решение вслед за
  `10-domain-model.md` («Tenant содержит TenantSettings»); если в ходе DTJ-059 (валидация
  брендинга) выяснится, что `TenantSettings` нужен собственный жизненный цикл, решение
  пересматривается там, не здесь — не блокирует этот тикет.
- `26-module-tenancy-whitelabel.md` §12 добавляет к `tenant_settings` поля
  (`brandLogoSquareUrl`, `brandFaviconUrl`, `supportPhone`, `supportEmail`,
  `merchantCredentialsStatus`) — они относятся к DTJ-051 (схема) и DTJ-059 (брендинг); здесь
  включён минимальный набор, достаточный для резолвинга/изоляции (заявленная зона ответственности
  тимлида по EP-02), полный набор полей появляется по мере готовности этих тикетов.
