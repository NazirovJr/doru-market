## Задача
Замыкает движок брендинга (DTJ-059) на клиенте: без этого шага `GET /tenant/branding` существует,
но ни один пиксель интерфейса не реагирует на него — White-Label-архитектура осталась бы
демонстрируемой только через Postman. Это прямое условие критерия приёмки R1 №6 (Pivot §3.2):
смена `BRAND_NAME` должна быть видна в реальном UI без пересборки и без деплоя.

## Технический контекст
`apps/web/src/app/bootstrap-branding.ts` — новый файл в `app/`-слое (`02` §5, bootstrap-скрипты
выполняются ДО монтирования React). `index.html` — существующий файл, скаффолженный EP-01
(«Scaffolding `apps/web` (shell, роутер, auth-экран)») — этот тикет вносит ТОЛЬКО одну секцию
`:root { --brand-* }` с нейтрально-серыми дефолтами, не трогает остальную разметку файла (аналог
правила «гостевая правка», `00-EPICS.md`). ESLint-правило запрета хардкода бренда — редактирование
`eslint.config.mjs` остаётся ИСКЛЮЧИТЕЛЬНО за EP-19 (`00-EPICS.md` п.5, корневые конфиги), поэтому
этот тикет готовит формулировку правила и тестовые фикстуры, но не мержит его в корневой конфиг
самостоятельно — см. «Что сделать» п.4 и «Риски».

## Что сделать
1. `index.html`: добавить блок `<style>:root { --brand-primary: #64748b; --brand-primary-hover:
   #475569; --brand-secondary: #94a3b8; --brand-accent: #0ea5e9; --brand-bg: #ffffff; --brand-surface:
   #f8fafc; --brand-text: #0f172a; --brand-text-muted: #64748b; --brand-border: #e2e8f0; --brand-
   success: #16a34a; --brand-danger: #dc2626; --brand-warning: #d97706; --brand-radius: 8px;
   --brand-font-family: system-ui, sans-serif; }</style>` — значения ДОЛЖНЫ побитово совпадать с
   `NEUTRAL_FALLBACK_PALETTE` из `packages/contracts/src/tenancy.ts` (DTJ-057/059) — источник истины
   один, здесь значения переписаны буквально (build-time CSS не может импортировать TS-константу
   напрямую без сборочного шага, поэтому оба места держат идентичные значения и связаны комментарием
   `/* keep in sync with packages/contracts/src/tenancy.ts NEUTRAL_FALLBACK_PALETTE */`).
2. `app/bootstrap-branding.ts`: экспортирует async-функцию `bootstrapBranding(): Promise<void>`,
   вызываемую в точке входа `apps/web` ДО `ReactDOM.createRoot(...).render(...)` (само подключение к
   `main.tsx` — одна строка в файле, владение которым у EP-01/EP-18 в зависимости от того, кто его
   создал; координация аналогична правилу «гостевая правка», не переписывать файл целиком).
   Логика: `fetch('/api/v1/tenant/branding', { headers: { 'If-None-Match': cachedEtag ?? '' } })` →
   при `200` — для каждого ключа объекта `palette` вызывает
   `document.documentElement.style.setProperty(key, value)`, обновляет `document.title` из
   `brandName` (через уже существующий/будущий механизм `useT()`/i18n — на этом шаге достаточно
   прямого присвоения, интеграция с `packages/i18n` — по мере готовности EP-18) и `<link
   rel="icon">` из `faviconUrl`; при `304` — ничего не делает (браузерный кэш уже применил заголовки
   HTTP, но CSS-переменные из предыдущей загрузки уже применены предыдущим вызовом в этой же
   сессии — эффект `304` полезен только для повторных загрузок страницы, не в рамках одной SPA-сессии).
3. Сетевая ошибка/таймаут `fetch` — перехватывается, страница остаётся на нейтрально-серых
   `:root`-дефолтах из `index.html` (graceful degradation — не блокирует рендер приложения).
4. Подготовить (НЕ мержить в `eslint.config.mjs`) формулировку правила для передачи владельцу EP-19:
   `no-restricted-syntax` на строковые литералы, совпадающие с `/DoruTJ|Sifat|Oson/i`, область
   действия — везде КРОМЕ `packages/i18n/**` и `**/*.spec.ts`/`**/*.test.ts`/`db/seed/**` (последнее
   исключение — из-за литерала `'DoruTJ'` в seed-файле DTJ-051). Формулировка — в виде готового
   объекта конфигурации ESLint, оформленного как markdown-фрагмент внутри комментария в
   `bootstrap-branding.ts` (временное место хранения до передачи EP-19) либо как отдельный
   `docs/`-файл координации, если так удобнее интегрировать — на усмотрение исполнителя, главное:
   готовая формулировка, не абстрактное описание.

## Критерии приёмки
1. Given `tenant_settings.brand_palette` заполнена для тенанта X, When первая загрузка `apps/web` на
   домене тенанта X (холодный кэш браузера), Then до ответа `/tenant/branding` видна нейтральная
   серая палитра; после ответа — палитра тенанта X, без перезагрузки страницы (проверяется
   инспекцией `getComputedStyle(document.documentElement).getPropertyValue('--brand-primary')` до и
   после разрешения промиса `bootstrapBranding()`).
2. Given `/tenant/branding` недоступен (симулированный сетевой сбой), When загрузка страницы, Then
   приложение рендерится с нейтральными дефолтами `index.html`, без необработанного исключения в
   консоли.
3. Given значения `NEUTRAL_FALLBACK_PALETTE` в `packages/contracts` и значения `:root` в `index.html`,
   When сравнение построчно (ручная или автоматизированная проверка в тесте), Then они идентичны —
   негативный сценарий: намеренно рассинхронизированное значение должно быть поймано тестом
   `bootstrap-branding.sync.spec.ts` (п.4 тест-плана).
4. Given подготовленная формулировка ESLint-правила, When тестовый файл-фикстура содержит литерал
   `"DoruTJ"` вне разрешённых директорий, Then правило (прогнанное ЛОКАЛЬНО как proof-of-concept,
   например через `eslint --no-eslintrc --config <временный файл>`, не через прод-конфиг) отклоняет
   фикстуру — доказательство корректности формулировки ДО передачи владельцу EP-19.

## Тест-план
Unit (Vitest + jsdom): `bootstrap-branding.spec.ts` (сценарии 1–2, мокированный `fetch`).
`bootstrap-branding.sync.spec.ts` — импортирует `NEUTRAL_FALLBACK_PALETTE` из `packages/contracts` и
парсит `:root`-блок `index.html` (простой regex-парсер CSS custom properties), сравнивает объекты
построчно (сценарий 3). Отдельный, НЕ часть обычного `pnpm test`, скрипт/тест, доказывающий
формулировку ESLint-правила на фикстурах (сценарий 4) — оформить как `eslint-rule-poc.spec.ts` или
эквивалент, с явным комментарием «доказательство для передачи EP-19, не встроено в CI до
координации». Порог `frontend/` ≥ 70%.

## Риски и подводные камни
- Реальное встраивание ESLint-правила и Playwright e2e-теста BRAND_NAME (SRS-TEN-017, критерий
  приёмки R1 №6) требуют доступа к `eslint.config.mjs` и `tests/e2e/**` — ОБА владения EP-19
  («Корневые конфиги... принадлежат только EP-19», `tests/{e2e,load,arch}/**` — EP-19). Этот тикет
  доводит работу до состояния «готово к передаче»: формулировка правила + пример e2e-сценария
  (описание шагов: изменить `BRAND_NAME` демо-тенанта через `PUT /branding`, прогнать полный
  Playwright-набор customer/admin UI, искать строку старого имени в DOM) — фактическая интеграция
  в CI и `tests/e2e/` — ответственность владельца EP-19, зафиксировать как явный передаточный пункт
  при закрытии тикета, не как «сделано, но не работает».
- `app/bootstrap-branding.ts` подключается ОДНОЙ строкой к `main.tsx`/точке входа, владение которой,
  вероятно, у EP-01 (auth-экран scaffolding) — координация по аналогии с правилом «гостевая правка».
