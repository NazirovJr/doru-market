## Задача
Платёжные креды и Telegram-токены тенанта хранятся НЕ как секрет напрямую в БД, а как непрозрачная
ссылка (`merchant_credentials_ref`/`telegram_bot_token_ref`), разрешаемая через порт — это защищает
секреты от утечки через обычный `SELECT`/бэкап БД и даёт путь миграции на реальный Vault в R3 без
изменения кода потребителей (Provider Pattern, Charter §3.3). Без этого порта `PaymentsFacade`
(EP-10) и Telegram-роутер (DTJ-062) не имеют легального способа получить реальные значения.

## Технический контекст
Порт объявляется в `application/ports` модуля `tenancy` (по конвенции `02` §1.3), т.к. владение
конфигурацией секретов тенанта — часть домена tenancy; ПОТРЕБИТЕЛИ порта — другие модули
(`payments`/EP-10, сам `tenancy`/DTJ-062) — импортируют интерфейс порта через `index.ts` барабан
(публичный тип, разрешённый межмодульный импорт), реализацию (`EnvSecretsVaultAdapter`) выбирает DI
самого модуля `tenancy` по ENV `SECRETS_VAULT_DRIVER` (Provider Pattern, дефолт `env`).

## Что сделать
1. `application/ports/secrets-vault.port.ts`: `SecretsVaultPort` — `resolve(ref: string):
   Promise<Record<string, string>>` (возвращает разрешённые пары ключ-значение, например
   `{ merchantId, apiKey }` для платёжных кредов или `{ token }` для Telegram) — бросает
   `SecretResolutionError` (новый класс `domain/errors`, маппится на `503
   PAYMENT_PROVIDER_UNAVAILABLE` или отдельный код на усмотрение потребителя через `cause`) при
   недоступности хранилища.
2. `infrastructure/adapters/env-secrets-vault.adapter.ts`: `EnvSecretsVaultAdapter implements
   SecretsVaultPort` — парсит `ref` формата `vault://tenants/{tenantId}/merchant-credentials` или
   `vault://tenants/{tenantId}/telegram-bot-token`, ищет ENV-переменные с префиксом
   `TENANT_SECRET_{tenantId}_*` (например `TENANT_SECRET_<uuid>_MERCHANT_ID`,
   `TENANT_SECRET_<uuid>_API_KEY`) — работает ТОЛЬКО в `NODE_ENV !== 'production'` (dev/CI), при
   попытке использования в проде — адаптер бросает ошибку конфигурации при старте приложения
   (`FailFastError`, чтобы прод никогда не полагался на ENV-секреты — жёсткое ограничение
   SRS-TEN-022).
3. Значение `ref`, не соответствующее формату `vault://tenants/{uuid}/{key}`, → `ValidationError`
   немедленно, без попытки резолвинга.
4. Явный unit-тест, доказывающий, что НИ ОДИН метод адаптера не вызывает `console.log`/`pino`-лог с
   разрешённым значением секрета целиком (проверка через spy на логгер — секрет никогда не попадает
   в аргумент лога этого адаптера, редактирование на уровне общего логгера — вне этого тикета, но
   локальная дисциплина адаптера проверяется здесь).

## Критерии приёмки
1. Given `NODE_ENV=development`, `TENANT_SECRET_<id>_MERCHANT_ID=m1`,
   `TENANT_SECRET_<id>_API_KEY=k1` в ENV, When `resolve('vault://tenants/<id>/merchant-credentials')`,
   Then возвращается `{ merchantId: 'm1', apiKey: 'k1' }`.
2. Given ENV-переменные для данного `tenantId` отсутствуют, When `resolve(...)`, Then
   `SecretResolutionError` (не `undefined`-значения молча).
3. Given `NODE_ENV=production`, When создание `EnvSecretsVaultAdapter` (конструктор/фабрика при
   старте DI), Then приложение падает со стартовой ошибкой конфигурации — негативный сценарий,
   защита от случайного прод-деплоя на dev-адаптере.
4. Given `ref = 'not-a-valid-ref'`, When `resolve(ref)`, Then `ValidationError` немедленно, без
   попытки чтения ENV.

## Тест-план
Unit (Vitest, мокированный `process.env`): `env-secrets-vault.adapter.spec.ts` — все 4 сценария +
кейс частично заполненных переменных (например, есть `MERCHANT_ID`, нет `API_KEY` — результат:
ошибка резолвинга, не частичный объект). `secrets-vault.port.spec.ts` не требуется отдельно (порт —
чистый интерфейс). Порог `infrastructure/` ≥ 70%.

## Риски и подводные камни
- Глобальное правило редакции логов (`*.apiKey`/`*.merchantCredentials` в `redact`-списке pino,
  SRS-API-068) — общая конфигурация логгера, вероятно владение EP-01; этот тикет добавляет ЛОКАЛЬНУЮ
  дисциплину (адаптер сам не логирует секрет), но не может гарантировать глобальную редакцию, если
  какой-то ДРУГОЙ модуль (например, `payments`, EP-10) залогирует результат `resolve()` целиком по
  ошибке — рекомендация в риске: заводить отдельный запрос владельцу общей конфигурации логирования
  на добавление паттернов `*.apiKey`/`*.merchantCredentials`/`*.token` в глобальный `redact`-список,
  не блокирует этот тикет.
- `HashiCorpVaultAdapter` (R3) не реализуется здесь (вне зоны R1) — только порт, совместимый с
  будущей заменой без изменения потребителей (принцип Provider Pattern).
