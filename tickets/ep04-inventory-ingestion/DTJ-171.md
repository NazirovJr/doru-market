## Задача

Сетка массового редактирования (DTJ-168, SRS-INV-015 (б) — «таблица остатков своей аптеки») сейчас
умеет только добавлять строки в рамках сессии: в бэкенде нет ни одного эндпоинта, отдающего текущий
ассортимент аптеки. Без него фармацевт не видит, что у аптеки уже лежит и по какой цене, и массовое
редактирование реального ассортимента невозможно (R1-9 «кабинет аптеки: свои остатки и цены»).
Найдено при приёмке DTJ-168 (2026-09-24).

## Технический контекст

Источник — `pharmacy_inventory` (денормализованная FEFO-проекция: цена, остаток, партия и срок
выбранной партии, `last_synced_at`). `inventory_batches` не раскрывается — сетке нужна одна строка
на пару аптека×лекарство. `DTJ-362` — другая вещь: агрегированная сводка для `pharmacy_admin`, не
построчный список.

Скоуп по роли — тот же паттерн, что `DTJ-163` (`GET /inventory-sync-batches`): аптека берётся из
токена, чужой `pharmacyId` из запроса не расширяет доступ.

Деньги наружу — целые дирамы (`priceDiram`, как `SearchResultItemDto`), в БД цена уже хранится целыми дирамами (`pharmacy_inventory.price INTEGER`; `11-database-schema.md` описывает `price_tjs
NUMERIC(10,2)`, код разошёлся со спекой) — конвертация не нужна. Сетка
DTJ-168 редактирует цену в TJS (`ManualEntryRow.priceTjs`) — перевод дирамы↔TJS на клиенте.

## Что сделать

1. `packages/contracts/src/inventory/pharmacy-inventory-list.schema.ts`:
   `PharmacyInventoryListQuerySchema` (`cursor`, `limit` 1..100 по умолчанию 50, `filter[q]` —
   необязательный поиск по торговому названию) и `PharmacyInventoryItemDto`: `inventoryId`,
   `medicineId`, `tradeName`, `dosageForm`, `dosageStrength`, `priceDiram`, `stockQuantity`,
   `batchNumber | null`, `expiryDate` (`YYYY-MM-DD`), `lastSyncedAt` (ISO-8601). Экспорт — строкой
   в barrel `packages/contracts/src/inventory/index.ts`.
2. `PharmacyInventoryRepositoryPort.listByPharmacy({ pharmacyId, q, cursor, limit })` → страница
   строк + `nextCursor`. Keyset-пагинация по `(trade_name, id)`, сортировка по торговому названию
   по возрастанию (SRS-API-004); JOIN с `medicines` только ради названия, формы и дозировки.
3. `ListPharmacyInventoryUseCase` — принимает `pharmacyId` уже из токена, ничего не решает о правах.
4. `InventoryListController`: `GET /api/v1/inventory`, `@Roles('pharmacist', 'pharmacy_admin')`,
   `pharmacyId` — как в `InventoryManualEntryController` (`requirePharmacyId(claims)`; нет
   `pharmacyId` в токене → `400 VALIDATION_ERROR`, тот же код, что ручной ввод). Ответ — конверт
   `data` + `meta.pagination` (SRS-API-004). Зарегистрировать в `InventoryModule.controllers`.
5. `apps/pharmacy`: `use-bulk-grid.ts` читает список `useInfiniteQuery` под существующим ключом
   `INVENTORY_LIST_QUERY_KEY` (`shared/api/inventory-query-keys.ts`), строки из сервера приходят
   в сетку как нередактированные (`isDirty=false`); сохранение по-прежнему шлёт только изменённые.

## Критерии приёмки

1. **Given** аптека с 120 позициями в `pharmacy_inventory`, **When** `pharmacist` этой аптеки
   делает `GET /inventory?limit=50` и дважды идёт по `nextCursor`, **Then** получены 50 + 50 + 20
   строк по алфавиту торгового названия, без дублей и пропусков, на последней `hasMore=false`.
2. **Given** в БД есть остатки двух аптек, **When** `pharmacist` аптеки А делает запрос (в том числе
   с `pharmacyId` аптеки Б в query), **Then** в ответе только строки аптеки А.
3. **Given** `customer` или аноним, **When** `GET /inventory`, **Then** `403 INSUFFICIENT_ROLE` /
   `401 UNAUTHENTICATED`.
4. **Given** `limit=101` или курсор с полем `v` не того типа, **When** запрос, **Then** `400
   VALIDATION_ERROR` (SRS-API-004/005), а не обрезание и не 500.
5. **Given** цена `125.50 TJS` (в БД `12550`), **When** строка отдана API, **Then** `priceDiram = 12550`
   (целое число).
6. **Given** фармацевт открыл вкладку «Массовое редактирование», **When** список загружен и он
   поменял цену у 2 строк, **Then** `POST /inventory-manual-entry` уходит ровно с 2 строками.

## Тест-план

- Unit: use case (передача параметров, пустая страница), маппер цены (целые дирамы без изменения, граничные
  значения `1` и максимальная цена), разбор/сборка курсора.
- Интеграционный (реальный Postgres, не фейковый репозиторий — урок волны 4): критерии 1–5.
- Фронт: `use-bulk-grid` — загрузка страниц, склейка с локально добавленными строками, отправка
  только изменённых (критерий 6).

## Риски и подводные камни

- Keyset по `trade_name` неуникален — обязательно второй ключ `id`, иначе при одинаковых названиях
  страницы теряют строки.
- `pharmacy_admin` с несколькими аптеками: в R1 работает в скоупе `pharmacyId` из токена, как
  ручной ввод; выбор аптеки сети в UI — вне тикета.
- Не отдавать строки с `stock_quantity = 0` отдельно не требуется: сетка должна позволять поднять
  нулевой остаток, поэтому они в списке.
