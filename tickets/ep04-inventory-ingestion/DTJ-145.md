## Задача

`IngestInventoryBatchCommand.rows` (`22-module-inventory-sync-1c.md` §3, SRS-INV-010) — дискриминированное
объединение `resolved: true | false`, общее для ВСЕХ четырёх каналов. Без единого VO с валидацией на
границе (не примитивный тип `{ resolved, ... }` россыпью) каждый маппер канала (REST/Excel/ручной
ввод) будет заново решать, что такое валидная строка — прямое нарушение C15 (дублирование на втором
же потребителе) и `02` §2 п.3 (Value Objects обязательны, примитивы в домене — запах).

## Технический контекст

Форма команды — буквально `22-module-inventory-sync-1c.md` строки 234-238. Domain-ошибки этого
модуля переиспользуют иерархию `DomainError` из `10-domain-model.md` (базовый класс — владение
EP-01), не создают параллельную иерархию.

## Что сделать

1. `inventory-batch-upsert-row.vo.ts`: тип `InventoryBatchUpsertRow` (readonly discriminated union,
   дословно по SRS-INV-010: `resolved: true` ветка — `medicineId: MedicineId; priceDiram: Money;
   quantity: number; expiryDate: ExpiryDate; batchNumber?: string; op: 'upsert' | 'delete'`,
   `resolved: false` ветка — `rawBarcode?: string; internalSku: string; tradeName: string;
   dosageForm?: string; dosageStrength?: string; manufacturerName?: string; priceDiram: Money;
   quantity: number; expiryDate: ExpiryDate; batchNumber?: string; op: 'upsert' | 'delete'`).
2. Фабричные функции `InventoryBatchUpsertRow.resolved({...}): InventoryBatchUpsertRow` и
   `InventoryBatchUpsertRow.unresolved({...}): InventoryBatchUpsertRow` — валидируют на конструкции
   (`quantity >= 0` иначе `InvalidQuantityError`, `priceDiram` через `Money`-VO уже валиден на входе
   конструктора `Money`, `internalSku`/`tradeName` непустые для unresolved-ветки иначе
   `MissingRequiredFieldError('internalSku' | 'tradeName')`).
3. `batchNumber` — если не передан, применяется `AUTO-{internalSku}` ТОЛЬКО для unresolved-ветки
   (SRS-INV-006 — генерация синтетического номера партии); для resolved-ветки (ручной ввод) поле
   остаётся `undefined`, если не передано явно (ручной ввод обычно работает с уже известной партией
   через `medicineId`, генерация `AUTO-{internalSku}` не применима, т.к. `internalSku` в этой ветке
   отсутствует — вызывающий код (use case) обязан подставить осмысленный `batchNumber` иначе для
   resolved-строк).
4. `errors/inventory.errors.ts`: классы, наследующие `DomainError` (EP-01) —
   `InvalidPriceError(priceDiram)`, `InvalidQuantityError(quantity)`,
   `InvalidRestockQuantityError(quantity)`, `MissingRequiredFieldError(field: string)`,
   `IllegalBatchStatusTransitionError(from: string, to: string)`, `InsufficientStockError(
   pharmacyId, medicineId, requested, available)`. Каждый класс — короткий, с `readonly code:
   string` для маппинга в HTTP presentation-слоем (`02` §2 п.5 — маппинг доменная ошибка → HTTP
   происходит в presentation, не здесь).
5. Если файл `inventory.errors.ts` уже частично создан тикетом DTJ-143/DTJ-144 (параллельная
   разработка) — дополнять, не переписывать (использовать `replace_symbol_body`/точечный `Edit`).

## Критерии приёмки

1. **Given** валидные поля unresolved-строки без `batchNumber`, **When**
   `InventoryBatchUpsertRow.unresolved({ internalSku: 'SKU-1', ... })`, **Then** результат имеет
   `batchNumber === 'AUTO-SKU-1'`.
2. **Given** `quantity = -1`, **When** `InventoryBatchUpsertRow.resolved({ quantity: -1, ... })`,
   **Then** бросается `InvalidQuantityError` — негативный сценарий.
3. **Given** unresolved-строка с пустым `tradeName: ''`, **When** конструируется VO, **Then**
   бросается `MissingRequiredFieldError('tradeName')` — второй негативный сценарий.
4. **Given** валидная resolved-строка с явным `batchNumber`, **When** конструируется VO, **Then**
   `AUTO-`-генерация НЕ применяется, переданное значение сохраняется как есть.

## Тест-план

Unit (`inventory-batch-upsert-row.vo.spec.ts`):
- `resolved() создаёт валидный VO с ветвью resolved:true`
- `unresolved() создаёт валидный VO с ветвью resolved:false`
- `unresolved() генерирует batchNumber=AUTO-{internalSku} при отсутствии явного значения`
- `resolved() НЕ применяет AUTO-генерацию`
- `отрицательное quantity бросает InvalidQuantityError`
- `пустой internalSku бросает MissingRequiredFieldError`
- `пустой tradeName бросает MissingRequiredFieldError`
Отдельный unit-файл для каждого класса ошибки не требуется — достаточно проверить, что каждый класс
инстанциируется с ожидаемым `.code`/`.message` в рамках теста VO выше или отдельного
`inventory.errors.spec.ts`, если ошибок нет ни в одном сценарии VO (например,
`IllegalBatchStatusTransitionError`/`InsufficientStockError` тестируются в DTJ-144/DTJ-143
соответственно — здесь достаточно smoke-теста конструктора). Порог покрытия `domain/` — 90%.
