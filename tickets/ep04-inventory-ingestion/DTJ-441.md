## Задача

Канал Excel (D-12) вживую не работает, найдено E2E DTJ-418 (2026-09-28):
1. `inventory-excel-import.controller.ts` ставит батчи в очередь `inventory-sync-queue`
   (`inventory.sync_batch.queued`), но НИ ОДИН процессор её не читает — батчи навсегда `queued`,
   остатки не обновляются, поиск их не видит. Пробел записан в JSDoc контроллера, тикета не было.
2. `requirePharmacyId` берёт аптеку из пользователя; у `pharmacy_admin` сети `pharmacyId=null`,
   поэтому любой его импорт — 400 «acting user has no associated pharmacy».

## Что сделать

1. Процессор очереди в apps/worker по образцу соседних джоб: вызывает существующий use case обработки
   батча (тот же, что REST-канал 1С выполняет синхронно) — второй реализации логики не писать.
   Статусы `completed` / `completed_partial_success` / `failed` со счётчиками и ошибками по строкам,
   событие завершения для инвалидации кэша поиска (SRS-CAT-059).
2. Импорт от `pharmacy_admin`: аптека выбирается явно (параметр запроса) и проверяется
   на принадлежность его сети; pharmacist — по-прежнему своя аптека. UI apps/pharmacy — выбор аптеки
   сети перед загрузкой файла.

## Критерии приёмки

1. Given валидный Excel от pharmacy_admin сети excel с выбранной аптекой `excelCenter`, When worker
   обработал батч, Then статус `completed`, позиция находится в `GET /medicines/search`.
2. Given файл с неоднозначной датой в одной строке, Then `completed_partial_success`, ошибка с номером строки,
   остальные строки приняты.
3. Given аптека чужой сети, Then 403.
4. Спеки CUJ-6' DTJ-418 «valid import» и «partial success» зелёные вживую на E2E-стенде.
