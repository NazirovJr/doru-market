## Задача

Аптека без автоматизации (R1-5, ключевой сценарий пивота «работает с аптеками без автоматизации»)
должна получить готовый файл с фиксированными колонками, а не гадать формат самостоятельно.
Валидация Excel-парсера (DTJ-160) идёт ПО ЗАГОЛОВКУ колонки, не по позиции — этот шаблон и есть
источник истины заголовков, обязан быть идентичен ожиданиям парсера побайтово по названиям.

## Технический контекст

Колонки — дословно таблица `22-module-inventory-sync-1c.md` строки 258-269 (SRS-INV-012): 10
колонок, 4 обязательные (`Внутренний код (SKU)`, `Торговое название`, `Цена (TJS)`, `Остаток
(шт.)`, `Срок годности`), формат даты строго `ДД.ММ.ГГГГ`.

## Что сделать

1. Новая зависимость `exceljs` (генерация `.xlsx` с заголовками и форматированием ячеек) — не
   входит в `01-TECH-BASELINE.md`, требует однострочного обоснования в PR по правилу
   `01-TECH-BASELINE.md` §«Правила» п.3 (`exceljs` — стандартный выбор для генерации/парсинга `.xlsx`
   в Node.js экосистеме, активно поддерживается, тот же пакет использовать и в DTJ-160, чтобы не
   плодить два XLSX-парсера/генератора в одном модуле).
2. `inventory-import-template.controller.ts`: `@Get('/api/v1/inventory-import-template')`,
   `@UseGuards(RolesGuard)` `@Roles('pharmacy_admin', 'super_admin')` (та же RBAC-граница, что и
   ручной ввод/Excel-импорт — permission `inventory:ingest`, `12-api-conventions-auth-tenancy.md`
   §4, см. риски по `pharmacist` в DTJ-162), `@TenantScopeGuard` (EP-02).
3. Генерация `.xlsx` в памяти (`exceljs.Workbook`, один лист `Остатки`): строка заголовков ровно в
   порядке §2, форматирование ячеек колонки `Срок годности` как ТЕКСТ (не Excel date-тип — чтобы
   пользователь не мог случайно получить локализованный формат `MM/DD/YYYY` при вводе, что сразу
   давало бы `ambiguous_date_format`, SRS-INV-013), ширина колонок по содержимому заголовка.
4. Опционально — одна строка примера данных серым цветом ниже заголовков (UX-подсказка формата,
   не обязательное требование SRS, но дешёвое улучшение — если добавляется, ПОМЕТИТЬ явно как
   пример, не как реальные данные, чтобы не была случайно загружена обратно).
5. Ответ: `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
   `Content-Disposition: attachment; filename="doru-tj-inventory-template.xlsx"`.
6. Также сгенерировать `.csv`-вариант по query-параметру `?format=csv` (SRS-INV-012 упоминает оба
   формата `.xlsx`/`.csv` как допустимые для импорта — шаблон должен предлагать оба).

## Критерии приёмки

1. **Given** `pharmacy_admin` авторизован, **When** `GET /inventory-import-template`, **Then** `200`
   с валидным `.xlsx`-файлом, первая строка листа содержит РОВНО 10 заголовков в порядке SRS-INV-012.
2. **Given** тот же запрос с `?format=csv`, **When** выполняется, **Then** `200` с
   `Content-Type: text/csv`, те же заголовки через запятую (CSV — UTF-8 с BOM, чтобы Excel на
   Windows корректно открывал кириллицу).
3. **Given** неавторизованный запрос (роль `customer`/`courier`), **When** `GET
   /inventory-import-template`, **Then** `403 INSUFFICIENT_ROLE` — негативный сценарий.
4. **Given** сгенерированный `.xlsx`, **When** колонка `Срок годности` открывается в Excel/парсится
   `exceljs` обратно, **Then** тип ячейки — текстовый, не date-тип (проверяется чтением сгенерированного
   файла тем же `exceljs` в тесте и сверкой `cell.type`).

## Тест-план

Unit/интеграционный (`inventory-import-template.controller.spec.ts`):
- `xlsx-шаблон содержит 10 заголовков в правильном порядке`
- `csv-шаблон содержит те же заголовки через запятую, с BOM`
- `неавторизованная роль получает 403`
- `колонка Срок годности форматирована как текст, не date`
- `сгенерированный файл открывается тем же exceljs без ошибок парсинга` (round-trip проверка)

  пользуются оба тикета — реализовать этот файл ЗДЕСЬ первым (этот тикет не зависит от DTJ-160, а

  то же решение для консистентности.
