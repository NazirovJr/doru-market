## Задача

Каждый батч синхронизации проходит через фиксированный набор статусов (`queued → processing →
{completed_full_success | completed_partial_success | failed_validation}`), и переход в любой
терминальный статус необратим. `02-CLEAN-ARCHITECTURE-AND-CODE.md` §2 п.4 требует явную state
machine в домене вместо `if (status === ...)`, разбросанного по use case'ам трёх каналов и воркеру.
Этот агрегат — единственное место, которое решает, допустим ли переход.

## Технический контекст

Таблица переходов — `10-domain-model.md` строки 922-930 (SRS-DOM-145..150), запрещённые переходы —
там же (SRS-DOM-150): любой `completed_*`/`failed_validation → *` терминален, `queued →
completed_*` напрямую запрещён (обязателен проход через `processing`). Идемпотентность повторной
отправки того же `batch_id` — SRS-DOM-168/SRS-INV-009: агрегат сам не отвечает за поиск дубликата
(это на уровне репозитория — `UNIQUE(id)` + `ON CONFLICT DO NOTHING RETURNING *`), но обязан
экспортировать текущее состояние для возврата клиенту без повторного исполнения бизнес-логики.

## Что сделать

1. `inventory-sync-batch.entity.ts`: класс `InventorySyncBatch`, приватный конструктор, фабрика
   `InventorySyncBatch.create({ id, pharmacyId, channel, syncType, syncTimestamp, totalRows,
   fullSyncSessionId?, pageNumber, isLastPage }): InventorySyncBatch` — начальный статус `'queued'`.
   `InventorySyncBatch.restore(snapshot)` — без повторной валидации.
2. Приватная константа `ALLOWED_TRANSITIONS: Record<BatchStatus, readonly BatchStatus[]>` —
   буквальная таблица переходов SRS-DOM-145..150 (`queued → [processing]`, `processing →
   [completed_full_success, completed_partial_success, failed_validation]`, три терминальных →
   `[]`).
3. Метод `transitionTo(next: BatchStatus): void` — проверяет `ALLOWED_TRANSITIONS`, бросает
   `IllegalBatchStatusTransitionError(from, to)` при недопустимом переходе; не принимает произвольный
   статус без валидации (никаких публичных сеттеров на `status`).
4. Метод `markProcessing(): void`, `markCompletedFullSuccess(): void`,
   `markCompletedPartialSuccess(acceptedRows: number, rejectedRows: number): void`,
   `markFailedValidation(): void` — тонкие обёртки над `transitionTo` с доменной семантикой имени
   (методы-намерения, C18 «функция делает то, что обещает имя»), обновляют `completedAt` через
   параметр `Clock` (не `Date.now()` внутри домена, `02` §2 п.6).
5. Геттеры `isTerminal(): boolean`, `channel: InventorySyncChannel`, `syncType: 'full' | 'delta'`.
6. `get isFullSyncLastPage(): boolean` — `this.syncType === 'full' && this.isLastPage` (используется
   DTJ-151 как триггер шага «обнуление отсутствующих позиций», SRS-INV-041).

## Критерии приёмки

1. **Given** свежесозданный агрегат (статус `queued`), **When** `markProcessing()`, **Then** статус
   `processing`, `transitionTo` не бросает исключения.
2. **Given** статус `processing`, **When** `markCompletedPartialSuccess(988, 12)`, **Then** статус
   `completed_partial_success`, `acceptedRows=988`, `rejectedRows=12`, `completedAt` установлен.
3. **Given** статус `completed_full_success` (терминальный), **When** вызывается ЛЮБОЙ метод
   перехода (`markProcessing()`), **Then** бросается `IllegalBatchStatusTransitionError` — негативный
   сценарий, точное соответствие SRS-DOM-150.
4. **Given** статус `queued`, **When** вызывается `markCompletedFullSuccess()` напрямую (минуя
   `processing`), **Then** бросается `IllegalBatchStatusTransitionError` — второй негативный сценарий
   («queued → completed_* напрямую» явно запрещён SRS-DOM-150).

## Тест-план

Unit (`inventory-sync-batch.entity.spec.ts`, без БД):
- `create() инициализирует статус queued`
- `markProcessing переводит из queued в processing`
- `markCompletedFullSuccess переводит из processing в терминальный статус`
- `markCompletedPartialSuccess сохраняет acceptedRows/rejectedRows`
- `markFailedValidation переводит из processing в failed_validation`
- `любой переход из терминального статуса бросает IllegalBatchStatusTransitionError` (параметризованный
  тест по всем трём терминальным статусам × всем методам перехода)
- `queued -> completed_* напрямую запрещён`
- `isFullSyncLastPage истинен только для syncType=full И isLastPage=true`
- `isFullSyncLastPage ложен для delta даже при isLastPage=true`
Порог покрытия `domain/` — 90%. Интеграционные/E2E — не требуются для этого тикета (чистая state
machine).
