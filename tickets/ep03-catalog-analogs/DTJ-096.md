## Задача

`orders` (D-06/SRS-DOM-107: снимок названия/дозировки на момент заказа) и `orders/cart`
(SRS-CAT-051: предупреждение о дубле действующего вещества) не имеют права импортировать
`modules/catalog/domain|application/*` напрямую (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.2) — им
нужен ТОЛЬКО публичный фасад. Этот тикет заменяет заглушку из DTJ-090 (`index.ts`) на реальную
реализацию трёх методов фасада, которые не требуют композитного матчинга (тот — отдельно, DTJ-097).

## Технический контекст

`modules/catalog/index.ts` экспортирует ИСКЛЮЧИТЕЛЬНО интерфейс `CatalogFacade` + публичные типы
(`MedicineSnapshot`, `SubstanceRef`) + доменные события — ничего из `domain/*`/`application/*`
(кроме use case'ов, вызываемых presentation этого же модуля) наружу не течёт (SRS-CAT-064,
`10-domain-model.md` SRS-DOM-001). `resolveMedicineByComposite`
(4-й метод интерфейса `CatalogFacade` из SRS-CAT-064) реализуется отдельным тикетом DTJ-097 — этот
тикет объявляет метод в интерфейсе как заглушку (`Promise<never>`/`throw new
NotImplementedYetError()`), чтобы интерфейс компилировался целиком уже сейчас для потребителей
(inventory, EP-05), но НЕ пытается реализовать сам матчинг.

## Что сделать

1. `application/use-cases/publish-medicine.use-case.ts` — `PublishMedicineUseCase.execute({
   medicineId, actor })`: загружает `Medicine` через `CatalogRepository`, вызывает
   `medicine.publish()` (DTJ-093), при успехе — `CatalogRepository.save()` + запись
   `MedicinePublishedEvent` в `outbox` в ТОЙ ЖЕ транзакции (`unitOfWork.run(...)`, `02` §3.3); при
   ошибке (`MissingSubstancesError`) — пробрасывает наружу без изменений.
2. `application/use-cases/propose-control-category.use-case.ts` —
   `ProposeControlCategoryUseCase.execute({ medicineId, category, actor })`: аналогично, вызывает
   `medicine.proposeControlCategory()`, кладёт `NewControlCategoryCandidateEvent` в outbox (поле
   `controlCategory` самой записи БД НЕ меняется этим use case — SRS-DOM-014, изменение происходит
   отдельным модерационным процессом вне зоны этого эпика).
3. `modules/catalog/index.ts` — реализация фасада:
   ```typescript
   export interface CatalogFacade {
     getMedicineSnapshot(ids: readonly string[]): Promise<Map<string, MedicineSnapshot>>;
     getSubstances(ids: readonly string[]): Promise<Map<string, SubstanceRef[]>>;
     resolveMedicineByComposite(input: CompositeMatchInput): Promise<MedicineMatchResult>; // DTJ-097
     isVisible(medicineId: string): Promise<boolean>;
   }
   ```
   - `getMedicineSnapshot`: батч-запрос `CatalogRepository.findMedicinesByIds(ids)`, маппинг в
     `MedicineSnapshot { medicineId, tradeName, dosageForm, dosageStrength,
     isPrescriptionRequired, controlCategory }` (цена НЕ включается — принадлежит `inventory`,
     SRS-DOM-107 явно: «цена/название на момент заказа не хранится в catalog» относится к цене,
     название/дозировка/Rx-флаг фиксируются здесь).
   - `getSubstances`: `CatalogRepository.findSubstancesByMedicineIds(ids)` — прямой проброс без
     трансформации (уже нужная форма `Map<medicineId, SubstanceRef[]>`, используется `orders/cart`
     для SRS-CAT-051 частичного пересечения — ЧАСТИЧНОЕ пересечение вычисляет ВЫЗЫВАЮЩИЙ модуль
     `orders`, не `catalog` — этот метод только отдаёт данные, не сравнивает).
   - `isVisible`: `CatalogRepository.findMedicineById(id)` → `record !== null && record.isPublished
     && !['psychotropic','narcotic'].includes(record.controlCategory)` (SRS-CAT-064 «для
     moderation-отчётности» — переиспользует ТОЧНО ТЕ ЖЕ условия видимости, что DTJ-095, вынесенные в
     общую приватную функцию `isPubliclyVisible(record)` внутри модуля, чтобы не дублировать правило
     в двух местах, C15).
4. Экспортировать `MedicinePublishedEvent`/`NewControlCategoryCandidateEvent` из `index.ts` рядом с
   интерфейсом (SRS-CAT-064, комментарий в исходном контракте).

## Критерии приёмки

- Given `ids = ['a','b']`, где `a` существует, `b` — нет, When
  `catalogFacade.getMedicineSnapshot(['a','b'])`, Then возвращается `Map` с ОДНИМ ключом `'a'`
  (несуществующие `id` молча пропускаются, не бросают ошибку — снапшот для orders не обязан знать
  про existence-проверку, это ответственность `orders`, вызывающего с уже валидными `id` из корзины).
- Given `medicineId` опубликован, `controlCategory='none'`, When `catalogFacade.isVisible(id)`, Then
  `true`; given `controlCategory='narcotic'`, Then `false` (даже при `isPublished=true`).
- Given `PublishMedicineUseCase.execute()` успешен, When читается таблица `outbox` в той же
  транзакции, Then строка с `event_type='MedicinePublishedEvent'` присутствует (интеграционный тест —
  атомарность записи домена + события).
