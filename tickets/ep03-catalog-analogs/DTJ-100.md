## Задача

`AnalogEquivalenceService.isAnalog()` (DTJ-099) — O(1) на пару, но полный каталог может достигать
нескольких тысяч позиций (D-13) — сравнивать референсный препарат С КАЖДЫМ было бы O(N) на запрос
карточки товара, нарушая бюджет `p95 < 300мс` (SRS-CAT-061). Этот тикет — быстрая, приближённая SQL-
выборка топ-50 кандидатов ПО ТЕМ ЖЕ (catalog-owned) таблицам, сужающая работу домена до
управляемого множества.

## Технический контекст

Запрос — расширение запроса 3 из `11-database-schema.md`, но БЕЗ join'а на `pharmacy_inventory`/
`pharmacies` (та часть оригинального запроса документа — иллюстративная, объединяющая фильтрацию и
получение цены в одном SQL для простоты примера; в реальной архитектуре это ДВЕ разные ответственности
— наличие/цена принадлежит `inventory`, получается отдельно в DTJ-101 через
`AnalogOfferLookupPort`). Здесь — ТОЛЬКО `medicines`/`medicine_substances`, обе таблицы физически
принадлежат `catalog` — прямой SQL внутри своего модуля разрешён без каких-либо исключений
(`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.1 запрещает только МЕЖМОДУЛЬНЫЕ прямые джойны). Расхождение
SQL-предфильтра и domain-правила (SRS-CAT-043) — сознательное разделение «быстрая грубая выборка» /
«точное решение в DTJ-099», не дефект.

## Что сделать

1. `application/ports/analog-candidates.port.ts`:
   ```typescript
   export const ANALOG_CANDIDATES_REPOSITORY = Symbol('ANALOG_CANDIDATES_REPOSITORY');
   export interface AnalogCandidatesRepository {
     findCandidates(referenceMedicineId: string, limit: number): Promise<readonly string[]>; // medicineId[]
   }
   ```
2. `infrastructure/adapters/analog-candidates.adapter.ts` — Drizzle/raw SQL реализация:
   ```sql
   WITH target_substances AS (
       SELECT substance_id FROM medicine_substances WHERE medicine_id = :referenceMedicineId
   ), target_form AS (
       SELECT dosage_form_class FROM medicines WHERE id = :referenceMedicineId
   )
   SELECT m.id
   FROM medicines m
   WHERE m.id != :referenceMedicineId
     AND m.is_published = true
     AND m.control_category NOT IN ('psychotropic', 'narcotic')  -- SRS-DOM-157
     AND m.dosage_form_class = (SELECT dosage_form_class FROM target_form)
     AND (SELECT array_agg(ms2.substance_id ORDER BY ms2.substance_id)
          FROM medicine_substances ms2 WHERE ms2.medicine_id = m.id)
         = (SELECT array_agg(ts.substance_id ORDER BY ts.substance_id) FROM target_substances)
   LIMIT :limit;
   ```
   Возвращает ТОЛЬКО `medicineId[]` (не полные записи — DTJ-101 подгружает полные `Medicine`-агрегаты
   через `CatalogRepository.findMedicinesByIds()`, DTJ-092, избегая дублирования пути загрузки).
3. `LIMIT` передаётся параметром (не захардкожен), дефолт `ANALOG_CANDIDATES_LIMIT = 50` (именованная
   константа, C6, SRS-CAT-061 «O(50), не O(N)») — объявляется вызывающим (DTJ-101), не этим файлом.
4. Given `referenceMedicineId` не имеет ни одного вещества (`target_substances` пуст — некорректные
   данные/черновик), Then запрос возвращает ПУСТОЙ результат (array_agg NULL никогда не равен
   array_agg NULL по SQL-семантике `=` с NULL → не совпадёт ни с чем, что и есть желаемое поведение
   — не нужен отдельный явный `WHERE target_substances IS NOT NULL`, но добавить unit/интеграционный
   тест, фиксирующий это как осознанное поведение, не случайность).

## Критерии приёмки

- Given референсный препарат `{парацетамол 500мг, tablet}` и кандидат с ИДЕНТИЧНЫМ множеством
  веществ+формой, When `findCandidates(refId, 50)`, Then кандидат присутствует в результате.
- Given кандидат с ЧАСТИЧНЫМ пересечением веществ (`{парацетамол 500мг}` vs `{парацетамол 500мг,
  кофеин 50мг}`), When `findCandidates`, Then кандидат ОТСУТСТВУЕТ (SQL array-equality отсеивает по
  кардинальности множества — TC-CAT-030, первый рубеж защиты ДО применения `AnalogEquivalenceService`
  в памяти).
- Given >50 кандидатов теоретически подходят по множеству веществ+форме, When `findCandidates(refId,
  50)`, Then возвращается РОВНО ≤50 (`LIMIT` соблюдён).
- Given референсный препарат — черновик (`is_published=false`), When `findCandidates` вызывается ДЛЯ
  ДРУГОГО опубликованного референса, Then черновик НЕ появляется среди кандидатов (`is_published=true`
  фильтр).

## Тест-план

Интеграционные тесты (vitest + testcontainers, реальная БД с фикстурами):
- `analog-candidates.adapter.integration.spec.ts`: точное совпадение множества → кандидат найден;
  частичное пересечение → кандидат НЕ найден (TC-CAT-030); разная форма при одинаковом веществе →
  не найден; `psychotropic`/`narcotic`-кандидат → не найден, даже при совпадении множества/формы
  (defense-in-depth, SRS-CAT-055); `LIMIT` соблюдён на фикстуре с 60+ кандидатами.

Unit — не применимо (адаптер — тонкая обёртка над SQL, вся логика — в самом запросе, проверяемом
только интеграционно).

  либо материализованная колонка "substance set hash", либо переход на `EXISTS`-переформулировку —
