## Задача

D-13 фиксирует критерий приёмки R1: seed ≥300 курированных позиций с корректными связями МНН и
веществами — заменяет нереалистичное «8000+ позиций за Спринт 2». Без этого seed'а ни один
последующий эпик (поиск EP-06, аналоги EP-07, корзина EP-09, E2E CUJ-1/2') не может быть
продемонстрирован на реалистичных данных, а движок аналогов буквально не с чем сравнивать — набор
обязан содержать НЕСКОЛЬКО препаратов с идентичным множеством веществ+формой+дозировкой (реальные
аналоговые группы), иначе `FindAnalogsUseCase` (DTJ-099-101) нечем тестировать вручную/на демо.

## Технический контекст

Данные читаются из `db/seed/medicines/*.json` (курируемые вручную/полусобранные из открытого реестра
лекарств РТ/СНГ — источник вне охвата тикета, разработчик волен использовать любой легальный
открытый справочник МНН, главное — корректность связей, не происхождение данных) и загружаются
скриптом `apps/api/src/db/seed/seed-catalog.ts`, идемпотентным (`INSERT ... ON CONFLICT DO NOTHING`
по `trade_name+dosage_strength+manufacturer_name` — уникального constraint на эту тройку в схеме НЕТ,
идемпотентность реализуется на уровне скрипта явной проверкой перед вставкой, не полагаясь на БД).

## Что сделать

1. `db/seed/medicines/categories.seed.json` — дерево категорий (≥15 узлов, ≤3 уровня глубины,
   SRS-CAT-002), каждая с `commissionCategory ∈ {rx,otc,parapharma}` (SRS-CAT-003) — распределение
   намеренно смешанное (одна категория навигации может содержать и `rx`, и `otc` товары, как того
   требует SRS-CAT-003 — включить минимум один такой смешанный случай явно для последующих тестов
   EP-06/EP-15).
2. `db/seed/medicines/substances.seed.json` — ≥80 уникальных действующих веществ (`inn_name`), включая
   часто комбинируемые (парацетамол, ацетилсалициловая кислота, кофеин, ибупрофен, …) — реальные МНН,
   не выдуманные названия.
3. `db/seed/medicines/medicines.seed.json` — ≥300 позиций, каждая с 1..N `medicine_substances`
   (комбинированные препараты — не менее 30 позиций с 2+ веществами, SRS-DOM-013/D-07). Обязательные
   включения:
   - Минимум **5 независимых аналоговых групп** (≥2 препарата в каждой) — идентичное множество
     `substanceId`, идентичный `dosageFormClass`, эквивалентная `dosage_strength` ПОСЛЕ конвертации
     единиц, РАЗНЫЕ `manufacturer_name` и РАЗНЫЕ цены (цены — часть seed'а `pharmacy_inventory`,
     ВНЕ этого тикета, принадлежит EP-05; здесь только сами позиции `medicines`, готовые стать
     аналоговой группой при появлении остатков) — используется TC-CAT-013 (расчёт экономии).
   - Минимум 1 пара «похожая дозировка, но НЕ эквивалентная после конвертации» (например, `500 мг` и
     `1000 мг` одного вещества) — намеренный anti-паттерн для regression-теста TC-CAT-010 (500мг×2 vs
     1000мг×1 НЕ аналоги).
   - Минимум 1 пара «эквивалентна после конвертации единиц» (`500 mcg` vs `0.5 mg`) — для TC-CAT-011.
   - Минимум 1 пара «то же вещество+дозировка, но РАЗНЫЙ `dosageFormClass`» (tablet vs capsule) — для
     TC-CAT-008 (форма НЕ совместима, несмотря на бытовую интуицию).
   - Минимум 3 позиции с `controlCategory = 'potent'` (`isPrescriptionRequired=true`) — для
     TC-CAT-018/SRS-CAT-056; НИ ОДНОЙ позиции с `psychotropic`/`narcotic` в публичном seed'е (эти
     значения по SRS-DOM-014 достижимы только через модерацию, не через прямой seed — сидить их
     напрямую нарушало бы собственный домен-инвариант; для тестов исключения narcotic из выдачи
     (TC-CAT-017) использовать отдельную ТЕСТОВУЮ фикстуру `apps/api/src/modules/catalog/domain/
     __fixtures__/narcotic-medicine.fixture.ts`, не общий seed).
   - Изображения (`image_url`) — НЕ обязательны для всех 300 (SRS-CAT-007 явно допускает
     плейсхолдер по `dosage_form_class`); достаточно заполнить `image_url` для ~10% позиций (демо
     разнообразия), остальные `null`.
4. `apps/api/src/db/seed/seed-catalog.ts` — читает JSON, вызывает `Medicine.create()` +
   `medicine.publish()` (используя доменные фабрики из DTJ-093, НЕ прямой `INSERT` в обход инвариантов
   — seed обязан пройти через тот же домен, что и продакшен-путь, иначе seed может создать
   невалидное с точки зрения домена состояние) — каждая позиция публикуется сразу (`is_published =
   true`), т.к. seed — курированные, уже проверенные данные, не черновики на модерацию.
5. Добавить npm-скрипт `db:seed` в `apps/api/package.json` (`"db:seed": "tsx src/db/seed/seed-
   catalog.ts"`), запускаемый командой `pnpm db:seed` (D-13 явно требует «одной команды»).

## Критерии приёмки

- Given чистая БД после миграций, When `pnpm db:seed`, Then `SELECT COUNT(*) FROM medicines WHERE
  is_published = true` возвращает `>= 300`.
- Given `pnpm db:seed` запущен повторно на уже засеянной БД, Then количество строк `medicines` НЕ
  увеличивается (идемпотентность — второй запуск не создаёт дублей).
- Given seed применён, When выполняется `AnalogEquivalenceService.isAnalog(A, B)` (DTJ-099) для пары
  из обязательной аналоговой группы (п.3), Then результат `true` для хотя бы одной такой пары в
  каждой из 5 групп.
- Given seed применён, When `medicines.controlCategory = 'narcotic'` ищется в `medicines.seed.json`,
  Then ноль совпадений (инвариант не нарушен намеренно самим seed'ом).

## Тест-план

Интеграционный (vitest + testcontainers, реальная БД):
- `seed-catalog.integration.spec.ts`: запуск `seedCatalog()` дважды подряд → количество строк
  совпадает (идемпотентность); `COUNT(*) >= 300`; хотя бы 5 групп с `array_agg(substance_id) ORDER
  BY substance_id`-эквивалентностью существуют (SQL-проверка по образцу запроса 3
  `11-database-schema.md`); хотя бы 30 позиций с `medicine_substances`-count `>= 2`.

Unit — не применимо (seed — скрипт, не бизнес-логика; корректность самих доменных инвариантов уже
покрыта тестами DTJ-093, здесь только проверяется, что seed их СОБЛЮДАЕТ, не переопределяет их).

## Риски и подводные камни

- Источник данных для 300+ позиций — открытый справочник МНН/торговых названий; корректность
  медицинских данных (реальные дозировки/формы конкретных производителей) НЕ верифицируется
  фармацевтом на этом этапе (ASSUMPTION, как и весь MVP-каталог, `03-ARCHITECT-DECISIONS.md` D-13) —
  риск явно принят архитектором, не блокирует тикет.
- Seed НЕ включает `pharmacy_inventory`/цены (это `inventory`, EP-05) — аналоговые группы seed'а
  «готовы» стать демонстрируемыми только после того, как EP-05 добавит остатки хотя бы для части
  аптек к этим `medicineId`; координация по датам между эпиками — вне контроля этого тикета, но
  критична для демо TC-CAT-013 (нужен seed остатков поверх этого seed'а).
- Публикация 300 записей через `Medicine.create()+publish()` по одной (не bulk INSERT) может быть
  медленной (сотни отдельных транзакций) — для seed-скрипта это приемлемо (разовая операция, не
  прод-путь), не оптимизировать преждевременно (C15).
- Файл `apps/api/package.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
