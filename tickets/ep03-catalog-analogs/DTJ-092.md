## Задача

Все use case'ы модуля (`GetMedicineDetailUseCase`, `GetCategoryTreeUseCase`, `FindAnalogsUseCase`,
`CatalogFacade`) читают/пишут `medicines`/`substances`/`categories`/`medicine_substances` через ОДИН
порт, а не напрямую через Drizzle — иначе `application` знает про инфраструктуру
(`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.1, запрет `application → infrastructure`). Этот тикет вводит
порт и единственную реализацию (Drizzle) для оставшихся тикетов эпика.

## Технический контекст

Порт объявляется в `application/ports/*.port.ts` с DI-токеном `Symbol`, реализация — в
`infrastructure/adapters/*.adapter.ts`, связывание — в `catalog.module.ts` (`02` §1.3). Метод
получения полного агрегата `Medicine` обязан подгружать `MedicineSubstance[]` (JOIN
`medicine_substances`) за ОДИН запрос — доменные инварианты SRS-DOM-013/017 требуют, чтобы
`AnalogEquivalenceService`/`Medicine.publish()` видели полное множество веществ, не ленивую
подгрузку по требованию.

## Что сделать

1. `application/ports/catalog-repository.port.ts`:
   ```typescript
   export const CATALOG_REPOSITORY = Symbol('CATALOG_REPOSITORY');
   export interface CatalogRepository {
     findMedicineById(id: string): Promise<MedicineRecord | null>;       // включая substances[]
     findMedicinesByIds(ids: readonly string[]): Promise<MedicineRecord[]>;
     findCategoryTree(tenantId: TenantId): Promise<CategoryNode[]>;
     findSubstancesByMedicineIds(ids: readonly string[]): Promise<Map<string, SubstanceRef[]>>;
     save(medicine: Medicine): Promise<void>;                             // используется DTJ-097/DTJ-099-101 косвенно
   }
   ```
   `MedicineRecord`/`CategoryNode`/`SubstanceRef` — DTO инфраструктуры (не путать с доменной
   сущностью `Medicine` — маппинг DTO↔domain делает `infrastructure/mappers/medicine.mapper.ts`,
   доменный `Medicine.restore(...)` вызывается адаптером, не наоборот).
2. `infrastructure/adapters/catalog-repository.adapter.ts` — Drizzle-реализация:
   - `findMedicineById`: один запрос `SELECT ... FROM medicines LEFT JOIN medicine_substances ...
     WHERE medicines.id = :id` (агрегация в JS, не `array_agg` — проще мапить в TS).
   - Фильтрация `control_category NOT IN ('psychotropic','narcotic')` НЕ применяется на уровне этого
     репозитория (это ответственность use case/presentation, SRS-CAT-006 — репозиторий возвращает
     запись как есть, включая черновики и любые категории контроля — иначе `super_admin`-эндпоинты
     модерации не смогут читать скрытые записи через тот же репозиторий).
   - `findCategoryTree`: одна выборка всех строк `categories WHERE is_active = true ORDER BY
     sort_order`, построение дерева в памяти (≤200 узлов ожидаемо, SRS-CAT-004 — без рекурсивного CTE,
     достаточно одного `SELECT` + JS-группировка по `parent_id`).
3. `infrastructure/mappers/medicine.mapper.ts` — `toDomain(record: MedicineRecord): Medicine`,
   `toRecord(medicine: Medicine): MedicineRecord` (двусторонний маппинг, используется адаптером и
   будущими write-путями DTJ-097/DTJ-099).
4. Зарегистрировать провайдер в `catalog.module.ts`: `{ provide: CATALOG_REPOSITORY, useClass:
   CatalogRepositoryAdapter }`.

## Критерии приёмки

- Given `medicineId` существует и имеет 2 связанных вещества, When
  `catalogRepository.findMedicineById(id)`, Then возвращается ОДНА запись `MedicineRecord` с
  `substances.length === 2` за один SQL-запрос (проверяется через `pg_stat_statements`/подсчёт
  запросов в интеграционном тесте — не N+1).
- Given `medicineId` не существует, When `findMedicineById`, Then возвращается `null` (не бросает
  исключение — решение о `404` принимает use case, не репозиторий).
- Given `categories` содержит дерево глубиной 3 с 10 узлами, When `findCategoryTree`, Then
  возвращается корректно вложенная структура `CategoryNode[]` (проверка на фикстуре).

## Тест-план

Интеграционные тесты (vitest + testcontainers Postgres, реальная миграция DTJ-091):

  substances), `findMedicinesByIds` (пустой массив на входе → пустой массив, не ошибка),

## Риски и подводные камни

- `findMedicineById` возвращает записи БЕЗ фильтра видимости намеренно (см. «Что сделать» п.2) —
  разработчикам DTJ-095/DTJ-096, использующим этот метод для публичных эндпоинтов, ОБЯЗАТЕЛЬНО
  применить фильтр `is_published`/`control_category` на своём уровне (use case), иначе — прямое
  нарушение SRS-CAT-005/006 (утечка черновиков/запрещённых веществ в публичный API). Явно
  задокументировать это в JSDoc метода при реализации.
- Метод `save()` в порте зарезервирован для DTJ-097 (создание черновика при composite-матчинге) и
  DTJ-099 (домен `Medicine.publish()`/`proposeControlCategory()` требует персистентности решения) —
  в этом тикете достаточно объявить сигнатуру и минимальную реализацию (`INSERT ... ON CONFLICT (id)
  DO UPDATE`), не покрывать все ветки — полное покрытие тестами откладывается на потребляющие тикеты.
- Файл `apps/api/src/modules/catalog/catalog.module.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
