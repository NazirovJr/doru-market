## Задача

Юридически чувствительный текст (дисклеймер об отсутствии медицинской рекомендации) обязан
существовать с первого дня, даже в ASSUMPTION-версии (REQ-NORM-3 категоричен) — отсутствие
дисклеймера хуже неидеальной формулировки. Этот тикет вносит переводы и версионирование юридического
статуса текста, без чего DTJ-102 не может резолвить `disclaimer` для ответа.

## Технический контекст

`i18n_overrides` — уже существующая таблица (`11-database-schema.md` строка 1373, владелец —
общая инфраструктура, не отдельный эпик) — этот тикет ДОБАВЛЯЕТ колонку `review_status` (не создаёт
таблицу заново) и СИДИТ 5 ключей (`savings_banner`, `title_neutral`, `title_savings`, `disclaimer`,
`rx_required_badge`) на tj/ru/en. Переводы `packages/i18n/src/dictionaries/*/catalog.json` — по
правилу «Пересекающееся владение» п.6 `00-EPICS.md`: `packages/i18n` в целом принадлежит EP-18, но
каждый эпик добавляет СВОЙ файл-неймспейс (`catalog.json`) без правки инфраструктуры пакета.

## Что сделать

1. `apps/api/migrations/0008_i18n_overrides_review_status.sql`:
   ```sql
   ALTER TABLE i18n_overrides
     ADD COLUMN review_status VARCHAR(20) NOT NULL DEFAULT 'pending_legal_review';
   -- 'pending_legal_review' | 'approved' — блокирует ТОЛЬКО visual-индикатор в apps/admin,
   -- НЕ блокирует показ пользователю (SRS-CAT-041).
   ```
2. `apps/api/src/db/seed/i18n-overrides-catalog.seed.ts` — сидит 5 ключей × 3 локали (15 строк) в
   `i18n_overrides`, каждая с `review_status='pending_legal_review'` (текст — ASSUMPTION-плейсхолдер
   до визирования юристом, SRS-CAT-041):
   - `catalog.analogs.savings_banner` — параметризованный (`{{amount}}`, `{{substanceNames}}`,
     `{{cheapPrice}}`, `{{refPrice}}`), 3 языка дословно из SRS-CAT-038.
   - `catalog.analogs.title_neutral` — «Другие варианты с тем же действующим веществом» (ru), tj/en
     аналоги (SRS-CAT-037).
   - `catalog.analogs.title_savings` — «Сэкономьте X сомони» (шаблон, параметризован `{{amount}}`).
   - `catalog.analogs.disclaimer` — дословный текст трёх языков из SRS-CAT-039 (RU/TJ/EN, TJ
     ПОМЕЧЕН как требующий вычитки носителем — само примечание НЕ идёт в БД, только в комментарий
     сидового скрипта).
   - `catalog.analogs.rx_required_badge` — «Требуется рецепт» / «Бо нусха» / «Prescription required»
     (SRS-CAT-040).
3. `packages/i18n/src/dictionaries/{tj,ru,en}/catalog.json` — ТЕ ЖЕ 5 ключей продублированы в
   статический словарь пакета `packages/i18n` (для случаев, когда `useT()`-механизм читает статические
   JSON, а не динамический `i18n_overrides` — если к моменту реализации архитектура i18n уже
   определилась на ОДИН источник истины (или статический словарь, или `i18n_overrides`), этот пункт
   адаптируется под факт: динамический `i18n_overrides` — источник для ЮРИДИЧЕСКОГО текста
   (версionируемый, требует `review_status`), статический словарь — для НЕюридических UI-строк того
   же экрана (заголовки кнопок и т.п., если такие понадобятся блоку аналогов) — не дублировать один и
   тот же ключ в обоих местах, выбрать одно place per ключ и задокументировать почему).

## Критерии приёмки

- Given миграция применена, When `SELECT review_status FROM i18n_overrides LIMIT 1`, Then колонка
  существует с дефолтом `'pending_legal_review'`.
- Given сид применён, When `SELECT text FROM i18n_overrides WHERE key='catalog.analogs.disclaimer'
  AND locale='ru'`, Then текст совпадает дословно с SRS-CAT-039 RU-вариантом (побайтовое сравнение в
  тесте, чтобы уловить случайную правку).
- Given все 5 ключей × 3 локали, When `SELECT COUNT(*) FROM i18n_overrides WHERE key LIKE
  'catalog.analogs.%'`, Then `= 15`.

## Риски и подводные камни

- Таджикский текст дисклеймера/плашки — машинный, требует вычитки носителем/фармацевтом ДО
  продакшен-релиза (явная оговорка исходного документа) — этот тикет закрывает функциональный
  критерий (текст присутствует), не юридический (текст утверждён). Не путать «Definition of Done
  тикета» с «готовностью к продакшену всего продукта» — `review_status='approved'` проставляется
  ЮРИСТОМ через `apps/admin` позже, вне этого тикета.
- `i18n_overrides` — общая таблица без явного эпика-владельца в `00-EPICS.md`; если DDL этой таблицы
  ещё не создан на момент выполнения тикета (владелец миграции — неизвестен из документов), этот
  тикет ДОЛЖЕН создать таблицу сам (по DDL `11-database-schema.md` строка 1373) перед добавлением
  колонки — свериться перед стартом, не дублировать `CREATE TABLE`, если её уже завела другая
  команда.
