## Задача

Все остальные тикеты EP-04/EP-07 живут внутри `modules/catalog/{domain,application,infrastructure,
presentation}` и опираются на два value object'а (`Dosage`, `Barcode`), которые по `10-domain-model.md`
обязаны быть переиспользуемы модулем `inventory` (composite-матчинг, D-06) БЕЗ прямого импорта
`catalog/domain/*` — межмодульный импорт домена запрещён (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.1).
Этот тикет закладывает физический скелет модуля и общий пакет для таких VO, чтобы дальнейшие тикеты
не блокировали друг друга структурными решениями.

## Технический контекст

`SRS-INV-019` (`22-module-inventory-sync-1c.md`) явно предписывает: `Barcode` VO «живёт в общем
`libs/domain-kernel` или пакете, доступном обоим модулям как shared kernel». В текущем workspace
(`pnpm-workspace.yaml`) заведены только глобы `apps/*`, `packages/*`, `tests/*` — поэтому пакет
создаётся как `packages/domain-kernel` (не `libs/*`, чтобы не трогать корневой `pnpm-workspace.yaml`,
владение которым не закреплено ни за одним эпиком явно и по духу `00-EPICS.md` п.5 такие правки лучше
не делать явочным порядком). Пакет содержит ТОЛЬКО чистые VO без побочных эффектов (`02` §2 — ноль
импортов фреймворка), в этом тикете — `Dosage`, `DosageForm`, `Barcode` (используются доменом
`catalog` в DTJ-093 и доменом `inventory`, другой командой, для composite-матчинга).

`Money`/`PhoneNumber`/`GeoPoint`/`OtpCode`/`TenantId` в этот пакет НЕ входят — эти VO вероятнее всего
уже заведены фундаментальным эпиком (EP-01) в собственном месте; если на момент реализации
`packages/domain-kernel` уже существует под другим именем/структурой — новые файлы этого тикета
добавляются В НЕГО (тот же приём, что `packages/contracts`, `00-EPICS.md` «Пересекающееся владение»
п.3), а не создают дублирующий пакет.

## Что сделать

1. Создать `packages/domain-kernel/package.json` (имя `@dorutj/domain-kernel`, `"type": "module"`,
   без рантайм-зависимостей — только `typescript`/`vitest` в `devDependencies`), `tsconfig.json`
   (наследует `tsconfig.base.json`).
2. `packages/domain-kernel/src/value-objects/dosage.vo.ts`:
   - `enum DosageUnit { mg, mcg, g, ml, iu, percent, mg_per_ml }` (значения — те же строки, что enum
     `dosage_unit` в `11-database-schema.md`, без переименования).
   - `class Dosage` с приватным конструктором, фабрикой `Dosage.create(value: number, unit: DosageUnit):
     Result<Dosage, InvalidDosageError>` и методом `isEquivalentTo(other: Dosage): boolean`
     (SRS-DOM-077/078): конвертация ТОЛЬКО внутри семейства масс (`mg/mcg/g`) через `bigint`-множитель
     в микрограммы (`1g=1_000_000mcg`, `1mg=1_000mcg`), без float; `ml`/`iu`/`percent`/`mg_per_ml`
     сравниваются только внутри своей единицы, без кросс-конверсии; `DOSAGE_EQUIVALENCE_TOLERANCE_PCT =
     0` — точное совпадение после конвертации, без допуска.
   - `Dosage.parse(raw: string): Result<Dosage, DosageParseError>` — разбор строк вида `"500 мг"`,
     `"10 мг/мл"` (SRS-DOM-077) для использования сидом/импортом (не домен-инвариант, вспомогательный
     парсер, но без I/O — чистая функция).
3. `packages/domain-kernel/src/value-objects/dosage-form.vo.ts`:
   - `enum DosageFormClass { tablet, capsule, syrup, injection, ointment, drops, inhaler, suppository,
     other }` (те же значения, что `dosage_form_class` в `11-database-schema.md`).
   - `class DosageForm` — обёртка над `DosageFormClass` с методом `isEquivalentTo(other: DosageForm):
     boolean` — СТРОГО диагональное сравнение (класс эквивалентен только самому себе, SRS-DOM-079,
     `20-module-catalog-search.md` §6.2) — без какой-либо матрицы совместимости внутри VO (полная
     матрица тривиальна, т.к. диагональ; вычисление задокументировано комментарием со ссылкой на
     SRS-CAT-032/033, объясняющим ПОЧЕМУ tablet≠capsule НЕ смягчается без ADR архитектора).
4. `packages/domain-kernel/src/value-objects/barcode.vo.ts`:
   - `class Barcode` — `Barcode.parse(raw: string)`: EAN-13 контрольная цифра (mod-10, стандартный
     алгоритм), `format: 'ean13' | 'non_ean13'`, `isInternalPrefix(): boolean` (первая цифра `'2'`,
     D-06), `isValidEan13(): boolean` (SRS-DOM-016, SRS-DOM-074..076). Строка длиной ≠13 НЕ бросает
     исключение конструктора — сохраняется с `format='non_ean13'` (SRS-DOM-076).
5. `packages/domain-kernel/src/index.ts` — барабанный экспорт трёх VO + их error-классов и
   вспомогательных типов (`Result<T,E>` — общий тип, если ещё не заведён EP-01 в `packages/contracts`,
   определить локально как `{ ok: true, value: T } | { ok: false, error: E }`).
6. Создать директории `apps/api/src/modules/catalog/{domain,application,infrastructure,presentation}/`
   с `README.md`, кратко описывающим назначение слоя и ссылку на `02-CLEAN-ARCHITECTURE-AND-CODE.md`
   §1 (файлы-плейсхолдеры нужны, чтобы структура была видна в git до появления первого реального
   файла слоя в DTJ-091..104).
7. `apps/api/src/modules/catalog/catalog.module.ts` — пустой `@Module({})`-скелет NestJS без
   провайдеров (провайдеры добавляются последующими тикетами через `{ provide: TOKEN, useClass }`).
8. `apps/api/src/modules/catalog/index.ts` — публичный фасад-заглушка: экспортирует пустой интерфейс
   `CatalogFacade` (наполняется в DTJ-096) и комментарий-заглушку, чтобы `catalog.module.ts` мог
   компилироваться и подключаться в корневой `AppModule` уже сейчас.
9. `packages/contracts/src/catalog.ts` — скелет: пустые заготовки типов `MedicineSnapshot`,
   `SubstanceRef`, `CompositeMatchInput`, `MedicineMatchResult` (наполняются DTJ-096/097) + одна
   строка экспорта в барабанный `index.ts` пакета `contracts` (файл принадлежит EP-01, здесь только
   ДОБАВЛЯЕТСЯ строка экспорта — `00-EPICS.md` «Пересекающееся владение» п.3).

## Критерии приёмки

- Given `Dosage.create(500, 'mg')` и `Dosage.create(0.5, 'g')`, When `a.isEquivalentTo(b)`, Then
  `true` (конвертация в микрограммы совпадает: `500_000 === 500_000`).
- Given `Dosage.create(500, 'mg')` и `Dosage.create(500, 'iu')`, When `isEquivalentTo`, Then `false`
  (разные семейства единиц не сравниваются, даже при числовом совпадении).
- Given `Barcode.parse('4870123456789')` (валидный EAN-13, контрольная цифра верна), Then
  `isValidEan13() === true`, `format === 'ean13'`; given строка длиной 8 символов, Then НЕ бросает,
  `format === 'non_ean13'`.
- Given `packages/domain-kernel` собран, When `apps/api` импортирует `@dorutj/domain-kernel` в
  `catalog.module.ts`, Then `pnpm build` проходит без циклических зависимостей workspace.

## Тест-план

Unit (vitest, `packages/domain-kernel/src/value-objects/*.spec.ts`, покрытие ≥90% — чистый VO-пакет
приравнивается к `domain/`, порог `02` §6):
- `dosage.vo.spec.ts`: конвертация mg↔mcg↔g (включая TC-DOM-012/013 из `10-domain-model.md`:
  `500мг` vs `0.5г` → `true`; `500мг` vs `500 IU` → `false`), нулевые/отрицательные значения → ошибка
  парсинга, `ml` не конвертируется в `mg` при числовом совпадении.
- `dosage-form.vo.spec.ts`: `tablet.isEquivalentTo(tablet)` → `true`; `tablet.isEquivalentTo(capsule)`
  → `false` (TC-CAT-008); `syrup.isEquivalentTo(injection)` → `false` (TC-CAT-009).
- `barcode.vo.spec.ts`: валидный/невалидный EAN-13 (контрольная цифра), внутренний префикс `'2'`,
  строка неверной длины.

Интеграционных/E2E тестов не требуется — пакет не содержит I/O.

## Риски и подводные камни

- Если к моменту выполнения тикета EP-01 уже создал общий VO-пакет под другим именем (например,
  `packages/kernel`) — этот тикет должен ДОБАВИТЬ файлы `dosage.vo.ts`/`dosage-form.vo.ts`/
  `barcode.vo.ts` туда, а не плодить параллельный `packages/domain-kernel`. Разработчику — свериться
  с актуальным состоянием `packages/` перед началом.
- `packages/domain-kernel` — общий ресурс с командой EP-05 (inventory, D-06 composite-матчинг также
  использует `Barcode`/`Dosage`). Требуется предупредить владельца EP-05 о появлении пакета до того,
  как они начнут реализацию своего composite-матчинга — иначе риск дублирования VO внутри
