## Задача

Каталог, поиск (EP-06) и аналоги (EP-07) не могут существовать без физической схемы `categories`,
`substances`, `medicines`, `medicine_substances`. Документ `11-database-schema.md` уже задаёт DDL
буквально (Группа A, п.3-6) — этот тикет переносит его в Drizzle-схему и первую миграцию модуля
`catalog`, без изменения ни одного поля/ограничения оригинального DDL.

## Технический контекст

DDL — «закон», цитируется, не переопределяется (`20-module-catalog-search.md`, преамбула). Enum'ы
`dosage_unit`, `dosage_form_class`, `control_category` объявлены централизованно в
`11-database-schema.md` §«ENUM-типы» — создаются в этой же миграции, т.к. первые потребители
(`medicines.dosage_unit`/`dosage_form_class`/`control_category`, `medicine_substances.strength_unit`)
принадлежат этому модулю; если к моменту выполнения enum уже создан миграцией другого модуля (напр.
EP-01 базовым скелетом) — переиспользовать `CREATE TYPE IF NOT EXISTS` эквивалент (Drizzle: сверка по
существующей миграции перед добавлением). `pharmacy_chains`/`pharmacies` (та же «Группа A» в DDL) —
**НЕ входят** в этот тикет: они принадлежат `onboarding` (EP-03, `apps/api/src/db/schema/` там же, но
владение файлом `pharmacies.ts`/`pharmacy-chains.ts` — за EP-03).

## Что сделать

1. Мигрировать расширения, если ещё не сделаны EP-01: `CREATE EXTENSION IF NOT EXISTS pg_trgm`,
   `unaccent`, `postgis` — SRS-DB-007 (проверить, не задваивает ли миграцию с EP-01/EP-19; если уже
   есть — пропустить в этом файле, только зависимость по номеру миграции).
2. `apps/api/src/db/schema/categories.ts` (Drizzle) — 1:1 DDL `categories` (`11-database-schema.md`
   строки 321-334): `id SERIAL`, `parent_id` self-FK `ON DELETE SET NULL`, `slug UNIQUE`, `name_tj/
   name_ru/name_en`, `commission_category VARCHAR(20)` (значения `'rx'|'otc'|'parapharma'`, БЕЗ
   отдельного enum-типа — как в оригинальном DDL, VARCHAR+CHECK, не переопределять на ENUM),
   `sort_order`, `is_active`.
3. `apps/api/src/db/schema/substances.ts` — 1:1 DDL `substances`: `id UUID`, `inn_name UNIQUE`,
   `inn_name_en`, `created_at`.
4. `apps/api/src/db/schema/medicines.ts` — 1:1 DDL `medicines` (11-database-schema.md строки 349-390),
   включая генерируемую колонку `search_vector` (используется только EP-06, но колонка — часть DDL
   таблицы, создаётся здесь целиком, включая `tsvector`-выражение буквально из DDL) и
   `CONSTRAINT chk_medicines_control_category_requires_rx` (SRS-DOM-015 дублируется на уровне БД).
5. `apps/api/src/db/schema/medicine-substances.ts` — 1:1 DDL `medicine_substances`: композитный
   `PRIMARY KEY (medicine_id, substance_id)`, `CONSTRAINT chk_medicine_substances_strength_positive`.
6. Создать enum-типы `dosage_unit`, `dosage_form_class`, `control_category` (`11-database-schema.md`
   §«ENUM-типы») в этой же миграции — они впервые используются здесь.
7. `apps/api/migrations/0006_catalog_core.sql` — сгенерировать через `drizzle-kit generate`, ПРОВЕРИТЬ
   вручную, что итоговый SQL совпадает 1:1 с DDL документа (в т.ч. `GENERATED ALWAYS AS (...) STORED`
   для `search_vector` — drizzle-kit не всегда корректно генерирует generated columns, при
   расхождении — править сгенерированный SQL руками, не схему).
8. Индексы из `11-database-schema.md` §«Индексы» → «Каталог / инвентарь», относящиеся ИСКЛЮЧИТЕЛЬНО
   к этим 4 таблицам (без поисковых GIN/trgm-индексов — те создаёт EP-06 отдельной миграцией при
   вводе `PostgresSearchProvider`, чтобы не блокировать эту миграцию ожиданием поискового модуля):
   `ix_medicines_control_category` (частичный), `ix_medicines_published` (частичный), FK-индексы на
   `category_id`, `medicine_substances.substance_id`.

## Критерии приёмки

- Given миграция применена к чистой БД (`pnpm db:migrate`), When выполняется `\d medicines` в psql,
  Then все поля/constraints совпадают с DDL `11-database-schema.md` строка в строку (включая
  `chk_medicines_control_category_requires_rx`).
- Given `INSERT INTO medicines (...) VALUES (control_category='potent', is_prescription_required=false)`,
  Then INSERT падает с нарушением CHECK-constraint (SRS-DOM-015 на уровне БД).
- Given `INSERT INTO medicine_substances (strength_value=0, ...)`, Then падает
  `chk_medicine_substances_strength_positive`.
- Given миграция откатывается (`pnpm db:migrate:down`), Then все 4 таблицы и 3 enum-типа удаляются
  без ошибок (down-миграция написана явно, не автогенерацией «best effort»).

## Тест-план

Интеграционные тесты (vitest + testcontainers/docker Postgres, `apps/api/src/db/schema/*.integration.spec.ts`):
- `medicines_schema.integration.spec.ts`: INSERT валидной записи проходит; нарушение
  `chk_medicines_control_category_requires_rx` откатывается с ожидаемым кодом ошибки Postgres
  (`23514`).
- `medicine_substances_schema.integration.spec.ts`: композитный PK не даёт вставить дубль
  `(medicine_id, substance_id)`; `strength_value <= 0` отклоняется.
- `categories_schema.integration.spec.ts`: self-FK `parent_id` работает, `ON DELETE SET NULL` не
  каскадирует удаление дочерних категорий.

Unit-тестов не требуется (чистая схема, без бизнес-логики). E2E не требуется на этом уровне.

## Риски и подводные камни

- `drizzle-kit generate` может некорректно воспроизвести `GENERATED ALWAYS AS (...) STORED` для
  `search_vector` (известное ограничение генераторов миграций для generated columns) — обязательна
  ручная проверка сгенерированного SQL.
- Если EP-01 к моменту выполнения уже создал расширения `pg_trgm`/`unaccent`/`postgis` в своей
  миграции — эта миграция не должна дублировать `CREATE EXTENSION` без `IF NOT EXISTS`, иначе падение
  на повторном применении.
- Enum-типы `dosage_unit`/`dosage_form_class`/`control_category` используются также модулем
  `inventory` (EP-05) — порядок миграций (эта раньше их) должен быть зафиксирован в общем порядке
  `apps/api/migrations/` (см. `11-database-schema.md` §«Миграции», «топологический порядок»);
  скоординировать номер файла с оркестратором тикетов, чтобы не столкнуться номерами с другой
  командой.
