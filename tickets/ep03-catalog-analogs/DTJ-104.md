## Задача

Клиентское представление единственного признанного защитимого отличия продукта. Дизайн-референс
(`32-design-reference.md` строка 176) описывает `AnalogBanner` на экране `Medicine` как обязательный
компонент рядом с дисклеймером и списком предложений — этот тикет реализует его как переиспользуемый
`feature`-модуль `apps/web/src/features/analogs`.

## Технический контекст

Структура `feature` — по `02-CLEAN-ARCHITECTURE-AND-CODE.md` §5: `api/` (TanStack Query поверх
`GET /medicines/:id/analogs`, DTJ-102), `model/` (чистые функции форматирования — НЕ бизнес-правила,
те уже посчитаны бэкендом, здесь только `Intl.NumberFormat` для отображения сумм), `ui/` (компоненты,
только рендер). Ноль хардкодных строк (`useT()` из `packages/i18n`) и ноль хардкодных цветов (CSS-
переменные дизайн-токенов `packages/ui`) — `02` §5.

## Что сделать

1. `api/use-analogs-query.ts` — `useAnalogsQuery(medicineId, { geo, radiusMeters })` — TanStack Query
   хук поверх `GET /api/v1/medicines/:id/analogs`, БЕЗ `fetch`/`axios` внутри компонента (`02` §5).
2. `model/format-savings.ts` — чистая функция `formatSavings(amountDiram: number, locale): string` —
   `Intl.NumberFormat(locale, { minimumFractionDigits: 2, maximumFractionDigits: 2 })` на конвертации
   `diram → TJS` (ДЕЛЕНИЕ на 100, БЕЗ округления суммы — SRS-CAT-038 «БЕЗ округления до вменяемых
   чисел», разброс ×9.8–10 отображается точно).
3. `ui/AnalogsBlock.tsx` (≤150 строк, `02` §5) — композиция: `SavingsBanner` (условно, только если
   `savingsDiram` присутствует) ИЛИ нейтральный заголовок (`titleKey` из ответа API определяет,
   какой блок рендерить — компонент не решает это сам, следует серверному `titleKey`), список
   `AnalogCard[]`, дисклеймер (ВСЕГДА рендерится, вне зависимости от ветки заголовка — TC-CAT-015).
4. `ui/AnalogCard.tsx` (≤150 строк) — одна карточка аналога: название, производитель, цена, Rx-бейдж
   (`Badge`-компонент `packages/ui`, ТОЛЬКО если `item.isPrescriptionRequired === true` — рендерится
   РЯДОМ с конкретной карточкой, не общим баннером над списком, TC-CAT-016).
5. `ui/SavingsBanner.tsx` (≤150 строк) — плашка «Сэкономьте N сомони», текст — через `useT()` с ключом
   `catalog.analogs.title_savings` и параметром `{{amount}}` (форматированным п.2), НЕ raw-строка из
   API-ответа напрямую (API возвращает `savingsDiram`-число и `titleKey`, не готовый локализованный
   текст — фронт сам подставляет параметры в i18n-шаблон, чтобы локаль переключалась без повторного
   запроса к API при смене языка пользователем на клиенте).
6. Given `useAnalogsQuery` в состоянии `isLoading`, Then рендерится `Skeleton` (компонент `packages/
   ui`, форма повторяет карточку аналога — по дизайн-референсу «форма скелетона повторяет форму
   реального контента», `32-design-reference.md` строка 147); given ошибка сети, Then блок скрывается
   целиком (аналоги — дополнительная, не критичная для покупки информация, деградация без блокировки
   основной карточки товара).

## Критерии приёмки

- Given API вернул `savingsDiram: 6500`, When рендерится `AnalogsBlock`, Then отображается «Сэкономьте
  65.00 сомони» (точное форматирование, TC-CAT-013).
- Given API вернул `titleKey: 'catalog.analogs.title_neutral'` (savings отсутствует), Then рендерится
  нейтральный заголовок, `SavingsBanner` НЕ рендерится, список аналогов присутствует (TC-CAT-014).
- Given любой валидный ответ с ≥1 элементом `items`, When рендерится `AnalogsBlock`, Then текст
  `catalog.analogs.disclaimer` присутствует в DOM НЕЗАВИСИМО от ветки заголовка (TC-CAT-015).
- Given один элемент `items` с `isPrescriptionRequired: true`, другой — `false`, When рендерится
  список, Then Rx-бейдж присутствует ТОЛЬКО у первой карточки, не как общий баннер (TC-CAT-016).

## Тест-план

Компонентные тесты (vitest + `@testing-library/react`):
- `AnalogsBlock.spec.tsx` — TC-CAT-013/014/015 буквально (мокированный ответ хука), плюс: пустой
  `items` → блок не рендерится вовсе (нет смысла показывать пустой список с одним дисклеймером).
- `AnalogCard.spec.tsx` — TC-CAT-016 (Rx-бейдж только у нужной карточки).
- `format-savings.spec.ts` (unit, model/) — форматирование `6500` diram → `"65.00"`, крупные разбросы
  (`×9.8-10`, REQ-MARKET-3) не округляются до «круглых» чисел.

E2E — не заводится отдельным тикетом здесь; используется сквозным CUJ-1 (EP-19), где переход
поиск→карточка→блок аналогов — один из шагов сценария.
