## Задача

Публичный HTTP-контракт блока аналогов: собирает результат `FindAnalogsUseCase` (DTJ-101) в JSON,
подставляет дисклеймер (обязателен при КАЖДОМ рендере, не одноразово) и per-карточечный Rx-бейдж —
единственный слой, которому разрешено читать `i18n_overrides` для резолвинга текста дисклеймера по
`Accept-Language` (SRS-CAT-042 «presentation — маппинг DTO→JSON, дисклеймер подставляется на этом
уровне»).

## Технический контекст

`presentation/controllers/analogs.controller.ts` зависит только от `application`
(`FindAnalogsUseCase`) — не от `domain` напрямую (`02` §1.1). Локаль резолвится из `Accept-Language`
(SRS-API-008, дефолт `tj`). Дисклеймер — версионируемая запись в `i18n_overrides` (ключ
`catalog.analogs.disclaimer`, поле `review_status`, DTJ-103) — контроллер ЧИТАЕТ её через существующий
i18n-механизм (не хардкод строки в этом файле, `02` §5 «Ноль хардкодных строк»).

## Что сделать

1. `presentation/controllers/analogs.controller.ts` — `GET /api/v1/medicines/:id/analogs`:
   query-параметры `radiusMeters?` (дефолт — переиспользует `SEARCH_DEFAULT_RADIUS_METERS=5000`,
   константа EP-06, ИМПОРТИРУЕТСЯ, не дублируется, C15), `lat?`/`lon?`. Публичный (анонимный доступ
   разрешён — тот же уровень доступа, что карточка товара).
2. `presentation/dto/analog-result.dto.ts` — маппинг результата `FindAnalogsUseCase` в JSON:
   ```json
   {
     "data": {
       "referenceMedicineId": "...",
       "items": [ {
         "medicineId": "...", "tradeName": "...", "manufacturerName": "...",
         "cheapestOffer": { "pharmacyId": "...", "priceDiram": 1800, "distanceMeters": 800, "isStale": false },
         "isPrescriptionRequired": true
       } ],
       "savingsDiram": 6500,
       "titleKey": "catalog.analogs.title_savings",
       "disclaimer": "Это не медицинская рекомендация. ..."
     }
   }
   ```
3. Given `savingsDiram === null` (use case вернул `savings: null`, SRS-CAT-037), Then
   `titleKey = 'catalog.analogs.title_neutral'`, поле `savingsDiram` отсутствует/`null` в ответе,
   `items` всё равно присутствуют, если непусты (SRS-CAT-037 — список остаётся видимым без плашки).
4. `isPrescriptionRequired: true` на КОНКРЕТНОЙ карточке аналога → фронт рендерит Rx-бейдж РЯДОМ с
   этой карточкой (SRS-CAT-040) — контроллер лишь пробрасывает поле per-item, НЕ агрегирует общий
   баннер «есть Rx-товары» — микс Rx/OTC в одном списке — валидный случай, каждая карточка сама несёт
   свой флаг.
5. `disclaimer` — резолвится через `I18nOverridesService.get('catalog.analogs.disclaimer', locale)`
   (сервис уже существующего механизма `i18n_overrides`, если инфраструктура i18n ещё не готова
   другой командой на момент реализации — временная реализация читает напрямую из таблицы через
   `CATALOG_REPOSITORY`-подобный минимальный запрос, с TODO на миграцию к общему сервису).
6. Given `medicineId` не найден/не виден (см. DTJ-095/DTJ-101), Then `404 NOT_FOUND` — тот же паттерн,
   что карточка товара, единообразно.

## Критерии приёмки

- Given ≥1 результат аналогов, When `GET /medicines/:id/analogs`, Then поле `disclaimer` присутствует
  в ответе НЕЗАВИСИМО от наличия/отсутствия `savingsDiram` — TC-CAT-015.
- Given список содержит один OTC- и один Rx-вариант, When `GET /medicines/:id/analogs`, Then
  `isPrescriptionRequired: true` присутствует ТОЛЬКО у соответствующего элемента `items` — TC-CAT-016.
- Given `savingsDiram <= 0` внутренне, When `GET /medicines/:id/analogs`, Then `titleKey =
  'catalog.analogs.title_neutral'`, `items` непусты, если список аналогов не пуст.
- Given `Accept-Language: en`, When `GET /medicines/:id/analogs`, Then `disclaimer` — англоязычный
  текст (SRS-CAT-039 EN-вариант), не `ru`/`tj` по умолчанию.

## Риски и подводные камни

- Зависимость от `SEARCH_DEFAULT_RADIUS_METERS`, объявленной EP-06 в `packages/contracts/src/
  search.ts` (SRS-CAT-011) — если на момент реализации этой константы ещё нет, временно определить
  локально с TODO на замену импортом, во избежание блокировки тикета ожиданием другой команды.
- `i18n_overrides`-механизм чтения (п.5) может быть ещё не абстрагирован в отдельный сервис на момент
  реализации — прямой запрос через существующий `CatalogRepository`/минимальный SQL как временное
  решение допустим, но должен быть явно помечен TODO, чтобы не закрепиться как постоянный хардкод
  доступа к чужой таблице (`i18n_overrides` в принципе не «чужая» — общая таблица без владельца
  контекста, но паттерн доступа должен быть единообразным для всех потребителей).
