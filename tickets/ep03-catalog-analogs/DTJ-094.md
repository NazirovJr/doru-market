## Задача

Дерево категорий — точка входа навигации каталога (главный экран, фильтр `filters.categoryId` в
поиске EP-06). Без него ни один клиент не может построить меню категорий, а `commission_category`
(база резолвинга комиссии, D-03) не будет провалидирована на глубину вложенности.

## Технический контекст

`categories` — self-reference дерево без ограничения глубины на уровне БД; ограничение накладывается
`application`-валидатором (SRS-CAT-002). `commission_category` — НЕ дерево навигации, отдельная
плоская группировка (SRS-CAT-003) — эндпоинт возвращает оба поля, но UI строит меню только по
`parentId`, не по `commissionCategory`.

## Что сделать

1. `domain/services/category-tree.service.ts` — `class CategoryTreeService` (чистая функция, домен):
   `validateDepth(tree: CategoryNode[]): Result<void, CategoryTreeTooDeepError>` — обходит дерево,
   бросает ошибку, если глубина превышает `CATEGORY_MAX_DEPTH = 3` (именованная константа, C6,
   SRS-CAT-002). Используется как валидация ПРИ ЧТЕНИИ (лог предупреждения/алерт при обнаружении
   нарушения, не блокировка ответа — дерево уже в БД, вина на данных админки, не на клиенте) — метод
   возвращает `Result`, use case решает, алертить или молча обрезать глубже 3 уровня в ответе.
2. `application/use-cases/get-category-tree.use-case.ts` — `GetCategoryTreeUseCase.execute({
   tenantId }): Promise<CategoryNode[]>` — вызывает `CatalogRepository.findCategoryTree(tenantId)`
   (DTJ-092), прогоняет через `CategoryTreeService.validateDepth()`, при `Err` логирует
   `pino.warn({ tenantId }, 'category_tree_depth_exceeded')`, НЕ бросает наружу (деградация без
   падения эндпоинта).
3. `presentation/controllers/categories.controller.ts` — `GET /api/v1/categories`: без пагинации
   (SRS-CAT-004, ≤200 узлов ожидаемо), формат ответа `{ data: CategoryDto[] }` (SRS-API-014).
4. `presentation/dto/category.dto.ts` — `{ id, parentId, slug, name: {tj,ru,en}, sortOrder,
   childrenCount }` (childrenCount вычисляется в use case/мапере, не хранится в БД).
5. Кэширование (Redis, TTL 6ч, ключ `catalog:categories:{tenantId}`, SRS-CAT-058) — ВНЕ этого тикета
   (Redis-инфраструктура и `CacheModule` заводятся отдельным сквозным тикетом EP-01/EP-19 либо первым
   потребителем кэша; если к моменту реализации `CacheModule` уже доступен — подключить декоратором
   `@Cacheable`, иначе — TODO с явной ссылкой на SRS-CAT-058, не блокировать этот тикет).
6. Добавить `CategoryDto`/`CategoryNode` типы в `packages/contracts/src/catalog.ts` (уже созданный
   файл-скелет DTJ-090, здесь — наполнение конкретными типами дерева категорий).

## Критерии приёмки

- Given `categories` содержит 3-уровневое дерево из 15 записей, When `GET /api/v1/categories`, Then
  `200`, `data` — вложенная структура (не плоский список), корневые узлы имеют `parentId: null`.
- Given одна категория деактивирована (`is_active=false`), When `GET /api/v1/categories`, Then эта
  категория И её потомки отсутствуют в ответе (неактивная ветка полностью скрыта, не только сам узел).
- Given (искусственно, тестовая фикстура) дерево глубже 3 уровней, When
  `GetCategoryTreeUseCase.execute()`, Then лог `category_tree_depth_exceeded` записан, но эндпоинт
  всё равно возвращает `200` с полным деревом (не падает, не обрезает данные молча).
