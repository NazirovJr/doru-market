## Задача

Карточка товара (`GET /medicines/:id`) — целевая страница любого клика по результату поиска или
блоку аналогов. Она обязана скрывать черновики и запрещённые к обороту вещества строже, чем список
поиска (прямой запрос по известному `id` — самый частый вектор попытки обхода), и корректно
резолвить fallback описания tj→ru.

## Технический контекст

`application/use-cases/get-medicine-detail.use-case.ts`, использует `CATALOG_REPOSITORY` (DTJ-092) и
`FIND_ANALOGS_USE_CASE`-подобный вызов (`FindAnalogsUseCase` из DTJ-101, тот же модуль — прямой вызов
класса use case из другого use case внутри ОДНОГО модуля разрешён, `02` §1.2 запрещает только
МЕЖМОДУЛЬНЫЙ обход фасада, не внутримодульную композицию use case'ов). `offers` (цена/остаток по
аптекам) в карточке — поле ответа, но его РЕАЛЬНОЕ наполнение (JOIN на `pharmacy_inventory`/
`pharmacies`) требует того же типа read-модели, что и поиск (EP-06)/аналоги (EP-07, DTJ-101) — этот
тикет ПОТРЕБЛЯЕТ уже готовый `AnalogOfferLookupPort` (DTJ-101) для получения `offers`, не заводит
собственный SQL-путь (DRY, C15 — третий потребитель одной и той же задачи «дай мне офферы по
medicineId в радиусе» переиспользует существующий порт, не дублирует его).

## Что сделать

1. `application/use-cases/get-medicine-detail.use-case.ts` — `GetMedicineDetailUseCase.execute({
   medicineId, locale, radiusMeters?, geo? })`:
   1. `CatalogRepository.findMedicineById(medicineId)` — `null` → `MedicineNotFoundError` (404,
      единообразно, SRS-CAT-006 — ТА ЖЕ ошибка для «не существует» и для «existует, но
      psychotropic/narcotic» — не отличимо снаружи).
   2. Given найдено, но `is_published === false` ИЛИ `controlCategory ∈ {'psychotropic','narcotic'}`,
      Then тоже `MedicineNotFoundError` (SRS-CAT-005, SRS-CAT-006, SRS-DOM-157) — единственное
      исключение: вызывающий с ролью `super_admin`/каталожным оператором обходит это условие (флаг
      `bypassVisibilityCheck: boolean`, передаётся presentation-слоем ТОЛЬКО после проверки роли в
      guard — use case не проверяет роль сам, `02` §3.4, политика авторизации — на границе, не
      внутри use case бизнес-правила видимости).
   3. Резолвит описание: `locale==='tj' ? description_tj || description_ru || null : description_ru ||
      null` (SRS-CAT-008 — фолбэк tj→ru, `en` не существует как поле).
   4. Вызывает `AnalogOfferLookupPort.getOffersForMedicines([medicineId], geo, radiusMeters ??
      MEDICINE_DETAIL_ALL_OFFERS)` — Given `radiusMeters` не передан явно клиентом, Then `offers` —
      ВСЕ активные предложения без ограничения радиусом (SRS-CAT-050 — карточка товара НЕ ограничена
      радиусом поиска по умолчанию, в отличие от списка результатов).
   5. Вызывает `FindAnalogsUseCase.execute({ medicineId, geo, radiusMeters, limit: 1 })` (DTJ-101) —
      `hasAnalogs = result.items.length > 0` (SRS-CAT-050 — тот же use case с `limit=1`, не отдельная
      логика существования).
2. `presentation/controllers/medicines.controller.ts` — `GET /api/v1/medicines/:id` — публичный
   (анонимный доступ разрешён), опциональные query `radiusMeters`, `lat`/`lon`.
3. `presentation/dto/medicine-detail.dto.ts` — маппинг на JSON-контракт SRS-CAT-049 буквально:
   `{ id, tradeName, innName, dosageForm, dosageFormClass, dosageStrength, manufacturerName,
   manufacturerCountry, controlCategory, isPrescriptionRequired, requiresColdChain, imageUrl,
   description, substances, offers, hasAnalogs }`.
4. Плейсхолдер изображения (SRS-CAT-007): given `imageUrl === null`, Then DTO возвращает
   `imageUrl: null` и дополнительное поле `dosageFormClass` (уже есть в ответе) — САМ SVG-плейсхолдер
   рендерится фронтендом по `dosageFormClass` (компонент `packages/ui`, EP-18, вне зоны этого тикета);
   бэкенд лишь гарантирует, что `dosageFormClass` ВСЕГДА присутствует в ответе (не `null`, enum имеет
   значение `'other'` по умолчанию на уровне БД).

## Критерии приёмки

- Given `medicine.controlCategory = 'narcotic'`, известен точный `id`, When `GET /api/v1/medicines/
  :id` анонимно, Then `404 NOT_FOUND` (НЕ `422`) — TC-CAT-017.
- Given `medicine.isPublished = false` (черновик в модерации), When `GET /api/v1/medicines/:id` от
  роли `customer`, Then `404 NOT_FOUND`; When тот же запрос с ролью `super_admin` и явным флагом
  обхода видимости (presentation передал `bypassVisibilityCheck=true` после проверки RBAC), Then
  `200` с данными черновика.
- Given `locale='tj'`, `description_tj` пусто, `description_ru` заполнено, When `GET /medicines/:id`,
  Then `description` в ответе равен `description_ru` (не `null`, не placeholder-строка).
- Given у медикамента есть ≥1 аналог в радиусе, When `GET /medicines/:id`, Then `hasAnalogs: true`;
  given аналогов нет, Then `hasAnalogs: false` — БЕЗ полного списка аналогов в этом ответе (это
  предвычисленный флаг, не embedding).

## Риски и подводные камни

- Прямая зависимость от `DTJ-101` (`FindAnalogsUseCase`, эпик EP-07 в этом же батче) — при выполнении

  явно проверить, что флаг устанавливается ТОЛЬКО после `RolesGuard`-проверки `super_admin`/
  каталожного оператора, не на основании самого факта аутентификации.
- Файл `apps/api/src/modules/catalog/catalog.module.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
