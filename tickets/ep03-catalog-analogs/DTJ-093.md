## Задача

`Medicine` — корневой агрегат каталога (D-07). Без защищённых инвариантов (непустое множество
веществ у опубликованной записи, запрет прямой мутации `control_category` в обход модерации) любая
запись каталога может попасть в публичную выдачу с некорректными/незаконными данными — прямой риск
нарушения REQ-REG-4/5 (запрет дистанционной продажи наркотических/психотропных веществ). Это ядро,
от которого зависят `GetMedicineDetailUseCase` (DTJ-095), `CatalogFacade` (DTJ-096) и
`AnalogEquivalenceService` (DTJ-099).

## Технический контекст

`modules/catalog/domain/medicine.entity.ts` — домен, НОЛЬ импортов фреймворка (`02` §1.1, §2.6):
никаких `drizzle-orm`, `Date.now()`, `Math.random()`. Использует VO `Dosage`/`DosageForm`/`Barcode` из
`packages/domain-kernel` (DTJ-090). Приватный конструктор + фабрики `Medicine.create(cmd)` (новая
запись, `is_published=false` по умолчанию) и `Medicine.restore(record)` (реконструкция из
персистентности, вызывается ТОЛЬКО адаптером `infrastructure/mappers/medicine.mapper.ts`, DTJ-092) —
`02` §2.2.

## Что сделать

1. `domain/medicine-substance.entity.ts` — value entity `MedicineSubstance { substanceId: string;
   strengthValue: number; strengthUnit: DosageUnit }` (immutable, `readonly`-поля, C13).
2. `domain/medicine.entity.ts` — `class Medicine`:
   - Приватные поля: `id`, `tradeName`, `innName`, `barcode: Barcode | null`, `categoryId`,
     `dosageForm: DosageForm`, `dosageStrengthRaw: string` (исходная строка для отображения,
     SRS-CAT-005..009), `manufacturerCountry`, `manufacturerName`, `isPrescriptionRequired: boolean`,
     `controlCategory: ControlCategory` (default `'none'`), `substances: readonly
     MedicineSubstance[]`, `isPublished: boolean`, `isGloballyIdentifiableByBarcode: boolean`,
     `requiresColdChain: boolean`.
   - `Medicine.create(cmd): Result<Medicine, InvalidMedicineStateError>` — конструирует с
     `controlCategory='none'`, `isPublished=false`; бросает `InvalidMedicineStateError`, если на входе
     `controlCategory` уже в `{potent,psychotropic,narcotic}` без `isPrescriptionRequired=true`
     (SRS-DOM-015 — инвариант конструктора, дублирует CHECK БД из DTJ-091 как второй рубеж, SRS-CAT-055).
   - `medicine.publish(): Result<void, MissingSubstancesError>` — переводит `isPublished=true`; бросает
     `MissingSubstancesError`, если `substances.length === 0` (SRS-DOM-013); публикует
     `MedicinePublishedEvent` (application-уровня — метод возвращает событие в результате, само
     событие в outbox кладёт use case/facade, домен НЕ пишет в БД, `02` §2.6).
   - `medicine.addSubstance(substanceId: string, strength: Dosage): void` — добавляет к массиву
     `substances` (используется до публикации, при курации черновика).
   - `medicine.proposeControlCategory(category: ControlCategory, actor: UserId):
     NewControlCategoryCandidateEvent` — НЕ мутирует `controlCategory` синхронно (SRS-DOM-014);
     единственный способ инициировать смену — возвращает доменное событие, которое application-слой
     кладёt в outbox для `moderation`. Прямого сеттера `medicine.controlCategory = ...` не существует.
   - `medicine.attachBarcode(raw: string): Result<void, never>` — парсит через `Barcode.parse`,
     устанавливает `isGloballyIdentifiableByBarcode = barcode.isValidEan13() &&
     !barcode.isInternalPrefix()` (SRS-DOM-016).
   - Геттеры для всех полей (без публичных сеттеров, `02` §2.1).
3. `domain/errors/*.error.ts` — три класса ошибок, наследники `DomainError`
   (`packages/contracts`/`domain-kernel`, DTJ-090 — если базовый класс там уже есть, наследоваться от
   него; если нет — создать локальный `abstract class DomainError extends Error` в этом же файле как
   временное решение с TODO-комментарием на перенос).
4. `domain/events/medicine-published.event.ts`, `new-control-category-candidate.event.ts` — плоские
   `readonly`-структуры данных (`{ medicineId, publishedAt }` / `{ medicineId, proposedCategory,
   actorId, proposedAt }`), без методов.

## Критерии приёмки

- Given `Medicine.create({ substances: [] })`, When `medicine.publish()`, Then возвращается `Err(new
  MissingSubstancesError(...))`, `isPublished` остаётся `false`.
- Given `Medicine.create({ substances: [{substanceId:'x', strengthValue:500, strengthUnit:'mg'}] })`,
  When `medicine.publish()`, Then `Ok(undefined)`, `isPublished === true`, возвращённое событие —
  `MedicinePublishedEvent` с корректным `medicineId`.
- Given опубликованный `medicine` с `controlCategory='none'`, When
  `medicine.proposeControlCategory('narcotic', actorId)`, Then `controlCategory` на сущности
  НЕ меняется (остаётся `'none'`), возвращается `NewControlCategoryCandidateEvent` с
  `proposedCategory='narcotic'` — прямой попытки присвоения (`medicine.controlCategory = 'narcotic'`)
  не существует в публичном API класса (проверяется TypeScript-компиляцией — приватное поле).
- Given `Medicine.create({ controlCategory: 'potent', isPrescriptionRequired: false })` (некорректный
  вход), Then фабрика возвращает `Err(new InvalidMedicineStateError(...))`, объект не создаётся.

## Риски и подводные камни

- `DomainError` базовый класс может ещё не существовать на момент выполнения этого тикета (зависит от
  того, успел ли EP-01 его завести в `packages/contracts`) — см. п.3 «Что сделать», временное решение
  с TODO обязательно, чтобы не блокировать тикет ожиданием другой команды, но и не создавать
  постоянного дублирования.
- `medicine.publish()`/`proposeControlCategory()` возвращают события, но НЕ публикуют их в outbox —
  ответственность за фактическую публикацию (транзакционная запись в `outbox`) лежит на use case,
  вызывающем эти методы (DTJ-096/DTJ-097) — если разработчик по ошибке решит публиковать событие
  прямо из домена (импорт BullMQ/outbox-репозитория в `domain/`), это блокирующее нарушение §1.1,
  проверяемое `dependency-cruiser`.
- Диагональная матрица совместимости форм (SRS-CAT-032/033) НЕ реализуется в `Medicine`/`DosageForm`
  как отдельный метод здесь — она уже покрыта `DosageForm.isEquivalentTo()` из DTJ-090; дублировать её
  в `Medicine` не нужно (DRY, C15).
