## Задача

Каждый Value Object и state machine, описанные в `docs/spec/10-domain-model.md`, используют
`Result<T, E>` вместо исключений на «ожидаемый» пользовательский ввод и НИКОГДА не читают время или
генерируют идентификаторы напрямую (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §2.6: «домен чист... без
`Date.now()`, `Math.random()`»). Этот тикет создаёт «нулевой слой» доменного ядра — общий для ВСЕХ
последующих модулей (`orders`, `payments`, `catalog`, …), а не только для `auth`. Без него ни один VO
(`Money`, `OtpCode`, …), заводимый следующими тикетами этого же эпика, не имеет базового типа для
возврата ошибки валидации.

## Технический контекст

`apps/api/src/shared-kernel/**` — новая директория, НЕ являющаяся `modules/<context>`; это осознанный
Shared Kernel (общее доменное ядро, паттерн DDD), необходимый, потому что `Money`, `PhoneNumber`,
`GeoPoint`, `OtpCode` и т.д. используются МНОЖЕСТВОМ будущих модулей одновременно — помещение их
внутрь одного `modules/<context>/domain` и последующий импорт из других модулей нарушил бы
`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.1 («любой модуль импортирует `../<другой-модуль>/domain` —
нарушение границ контекста»). `shared-kernel` — не модуль в этом смысле, импортируется ЛЮБЫМ
`modules/<context>` наравне с `packages/contracts`, но живёт внутри `apps/api` (не отдельный pnpm-пакет,
т.к. VO активно используют доменную бизнес-логику, не предназначенную для frontend/Dart-потребления —
в отличие от `packages/contracts`, который именно поэтому остаётся отдельным пакетом).

`SRS-DB-001`: новые сущности используют UUID v7 (монотонный, лучше для B-tree-локальности), генерация —
ИСКЛЮЧИТЕЛЬНО через `IdGeneratorPort`, не `crypto.randomUUID()` напрямую внутри домена. `SRS-API-008`:
конвертация UTC↔`Asia/Dushanbe` — исключительно на границе `infrastructure`
(`ClockPort.nowInTenantTz()`), никогда в domain/application напрямую через `Date.now()`.

## Что сделать

1. `result.ts`: `type Result<T, E> = { ok: true; value: T } | { ok: false; error: E }` + фабрики
   `Result.ok(value)`/`Result.err(error)` + утилиты `isOk`/`isErr` (type guards), `map`/`mapErr`
   (без монадической навороченности — минимум, реально используемый VO-парсерами следующих тикетов).
2. `clock.port.ts`: `interface ClockPort { now(): Date; nowInTenantTz(tz: string): Date }` — `now()`
   возвращает `Date` в UTC (внутреннее хранение всегда UTC, `SRS-DB-002`), `nowInTenantTz` — та самая
   единственная легальная точка конвертации в `Asia/Dushanbe` (`SRS-API-008`), принимает IANA-таймзону
   как параметр (не хардкодит `Asia/Dushanbe` внутри порта — конкретное значение передаёт вызывающий
   код через `tenant_settings`/константу, порт универсален).
3. `system-clock.adapter.ts`: `SystemClockAdapter implements ClockPort` — `now()` через
   `new Date()`, `nowInTenantTz` через `Intl.DateTimeFormat` с переданной `timeZone`. Единственное
   место в проекте, где системное время читается напрямую (комментарий в файле, объясняющий, почему
   ESLint-правило C6/`no-restricted-globals` для `Date.now()` в `domain/`/`application/` НЕ
   применяется к ЭТОМУ конкретному файлу — он `infrastructure`).
4. `id-generator.port.ts`: `interface IdGeneratorPort { generate(): string }` — возвращает UUID v7
   как строку.
5. `uuid-v7-id-generator.adapter.ts`: `UuidV7IdGeneratorAdapter implements IdGeneratorPort` — через
   пакет, генерирующий UUID v7 (например `uuid` версии с поддержкой `v7()` — сверить фактическую
   версию `01-TECH-BASELINE.md` на момент реализации; если пакет `uuid` в зафиксированной версии не
   поддерживает v7 — реализовать вручную по RFC 9562 §5.7, не откладывать на «потом»).
6. `shared-kernel.module.ts`: NestJS-модуль, регистрирующий `ClockPort`/`IdGeneratorPort` DI-токены
   (`Symbol('ClockPort')`/`Symbol('IdGeneratorPort')`) на конкретные адаптеры через
   `{ provide: TOKEN, useClass: ... }` (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.3), экспортирует оба —
   импортируется ЛЮБЫМ `modules/<context>.module.ts`, которому нужны время/идентификаторы.
7. `index.ts`: барабанный экспорт `Result`, портов (интерфейсы+токены), `SharedKernelModule`. Домен
   `modules/<context>/domain/**` импортирует ТОЛЬКО типы (`Result`, интерфейсы портов) отсюда — НИКОГДА
   адаптеры (`infrastructure`-детали не протекают в domain, даже общего ядра).

## Критерии приёмки

1. **Given** `SystemClockAdapter.now()`, **When** вызван дважды подряд, **Then** второе значение
   `>=` первого (монотонность в пределах системных часов — базовая санити-проверка, не строгая
   гарантия против NTP-корректировки).
2. **Given** `UuidV7IdGeneratorAdapter.generate()` вызван 1000 раз, **When** значения отсортированы
   лексикографически, **Then** порядок совпадает с порядком вызовов (свойство time-ordered UUID v7).
3. **Негативный:** **Given** `Result.err(someError)`, **When** код по ошибке пытается прочитать
   `.value` без предварительной проверки `isOk`, **Then** TypeScript отказывается компилировать
   (дискриминированное объединение `ok`/не `ok` — проверяется через `// @ts-expect-error` тест-кейс
   с описанием, C7).

## Тест-план

- Unit: `Result` — `map`/`mapErr` на `ok`/`err` ветках, type-guard корректность.
- Unit: `SystemClockAdapter.nowInTenantTz('Asia/Dushanbe')` — известная UTC-дата конвертируется в
  ожидаемое локальное время (UTC+5, без перехода на летнее — фиксированный оффсет, `SRS-DB-002`).
- Unit: `UuidV7IdGeneratorAdapter` — формат (валидный UUID), монотонность по времени (см. приёмку 2).
- Порог покрытия `domain/` (`result.ts`, порты) — ≥90% (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §6.4);
  `infrastructure/` (адаптеры) — ≥70%.

## Риски и подводные камни

- `dependency-cruiser` конфиг (`.dependency-cruiser.cjs`, владелец — EP-19) на момент этого тикета уже
  существует (`docs/STATE-AND-RESUME-POINT.md` §2.3 «проверено на живых нарушениях»), но НЕ содержит
  специфичных правил для `shared-kernel/` (новая директория вне `modules/<context>`) — риск, что
  правило «`domain` не импортирует `infrastructure`» технически не покрывает `shared-kernel/domain` из
  коробки. Если конфиг не подхватывает директорию автоматически по общему паттерну `**/domain/**` —
  завести отдельный follow-up к владельцу EP-19 (не трогать `.dependency-cruiser.cjs` самостоятельно,
  правило `tickets/00-EPICS.md` §«Пересекающееся владение» п.5 — корневые конфиги трогает только EP-19).
- UUID v7 поддержка конкретной версией пакета `uuid`, зафиксированной на момент реализации, может
  отличаться от предположения этого тикета — сверить фактически установленную версию перед
  реализацией шага 5, при необходимости implement вручную (RFC 9562 §5.7 — не сложный алгоритм:
  48-битный unix ms timestamp + версия/вариант + случайные биты).
- Файл `apps/api/src/shared-kernel/shared-kernel.module.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `apps/api/src/shared-kernel/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
