## Задача

Четыре VO, без которых движок аналогов по МНН (EP-07, единственное признанное защитимое УТП продукта,
`04-SCOPE-DECISION-PIVOT.md` R1-1) не может определить эквивалентность двух препаратов, а модуль
доставки (EP-13) не может посчитать расстояние до клиента. Это не auth-специфичные VO, но
`shared-kernel` — общий для всего backend, и `10-domain-model.md` фиксирует их как «полный список
обязательных VO» в одном разделе — логично завести их одним тикетом того же эпика, который создаёт
сам `shared-kernel` (DTJ-006), не дробя дальше.

## Технический контекст

`GeoPoint` — координаты с валидацией диапазона + мягкая проверка «похоже на Таджикистан» (не
блокирует). `Barcode` — EAN-13 с контрольной цифрой по алгоритму GS1, префикс `2` — внутренний код
продавца (D-06), НЕ используется как единственный ключ сопоставления между аптеками разных сетей.
`Dosage`/`DosageForm` — разбор дозировки и формы выпуска для точного (без допуска) сравнения
эквивалентности при подборе аналогов (D-07).

## Что сделать

1. `geo-point.vo.ts`: `GeoPoint.create(lat: number, lon: number): Result<GeoPoint, InvalidCoordinatesError>`
   — `lat ∈ [-90, 90]`, `lon ∈ [-180, 180]` (SRS-DOM-072). `geoPoint.isLikelyWithinTajikistan(): boolean`
   — мягкая проверка bbox `lat 36.6–41.1`, `lon 67.3–75.2` — используется ТОЛЬКО для UX-предупреждения,
   НЕ блокирует сохранение (GPS-дрейф/приграничные районы реальны). `geoPoint.distanceTo(other: GeoPoint):
   number` (метры) — формула гаверсинуса (SRS-DOM-073), радиус Земли — именованная константа
   `EARTH_RADIUS_METERS = 6_371_000` (не магическое число, C6).
2. `barcode.vo.ts`: `Barcode.parse(raw: string): Barcode` — конструктор НЕ бросает исключение на
   невалидный штрихкод (SRS-DOM-074: «несовпадение — `isValidEan13() === false`, НЕ исключение»,
   отличие от остальных VO этого пакета — специально задокументировать в JSDoc класса, почему тут
   ИНАЧЕ, чем у прочих `parse()`, возвращающих `Result`). Алгоритм контрольной цифры GS1: для
   `d1..d12` (первые 12 цифр 13-значной строки) `S = Σ(нечётные позиции ×1) + 3×Σ(чётные позиции
   ×3)`, `d13_expected = (10 - (S % 10)) % 10`; `barcode.isValidEan13(): boolean` — длина ровно 13 цифр
   И `d13 === d13_expected`. `barcode.isInternalPrefix(): boolean` — `true`, если первая цифра `'2'`
   (SRS-DOM-075). Строки длиной ≠13 — `barcode.format === 'non_ean13'` (SRS-DOM-076), не ошибка;
   `barcode.rawValue: string` сохраняет исходную строку для аудита в любом случае.
3. `dosage.vo.ts`: `Dosage.parse(raw: string): Result<Dosage, ValidationError>` — разбор строк вида
   `"500 мг"`/`"10 мг/мл"` на `{ value: number; unit: DosageUnit }`
   (`DosageUnit = 'mg'|'mcg'|'g'|'ml'|'iu'|'percent'|'mg_per_ml'`, SRS-DOM-077).
   `dosage.isEquivalentTo(other: Dosage): boolean` — эквивалентность ТОЛЬКО внутри одного семейства
   единиц: масса (`mg`/`mcg`/`g` — конвертация ЦЕЛОЧИСЛЕННО через `bigint`-множитель, `1 g = 1000 mg =
   1_000_000 mcg`, без float), объём (`ml`, не конвертируется в массу), активность (`iu`, не
   конвертируется ни во что); сравнение строгое, БЕЗ допуска `±10%` по умолчанию — константа
   `DOSAGE_EQUIVALENCE_TOLERANCE_PCT = 0`, явно конфигурируемая (SRS-DOM-078), но с дефолтом `0`.
4. `dosage-form.vo.ts`: `DosageForm.parse(raw: string): Result<DosageForm, ValidationError>` —
   укрупнённые классы `'tablet'|'capsule'|'syrup'|'injection'|'ointment'|'drops'|'inhaler'|
   'suppository'|'other'`; `dosageForm.isEquivalentTo(other): boolean` — точное совпадение класса
   (SRS-DOM-079).
5. `invalid-coordinates.error.ts`: расширяет `DomainError`, `ErrorCode.INVALID_COORDINATES`
   (уже есть в каталоге DTJ-005 §2.1 транспортного документа — сверить точное имя при реализации).

## Критерии приёмки

1. **Given** известный валидный EAN-13 (например `4870204347364`), **When**
   `Barcode.parse(...).isValidEan13()`, **Then** `true`; **Given** та же строка с изменённой
   последней цифрой, **When** та же проверка, **Then** `false`, но `Barcode.parse(...)` НЕ бросает
   исключение в обоих случаях.
2. **Given** `Dosage.parse("1 g")` и `Dosage.parse("1000 mg")`, **When**
   `.isEquivalentTo(...)` в обе стороны, **Then** `true`. **Given** `Dosage.parse("500 mg")` и
   `Dosage.parse("500 ml")`, **When** `.isEquivalentTo(...)`, **Then** `false` (разные семейства
   единиц, масса ≠ объём).
3. **Негативный:** **Given** `GeoPoint.create(91, 50)` (широта вне диапазона), **When** вызов, **Then**
   `Result.err(InvalidCoordinatesError)`.

## Тест-план

- Unit `GeoPoint`: граничные значения диапазона (89.999/90/90.001), `isLikelyWithinTajikistan` —
  внутри/снаружи bbox (не блокирует ни в каком случае), `distanceTo` — известная пара координат с
  заранее посчитанным ожидаемым расстоянием (например Душанбе↔Худжанд, допуск погрешности формулы).
- Unit `Barcode`: ≥3 валидных EAN-13 из реальных фарм-товаров (контрольная цифра верна), ≥2 с испорченной
  контрольной цифрой, ≥2 с префиксом `2` (`isInternalPrefix() === true`), ≥1 строка длиной ≠13
  (`format === 'non_ean13'`, `isValidEan13() === false`, без исключения).
- Unit `Dosage`: конвертация `mg↔mcg↔g` в обе стороны, `ml`/`iu` НЕ конвертируются ни во что,
  `isEquivalentTo` с разными единицами одного семейства и разных семейств.
- Unit `DosageForm`: все 9 классов парсятся, невалидная строка — `Result.err`.
- Порог покрытия `domain/` — ≥90%.

## Риски и подводные камни

- `Barcode.parse()` намеренно НЕ возвращает `Result` (в отличие от остальных VO этого пакета) —
  риск, что будущий разработчик по аналогии «исправит» на `Result` без понимания, зачем сделано
  иначе (штрихкод из 1С-выгрузки не должен ронять весь батч на одной кривой строке, D-06). JSDoc
  обязателен, чтобы риск не материализовался в code review будущих эпиков.
- Таблица реальных EAN-13 для тестов — нужно взять реально валидные штрихкоды (посчитать контрольную
  цифру вручную по алгоритму, не выдумывать случайные 13 цифр, которые могут случайно оказаться
  валидными/невалидными непреднамеренно) — риск ошибки в тестовых фикстурах, а не в самом коде.
