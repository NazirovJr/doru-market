## Задача

Четыре контроллера auth подставляют `ipAddress = '0.0.0.0'` («Real IP извлекается в EP-19») — EP-19 закрыт,
заглушка осталась. Лимит OTP «N запросов в час с одного IP» (`OTP_REQUEST_MAX_PER_IP_PER_HOUR`) на проде становится
ОБЩИМ для всех пользователей: после N запросов кода в час войти не сможет никто. Сессии пишут неверный IP.
Найдено координатором при приёмке DTJ-442 (2026-09-29).

## Что сделать

1. Общий хелпер IP клиента поверх `request.ip` Fastify (trustProxy уже настроен в main.ts на число хопов nginx),
   использовать во всех четырёх контроллерах; заглушки удалить.
2. Проверить, что глобальный rate-limit (DTJ-432) и лимитер OTP берут тот же IP.

## Критерии приёмки

1. Given два клиента с разными X-Forwarded-For за доверенным прокси, When каждый исчерпывает свой лимит OTP по IP,
   Then лимит одного не влияет на другого (интеграционный тест).
2. Given запрос без прокси, Then IP = адрес сокета; подделанный X-Forwarded-For от недоверенного источника не принимается.
3. В БД сессий пишется реальный IP.
