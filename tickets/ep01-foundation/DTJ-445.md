## Задача

Аудит R1 (DTJ-001): Dockerfile api не копирует `packages/domain-kernel` (и, возможно, другие workspace-пакеты —
`testing-kit` теперь devDependency, `contracts`, `i18n`) в `deps`/`build`-стадии, хотя api объявляет их зависимостями —
`docker build` не пройдёт; `docker-entrypoint.sh` вызывает `drizzle-kit migrate` напрямую вместо рабочего
`pnpm db:migrate`/`migrate.ts`; `drizzle-kit` не в prod-срезе; runtime-образ не содержит `migrations/*.sql`.
Прод-контейнер не соберётся и не применит миграции. То же проверить для worker-таргета.

## Что сделать

1. Исправить Dockerfile(ы) api/worker: все нужные workspace-пакеты, сборка, prod-срез зависимостей, миграции в образе.
2. Миграции при старте — тем же `migrate.ts`, что локально (ролью мигратора, как в compose `migrate`).
3. РЕАЛЬНО собрать образы (`docker compose -f infra/docker/docker-compose.yml build api worker`) и поднять стек в отдельном
   compose-проекте на свободных портах (не 5432/6379/6380/3000/3300 — они заняты), убедиться: миграции применились, `/ready` 200.
   Контейнеры создавать с именем проекта `dorutj-imgcheck` и удалить после проверки (`down -v`); контейнеры dorutj-* не трогать.

## Критерии приёмки

1. `docker build` api и worker проходит с чистого клона.
2. Стек из собранных образов на чистой БД: миграции применены, `GET /ready` → 200, worker `/health` → 200.
3. Вывод сборки и проверки — в отчёте.
