## Задача

Каждая последующая таблица (`users`, `medicines`, `orders`, ...) требует уже работающего конвейера
`drizzle-kit generate → migrate`, единой команды применения и включённых PostgreSQL-расширений
(`pgcrypto` для `gen_random_uuid()`, `pg_trgm`/`unaccent` для будущего поиска EP-06, `btree_gin` для
композитных индексов). Без этого тикета ни один следующий тикет со схемой (DTJ-013..017 этого же
эпика, а транзитивно — вообще любая таблица любого эпика) не имеет куда писать миграцию.

## Технический контекст

`SRS-DB-007`: расширения — обязательны в ПЕРВОЙ миграции `0001_extensions.sql`: `pgcrypto`, `pg_trgm`,
`unaccent`, `btree_gin`. `SRS-DB-031`: `drizzle-kit generate` (schema-first, TS-схема — источник
истины); ручные миграции (расширения, кастомные типы, триггеры) — через `drizzle-kit generate --custom`,
не через попытку выразить их в TS. `SRS-DB-032`: единственная команда применения — `pnpm db:migrate`
(`drizzle-kit migrate`), НИКОГДА `drizzle-kit push` вне локального прототипирования разработчика ДО
первого коммита схемы. `SRS-DB-034`: каждая миграция, изменяющая существующую таблицу, обязана иметь
`*.down.sql`; чисто `CREATE TABLE`/`CREATE TYPE` — тривиальный `down`
(`DROP TABLE/TYPE IF EXISTS ...`).

## Что сделать

1. `apps/api/drizzle.config.ts`: `defineConfig({ schema: './src/infrastructure/db/schema/*.schema.ts',
   out: './migrations', dialect: 'postgresql', dbCredentials: { url: process.env.DATABASE_URL } })`.
2. `apps/api/src/infrastructure/db/index.ts`: экспорт `db` — `drizzle(pool, { schema })`, пул `pg.Pool`
   с `DB_POOL_MAX`/`DB_CONNECT_TIMEOUT_MS` из ENV (сверить с `env.schema.ts` DTJ-001 — добавить эти
   переменные туда же, не заводить параллельную схему валидации ENV).
3. `apps/api/src/infrastructure/db/migrate.ts`: программный раннер `drizzle-kit migrate` для вызова
   из `docker-entrypoint.sh` (DTJ-001) и из CI; логирует список применённых файлов.
4. `apps/api/migrations/0001_extensions.sql` (custom-миграция, `drizzle-kit generate --custom`):
   ```sql
   CREATE EXTENSION IF NOT EXISTS pgcrypto;
   CREATE EXTENSION IF NOT EXISTS pg_trgm;
   CREATE EXTENSION IF NOT EXISTS unaccent;
   CREATE EXTENSION IF NOT EXISTS btree_gin;
   ```
5. `apps/api/migrations/0001_extensions.down.sql`: `DROP EXTENSION IF EXISTS btree_gin; DROP EXTENSION
   IF EXISTS unaccent; DROP EXTENSION IF EXISTS pg_trgm; DROP EXTENSION IF EXISTS pgcrypto;` (обратный
   порядок).
6. `apps/api/package.json`: скрипты `db:generate` (`drizzle-kit generate`), `db:migrate`
   (`tsx src/infrastructure/db/migrate.ts`), `db:push` (`drizzle-kit push`, помечен в README как
   «только для локального прототипирования ДО коммита схемы», `SRS-DB-032`), `db:studio`
   (`drizzle-kit studio`).

## Критерии приёмки

1. **Given** пустая тестовая БД Postgres 16, **When** `pnpm db:migrate`, **Then** все четыре
   расширения (`pgcrypto`, `pg_trgm`, `unaccent`, `btree_gin`) присутствуют в
   `SELECT extname FROM pg_extension`.
2. **Given** миграции уже применены, **When** `pnpm db:migrate` запущен повторно, **Then** команда
   идемпотентна — не падает, не пытается применить уже применённые файлы повторно (журнал
   `drizzle/meta/_journal.json` отслеживает состояние).
3. **Негативный:** **Given** `DATABASE_URL` указывает на недоступный хост, **When** `pnpm db:migrate`,
   **Then** команда завершается с ненулевым кодом и понятным сообщением, не висит бесконечно (таймаут
   подключения).

## Тест-план

- Integration (реальный Postgres 16 в docker/testcontainers): применение `0001_extensions.sql` на
  чистой БД, повторный прогон идемпотентен, откат через `.down.sql` убирает расширения без ошибки
  (при отсутствии зависимых объектов).
- Coverage — неприменимо строго (инфраструктурные SQL-файлы + тонкий раннер); раннер `migrate.ts`
  покрыт unit-тестом на обработку ошибки подключения (мок пула).

## Риски и подводные камни

- `postgis`, упомянутый в иллюстративном списке миграций `11-database-schema.md` §«Порядок миграций»
  (`0001_extensions.sql -- pgcrypto, pg_trgm, unaccent, btree_gin, postgis (для GEOGRAPHY)»), явно
  противоречит перечню обязательных расширений из `SRS-DB-007` (`pgcrypto`, `pg_trgm`, `unaccent`,
  `btree_gin` — без postgis) — расхождение между двумя частями ОДНОГО документа. Решение этого
  тикета: следовать `SRS-DB-007` (пронумерованное `Must*`-требование) как более авторитетному, чем
  комментарий в иллюстративном списке; `postgis`/тип `GEOGRAPHY` НЕ включается — координаты в проекте
  везде представлены `NUMERIC(10,8)/NUMERIC(11,8)` + VO `GeoPoint` (DTJ-009) с гаверсинусом в
  application-коде, отдельный geo-тип БД не требуется ни одному прочитанному разделу схемы. Если
  выяснится обратное при реализации EP-08 (карта аптек) — доб авление `postgis` отдельной миграцией
  не потребует переделки этого тикета.
- `drizzle-kit generate --custom` — фактическое имя CLI-флага нужно сверить с версией `drizzle-kit
  ^0.31.10`, зафиксированной в `01-TECH-BASELINE.md`, на момент реализации (в разных минорных версиях
  флаг для «пустой»/ручной миграции мог называться иначе).
- Файл `apps/api/src/infrastructure/db/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `apps/api/package.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
