## Задача

`packages/contracts` — единственный источник правды для кодов ошибок, permission-строк RBAC и формата
пагинации, общий и для backend (`apps/api`), и для frontend (`apps/web`/`apps/admin`/...), и в
перспективе для Dart-клиентов через генератор OpenAPI (`SRS-API-060/063`). `tickets/00-EPICS.md`
фиксирует правило: EP-01 владеет барабанным `index.ts` и «общими файлами» (`errors.ts`,
`permissions.ts`) НАВСЕГДА — остальные эпики НЕ заводят свои файлы ошибок/прав, а используют уже
готовый каталог. Это возможно, потому что оба каталога уже ПОЛНОСТЬЮ специфицированы архитектором
(`10-domain-model.md` §«Доменные ошибки», `12-api-conventions-auth-tenancy.md` §2.1 и §4.1) — не
требуют додумывания, только точной транскрипции. Каждый последующий эпик добавляет СВОЙ файл в
подпапку (`src/inventory/`, `src/analogs/`, `src/payments/`, …) для DTO/Zod-схем конкретного модуля и
одну строку экспорта в баррель — это уже НЕ зона этого тикета.

## Технический контекст

`SRS-API-014/015`: успешный ответ — `{ data, meta? }`, ошибка — `{ error: { code, message, details? } }`.
`SRS-API-016`/`SRS-DOM-153`: маппинг ошибка→код происходит в ЕДИНОМ месте (`DomainExceptionFilter` +
`TransportExceptionFilter`, реализация — DTJ-018 этого же эпика), но САМ каталог кодов и классов
ошибок — это пакет. `SRS-API-004/005/006/007`: cursor-пагинация, `sort`/`filter` query-конвенции —
типы и Zod-хелперы, переиспользуемые каждым списковым эндпоинтом любого модуля. `SRS-API-038`:
формат permission-строки `<resource>:<action>[:<scope>]`.

   в начале файла, объясняющим правило добавления новых файлов (см. «Задача»).

## Критерии приёмки

1. **Given** любой класс из `domain-errors.ts`, **When** `new SomeError(...)`, **Then**
   `error.code === ErrorCode.SOME_CODE` и `ERROR_HTTP_STATUS[error.code]` возвращает HTTP-код,
   совпадающий с таблицей источника (проверяется тестом-сверкой, не вручную).
2. **Given** `encodeCursor({ v: '2026-08-27T00:00:00.000Z', id: 'uuid' })`, **When**
   `decodeCursor(encodeCursor(...))`, **Then** результат равен исходному объекту (round-trip).
3. **Негативный:** **Given** `decodeCursor('not-valid-base64!!!')`, **When** вызов, **Then**
   возвращается `null` (не бросает исключение — вызывающий код сам решает вернуть `400 INVALID_CURSOR`).

## Тест-план

- Unit: тест-сверка «каждый `ErrorCode`, упомянутый в `10-domain-model.md` §«Доменные ошибки» и
  `12-api-conventions-auth-tenancy.md` §2.1, присутствует в enum и имеет запись в
  `ERROR_HTTP_STATUS`» — можно оформить как явный массив-фикстура ожидаемых кодов в тесте, сверяемый
  с `Object.values(ErrorCode)`, чтобы будущее удаление кода не осталось незамеченным.
- Unit: каждый класс `domain-errors.ts` — `instanceof DomainError`, корректный `code`.
- Unit: `encodeCursor`/`decodeCursor` — round-trip, невалидный вход.
- Unit: `PERMISSIONS` — нет дублирующихся строковых значений (`new Set(Object.values(PERMISSIONS)).size === Object.values(PERMISSIONS).length`).
- Coverage — ≥70% (пакет вне domain/application backend, но чисто типовой/константный код —
  реалистично 100%).

## Риски и подводные камни

- Каталог ошибок специфицирован по ДВУМ документам (`10-domain-model.md` и
  `12-api-conventions-auth-tenancy.md`), которые не пересекаются по составу, но пересекаются по духу
  (транспортные коды §2.1 иногда переиспользуют доменные, например `SRS-API-020` явно говорит «домен-код
  переиспользуется здесь» для `INVALID_PHONE_FORMAT») — при добавлении новых кодов последующими
  эпиками ОБЯЗАТЕЛЬНО проверять оба источника на дубли по смыслу, не заводить второй код с тем же
  значением под другим именем.
- Это единственный файл в проекте, который физически ОБЯЗАН расти (`ErrorCode`/`PERMISSIONS`) по мере
  добавления модулей другими эпиками, хотя владеет им EP-01. Практическое разрешение риска
  (зафиксировано и в `tickets/00-EPICS.md` §«Пересекающееся владение» п.3 по аналогии с бареллем):
  последующие эпики добавляют СВОИ значения в конец существующих `enum`/`const` этого же файла (не
  создают отдельные файлы) — конфликт слияния при параллельной разработке решается rebase, не
  архитектурным пересмотром.
- Файл `packages/contracts/package.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `packages/contracts/tsconfig.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `packages/contracts/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
