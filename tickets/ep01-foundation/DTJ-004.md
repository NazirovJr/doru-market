## Задача

Экран OTP-логина (`apps/web`, DTJ-028) обязан не хардкодить ни одной строки (`04-SCOPE-DECISION-PIVOT.md`
§8: «хардкод строки бренда... — блокирующий дефект ревью», распространяется на весь UI-текст по духу
`02-CLEAN-ARCHITECTURE-AND-CODE.md` §5). Полноценные словари всех модулей — зона EP-18, но
`tickets/00-EPICS.md` «Волна 1» явно требует минимальный скелет ПАРАЛЛЕЛЬНО EP-01, «иначе экран
OTP-логина EP-01 хардкодит строки». Этот тикет создаёт именно этот минимум: пакет, хук `useT()`,
три словаря с ключами, реально нужными для `/login` и для канонических пустых/ошибочных состояний
`ux.*`, которые тикеты DTJ-023/024/028 обязаны переиспользовать, а не изобретать текст заново.

## Технический контекст

`SRS-UX-023`: каждый тип типовой ситуации — отдельный ключ словаря вида `ux.<category>.<name>`,
единый на 3 локали. `SRS-UX-027`: локали `tj` (дефолт)/`ru`/`en`, переключатель без авторизации на
всех экранах. Источник канонического текста для OTP-сценариев — `docs/spec/30-ux-screens-and-flows.md`
§5 (ключи `ux.error.otp_expired`, `ux.error.otp_locked` и подобные) и `docs/spec/32-design-reference.md`
§«Реализационные заметки» (таблица расхождений дизайн vs канонический текст — использовать
КАНОНИЧЕСКИЙ, не текст из `.dc.html`).

Полный словарь (`GET /api/v1/i18n/:locale`, `SRS-API-058`) — вне зоны этого тикета: он раздаётся
backend-эндпоинтом, который принадлежит EP-18/API-конвенциям за пределами auth. Здесь —
ФАЙЛОВЫЙ пакет, статически импортируемый `apps/web` до появления серверного эндпоинта (временное
решение, `apps/web` переключится на fetch по мере готовности `GET /api/v1/i18n/:locale` — не задача
этого тикета).

## Что сделать

1. `packages/i18n/package.json` — `name: "@dorutj/i18n"`, `exports` из `src/index.ts`.
2. `packages/i18n/src/dictionaries/{tj,ru,en}.json`: плоская структура `{ "ключ.через.точку": "текст" }`.
   Обязательный минимальный набор ключей (текст — 1:1 из `30-ux-screens-and-flows.md` §5, RU уже дан
   документом дословно; TJ/EN — переводы, помечаются `⚠ требует вычитки носителем` по конвенции
   глоссария `10-domain-model.md`, если переводчика нет под рукой — временный машинный перевод с
   явным комментарием в PR, не тихая заглушка):
   - `brand.name` (плейсхолдер-ключ, значение подставляется тенантом — здесь просто `"DoruTJ"` как
     дефолт нейтрального тенанта, D-01);
   - `auth.login.phone_title`, `auth.login.phone_hint` («Мы отправим код подтверждения по SMS»),
     `auth.login.phone_placeholder`;
   - `auth.login.code_title`, `auth.login.code_sent_to` (с плейсхолдером `{phone}`),
     `auth.login.resend_code`, `auth.login.resend_countdown` (с плейсхолдером `{seconds}`);
   - `ux.error.otp_expired` — «Код устарел. Запросите новый.» (дословно из `SRS-UX-023` §5);
   - `ux.error.otp_locked` — «Слишком много неверных попыток. Запросите новый код через SMS/Telegram.»
     (дословно, канонический текст ПОВЕРХ дизайна — `32-design-reference.md` расхождение №2);
   - `ux.error.otp_mismatch` (с плейсхолдером `{attemptsLeft}`);
   - `ux.error.network_offline`, `ux.error.generic_500` (общие, пригодятся другим экранам).
3. `packages/i18n/src/use-t.ts`: `useT(locale: Locale)` — хук, возвращающий функцию
   `t(key: string, params?: Record<string, string | number>) => string`; интерполяция `{param}` в
   строке словаря; отсутствующий ключ — в dev возвращает `` `[[missing: ${key}]]` `` заметно в UI
   (не тихий фолбэк на английский — пропущенный ключ обязан быть виден на code review/QA), в prod
   — фолбэк на `en`-словарь с `console.warn`.
4. `packages/i18n/src/index.ts`: барабанный экспорт `useT`, `Locale`, словарей.

## Критерии приёмки

1. **Given** `locale='tj'`, **When** `t('ux.error.otp_locked')`, **Then** возвращается таджикский
   канонический текст 1:1 из `30-ux-screens-and-flows.md` §5, не текст дизайн-канваса.
2. **Given** `t('auth.login.code_sent_to', { phone: '+992 90 123 45 67' })`, **When** вызов, **Then**
   плейсхолдер `{phone}` заменён на переданное значение.
3. **Негативный:** **Given** запрошен несуществующий ключ `ux.does.not.exist` в `NODE_ENV=development`,
   **When** `t(...)`, **Then** возвращается заметный маркер `[[missing: ...]]`, а не пустая строка и не
   тихий краш.

## Тест-план

- Unit: `useT` — интерполяция параметров, поведение на отсутствующий ключ (dev vs prod ветки),
  идентичность набора ключей во всех трёх словарях (тест, сверяющий `Object.keys(tj) === Object.keys(ru)
  === Object.keys(en)` — предотвращает «в одном словаре ключ есть, в другом забыли»).
- Coverage — ≥70% (пакет вне domain/application backend).

## Definition of Done

- [ ] `pnpm verify` зелёный локально
- [ ] Три словаря содержат идентичный набор ключей (проверено тестом из тест-плана, не только
  визуально)
- [ ] Каждый ключ, добавленный этим тикетом, реально используется хотя бы одним потребителем
  (DTJ-028) — не заводить ключи «про запас»
- [ ] TJ/EN переводы помечены в PR-описании как черновые (если не вычитаны носителем) — не выдавать
  за финальные

## Риски и подводные камни

- Это НЕ полноценная реализация `packages/i18n` из `04-SCOPE-DECISION-PIVOT.md` R1-14 (серверная
  раздача по `GET /api/v1/i18n/:locale`, полный словарь всех модулей, `tenant_settings`-переопределения
  через `i18n_overrides`) — та зона целиком у EP-18. Этот тикет закрывает ТОЛЬКО минимум для
  OTP-логина, чтобы не блокировать критический путь EP-01→EP-02→EP-03. Явно ожидается, что EP-18
  ПЕРЕПИШЕТ/расширит этот пакет (возможно, сменив статический JSON на серверную раздачу) — не
  проектировать этот API как окончательный, оставить простым.
- Таджикские спецбуквы (`Ғ ғ Ӣ ӣ Қ қ Ӯ ӯ Ҳ ҳ Ҷ ҷ`) — проверить кодировку файла `tj.json` как UTF-8 без
  BOM; риск «буквы превратились в кракозябры» при неверной кодировке редактора — визуально сверить
  после сохранения.
- Файл `packages/i18n/package.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `packages/i18n/tsconfig.json` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
- Файл `packages/i18n/src/index.ts` — barrel (D-27): правится ТОЛЬКО добавлением строки, перечитывать перед правкой, слияние конфликтов — за архитектором.
