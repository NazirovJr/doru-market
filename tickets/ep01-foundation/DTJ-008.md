## Задача

Auth (OTP-логин по номеру телефона) и мультитенантность — два самых ранних по волнам эпика R1 —
оба завязаны на эти три VO с первого запроса: `PhoneNumber` валидирует номер до отправки SMS,
`TenantId`/`TenantSlug` типизируют идентичность тенанта, которую auth обязан записать в `users.tenant_id`
(`SRS-API-017`) уже в DTJ-024 этого эпика, до того как полноценный модуль `tenancy` (EP-02) будет готов.

## Технический контекст

`PhoneNumber` — формат `+992 XX XXX XX XX`, домен хранит канонический вид без пробелов. `TenantId`/
`TenantSlug` принадлежат `shared-kernel`, а не `modules/tenancy/domain`, потому что `users` (модуль
`auth`, EP-01) и `orders`/`payments`/... (другие модули) ссылаются на тенанта, не имея права
импортировать `modules/tenancy/domain` напрямую (`02-CLEAN-ARCHITECTURE-AND-CODE.md` §1.1). Богатую
сущность `Tenant` (агрегат с методами `rename()`, `suspend()` и т.д.) по-прежнему создаёт EP-02 внутри
`modules/tenancy/domain/tenant.entity.ts` — она ИСПОЛЬЗУЕТ эти VO, не наоборот.

## Что сделать

1. `phone-number.vo.ts`: `PhoneNumber.parse(raw: string): Result<PhoneNumber, InvalidPhoneNumberFormatError>`
   — нормализация (удаление пробелов/дефисов/скобок) → валидация `^\+992\d{9}$` (SRS-DOM-069).
   `phoneNumber.operatorHint(): string | 'unknown'` — ASSUMPTION-таблица префиксов Tcell/Babilon-Mobile/
   Megafon Tajikistan/Beeline TJ (информационное поле, НЕ участвует в валидации — незнакомый префикс
   не блокирует, SRS-DOM-070; таблица префиксов — константа в этом же файле с комментарием
   `// ASSUMPTION: таблица префиксов операторов РТ, требует сверки`). `phoneNumber.toDisplayFormat():
   string` → `"+992 XX XXX XX XX"` (SRS-DOM-071 — используется ТОЛЬКО на presentation-уровне, домен
   хранит канонический вид без пробелов через `phoneNumber.value: string`).
2. `tenant-id.vo.ts`: `TenantId` — тонкая обёртка над `UUID` (SRS-DOM-083), `TenantId.parse(raw: string):
   Result<TenantId, ValidationError>` (валидный UUID-формат), `TenantId.equals(other)`.
3. `tenant-slug.vo.ts`: `TenantSlug.parse(raw: string): Result<TenantSlug, ReservedTenantSlugError |
   ValidationError>` — регэксп `^[a-z0-9-]{3,32}$`; зарезервированные значения `'admin'`, `'api'`,
   `'www'` ЗАПРЕЩЕНЫ как slug новой White-Label сети → `ReservedTenantSlugError`; `'neutral'` —
   РАЗРЕШЁН, но ТОЛЬКО через отдельную фабрику `TenantSlug.neutral(): TenantSlug` (константа, не
   `TenantSlug.parse('neutral')` — вызывающий код не должен иметь возможность создать «второй
   neutral» произвольным вызовом `parse`, единственность гарантируется на уровне БД constraint
   `EP-02`, но VO-уровень сигнализирует намерение явно, SRS-DOM-084).
4. `invalid-phone-number-format.error.ts` / `reserved-tenant-slug.error.ts`: расширяют `DomainError`
   из `packages/contracts` (DTJ-005), `ErrorCode.VALIDATION_ERROR` (для телефона — сверить, есть ли
   отдельный `INVALID_PHONE_FORMAT` в каталоге DTJ-005; SRS-API-020 упоминает `400 INVALID_PHONE_FORMAT`
   как «домен-код, переиспользуется» — добавить `INVALID_PHONE_FORMAT` в `ErrorCode` этим тикетом,
   если DTJ-005 к моменту реализации ещё не содержит его явно, тем же правилом «дописать в конец
   существующего enum», зафиксированным в DTJ-005 «Риски»).

## Критерии приёмки

1. **Given** `"+992 90 123 45 67"` (с пробелами), **When** `PhoneNumber.parse(...)`, **Then**
   `Result.ok`, `.value === '+992901234567'` (нормализовано, без пробелов).
2. **Given** `"+7 900 123 45 67"` (российский номер), **When** `PhoneNumber.parse(...)`, **Then**
   `Result.err(InvalidPhoneNumberFormatError)`.
3. **Негативный:** **Given** `TenantSlug.parse('admin')`, **When** вызов, **Then**
   `Result.err(ReservedTenantSlugError)`, а `TenantSlug.parse('admin-pharmacy')` (не точное совпадение
   с зарезервированным словом) — `Result.ok` (зарезервированы только точные значения, не префиксы).

## Тест-план

- Unit `PhoneNumber`: валидные форматы (с пробелами/дефисами/скобками — все нормализуются одинаково),
  невалидные (не тот код страны, не та длина, буквы в номере), `operatorHint()` для известного и
  неизвестного префикса (неизвестный не блокирует — assert `Result.ok`), `toDisplayFormat()`.
- Unit `TenantId`: валидный/невалидный UUID, `equals`.
- Unit `TenantSlug`: валидный slug, слишком короткий/длинный, недопустимые символы, все три
  зарезервированных слова, `TenantSlug.neutral()` возвращает `'neutral'`, а `parse('neutral')`
  — намеренно НЕ равнозначен `neutral()` (задокументировать это явно тестом, чтобы будущий рефакторинг
  не «упростил» два пути в один без обсуждения).
- Порог покрытия `domain/` — ≥90%.

## Риски и подводные камни

- Формат `TenantSlug.parse('neutral')` vs `TenantSlug.neutral()` — тонкое архитектурное решение этого
  тикета (не прописано дословно в SRS, вывод из SRS-DOM-042/084 о том, что нейтральный тенант ровно
  один и неизменяем); если EP-02 при реализации `modules/tenancy` найдёт более подходящий паттерн —
  это открытый вопрос для обсуждения между эпиками, не блокирующий данный тикет.
- Таблица префиксов операторов — ASSUMPTION, не верифицированная у оператора связи; расхождение с
  реальностью не критично (поле информационное, не блокирует регистрацию, SRS-DOM-070 явно это
  разрешает).
