## Задача
Глобальные (не per-tenant) константы — `RATE_LIMIT_*`, `PAYMENT_PROVIDER_TIMEOUT_MS`,
`WS_HEARTBEAT_INTERVAL_MS` — физически являются process-level ENV, требующими передеплоя. Экран
нужен НЕ для их изменения (это была бы иллюзия управляемости), а чтобы `super_admin` мог БЫСТРО
увидеть текущее действующее значение при диагностике инцидента («почему клиент упирается в rate
limit») без доступа к серверу/логам деплоя.

## Технический контекст
Единственный тикет эпика БЕЗ мутирующих эндпоинтов вообще (сознательное архитектурное решение
`SRS-ADM-037`: «чтобы не создавать иллюзию изменяемости того, что на самом деле требует релиза»).
Источник данных — `ConfigService` (`@nestjs/config`, уже используется по всему `apps/api` с
`EP-01`), НЕ БД — этот тикет читает ENV процесса напрямую, не создаёт таблицу настроек.

## Что сделать
1. `GetPlatformSettingsUseCase.execute()` — читает ФИКСИРОВАННЫЙ список ключей через
   `ConfigService.get(key)` (список ключей — константа `PLATFORM_SETTINGS_KEYS` в самом use case,
   НЕ магические строки россыпью, C6), возвращает массив `{ key, currentValue, description,
   requiresRedeploy: true }`.
2. `PlatformSettingsController`: `GET /api/v1/platform-settings` — `@Roles('super_admin')`. `PATCH`
   НЕ реализуется этим тикетом (несмотря на упоминание в `SRS-ADM-037` заголовка «GET/PATCH» — при
   внимательном чтении текста требования `PATCH` относится к `tenant_settings`, не к этому экрану;
   зафиксировать как уточнение в коде-комментарии со ссылкой на этот тикет, чтобы не переоткрывалось).
3. Frontend: `platform-settings-page.tsx` — простая READ-ONLY таблица (ключ, текущее значение,
   описание, статичная иконка/текст «требует передеплоя» рядом с каждой строкой — не глобальный
   баннер один раз, а построчная маркировка, т.к. список может расти со временем и не все будущие
   ключи обязательно ENV-only).

## Критерии приёмки
1. Given `RATE_LIMIT_GLOBAL_MAX` задан в ENV окружения, When `GET /platform-settings`, Then
   значение в ответе СОВПАДАЕТ с реальным ENV (не закешированное на старте процесса значение,
   если процесс перезапускался — `ConfigService` читает актуальное состояние при каждом вызове
   use case, не кеширует на уровне use case).
2. Given `super_admin` открывает экран, When рендерится таблица, Then КАЖДАЯ строка помечена
   «требует передеплоя» — нет ни одной строки без этой пометки (тест на полноту, не выборочно).
3. Given ЛЮБАЯ роль, включая `super_admin`, пытается вызвать `PATCH /api/v1/platform-settings`, When
   маршрутизация, Then `404 NOT_FOUND` (эндпоинт физически не существует).

## Риски и подводные камни
- Список ключей `RATE_LIMIT_*`/`PAYMENT_PROVIDER_TIMEOUT_MS`/`WS_HEARTBEAT_INTERVAL_MS` — примеры
  из `12-api-conventions-auth-tenancy.md`, помечены там `ASSUMPTION`. Точный финальный список ENV-
  переменных, годных для отображения (а какие из них секреты, недопустимые к показу даже
  `super_admin` — например, ключи внешних провайдеров) — уточняется на старте разработки с
  Architect/EP-01: этот тикет ОБЯЗАН явно исключить любые значения, похожие на секрет (по тому же
  списку `packages/contracts/src/sensitive-fields.ts`, вводимому `DTJ-375`, — если тот тикет ещё не
  готов, минимальный локальный список секретных префиксов `*_SECRET`/`*_KEY`/`*_TOKEN` заводится
  здесь как временная мера и заменяется на общий источник, как только `DTJ-375` сдан).
