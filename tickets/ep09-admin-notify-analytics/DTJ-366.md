## Задача
Четыре READ-ONLY отчётных экрана, дающих `pharmacy_admin` полную картину без обращения в
поддержку: продажи за период (GMV, средний чек, топ-10), история выплат, история 1С/Excel/ручных
батчей с ошибками, и здоровье данных остатков (доля просроченных по SLA, доля нулевых, ближайшие к
истечению партии) — последнее нужно, чтобы аптека увидела проблему актуальности данных РАНЬШЕ, чем
её увидит клиент как «данные могут быть неактуальны» (D-04).

## Технический контекст
Все четыре — агрегирующие READ-запросы через `OrdersFacadePort`/`PaymentsFacadePort` (продажи,
выплаты) и `InventoryFacadePort` (история синхронизации, здоровье остатков) — расширяются этим
тикетом. Для CSV/XLSX-выгрузки продаж (`format=csv`) — переиспользует инфраструктуру `DTJ-361`
(`ReportExportPort.renderSync`/`enqueueAsyncExport`), НЕ реализует собственный экспорт-механизм.

## Что сделать
1. Расширить `OrdersFacadePort`/`PaymentsFacadePort`: `getSalesAggregate(pharmacyId, period):
   Promise<{ gmvDiram, orderCount, averageCheckDiram, top10ByRevenue: MedicineRevenueDto[] }>`,
   `getPayoutHistory(pharmacyId, filter: { status?[] }, pagination)`.
2. Расширить `InventoryFacadePort`: `getSyncBatchHistory(pharmacyId, pagination):
   Promise<Page<InventorySyncBatchDto>>` (канал, `syncType`, `acceptedRows/rejectedRows`,
   `completedAt`, ссылка для раскрытия `inventory_sync_errors` конкретного батча),
   `getInventoryHealthReport(pharmacyId): Promise<{ staleSharePercent, zeroStockSharePercent,
   nearExpiryBatches: BatchExpiryDto[] }>` (FEFO — ближайшие к истечению партии).
3. `GetSalesReportUseCase.execute({ pharmacyId, period, format, actor })` — policy владения
   (`pharmacyId ∈ actor.ownPharmacyIds`, кроме `super_admin`); Given `format='csv'` И период ≤31 дня
   → синхронный вызов `ReportExportPort.renderSync` (`DTJ-361`); Given период >31 дня → делегирует
   `RequestReportExportUseCase` (`DTJ-361`), возвращает `202 { exportJobId }`.
4. `GetPayoutsReportUseCase`, `GetInventorySyncHistoryUseCase`,
   `GetInventoryHealthReportUseCase` — READ-ONLY, БЕЗ ветки экспорта у последних двух (эти два
   отчёта не специфицированы документом как экспортируемые, только JSON-просмотр в
   `apps/admin`, `SRS-ADM-048`: «доступно в `apps/admin`, не только как HTTP-ответ»).
5. `PharmacyReportsController`: `GET /api/v1/pharmacy-accounts/:id/reports/sales?period=YYYY-
   MM&format=json|csv`, `GET .../payouts?filter[status][in]=due,paid`, `GET
   .../inventory-sync-history`, `GET .../reports/inventory-health` — все `@Roles('pharmacy_admin',
   'super_admin')`.
6. Frontend: `sales-report-page.tsx` (переключатель периода, hero-цифры GMV/средний чек, таблица
   топ-10, кнопка экспорта — переиспользует `report-export-button.tsx` из `DTJ-361`).
   `payouts-report-page.tsx` (таблица истории выплат, READ-ONLY — управление статусом только через
   доменные переходы, `SRS-ADM-047`, никаких кнопок изменения статуса). `inventory-sync-history-
   page.tsx` (таблица батчей, раскрывающийся список ошибок по клику). `inventory-health-page.tsx`
   (3 метрики + список партий на истечении, Badge `warning`/`danger` по близости даты).

## Критерии приёмки
1. Given период отчёта продаж — 20 дней, `format=csv`, When запрос, Then синхронный поток файла
   (не `202`); Given период — 60 дней, When тот же запрос, Then `202 { exportJobId }` (делегирование
   `DTJ-361` подтверждено интеграционным тестом на границе 31 дня).
2. Given `pharmacy_admin` сети `A` запрашивает отчёт для аптеки сети `B`, When policy проверяется,
   Then `403 CROSS_TENANT_ACCESS_DENIED` для ВСЕХ четырёх эндпоинтов (единый тест на policy,
   параметризованный по эндпоинту).
3. Given батч 1С-синхронизации содержит `rejectedRows > 0`, When история раскрывается, Then видны
   конкретные `inventory_sync_errors` этого батча (не только агрегированное число).
4. Given `staleSharePercent` превышает `INVENTORY_DELTA_SLA_MINUTES`-порог, When рендерится
   `inventory-health-page`, Then метрика визуально помечена `warning`/`danger` (не нейтральным
   цветом — иначе теряется цель «увидеть проблему раньше клиента»).

## Риски и подводные камни
- Жёсткая зависимость от `DTJ-361` — без готовой инфраструктуры экспорта отчёт продаж не может
  корректно ветвиться sync/async; временная заглушка (только sync-путь, игнорируя период) допустима
  как промежуточный шаг разработки, но не финальная сдача.

  `staleSharePercent` относительно `INVENTORY_DELTA_SLA_MINUTES` — уже специфицирована там (D-04),
  этот тикет не переопределяет её, только отображает готовый результат.
