## Задача
`pharmacy_admin` должен видеть СВОИ точки (статус, лицензия, признак «открыто сейчас») и агрегированную
сводку по остаткам (доля просроченных данных, топ-10 оборота) в ОДНОМ месте, без прямого доступа к
детальному экрану ввода остатков (тот принадлежит модулю Catalog/Inventory, вне этого эпика). Экран
— обзорная витрина для владельца/менеджера сети, не операционный инструмент фармацевта.

## Технический контекст
Продолжает контроллер `pharmacy-accounts-admin.controller.ts`, созданный `DTJ-353` (ветка
`scope=own`, разрешена ЖЁСТКИЙ дизайн-выбор: `pharmacy_admin` НЕ может передать произвольный
`chainId` в query для этого эндпоинта — `actor.chainId` резолвится сервером, `SRS-ADM-039`, иначе
одна сеть могла бы читать список точек чужой). Сводка остатков — READ-ONLY витрина поверх
`InventoryFacadePort` (расширяется этим тикетом), НЕ дублирует детальный экран ввода (тот — `EP-05`).

## Что сделать
1. Расширить `OnboardingFacadePort.findPharmacyAccountsAny` веткой `scope=own`: use case ОБЯЗАН
   игнорировать любой переданный клиентом `chainId` при `actor.role==='pharmacy_admin'` и
   резолвить `chainId = actor.chainId` принудительно на сервере (не доверять query-параметру).
2. `ListPharmacyAccountsOwnUseCase` — переиспользует тот же метод порта, что `DTJ-353`, с
   принудительным `chainId`, добавляет `licenseExpiryDate`-предупреждение (`<30 дней` — визуальный
   флаг, синхронизировано с джобой `LicenseExpiryCheckJob`, `EP-03`).
3. Расширить `InventoryFacadePort`: `getInventorySummary(pharmacyId): Promise<{ skuCount,
   staleDataSharePercent, top10ByTurnover: MedicineTurnoverDto[] }>`.
4. `GetInventorySummaryUseCase.execute({ pharmacyId, actor })` — политика: `pharmacyId ∈
   actor.ownPharmacyIds` (application-policy, НЕ guard, `SRS-API-036`), иначе `403
   CROSS_TENANT_ACCESS_DENIED`.
5. Добавить в существующий `pharmacy-accounts-admin.controller.ts` (`DTJ-353`) метод `GET
   /api/v1/pharmacy-accounts/:id/inventory-summary` — `@Roles('pharmacy_admin', 'super_admin')`.
   Ветку `GET /pharmacy-accounts?scope=own` — добавить ВНУТРИ уже существующего метода списка
   (условие `if (query.scope === 'own')`, см. договорённость `DTJ-353`).
6. Frontend: `own-pharmacies-page.tsx` — карточки/таблица своих точек (статус, лицензия с
   предупреждением, признак 24/7), клик на точку раскрывает `inventory-summary` (доля SKU, доля
   просроченных остатков — Badge `warning` при превышении `INVENTORY_DELTA_SLA_MINUTES`).

## Критерии приёмки
1. Given `pharmacy_admin` сети `A` вызывает `GET /pharmacy-accounts?scope=own`, When запрос
   обрабатывается, Then видит ТОЛЬКО точки сети `A`, даже если в query каким-то образом передан
   `chainId` другой сети (параметр игнорируется, не читается use case вовсе для этой роли).
2. Given точка с `licenseExpiryDate = today + 20`, When рендерится обзорный список, Then строка
   помечена визуальным предупреждением (`<30 дней`).
3. Given `pharmacy_admin` сети `A` вызывает `GET /pharmacy-accounts/:id/inventory-summary` для
   `:id`, принадлежащего сети `B`, When policy проверяет владение, Then `403
   CROSS_TENANT_ACCESS_DENIED` — до выполнения самого агрегирующего запроса к `InventoryFacade`.
