## Задача

Аудит R1 (2026-09-28, DTJ-364): форма создания сотрудника в apps/admin шлёт `POST /api/v1/staff-accounts`
(DTJ-030, модуль auth), который не проверяет, что `pharmacyId` принадлежит сети actor'а —
`pharmacy_admin` сети A создаёт `pharmacist` в аптеке сети B и получает `201`. В `staff-account.policy.ts:37-40`
маркер без номера тикета. Прямое нарушение межтенантной изоляции.

## Что сделать

1. Для `pharmacy_admin`: `pharmacyId` (и `chainId`, если передаётся) обязаны принадлежать его сети — проверка через
   фасад onboarding (уже есть `findPharmacyChainId`/аналог); иначе `403 CROSS_TENANT_ACCESS_DENIED`.
   Для `super_admin` — без ограничения сети. Курьеры — через существующий `provisionCourier` (DTJ-364).
2. Убрать маркер без тикета, негативные тесты на каждый путь создания персонала (auth и admin).

## Критерии приёмки

1. Given pharmacy_admin сети A, When создаёт pharmacist в аптеке сети B, Then 403 CROSS_TENANT_ACCESS_DENIED, пользователь не создан.
2. Given pharmacy_admin сети A и аптека сети A, Then 201.
3. Интеграционный тест на реальной БД (оба случая).
