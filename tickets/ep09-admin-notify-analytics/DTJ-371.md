## Задача
Пользователь обязан уметь отключить маркетинговые/дайджестные уведомления и настроить тихие часы —
но НЕ операционные уведомления об активном заказе (`delivery_otp`, `order_updates` для заказа в
процессе) — их отключение сделало бы клиента слепым к собственному курьеру ночью. Это тикет,
защищающий пользователя ОТ САМОГО СЕБЯ (случайного отключения критичного канала), а не только
предоставляющий настройки.

## Технический контекст
`notification_preferences` — **[ДОПОЛНЕНИЕ]**, ОТСУТСТВУЕТ в `11-database-schema.md`, вводится
`27-module-admin-moderation-onboarding.md` §10.1 (`SRS-ADM-058`) дословно. `DispatchNotification
UseCase` (`DTJ-370`) — ПОТРЕБИТЕЛЬ этого тикета: перед постановкой job в очередь (для НЕ-`in_app`
каналов) обязан свериться с `NotificationPreference.resolve(category, channel)` — эта интеграция
дополняет `DTJ-370` ОДНИМ вызовом порта, не переписывает уже сданную логику диспетчера. Единая
таймзона `Asia/Dushanbe` для ВСЕХ тенантов (`SRS-ADM-088`, D-19) — `quiet_hours_start/end` хранятся
как `TIME` БЕЗ явной привязки к часовому поясу пользователя.

## Что сделать
1. Миграция `00XX_notification_preferences.sql` — DDL дословно по `SRS-ADM-058` (`user_id,
   category, channel, is_enabled, quiet_hours_start, quiet_hours_end`, PK составной).
2. `NotificationPreference` (domain): категория→критичность — константа `CRITICAL_CATEGORIES =
   ['order_updates', 'delivery_otp']` (C6 — именованная константа, не строка россыпью). Фабрика
   `NotificationPreference.create()` бросает доменную ошибку `CriticalCategoryCannotBeDisabled
   Error` при попытке `is_enabled=false` для критичной категории — ИНВАРИАНТ защищён на уровне
   домена, не только формой (`SRS-ADM-058`: «принудительно `true` на уровне Zod-схемы формы» —
   Zod ДОПОЛНЯЕТ доменную защиту для мгновенной обратной связи, не заменяет её).
3. `NotificationPreference.shouldSuppressNow(now: DateTime): boolean` — Given
   `quietHoursStart`/`quietHoursEnd` заданы И категория НЕ критична, вычисляет попадание `now`
   (время `Asia/Dushanbe`, порт `Clock`, `02` §2.6) в окно тихих часов (с учётом перехода через
   полночь, например `22:00–08:00`). Критичные категории — метод ВСЕГДА возвращает `false`
   (тихие часы игнорируются полностью, без обращения к полям времени, `SRS-ADM-059`).
4. `GetUserPreferencesUseCase`/`UpdateUserPreferencesUseCase` — `PATCH` игнорирует попытку изменить
   `is_enabled` критичной категории (не ошибка — тихое игнорирование ЭТОГО ПОЛЯ при принятии
   остальных полей формы, чтобы массовый `PATCH` формы настроек не падал целиком из-за одной
   защищённой категории).
5. Интеграция с `DTJ-370`: расширить `DispatchNotificationUseCase` (правка ОДНОЙ секции, не
   переписывание файла) — перед постановкой job внешнего канала вызывает
   `NotificationPreferencesRepositoryPort.findByUserCategoryChannel`, Given
   `shouldSuppressNow()===true` → job планируется с ОТЛОЖЕННЫМ временем исполнения (BullMQ delayed
   job до конца тихих часов), НЕ отбрасывается (`SRS-ADM-059`).
6. `NotificationPreferencesController`: `GET/PATCH /api/v1/notification-preferences` (собственные
   настройки пользователя, `scope=own` неявно — `userId` из JWT, без параметра).

## Критерии приёмки
1. Given `quiet_hours=22:00–08:00`, категория `'promotions'`, текущее время `23:00`, When
   диспетчеризация уведомления этой категории, Then отправка ОТКЛАДЫВАЕТСЯ до `08:00` следующего
   дня (`TC-ADM-023`).
2. Given категория `'order_updates'` активного заказа, те же тихие часы, When диспетчеризация,
   Then отправка НЕМЕДЛЕННО, тихие часы проигнорированы (`TC-ADM-024`).
3. Given `PATCH /notification-preferences` с телом, пытающимся установить `is_enabled=false` для
   `category='order_updates'`, When запрос обрабатывается, Then это ПОЛЕ игнорируется (остаётся
   `true`), ОСТАЛЬНЫЕ поля запроса (например, изменение `quiet_hours` для `'promotions'`)
   применяются успешно — не `400` на весь запрос.
4. Given окно тихих часов `22:00–08:00` (переход через полночь), When текущее время `02:00`, Then
   `shouldSuppressNow()` возвращает `true` (граничный случай перехода через полночь корректно
   обработан, не только простые интервалы в пределах одних суток).
