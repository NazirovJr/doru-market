## Задача
Расписание работы напрямую влияет на признак «открыто сейчас» на карте (CUJ-1, R1-6) — без
самостоятельного редактирования аптека вынуждена просить оператора платформы менять часы работы
вручную. Зона доставки (простая круговая модель, `max_delivery_radius_km`) — новое поле,
отсутствующее в исходной схеме, вводимое этим документом (D-06.1, §5.6) как основание для guard'а
checkout `DELIVERY_ZONE_EXCEEDED`.

## Технический контекст
`pharmacies.is_24_7`/`opening_time`/`closing_time` — существующие поля Группы A
(`11-database-schema.md`). `max_delivery_radius_km` — **[ДОПОЛНЕНИЕ]** этим тикетом (миграция,
дословно по DDL `SRS-ADM-050` из `27-module-admin-moderation-onboarding.md` §10.1). Использует
`OnboardingFacadePort` (расширяется методами `updateSchedule`/`updateDeliveryZone`) — оба поля
принадлежат агрегату `PharmacyAccount`, владеет `EP-03`, здесь — только presentation/application
обёртка `admin`, доменная валидация (например, `openingTime < closingTime`) — уже в
`PharmacyAccount`, не дублируется тут повторно.

## Что сделать
1. Миграция `00XX_pharmacies_max_delivery_radius_km.sql`: `ALTER TABLE pharmacies ADD COLUMN
   max_delivery_radius_km NUMERIC(5, 2) NOT NULL DEFAULT 10.0;` — дословно по `SRS-ADM-050`.
   Обновить Drizzle-схему `apps/api/src/db/schema/pharmacies.ts` (файл принадлежит `EP-01`/`EP-03`
   как создателю таблицы — здесь ТОЛЬКО добавление одной колонки, не переписывание файла целиком,
   координация аналогична правилу «одна строка экспорта» из `00-EPICS.md`).
2. Расширить `OnboardingFacadePort`: `updateSchedule(pharmacyId, { isOpen247, openingTime?,
   closingTime? }, actor)`, `updateDeliveryZone(pharmacyId, { maxDeliveryRadiusKm }, actor)`.
3. `UpdatePharmacyScheduleUseCase`/`UpdateDeliveryZoneUseCase` — policy владения
   (`pharmacyId ∈ actor.ownPharmacyIds` для `pharmacy_admin`), Zod-валидация формата времени
   (`HH:mm`) и диапазона радиуса (`> 0`, разумный верхний предел — например `≤ 50`, ASSUMPTION,
   задокументировать как таковой в коде).
4. `PharmacyScheduleController`: `PATCH /api/v1/pharmacy-accounts/:id/schedule`, `PATCH
   /api/v1/pharmacy-accounts/:id/delivery-zone` — `@Roles('pharmacy_admin', 'super_admin')`.
5. Frontend: `pharmacy-schedule-page.tsx` — форма с переключателем «Круглосуточно» (скрывает
   `openingTime`/`closingTime` при включении), два `TimePicker`/маскированных `Input`, отдельный
   блок «Зона доставки» — числовой инпут радиуса в км с текстовой подсказкой (через `useT()`) о
   связи с формулой тарифа доставки.

## Критерии приёмки
1. Given `pharmacy_admin` меняет расписание на своей точке, When `PATCH .../schedule` успешен,
   Then признак «открыто сейчас» на публичной карте немедленно отражает новое значение (проверяется
   косвенно — данные читаются картой `EP-08` из той же таблицы, без промежуточного кеша в этом
   тикете).
2. Given `maxDeliveryRadiusKm = -5` (отрицательное значение), When `PATCH .../delivery-zone`, Then
   `400 VALIDATION_ERROR`.
3. Given радиус аптеки установлен в `5` км, клиент оформляет заказ на адрес в `7` км, When checkout
   вызывает guard `OrdersFacade.isWithinDeliveryZone` (реализация — `EP-09`, вне этого тикета, но
   поле, которое ЧИТАЕТ этот guard, создано здесь), Then `422 DELIVERY_ZONE_EXCEEDED` — этот тикет
   ОТВЕЧАЕТ только за то, что значение корректно сохраняется и читаемо, не за сам guard.
4. Given `pharmacy_admin` сети `A` пытается изменить расписание аптеки сети `B`, When policy
   проверяется, Then `403 CROSS_TENANT_ACCESS_DENIED`.

## Риски и подводные камни
- `OrdersFacade.isWithinDeliveryZone` (реальный guard checkout, использующий это поле) —
  ответственность `EP-09`, реализуется отдельно и может отставать по времени от этого тикета —
  поле в БД полезно и без guard'а (уже используется формулой тарифа доставки, `REQ-DELIV-1`), не
  блокирующая зависимость.
- Полигональные зоны (не круг) — явно ASSUMPTION вне MVP (`SRS-ADM-050`), не реализуются этим или
  каким-либо другим тикетом R1 — если потребность возникнет, отдельный ADR архитектора.
- Файл `apps/api/src/db/schema/pharmacies.ts` — общий с `EP-01`/`EP-03` (создатель таблицы) — правка
  здесь ограничена ОДНОЙ колонкой, конфликт слияния решается rebase.
