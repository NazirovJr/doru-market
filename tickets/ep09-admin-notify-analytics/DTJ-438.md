## Задача

CUJ-11 (DTJ-422) не может проверить Telegram-уведомления на стенде: `TELEGRAM_API_BASE_URL`
захардкожен константой `https://api.telegram.org` в api и worker, у сид-пользователей нет
`telegram_chat_id`, нет способа повторно опубликовать событие для проверки дедупликации.
Найдено E2E DTJ-422 (2026-09-27).

## Что сделать

1. ENV `TELEGRAM_API_BASE_URL` (дефолт `https://api.telegram.org`) в api и worker через их
   конфиг-сервисы; обе константы убрать. Мок-сервер `tests/e2e/helpers/mock-telegram-bot-api-server.ts`
   должен быть достижим, если ENV указывает на него.
2. Контракт сида: поле `telegramChatId` у 1–2 пользователей (customer), сид заполняет его.
3. Повтор публикации для проверки дедупа: тестовый маршрут под флагом `E2E_TEST_ENDPOINTS`
   (как `GET /api/v1/_test/last-otp`, 404 при выключенном флаге, запрещён в production) —
   повторно отправить уже опубликованное outbox-событие по id.

## Критерии приёмки

1. Given `TELEGRAM_API_BASE_URL` на мок-сервер, When уведомление отправлено, Then мок получил запрос.
2. Given событие опубликовано повторно, Then в `notifications` ровно одна строка на канал (дедуп).
3. Given флаг выключен, Then тестовый маршрут отвечает 404; в production API с флагом не стартует.
