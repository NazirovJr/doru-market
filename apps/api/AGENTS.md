# apps/api — правила для агентов

Дополняет корневой [`AGENTS.md`](../../AGENTS.md); при конфликте прав корневой. Здесь только то, что специфично для API.

## Слои и модули
- Модуль `src/modules/<контекст>/`: `domain` → `application` → `infrastructure` и `presentation`; стрелки только внутрь.
  `domain` без фреймворков, ORM, `Date.now()`, `Math.random()`, `process.env` — время и id через порты `Clock`, `IdGenerator`.
- Порт в `application` объявляет интерфейс, а не тип инфраструктуры (`DrizzleDb` в сигнатуре порта — дефект); реализация — в
  `infrastructure`, привязка через DI-токен в `<контекст>.module.ts`.
- Межмодульно — только через фасад `modules/<контекст>/index.ts` (тип фасада + DI-токен). Глубокий импорт чужого слоя
  блокирует `arch:check`. Один адаптер/провайдер регистрируется в одном модуле.
- Написал use case, репозиторий, контроллер, guard — подключи в модуль; новый модуль — в `AppModule.imports` (гейт
  `tests/arch/runtime-connectivity.spec.ts`).

## Внедрение зависимостей
- **Каждый** параметр конструктора Nest-класса несёт явный `@Inject(ТОКЕН)`: сборка через esbuild и Node ESM не эмитит
  `design:paramtypes`, недекорированный параметр даёт `undefined` без ошибки компиляции (гейт `tests/arch/di-explicit-inject.spec.ts`).
- Исключение — класс, который создаётся вручную через `new` (pipes в `@Body(new …)`), и параметр со значением по умолчанию.

## Тесты
- Unit — `*.spec.ts` рядом с кодом: `pnpm --filter @dorutj/api test`. Интеграционные — `test/integration/**`, отдельный конфиг
  `vitest.integration.config.ts`, в `turbo run test` не входят: [`docs/guides/integration-tests.md`](../../docs/guides/integration-tests.md).
  Redis для тестов — только порт 6380; общая тестовая обвязка — алиас `@test/*`.
- В харнессах не ставь `PORT='0'`; своя миграция — своя БД `dorutj_test_<тикет>`.

## Миграции (`migrations/`)
- Файл `NNNN_<slug>.sql` + `NNNN_<slug>.down.sql`, запись в `migrations/meta/_journal.json`. Номер назначает координатор; занятые
  номера не переиспользуй.
- Drizzle применяет миграцию, только если её `when` в журнале **больше максимума уже применённых**: новая запись получает `when`
  выше всех существующих, иначе миграция молча пропускается.
- `ALTER TYPE … ADD VALUE` не выполняется в транзакции — выноси в отдельную миграцию. Права DDL — только у `dorutj_migrator`;
  приложение работает под `app_role`.

## Checkout и транзакции
- Запрос в БД на пути оформления заказа — только до открытия транзакции группы или внутри неё. Запрос через общий пул во время
  чужих транзакций даёт self-deadlock под нагрузкой (спека `checkout-race-conditions`): всё, что нужно (например, ставки
  комиссии), читай до `BEGIN`.
- Деньги — целые дирамы; `paid_escrow` достижим только по подписанному вебхуку (D-25).
