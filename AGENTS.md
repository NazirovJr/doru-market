# DoruTJ — правила работы в этом репозитории

> Читается автоматически агентскими инструментами. **Прочитай целиком перед первой строкой кода.**
> Это выжимка. Подробности — [`docs/05-DEVELOPER-HANDBOOK.md`](docs/05-DEVELOPER-HANDBOOK.md).

> **Твоя роль.** Если тебе выдали тикет `DTJ-*` и попросили написать код — ты **ИСПОЛНИТЕЛЬ**.
> Ты не принимаешь собственную работу, не меняешь решения `D-*`, версии пакетов, объём релиза
> и конфигурацию гейтов. Не согласен с решением — см. §6 [`CLAUDE-CTO.md`](CLAUDE-CTO.md),
> там порядок спора. Застрял — эскалируй, а не додумывай.

**Что это за проект:** фармацевтический маркетплейс Таджикистана + White-Label платформа
для аптечных сетей. Монорепо pnpm + Turborepo, NestJS 11 на Fastify, PostgreSQL + Drizzle,
React 19 + Vite, Flutter для мобильных клиентов.

**С чего начать:** [`docs/STATE-AND-RESUME-POINT.md`](docs/STATE-AND-RESUME-POINT.md) — где мы сейчас
и что делать дальше. Читать первым.

## Золотые правила

### 1. Не объявляй готовым непроверенное

```bash
pnpm verify    # typecheck + lint + arch:check + test:arch + test + build
```

Красное — это стоп. Не «потом починим», не «это чужой тест».
Упал тест, который ты не трогал — **разберись**: скорее всего ты сломал контракт. Это твой регресс.

**Однажды здесь сдали 12 красных тестов как готовую работу.** Среди них — тест, ловящий баг
в главной функции продукта. Тест написали правильно, но ни разу не запустили.

### 2. Написал компонент — подключи его в том же тикете

Написанный, но неподключённый код проходит все статические проверки и создаёт иллюзию готовности.

| Написал | Обязан подключить |
|---|---|
| Use case, репозиторий | провайдер в `<контекст>.module.ts` |
| Контроллер | `controllers: []` модуля |
| Модуль | `AppModule.imports` |
| Middleware | `AppModule.configure()` |
| Guard | провайдер модуля или `APP_GUARD` |
| npm-скрипт | **запусти его вручную** |
| Ключ i18n | во все три словаря `tj/ru/en` |

**Однажды здесь `TenantResolutionMiddleware` написали, а в `app.module.ts` оставили комментарий
«EP-02 подключит позже».** Не подключили. Ни один запрос не резолвил тенанта.
Оставлять комментарий вместо подключения — запрещено.

### 3. Никогда не отключай проверку ради зелёного гейта

Гейт, который зеленеет за счёт исключения кода из анализа, — не гейт.

| Запрещено | Что делать вместо |
|---|---|
| Удалить или закомментировать падающий тест | Починить код |
| Добавить `it.skip` | Починить код |
| Отключить правило в конфиге линтера | Исправить нарушение |
| Исключить папку из `arch:check` | Исправить нарушение или починить резолвер |
| Понизить `severity` с `error` на `warn` | Исправить нарушение |
| Ослабить порог покрытия | Дописать тесты |

**Однажды здесь `apps/admin` исключили из `arch:check`, и гейт позеленел.**

### 4. Подавление линтера — только с обоснованием

```ts
// eslint-disable-next-line no-restricted-globals -- этот файл И ЕСТЬ слой api, ему разрешён fetch
```

Без части после `--` подавление неотличимо от сокрытия дефекта и возвращается на доработку.

Подавлять можно, когда правило объективно неприменимо. Нельзя — когда правило нашло
настоящую проблему: `domain` импортирует ORM, `Date.now()` в домене, магическое число,
функция длиннее 40 строк.

### 5. Соблюдай направление зависимостей

```
presentation ──▶ application ──▶ domain ◀── infrastructure
```

- `domain/` — **ноль** фреймворков, ORM, сети, `Date.now()`, `Math.random()`, `process.env`.
  Время и идентификаторы — только через порты `Clock` и `IdGenerator`.
- `application/` не знает об `infrastructure` — она реализует его порты, но не импортируется.
- `presentation/` не лезет в `domain` напрямую — только через use case.
- Межмодульно — только через фасад `modules/<контекст>/index.ts`.
- Фронт: `app → pages → features → entities → shared`, горизонтальные импорты между фичами запрещены.

### 6. Деньги — целые дирамы, никогда float

```ts
const totalDiram: number = itemsDiram + deliveryDiram   // 1 TJS = 100 дирам
const total = 125.50 + 15.00                            // ЗАПРЕЩЕНО
```

### 7. Делай свой тикет и только его

Не реализуй то, что вне текущей волны. Увидел проблему в чужом коде — **напиши в отчёте,
не чини молча**. Не трогай файлы вне своего `files_owned`.

**Однажды здесь начали эпик из волны 6 и не закончили.** Потраченное время не дало ничего.

### 8. Barrel-файлы правь только добавлением строк

`index.ts`, `*.module.ts`, `package.json`, `tsconfig.json`, `ci.yml`, `docker-compose.yml`
не принадлежат никому. Перечитай файл непосредственно перед правкой, не удаляй чужие строки,
не переписывай целиком.

### 9. Ноль хардкода строк и цветов

Пользовательские строки — только через i18n (`tj/ru/en`). Цвета — только CSS-переменные
`--brand-*`. Смена бренда обязана стоить смену конфига, ноль правок кода.

### 10. Застрял — скажи, не додумывай

| Ситуация | Что делать |
|---|---|
| Требования нет или оно противоречиво | Реализуй разумно, запиши в `assumptions` |
| Нужен пакет, которого нет | **Не ставь.** Верни в `needsDependency` |
| Зависишь от несделанного тикета | Застабь порт `null`-адаптером с TODO и ссылкой на тикет |
| Не получается зелёная проверка | Верни `blockers` с текстом ошибки. **Не отключай проверку** |

**Честный отчёт с блокерами ценнее ложного «готово».** Ложное «готово» находят через три волны,
когда поверх уже построено ещё три эпика — и тогда оно стоит в разы дороже.

## Чего не делать никогда

- ❌ Сдавать непроверенное
- ❌ Оставлять написанный компонент неподключённым
- ❌ Отключать проверку ради зелёного гейта
- ❌ Удалять или скипать падающий тест
- ❌ Подавлять правило без обоснования
- ❌ Выдумывать `SRS-*` номера и несуществующие API
- ❌ Делать работу из другой волны
- ❌ `float` в денежных расчётах
- ❌ `Date.now()`, `Math.random()`, `process.env` в `domain/`
- ❌ Хардкодить строки и цвета
- ❌ Переписывать barrel-файл целиком
- ❌ Ставить зависимости внутри тикета реализации
- ❌ `TODO` без ссылки на тикет, который его закроет
- ❌ Коммитить мусор

## Формат отчёта о сдаче тикета

```
ТИКЕТ: DTJ-NNN
ФАЙЛЫ: путь — что сделано
ПОДКЛЮЧЕНИЕ К РАНТАЙМУ: где зарегистрировано / маршрут проверен curl'ом
КРИТЕРИИ ПРИЁМКИ: каждый — ВЫПОЛНЕН (файл:функция) или НЕ ВЫПОЛНЕН (причина)
ТЕСТЫ: файл — N кейсов, из них M негативных
ПРОВЕРКИ: вывод tsc / eslint / vitest / depcruise / test:arch
ДОПУЩЕНИЯ: что домыслил, потому что спека молчала
БЛОКЕРЫ: что не смог и почему
НАЙДЕННЫЕ ЧУЖИЕ ПРОБЛЕМЫ: что заметил вне своего тикета
НУЖНЫЕ ЗАВИСИМОСТИ: пакеты, которые не стал ставить сам
```
